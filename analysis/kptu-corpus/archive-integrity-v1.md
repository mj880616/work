# KPTU / Web1 아카이브 원문 무결성 검증 규칙 v1

배경:
코퍼스 수집 과정에서 게시목록 제목·작성부서와 상세페이지/첨부파일이 서로 맞지 않는 사례가 확인됐다.
특히 2026-09-11 공공기관 인력감축 취재요청 게시물은 목록 메타데이터와 상세페이지 작성부서가 달랐고, 연결된 HWP 본문은 다른 행사 자료였다.

따라서 '게시물 URL이 열리는가'만 확인해서는 아카이브 신뢰성을 보장할 수 없다.

## 1. 게시 직후 자동검사

### 메타데이터 일치
- 목록 제목 ↔ 상세 제목
- 목록 작성부서 ↔ 상세 작성부서
- 목록 날짜 ↔ 상세 날짜
- 문서 유형 ↔ 제목 태그

하나라도 다르면 manual_review 상태로 보낸다.

## 2. 첨부 본문 일치

HWP/PDF 텍스트를 추출해 제목 핵심어와 비교한다.

예:
제목:
공공기관 인력 감축 방침 규탄 기자회견

첨부 첫 본문:
폭염 지옥 뚫는 투쟁버스

→ 제목 핵심어 겹침 0
→ 오류 가능성 높음
→ 자동 게시/분석 제외

### 권장 기준
- 제목 핵심어 3개 이상 추출
- 본문에서 25% 미만만 확인 → 경고
- 0개 → 강한 경고
- 작성부서 불일치 + 제목 겹침 0 → 자동 제외

## 3. 파일명 검사

첨부의 Content-Disposition 파일명도 검사.

- 문서 제목과 파일명 핵심어가 완전히 다르면 경고
- 날짜가 크게 다르면 경고
- 취재요청 게시물에 보도자료/다른 행사 파일이 연결되면 경고

단, 파일명은 최종 판단 근거가 아니라 보조 신호.

## 4. Web1 원본 우선순위

같은 사건에 자료가 여러 군데 있을 경우:

1. 사용자가 검토·확정한 Web1 이벤트 페이지
2. 원본 Drive 파일
3. KPTU 게시물 본문
4. KPTU 첨부파일

순으로 신뢰 레이어를 둔다.

KPTU 첨부가 Web1/Drive 원본과 다르면 자동으로 덮어쓰지 않는다.

## 5. 아카이브 상태

문서마다 다음 상태를 저장하는 것이 좋다.

- verified: 제목/본문/첨부 일치 확인
- metadata_only: 메타만 수집
- attachment_unverified: 첨부는 있으나 텍스트 검증 전
- mismatch: 불일치 발견
- manual_review: 사람이 확인 필요

## 6. 분석 코퍼스 편입 조건

심층분석 기본 조건:
- 제목·작성부서 일치
- HWP/PDF 본문 500자 이상 또는 신뢰할 수 있는 HTML 본문
- 제목 핵심어와 본문 일치
- 중복자료 아님

예외는 별도 이유를 기록.

## 7. 현재 코퍼스에서 확인된 규모

180건 표본 자동검증에서:
- 작성부서 불일치: 5건
- 제목-본문 겹침이 매우 낮은 의심자료: 27건

27건 모두 원문 오류라는 뜻은 아니다.
이미지 중심 문서나 HTML 추출 실패도 포함된다.
따라서 의심 → 자동 제외가 아니라 의심 → 원본 확인 흐름이 적절하다.

## 8. 장기 개선

Web1 성명·보도자료 아카이브의 각 항목에 다음 필드를 추가할 수 있다.

- source_type: drive / kptu / local
- source_id
- verification_status
- verified_at
- checksum
- attachment_names
- extracted_text_chars

그러면:
- 중복 업로드
- 엉뚱한 첨부
- 이전 버전 게시
- KPTU 첨부 교체
를 추적할 수 있다.

## 결론

이번 코퍼스 구축에서 가장 중요한 기술적 교훈은:
웹페이지가 정상적으로 열리는 것과 그 안의 자료가 올바른 것은 별개라는 점이다.

향후 아카이브는 URL 수집이 아니라
메타데이터 + 원문내용 + 첨부파일의 삼중 일치 검증을 기본으로 하는 편이 좋다.

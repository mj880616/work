# 읽고 생각하고 쓰기 — 사이트 설계

작성일: 2026-09-17
상태: 사용자 승인 후 구현계획 작성 전 설계 고정본

## 1. 목적

이 사이트는 독서 기록장이 아니라 개인 지식·사고 저장소다. 핵심 흐름은 `읽기 → 메모 → 질문 → 연결 → 학습 → 다시 읽기 → 쓰기`다.

저장 자체보다 중요한 것은 과거의 자료와 메모가 이후의 생각과 글쓰기에 다시 연결되는 것이다.

## 2. 핵심 설계 원칙

1. 자료는 한 번만 저장한다.
2. 같은 자료를 날짜, 주제, 질문, 학습, 글쓰기에서 여러 방식으로 다시 본다.
3. 날짜는 기록의 시간축이고, 주제는 사고의 축이다.
4. 메모는 자료에 종속될 수도 있고 독립적으로 존재할 수도 있다.
5. 질문은 주제와 별도의 핵심 객체로 취급한다.
6. 학습은 날짜보다 과정·구조 중심으로 관리한다.
7. 글쓰기는 완성글뿐 아니라 씨앗부터 초안까지의 과정을 저장한다.
8. 분류는 기록을 방해하지 않도록 선택적으로 적용한다.

## 3. 사이트 정체성과 명칭

사이트 제목은 `읽고 생각하고 쓰기`로 한다.

가칭 저장소명은 `read-think-write`다. 기존 `mj880616/work`와 분리된 별도 GitHub Pages 사이트로 운영한다.

예상 주소는 `https://mj880616.github.io/read-think-write/` 형태다.

## 4. 정보 구조

메인 내비게이션은 다음 여섯 영역으로 구성한다.

- 읽기
- 생각
- 주제
- 학습
- 쓰기
- 아카이브

메인은 단순 메뉴판이 아니라 현재 사고 활동을 이어갈 수 있는 대시보드로 만든다.

메인 대시보드에는 다음을 우선 노출한다.

- 최근 읽은 글
- 최근 메모
- 계속 붙들고 있는 질문
- 진행 중인 학습
- 글쓰기 씨앗

## 5. 읽기

읽기는 기사, 칼럼, 논문, 책, 보고서, 인터뷰, SNS 글, 번역문 등 외부에서 읽은 자료를 보관하는 영역이다.

각 자료는 다음 필드를 가진다.

- 제목
- 원제(선택)
- 저자
- 출처
- 발표일
- 원문 링크
- 본문 또는 번역문
- 공개 여부
- 생성일/수정일

자료 하단에는 `나의 메모` 입력 영역을 둔다.

첫 등록 자료는 다음으로 한다.

- 날짜: 2026-09-14
- 제목: 기술노동자 권력의 부상과 몰락
- 원제: The Rise and Fall of Tech Worker Power
- 저자: JS Tan, Clarissa Redwine
- 출처: Boston Review
- 본문: 현재 대화에서 완성한 한국어 전체 번역문

초기 연결 주제는 `기술노동`, `노동운동` 정도만 둔다. 계급의식, 노동자 통제, 산업민주주의 등은 실제 메모가 쌓이면서 확장한다.

## 6. 날짜 아카이브

날짜 아카이브는 시간순으로 기록을 복원하기 위한 화면이다.

계층은 다음과 같다.

`연도 → 월 → 날짜 → 자료`

예:

`2026년 → 9월 → 9월 14일 → 기술노동자 권력의 부상과 몰락`

연도 페이지에서 월은 큰 토글로 표시한다. 월을 열면 날짜가 나오고, 날짜 아래 자료 제목을 누르면 본문이 펼쳐진다. 본문 아래에는 해당 자료에 연결된 `나의 메모`가 나타난다.

기본 URL은 다음 형식을 사용한다.

- `/archive/2026/`
- `/archive/2026/09/`

## 7. 생각과 메모

메모는 두 종류를 모두 지원한다.

1. 특정 자료에 연결된 메모
2. 특정 자료 없이 독립적으로 작성한 메모

메모는 자유 텍스트가 기본이며, 선택적으로 다음 유형을 붙일 수 있다.

- 생각
- 질문
- 좋은 문장
- 반론
- 글감
- 업무 연결

유형 선택은 필수가 아니다.

## 8. 질문

질문은 독립된 핵심 객체다. 주제와 구분한다.

예:

- 주제: AI와 노동
- 질문: AI가 절약한 시간은 누구에게 돌아가는가?

질문 페이지에는 다음이 연결될 수 있다.

- 관련 읽기
- 관련 메모
- 관련 학습
- 관련 글쓰기
- 현재 나의 생각

초기 버전에서는 질문 객체와 연결 구조를 구현하되, 생각 변화의 버전 히스토리는 2차 기능으로 둔다.

## 9. 주제

주제는 단순 태그가 아니라 여러 기록을 횡단해 보는 페이지다.

주제 페이지는 다음을 모은다.

- 관련 읽기
- 관련 메모
- 관련 질문
- 관련 학습
- 관련 글쓰기
- 현재까지의 생각

초기 주제를 과도하게 만들지 않고 실제 기록에서 반복되는 관심사를 기준으로 늘린다.

## 10. 학습

학습은 날짜가 아니라 구조화된 과정 중심으로 운영한다.

예:

`러시아 혁명사`

- 개요
- 연표
- 01. 1905년 혁명
- 02. 제1차 세계대전
- 03. 2월 혁명
- 04. 이중권력
- 05. 10월 혁명
- 인물
- 개념
- 관련 읽기
- 내 질문

학습 프로젝트 안에서 나온 메모와 개념도 주제·질문과 연결할 수 있어야 한다.

## 11. 쓰기

글쓰기 프로젝트는 완성글뿐 아니라 과정 전체를 저장한다.

상태는 다음과 같다.

`씨앗 → 문제의식 → 자료수집 → 개요 → 초안 → 완성`

각 글쓰기 프로젝트에는 관련 자료, 메모, 질문, 학습 프로젝트를 연결할 수 있다.

## 12. 검색

1차 단계에서는 제목·메모·주제·질문 중심의 기본 검색을 제공한다.

전체 본문 검색과 학습·글쓰기 전체 검색은 데이터가 쌓이는 2차 단계에서 확장한다.

의미 기반 AI 검색은 초기 범위에서 제외한다.

## 13. 데이터 모델

핵심 엔터티는 다음 여섯 가지다.

- Resource
- Note
- Topic
- Question
- LearningProject
- WritingProject

엔터티 간 연결을 위해 Relation 테이블을 둔다.

Relation은 최소 다음 정보를 가진다.

- id
- source_type
- source_id
- target_type
- target_id
- relation_type
- created_at

각 엔터티의 소유권은 인증 사용자 기준으로 제한한다.

## 14. 공개/비공개 정책

기본 원칙은 다음과 같다.

- 개인 메모: 기본 비공개
- 질문: 기본 비공개
- 글쓰기 초안: 기본 비공개
- 학습자료: 기본 비공개, 필요 시 공개 가능
- 자료 본문/번역문: 기본 비공개, 공개 가능 여부를 사용자가 별도로 선택

개인 메모 데이터는 GitHub 저장소에 직접 넣지 않고 Supabase에 저장한다.

저작권이 있는 외부 글의 전체 번역문은 공개 배포를 기본값으로 하지 않는다. 첫 Boston Review 전체 번역문도 인증 후 개인용으로만 보이도록 저장한다. 원문 링크와 서지정보는 별도로 표시한다.

## 15. 인증 및 저장 구조

별도 사이트는 기존 `work` 앱 전체 구조를 복제하지 않는다.

재사용하는 것은 개념과 패턴이다.

- Supabase 인증
- 중앙화된 API 호출
- 세션 갱신 처리
- 사용자별 데이터 접근 제어

새 사이트에는 이 기능만 담은 작은 전용 런타임을 둔다.

기존 `work`의 복잡한 업무 모듈, 캘린더, 프로젝트, 메시지, 알림 구조는 가져오지 않는다.

## 17. 오류 및 저장 UX

모든 저장 동작은 다음 상태를 구분한다.

- 저장 중
- 저장 완료
- 저장 실패

저장 실패 시 사용자가 작성 중인 텍스트를 잃지 않도록 브라우저 내 임시 상태를 유지한다.

네트워크 오류와 인증 만료는 별도 메시지로 구분한다.

## 18. 구현 단계

전체 사이트는 한 번에 구현하지 않고 세 단계로 나눈다.

### 1단계 — 기록 기반

첫 구현계획의 범위다.

포함:

- 별도 사이트 기본 셸과 로그인
- 메인 대시보드 최소형
- 읽기 자료 상세
- 2026년 날짜별 아카이브
- 자료별 `나의 메모` 저장
- 독립 메모 작성
- 주제 생성 및 자료/메모 연결
- 질문 생성 및 자료/메모 연결
- 제목·메모·주제·질문 기본 검색
- 첫 Boston Review 자료 등록

성공하면 즉시 실제 기록을 시작할 수 있어야 한다.

### 2단계 — 학습과 쓰기

- 학습 프로젝트
- 구조화된 학습 목차와 문서
- 글쓰기 프로젝트
- `씨앗 → 문제의식 → 자료수집 → 개요 → 초안 → 완성` 상태
- 자료·메모·질문과 학습/글쓰기 간 연결
- 검색 범위 확장

### 3단계 — 사고 확장

- 생각 변화 버전 기록
- 자동 관계 추천
- 의미 기반 AI 검색
- 과거 메모 재발견 기능
- 주제별 사고 변화 요약
- 관련 읽을거리 제안

## 21. 1단계 성공 기준

첫 단계가 성공했다고 보는 기준은 다음과 같다.

## 22. 장기 방향

이 사이트의 장기 목표는 개인 위키나 북마크 목록이 아니다.

`무엇을 저장했는가`보다 `저장한 것들이 이후의 생각과 다시 만날 수 있는가`를 중심에 둔다.

최종적으로는 읽은 자료, 생각, 질문, 학습, 글쓰기가 서로 연결되면서 사용자의 장기적인 문제의식과 사고 변화를 추적하고 확장하는 작업공간이 되는 것을 목표로 한다.

# 📱 폰 가능 — 바구니 메모를 "쓰기요청 후보"로 보내기 설계(BASKET-4b-2)

2026-10-14 야간, Claude Code 웹. 시작 main `a128799`(#544). **문서 전용 설계 메모이며 코드·DB·Edge는 바꾸지 않는다.** 구현은 아래 "사용자가 결정할 항목"이 정해진 뒤 별도 PR로 한다.

## 1. 기준(바뀌지 않는 것)

- [원본 경계](ai-work-system-source-of-truth.md): 역사·근거는 Drive 업무·장기기억 원장, Web2는 현재판. Web2 기록은 원장의 `쓰기요청`으로만 승격하고 **자동 승격은 만들지 않는다.** 원장 쓰기는 ChatGPT 단일 writer만 한다. **Web2·Claude·개발 도구는 Drive 원장에 쓰지 않는다.**
- [바구니 확정 설계](basket-design.md) 11번 결정(2026-10-09): 원장은 **쓰기요청 후보까지만** 표시한다. 후보 확정은 제출·승격 완료가 아니다. 가짜 원장 ID·완료 연결을 만들지 않는다. 화면 표시는 "쓰기요청 후보(미제출)".
- 바깥 AI 제안(`write_request_candidate`)은 이유·근거 메모 ID만 담고, 제안만으로 아무것도 바뀌지 않는다. 지금 AI 정리 결과 화면은 담당조직·프로젝트만 확정할 수 있다(`basket-classification-ui.js`의 `supported`).

| 항목 | 현재 |

| 쓰기요청 후보 저장 | 없음. `write_request_candidate`는 AI 정리 결과 파서가 종류로만 인정하고 확정은 막혀 있다. |

| Drive 원장 | Web2에서 접근 경로 없음(그대로 둔다). |

## 3. 저장 위치

**권장: 메모 `app_notes.metadata.write_request` 객체 하나(메모당 후보 1개).** DB 변경 없음.

```json
{"write_request":{"reason":"10/20 기자회견 합의 근거","marked_at":"2026-10-15T01:00:00.000Z","handed_off_at":null}}
```

- `reason`: 선택, 500자 이하 일반 글. `marked_at`: 후보로 표시한 시각. `handed_off_at`: 사용자가 "ChatGPT에 넘겼어요"를 직접 누른 시각(넘김 ≠ 원장 기록).
- 다른 metadata 키(`tasks` 등)는 그대로 둔다. `updated_at`(원문 버전)은 올리지 않는다 → AI 맡기기·AI 정리 결과·사진 글자 버전 비교에 영향 없음(#544와 같은 이유).
- 원장 행 ID·URL·실행 명령은 저장하지 않는다.

다른 안과 비교:

| 안 | 장점 | 단점 |
| --- | --- | --- |
| **A. 메모 metadata(권장)** | DB·Edge 변경 없음, #544와 같은 검증된 경로, 메모와 함께 지워짐 | metadata 키·크기를 DB가 검사하지 않음(소유자만 쓸 수 있으므로 화면에서 제한) |
| B. `app_record_links`에 새 종류 | 연결 목록·홈 표시와 한 구조 | DB 제약·RLS·RPC 변경 필요(§6 정지 지점), 원장 후보를 "연결"처럼 보이게 할 위험 |
| C. 새 표 | 상태 이력 관리 쉬움 | 새 상태 저장소 금지 원칙(AGENTS.md 4절)에 어긋남, DB 변경 |

## 4. DB·Edge 필요 여부

- **DB: 필요 없음(A안).** 기존 owner RLS의 `app_notes` PATCH만 쓴다. 나중에 metadata 키 검사를 서버에서 강제하고 싶으면 그때 DB check 제약을 별도 제안한다.
- **Edge: 필요 없음.** 복사 글은 화면에서 만든다. Drive·원장 쓰기 없음.
- 따라서 구현 PR은 📱 폰 가능(화면·검사·캐시 연쇄)이고 운영 적용은 Pages 배포뿐이다.

## 5. 중복과 결과 불명 처리

- **중복**: 메모당 후보 1개라서 "이미 후보예요"가 기본 동작. 표시 요청은 `metadata->write_request`가 비어 있을 때만 쓰는 조건부 PATCH(`updated_at=eq.<읽은 값>&metadata->write_request=is.null`)로 보낸다. 0행이면 한 번 다시 읽어 이미 후보면 "이미 후보예요", 아니면 "메모가 바뀌었어요. 다시 열어 주세요".
- **결과 불명**(시간 초과·응답 유실·5xx): 다시 보내지 않는다. 한 번 다시 읽어 `write_request`가 있으면 성공으로 보고, 읽기도 실패하면 "확인하지 못했어요. [메모 다시 불러오기]로 확인해 주세요"만 표시하고 버튼을 끈다.
- **후보 취소**: `metadata->write_request->>marked_at=eq.<표시 시각>` 조건으로 그 키만 지운다(다른 탭이 새로 표시한 것을 지우지 않음).
- **복사**: 클립보드 복사는 외부 쓰기가 아니므로 몇 번 눌러도 된다. 복사 성공을 "넘김"이나 "원장 기록"으로 표시하지 않는다.
- 계정·업무공간이 바뀐 뒤 도착한 결과는 반영·표시하지 않는다(#544와 같은 epoch·scope 확인).

## 6. 화면 흐름(바구니 메모 읽기 화면)

1. 읽기 화면 버튼 줄에 **[쓰기요청 후보]** 추가(연결하기·할 일 만들기 옆).
2. 누르면 작은 입력: "왜 원장에 남길까요?(선택)" 한 칸 + [후보로 표시] [취소].
3. 표시 뒤 메모 아래에 상자 하나: **쓰기요청 후보(미제출)** · 이유 · [ChatGPT에 넘길 글 복사] · [넘겼어요] · [후보 취소].
4. [ChatGPT에 넘길 글 복사]: 메모 원문, 이유, 메모 링크(`?view=basket&note=`), "이 글은 쓰기요청 후보이며 아직 원장에 기록되지 않았다"는 안내를 묶어 복사. 원장 쓰기 지시·자동 실행 문구는 넣지 않는다(외부 입력과 실행 분리).
5. [넘겼어요]를 누르면 `handed_off_at`만 기록하고 표시를 **쓰기요청 후보(ChatGPT에 넘김)**로 바꾼다. 원장에 실제로 들어갔는지는 Web2가 알 수 없으므로 "기록됨"으로 표시하지 않는다.
6. 바구니 목록·메모 상태줄에 "쓰기요청 후보" 표시(선택 사항, 결정 4).
7. 390·1280 폭, 키보드·터치 접근성, 수정 화면에서는 숨김. 기존 버튼 컴포넌트 재사용.

AI 정리 결과에서 온 `write_request_candidate` 제안은 첫 구현에서 "직접 [쓰기요청 후보]로 표시해 주세요" 안내만 하고 자동 반영하지 않는다(결정 5).

## 7. 사용자가 결정할 항목(일상어)

1. **이유를 꼭 적어야 하나요?** — 권장: 적지 않아도 됨(빈칸 허용).
2. **메모 하나에 후보는 하나만?** — 권장: 하나만. 같은 메모를 두 번 올릴 일이 생기면 그때 늘린다.
3. **ChatGPT에 넘겼다는 표시는 누가?** — 권장: 사용자가 [넘겼어요]를 직접 누름. 복사만으로는 바꾸지 않음.
4. **바구니 목록에도 "쓰기요청 후보" 표시를 붙일까요?** — 권장: 붙임(찾기 쉬움).
5. **AI 정리 결과가 "쓰기요청 후보"를 제안하면?** — 권장: 이번엔 안내만, 자동 표시는 다음 단계.
6. **Drive 읽기용 사본에 후보 목록을 넣을까요?** — 권장: 넣지 않음(사본이 원장처럼 읽힐 위험).
7. **원장에 실제로 들어간 뒤 Web2에 원장 번호를 적을까요?** — 권장: 적지 않음(Web2는 원장을 확인할 수 없고, 가짜 ID 금지 원칙).

## 8. 하지 않는 것

Drive 원장 직접 쓰기, ChatGPT 자동 호출·자동 제출, 원장 ID 저장, 새 표·RPC·Edge, AI 제안 자동 확정, `app_record_links` 변경.

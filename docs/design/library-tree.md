## 0. 한눈에

- 자료실 목록을 **토글 안에 토글이 들어가는 나무 모양**으로 바꾼다. 기본 묶음은 프로젝트 3단, 맨 아래 '프로젝트 없음'.
- 프로젝트 토글은 **프로젝트 화면을 그대로 따라간다**(자료실에서 추가·이름·삭제·순서 변경 없음).
- 프로젝트 틀 안(그리고 '프로젝트 없음' 안)에 **자료실 전용 폴더**를 자유롭게 만든다. 폴더 안 폴더 가능. 다른 화면에는 보이지 않는다.
- 폴더는 **Web2 DB에만** 있는 정리 틀이다. Drive 원본 폴더·파일은 그대로 둔다.
- DB는 **새 표 2개**(폴더, 자료-폴더 연결)만 더한다. 기존 표(`app_documents` 등)·정책·함수는 고치지 않는다. 권한은 지금과 같은 "소유자 한 사람만" 경계.
- 순서: ① DB(이번 DB PR, 적용 직전 정지) → ② 화면 보기(트리 그리기, 묶기 전환) → ③ 폴더 편집(⋯ 메뉴) → ④ PC 끌어다 놓기.

## 3. 폴더 저장 구조

### 3.1 후보 비교

권한을 넓히거나 RLS를 느슨하게 하는 후보는 뺐다. 셋 다 기존 소유자 경계(`private.app_is_workspace_owner`)를 그대로 쓴다.

| | A. 새 표 2개: 폴더 + 자료-폴더 연결 (**추천**) | B. 새 폴더 표 + `app_documents.library_folder_id` 칸 | C. 새 표 없이 `app_profiles` 칸(jsonb)에 폴더 나무 저장 |
| --- | --- | --- | --- |
| 기존 표 변경 | **없음** | `app_documents`에 칸 추가 + 기존 정책 `task12a_owner_all`의 WITH CHECK 고치기 | `app_profiles`에 칸 추가 |
| 승인형 DB workflow | 확장 규칙으로 통과(새 표·새 정책·새 함수·새 표 트리거) | 기존 정책 ALTER는 확장 규칙이 거절(`policy-drop-alter`) → SQL Editor 경로 | 통과하지만 검사 조건이 복잡 |
| 다른 화면 영향 | 없음(아무도 새 표를 안 읽음) | 칸이 늘어 `select=*`로 읽는 곳(자료실·Edge)이 칸 하나를 더 받음. 동작은 같지만 핵심 표를 건드림 | 없음 |
| 순환·삭제 시 위로 | DB 트리거가 한 곳에서 지킴 | 같음 | 앱이 jsonb 전체를 고쳐 씀(동시 저장 시 덮어쓰기 위험) |
| 자료 하나 = 폴더 하나 | 연결 표의 기본키(`document_id`)가 지킴 | 칸 하나라 자연히 지킴 | 앱이 지킴 |
| 자료를 지우면 | 연결 행이 함께 지워짐(외래키 cascade) | 칸이 함께 사라짐 | 앱이 정리해야 함(남은 id는 무시) |
| 되돌리기 | 새 표 2개만 지우면 끝(자료·기존 표 그대로) | 칸 지우기 + 정책 원복(정책 원복은 별도 승인) | 칸 지우기 |

추천 이유: 요구 ③의 "다른 화면 영향 없음"을 저장 구조에서부터 지킨다. 자료 표·정책·Edge를 하나도 고치지 않고, 되돌리기도 새 표 2개 삭제로 끝난다. 노트 폴더 설계(`note-folders.md` 결정 1)의 "빈 폴더·폴더 순서가 필요하면 새 표" 기준에도 맞는다(이번 요구는 빈 폴더·순서·폴더 안 폴더가 모두 필요).

### 3.2 A안 표 모양 (DB PR에 그대로 들어감)

**`public.app_library_folders`** — 자료실 전용 폴더

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| `id` | uuid, 기본값 자동 | 폴더 번호 |
| `workspace_id` | uuid, 필수, `app_workspaces` 삭제 시 함께 삭제 | 소유 경계 |
| `project_id` | uuid, **비어 있어도 됨**, `app_spaces` 삭제 시 **비움**(set null) | 이 폴더가 들어 있는 프로젝트 토글. 비어 있으면 '프로젝트 없음' |
| `parent_id` | uuid, 비어 있어도 됨, 같은 표 | 상위 폴더. 비어 있으면 프로젝트 토글 바로 아래 |
| `name` | text, 1~40자, 앞뒤 공백·제어문자 없음 | 폴더 이름(같은 이름 허용) |
| `sort_order` | integer, 기본 0 | 같은 상위 안 순서(작은 값이 위) |
| `created_at` | timestamptz, 자동 | |

**`public.app_library_folder_items`** — 자료가 어느 폴더에 있는지

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| `document_id` | uuid, **기본키**, `app_documents` 삭제 시 함께 삭제 | 자료 하나는 폴더 하나에만 |
| `folder_id` | uuid, 필수, `app_library_folders` | 들어 있는 폴더 |
| `workspace_id` | uuid, 필수 | 소유 경계(정책 검사용) |
| `created_at` | timestamptz, 자동 | |

- 연결 행이 없는 자료 = 그 자료의 프로젝트 토글 바로 아래(폴더 밖).
- **폴더와 자료는 같은 프로젝트 틀이어야 한다.** 넣을 때 DB 정책이 "폴더의 `project_id`와 자료의 `project_id`가 같음(둘 다 비어 있음 포함)"을 검사한다.
- 넣은 뒤 다른 화면(⋯ 수정)에서 자료의 프로젝트를 바꾸면 연결 행이 어긋난다. 이때 화면은 **어긋난 연결을 없는 것으로 보고** 자료를 새 프로젝트 토글 바로 아래에 보인다(5.4). 어긋난 행은 그 자료를 다음에 옮길 때 고쳐 쓰거나 지운다. `app_documents`에 트리거를 달지 않기 위한 선택이다(기존 표 무변경).
- 프로젝트를 지우면: 자료는 기존 트리거가 '프로젝트 없음'으로 보내고, 폴더는 `project_id`가 비면서 **폴더째 '프로젝트 없음'으로 옮겨진다**. 둘 다 비어 있으므로 연결도 그대로 맞는다(정리한 폴더 구조가 살아남음, 결정 D4).

### 3.3 권한 (RLS)

- 두 표 모두 RLS 켬. 호스팅 기본 권한을 모두 걷고(`revoke all … from public, anon, authenticated, service_role`), authenticated에 필요한 것만 준다. anon·PUBLIC·service_role 권한 없음(Edge는 이 표를 안 씀).
- 폴더: 읽기·지우기, 넣기는 `workspace_id, project_id, parent_id, name, sort_order` 칸만, 고치기는 `parent_id, name, sort_order` 칸만. **`project_id`·`workspace_id`는 고칠 수 없다**(폴더를 다른 프로젝트로 옮기지 않음, 결정 D5).
- 연결: 읽기·지우기, 넣기는 `document_id, folder_id, workspace_id`, 고치기는 `folder_id`만.
- 정책은 표마다 하나, 대상 `authenticated`만:
  - 폴더: `private.app_is_workspace_owner(workspace_id)` + 넣기·고치기 때 `project_id`가 비었거나 같은 작업공간 프로젝트(`private.app_space_in_workspace`, 기존 함수 재사용).
  - 연결: `private.app_is_workspace_owner(workspace_id)` + 넣기·고치기 때 폴더와 자료가 같은 작업공간이고 같은 프로젝트 틀.
- 새 함수는 트리거 함수 2개뿐이고 둘 다 `SECURITY INVOKER`, `search_path = ''`, 실행권은 PUBLIC·anon·authenticated·service_role에서 모두 회수(트리거는 실행권 없이도 돈다). 즉 **로그인한 소유자가 자기 권한으로 하는 일만 한다.** 권한을 넘어서는 함수(DEFINER)는 없다.

### 3.4 순환 막기·삭제 시 한 단 위로: 트리거 vs 앱

| | DB 트리거 (**추천**) | 앱(화면 코드) |
| --- | --- | --- |
| 순환(자기 아래로 옮기기) | 저장 순간 DB가 거절. 두 창에서 동시에 서로를 아래로 옮겨도 작업공간 단위 잠금으로 한 번에 하나씩 | 화면이 가진 목록으로 검사. 두 창·두 기기에서 동시에 옮기면 순환이 생길 수 있음 |
| 삭제 시 한 단 위로 | 폴더를 지우는 한 번의 요청 안에서 하위 폴더·자료를 상위로 올린 뒤 지움. 중간 실패가 없음 | 하위 폴더 고치기 → 자료 연결 고치기 → 폴더 지우기를 여러 번 요청. 중간에 끊기면 자료가 사라진 폴더를 가리키다 cascade로 연결이 지워져 프로젝트 맨 위로 떨어질 수 있음 |
| 같은 프로젝트 틀 | 저장 때 확인 | 화면만 확인(다른 경로로 저장하면 못 막음) |
| 비용 | 트리거 함수 2개, DB 승인 1회 | DB 변경 없음 |

AGENTS.md §3-2("화면 제한만으로는 부족, 서버·DB에서 지킴")에 맞춰 트리거를 추천한다. PRJ-3단(`app_spaces_depth_guard`)과 같은 모양이라 시험 방식도 그대로 쓴다.

트리거 내용:

1. `app_library_folders_tree_guard` — 넣기, 또는 `parent_id`를 바꿀 때만.
   - 상위 폴더가 같은 작업공간·같은 프로젝트 틀인지(아니면 `LIB_FOLDER_SCOPE`).
   - 새 상위에서 맨 위까지 올라가며 자기 자신을 만나면 거절(`LIB_FOLDER_CYCLE`).
   - 폴더 깊이 3단 초과 거절(`LIB_FOLDER_DEPTH`, 결정 D3). 옮기는 폴더 아래 단 수까지 셈.
   - 작업공간 단위 트랜잭션 잠금(`pg_advisory_xact_lock`)으로 동시 옮기기를 한 줄로 세움.
2. `app_library_folders_lift_on_delete` — 지우기 직전.
   - 바로 아래 폴더의 `parent_id`를 지우는 폴더의 상위로(맨 위였으면 비움).
   - 안의 자료 연결을 상위 폴더로 옮김. 맨 위 폴더였으면 연결만 지움 → 자료는 프로젝트 토글 바로 아래.
   - 작업공간 삭제처럼 다른 삭제에 딸려 지워질 때(트리거 깊이 > 1)는 아무것도 하지 않는다.
   - 자료(`app_documents`)·Drive 파일은 어느 경우에도 지우지 않는다.
   - 다른 화면에서 프로젝트가 바뀌어 틀이 어긋난 연결은 위로 올리지 않고 지운다(그 자료는 이미 새 프로젝트 토글 바로 아래로 보이므로 잘못된 폴더로 들어가지 않게).
   - **폴더 지우기는 요청 하나에 폴더 하나.** 한 요청으로 부모와 자식을 함께 지우면 PostgreSQL이 "이미 트리거가 고친 행" 오류로 그 요청 전체를 취소한다(아무것도 안 바뀜, 로컬 시험으로 확인). 화면은 ⋯ 메뉴로 한 개씩만 지우므로 문제없고, 여러 개를 정리할 때는 아래 폴더부터 지운다.

거절 오류는 SQLSTATE `23514` + 문구 앞머리(`LIB_FOLDER_CYCLE:` 등)로 고정해 화면이 일상어로 바꿔 보인다.

## 4. 순서 저장

- 폴더 순서: `sort_order` 정수. 새 폴더는 같은 상위의 맨 아래(가장 큰 값 + 1024). 옮길 때는 앞뒤 두 값의 가운데를 쓰고, 틈이 없으면 그 상위의 형제만 1024 간격으로 다시 매긴다(형제 수만큼 요청, 보통 몇 개).
- 폰 ⋯ '위로·아래로': 바로 위(아래) 형제와 `sort_order`를 맞바꾼다(요청 2개).
- 파일 순서는 저장하지 않는다: 토글 안 파일은 지금처럼 날짜 최신순(자료 날짜 → 올린 날). 결정 D6.
- 프로젝트 토글 순서는 `app_spaces.sort_order`를 그대로 따른다(요구 ②).

## 5. 화면 (한 렌더러)

### 5.1 상태와 그리기

- 상태 주인 하나: 자료실 모듈(`library-upload.js` 또는 새 `library-tree.js`, 2단계에서 결정)이 `{groupBy, open:Set, query, categoryOff, docs, folders, items, projects}`를 가진다.
- 그리기 하나: `luRenderLibrary()`가 계속 유일한 그리기 함수이고, 안에서 `buildTree(state) → 노드 목록 → html` 순서로 한 번에 `#documentList`를 바꾼다. 묶기 4가지가 **같은 노드 모양**(`{kind:'group'|'folder'|'file', key, label, count, kinds, children}`)을 쓰므로 그리는 코드는 하나다(AGENTS.md §5 "한 영역 = 한 주인·한 그리기").
- 토글은 `<details>`/`<summary>`(키보드·터치 기본 지원, 프로젝트 상세와 같은 방식). 펼침 상태는 `open` Set에 노드 키로 기억하고 다시 그릴 때 되살린다. 자료실을 나갔다 오면 기본(맨 위 단만 펼침)으로.
- 'N건 더': 한 토글에 파일이 20개를 넘으면 20개만 보이고 `[N건 더]` 글자 버튼. 누르면 그 토글만 전부.
- '모두 펴기·모두 접기': 거르기 줄 끝 작은 글자 버튼 하나(누를 때마다 바뀜, UI-버튼기준의 작은 버튼).

### 5.2 줄 모양

- 접힌 줄(토글 머리): `▸ 이름 · 자료 수 · 종류 색 점(최대 5개, HWP 파랑·PDF 빨강 등 기존 `--ds-file-*` 색)`. 높이는 `--ds-compact-height`(32px), 누르는 범위 44px. 프로젝트 토글은 프로젝트 색 점(이미 있는 `colorDot`)을 이름 앞에.
- 폴더 줄: 프로젝트 줄과 같은 얇은 모양 + 폴더 표시 아이콘 + [⋯](폴더 편집).
- 파일 줄: 지금 `luRowHtml` 그대로(종류 태그·분류 태그·제목·날짜 또는 "올린 날 + 올림"·[⋯]). 들여쓰기만 단계별로 늘린다(폰은 단마다 12px, 최대 6단 = 72px, 그 아래는 더 들이지 않음).
- 월별 묶기도 같은 얇은 토글(지금의 `<h3 class="lu-month">` 제목을 토글로 바꿈).

### 5.3 묶기 전환

| 묶기 | 1단 | 2단 이하 | 폴더 |
| --- | --- | --- | --- |
| 프로젝트(기본) | 1단 프로젝트(프로젝트 화면 순서) … 맨 아래 '프로젝트 없음' | 하위 프로젝트(2·3단) → 그 프로젝트의 폴더 → 파일 | **보임·편집 가능** |
| 담당조직 | 조직(이름순) … 맨 아래 '조직 없음' | 파일 | 안 보임(파일만) |
| 종류 | 분류 목록 순서(교섭·투쟁… '기타') | 파일 | 안 보임 |
| 월별 | 최신 달부터, 맨 아래 '날짜 없음' | 파일 | 안 보임 |

- 프로젝트 토글에는 자료실 쪽 편집 버튼이 없다(요구 ②). [⋯]도 없고 끌어다 놓을 수도 없다. 이름 옆 작은 글자 링크 "프로젝트에서 편집"만 둘지 결정 D8.
- 지금 위쪽의 [프로젝트]·[세부] 칩 줄은 트리가 대신하므로 2단계에서 빼고, 그 자리에 '묶기' 세그먼트(32px 알약 4개)를 둔다. [종류] 칩 줄·[편집]·검색칸·담당조직으로 열기(`KPTULibrary.showOrganization`)는 유지.
- 하위 프로젝트에 자료·폴더가 하나도 없으면 그 토글은 숨긴다(빈 토글 줄이 길게 늘어서지 않게). 폴더는 비어 있어도 보인다(빈 폴더를 미리 만드는 용도).

### 5.4 거르기·검색과 펼침

- 종류 칩·검색어를 바꾸면 맞는 파일만 남기고, **맞는 파일이 든 토글만 펼친다**(위 단까지 자동). 맞는 파일이 없는 토글·폴더는 숨긴다. 거르기를 풀면 직전 펼침 상태로 돌아간다.
- 자료 수는 거르기 뒤 수를 보인다(검색 중 "3 / 12"처럼 둘 다 보일지 결정 D9, 추천: 거른 수만).
- 연결이 어긋난 자료(3.2)는 연결이 없는 것처럼 프로젝트 토글 바로 아래에 둔다.

## 6. 폴더 편집 (3·4단계)

| 동작 | PC | 폰 |
| --- | --- | --- |
| 폴더 만들기 | 프로젝트·'프로젝트 없음'·폴더 줄의 [⋯] → "폴더 만들기" | 같음 |
| 이름 바꾸기 | [⋯] → "이름 바꾸기" (줄 안에서 바로 입력, Enter 저장·Esc 취소) | 같음(작은 입력 창) |
| 지우기 | [⋯] → "폴더 지우기" → 확인 "“B” 폴더를 휴지통으로 옮길까요? 아래 폴더 n개·자료 m개도 함께 들어가고…"(TRASH-다른삭제 3단계: 휴지통으로. 아래 폴더는 같은 묶음으로 함께 들어가고, 자료는 폴더 안에 그대로 두되 자료실 목록에서만 함께 숨음. 되돌리면 원래 구조로 돌아옴. 영구 삭제만 지금처럼 안의 폴더·자료를 한 단 위로 올림. DB 적용 전에는 "준비 중") | 같음 |

## 7. Drive와의 관계 (요구 ④)

- **Drive 원본 폴더·파일은 움직이지 않는다.** 폴더 표는 Web2 DB에만 있고, 폴더를 만들거나 옮기거나 지워도 Drive 호출이 없다. 자료를 지워야 Drive 휴지통으로 가는 기존 동작(`document-actions`)만 그대로다.
- Drive 권한(`drive.file`)·Edge·토큰과 무관하다. 이 과제는 Drive 권한을 넓히지 않는다.
- **DRIVE-자료트리(10/15·10/16 구상)와의 관계**:
  - DRIVE-자료트리 = "지정한 Drive 폴더 하나를 **Drive의 실제 나무 그대로** 보여 주기 + Drive 별표 양방향". 원본은 Drive 폴더 구조이고, 기존 파일까지 보려면 `drive.metadata` 권한 확대가 필요(정지 지점, 아직 대기).
  - LIB-토글트리 = "Web2 자료실 자료(앱이 올린 것)를 **Web2 안에서 정리하는 나무**". 원본은 Web2 DB이고 Drive 구조와 일치시키지 않는다.
  - 둘은 다른 나무다. 그래서 **같은 화면에 섞지 않는다**(추천, 결정 D10): 자료실은 LIB 트리, 나중에 DRIVE-자료트리를 만들면 자료실 위쪽 '묶기'에 다섯 번째 "Drive 폴더" 보기를 더하거나 별도 탭으로 두고, LIB 폴더를 Drive로 복사하거나 Drive 폴더를 LIB 폴더로 가져오는 동기화는 하지 않는다.
  - 이 과제가 DRIVE-자료트리의 선행 조건은 아니다. 다만 같은 렌더러(5.1의 노드 모양)를 재사용할 수 있게 노드에 `source`(`library`·`drive`)를 둘 자리만 남긴다.
  - DRIVE-자료트리의 ⭐(별표) 구상은 이 과제 범위 밖이다.

## 9. 적용 순서와 되돌리기 (① DB)

1. DB PR(`feat/lib-tree-db`) 검토 → CC merge.
2. CC가 Actions **Approved DB migration workflow**를 branch `main`, mode `apply`, version 칸에 migration 파일 이름으로 시작.
3. 사용자: GitHub 알림 → Review deployments → `production-edge` → Approve(한 번).
4. workflow: 사전 확인 → 상태 저장 → 시험 적용(취소) → 적용 → 사후 확인. 하나라도 다르면 멈춤.
5. 되돌리기: 짝 rollback 파일을 **SQL Editor 새 쿼리 창**에서(승인형 workflow는 표 삭제를 막음). 새 표 2개·트리거 함수 2개·기록 1행만 지운다. 폴더가 하나라도 있으면 멈추고(사용자가 만든 정리를 지워서 통과시키지 않음), 먼저 화면 ③을 이전 코드로 되돌린 뒤 보관 여부를 정한다. 자료·프로젝트·Drive는 어느 경우에도 그대로.

계획 검사(`scripts/ops/db-workflow.mjs`의 `makePlan`, main ref·version `20261022120000_library_folders.sql`, 2026-10-22 로컬 실행):

| 모드 | 결과 | 뜻 |
| --- | --- | --- |
| apply | 통과(확장 규칙, 승인 한 번 흐름) | 버튼으로 적용 가능 |
| dry-run | 통과(확장 규칙) | 시험 적용(취소)만 따로 돌릴 수도 있음 |
| rollback | **거절**(의도) | rollback 모드는 표 삭제(`drop table`)를 허용하지 않는다. 새 표를 만든 기존 migration(share_pages_links, todo_radar_candidates, ledger_schema, task_attachments)도 같다. 되돌리기는 위 5번처럼 SQL Editor(폰 경로 C)로만 |

| D4 | 프로젝트를 지우면 그 안 폴더는 | 폴더째 '프로젝트 없음'으로 옮겨 정리를 살림(자료도 거기로 감) | 폴더를 지우고 자료만 '프로젝트 없음' 맨 위로 |
| D5 | 폴더·파일을 다른 프로젝트로 끌어다 놓기 | 안 됨. 같은 프로젝트 틀 안에서만. 프로젝트 바꾸기는 지금처럼 자료 ⋯ 수정에서 | 놓으면 자료의 프로젝트도 바뀜(다른 화면도 바뀜) |
| D6 | 토글 안 파일 순서 | 날짜 최신순 고정(손으로 순서 저장 안 함) | 파일도 손으로 순서 저장 |
| D7 | 폴더 이름 | 1~40자, 같은 이름 허용 | 같은 상위 안 같은 이름 금지 |
| D8 | 프로젝트 토글에서 프로젝트 화면으로 가는 길 | 두지 않음(토글 이름 누르면 펴고 접기만) | 작은 "프로젝트에서 편집" 글자 링크 |
| D9 | 검색 중 자료 수 | 거른 뒤 수만 | "거른 수 / 전체 수" |
| D10 | DRIVE-자료트리와 | 따로 둔다(섞지 않음, 동기화 없음). 나중에 '묶기'에 "Drive 폴더" 보기 추가 후보 | LIB 폴더를 Drive 폴더로 만들기(요구 ④와 충돌) |
| D11 | 담당조직·종류·월별 묶기에서 폴더 | 안 보임(파일만) | 폴더를 각 묶음 안에 다시 보임(같은 폴더가 여러 곳에 나타남) |
| D12 | 'N건 더' 기준 | 토글당 20개 | 10개, 50개 |
| D13 | 자료실에 들어올 때 펼침 | 1단(프로젝트 1단 토글)만 보이고 모두 접힘 | 마지막 펼침 상태 기억(이 기기에만) |

## 11. 남은 위험·범위 밖

- 한 요청으로 여러 폴더(부모와 자식)를 지우면 요청 전체가 취소된다(3.4). 화면 ③은 한 번에 한 폴더만 지운다.
- 연결이 어긋난 자료(다른 화면에서 프로젝트를 바꾼 경우)는 조용히 폴더 밖으로 나온다. 사용자가 "왜 폴더에서 빠졌지?"라고 느낄 수 있다. 화면 ③에서 자료 ⋯ 수정으로 프로젝트를 바꿀 때 "폴더에서 빠져요" 한 줄 안내를 둔다.
- 폴더 수 상한은 DB에 두지 않았다(sole-owner, 손으로 만드는 수). 필요하면 후속.
- 정적 검사는 정책 조건식의 의미를 증명하지 못한다. 로컬 Postgres 시험(소유자·남·비로그인·anon·service_role)으로 보완했고, 적용 뒤 postcheck가 권한 모양을 다시 본다.
- 범위 밖: Drive 폴더 만들기·옮기기, DRIVE-자료트리·별표, 프로젝트 화면 변경, 노트 폴더(UI-노트폴더)와의 통합.

## 12. LIB-폴더탐색기 (2026-10-26, 명진 시안 승인)

원장 행: LIB-폴더탐색기. 요구는 "자료실 폴더를 탐색기처럼": 묶기에 '폴더', 폴더 우클릭 메뉴, 끌어 옮기기(PC·폰), 폴더는 프로젝트와 상관없이 자유롭게, 여러 자료 일괄 수정. Drive 원본 폴더·파일은 건드리지 않는다(Web2 안 정리만).

### 12.1 폴더는 프로젝트와 상관없이 자유롭게 (결정 '가')

- 바뀌는 규칙: 폴더 안에 다른 프로젝트 틀의 폴더를 넣을 수 있고, 어느 프로젝트의 자료든 어느 폴더에나 넣을 수 있다. 깊이 3단·자기 아래로 옮기기 금지·소유자 한 사람 권한·anon/PUBLIC 권한 없음·"폴더의 `project_id`는 만든 뒤 못 바꿈"은 그대로다.
- **자료의 프로젝트 연결은 따로 그대로**다. 폴더에 넣고 옮겨도 `app_documents.project_id`는 바뀌지 않고, 프로젝트 화면·회의·주간정리 등 다른 화면은 영향이 없다.
- 폴더의 `project_id` 칸은 "만들 때 어느 프로젝트 토글에 놓였나"로만 남는다(프로젝트 묶기에서 그 토글 안에 그려짐). 폴더 보기는 이 칸을 보지 않고 `parent_id`만 따라 그린다.
- 프로젝트 묶기 화면은 이전과 같다. 그 화면에서는 자료가 자기 프로젝트 틀의 폴더에 들어 있을 때만 폴더 안에 보이고, 다른 프로젝트 폴더에 들어 있는 자료는 자기 프로젝트 토글 바로 아래에 보인다(3.2의 "어긋난 연결" 처리 그대로). 그래서 프로젝트 묶기 끌어 놓기는 계속 같은 틀 안에서만 허용하고, 틀을 넘는 정리는 폴더 보기에서 한다.
- DB(`20261026170000_library_folders_free`): ① 폴더 위치 검사 트리거에서 프로젝트 같음 조건 제거(작업공간 같음·순환·3단은 유지), ② 폴더 지우기 트리거가 프로젝트가 다른 자료도 한 단 위로 올림, ③ 자료 연결 정책에서 "자료와 폴더의 project_id 같음" 조건만 제거(교체). 새 표·새 칸·권한 변경 없음. 기존 정책 교체가 있어 승인형 workflow가 거절하므로 **SQL Editor(폰 경로 C)** 로 적용한다. **적용 전**에는 틀을 넘는 옮기기를 화면이 "아직 준비 중이에요"로 안내하고(DB가 거절), 같은 틀 안 옮기기는 이전처럼 동작한다.

### 12.2 폴더 보기(묶기 5번째) — 탐색기 모양

| 항목 | 내용 |
| --- | --- |
| 위치 | '묶기' 칩에 `폴더`를 더한다(프로젝트·담당조직·종류·월별·폴더). 폴더 보기는 프로젝트와 무관하게 `parent_id`로만 폴더 나무를 그린다 |
| 줄 | 폴더 줄 = ▾ 아이콘 · 이름 · 건수(그 안 전체). 안쪽 폴더·파일은 한 단 들여 보인다(`--lu-depth`). 맨 위 첫 줄 **'폴더 밖'** 은 폴더에 안 든 자료를 담고, 끌어서 놓으면 폴더 밖으로 나온다 |
| 기억 | '묶기' 선택은 폴더 포함 다섯 값 모두 내 프로필(`library_view.group_by`)에 저장한다(2026-10-26 명진 결정 '기억', migration `20261026180000_library_view_group_folder`가 DB 검사에 `folder`를 더함). 기억된 폴더 묶기는 폴더 표를 읽은 뒤 폴더로 열리고, 폴더 표를 못 읽으면 프로젝트로 연다. DB 적용 전 서버는 `folder` 저장을 400으로 거절하므로 화면이 폴더만 빼고 다시 보내 종류 칩 기억은 지키고 폴더는 이번 방문 동안만 유지한다 |
| 새 폴더 | 맨 위: 프로젝트 틀 없이(`project_id` 비움). 폴더 안: 그 폴더와 같은 틀 값(DB 적용 전에도 만들 수 있게) |

### 12.3 우클릭·⋯ 메뉴 (공용 `app/context-menu.js` 규칙)

- 폴더 줄 우클릭 = 그 줄 ⋯ 메뉴: **이름 바꾸기 F2**(줄 안에서 바로, #1238 자료 줄과 같은 방식) / **안에 새 폴더** / **접기·펼치기** / (키보드·폰 대안: 위로·아래로·옮기기…) / 구분선 / **폴더 지우기**(기존 휴지통 흐름 그대로).
- 빈 곳 우클릭 = 목록 영역 ⋯(`data-ctx="area"`) → **새 폴더**. 폴더 보기에서는 맨 위, 프로젝트 묶기에서는 '프로젝트 없음' 틀.
- 줄 안 이름 바꾸기: Enter·바깥 누르기 저장, Esc 취소. 저장은 폴더 이름(`app_library_folders.name` PATCH, 1~40자)만, 자료·Drive 이름은 안 바뀐다.

### 12.4 끌어 옮기기

- 대상: 파일 줄·폴더 줄(고른 여러 개를 한꺼번에 끌 수도 있음). 놓을 곳: 폴더 줄(그 안으로, **점선 + '여기에 놓기'** 표시) 또는 맨 위 '폴더 밖' 줄(폴더 밖으로). 형제 폴더 줄의 위·아래 끝에 놓으면 순서 바꾸기(이전 동작 유지).
- **밖에서 온 파일 = 올리기, 목록 안 줄 = 옮기기**: 올리기 끌어놓기(#1233)는 `dataTransfer.types`에 `Files`가 있을 때만 켜지고, 이 옮기기는 목록 안 줄에서 시작한 끌기(내부 표식 형식 `application/x-kptu-library-move`)만 받는다. 서로 반응하지 않는다.
- 화면 위·아래 끝 근처에서 끌면 목록이 자동으로 스크롤된다. 놓으면 한 줄 안내 **'옮겼어요 · 되돌리기'**(10초). 되돌리기는 옮기기 전 폴더 연결(또는 부모·순서)로 되돌린다.
- 폰: 줄을 길게 눌러 잡고(약 0.45초, 손가락이 8px 넘게 움직이면 그냥 스크롤) 움직여 놓는다. 잡은 뒤 움직임 없이 떼면 우클릭과 같은 ⋯ 메뉴가 열린다. 잡기 전 세로 스크롤은 그대로.
- 저장 실패(3단·순환·틀 제한)는 안내 한 줄과 서버 값으로 다시 그림.

### 12.5 여러 자료 일괄 수정

- 선택 모드: 고른 줄 위 한 줄에 `[프로젝트 바꾸기] [담당조직 바꾸기] [종류 바꾸기] [폴더로 옮기기] [삭제]`(작은 글자 버튼). 누르면 그 자리에 작은 목록. PC는 Ctrl/Shift+클릭으로 여러 개를 고른다.
- 저장은 자료 하나씩 같은 서버 길(`app_documents` PATCH, 소유자 RLS)로, 바꾼 칸은 `field_origin`에 `'user'`로 적어 AI 자동 정리가 되돌리지 않게 한다([수정] 창 저장과 같은 표시).
- 한 건이라도 실패하면 나머지는 계속하고 끝에 "n개 바꿨고 m개는 못 바꿨어요"로 알린다. [폴더로 옮기기]는 자료 연결(폴더 표)만 바꾼다.

### 12.6 단계(PR)

1. 설계 + DB(`lib-folders-db`, 적용 금지) 2. 화면 ①: 폴더 보기·메뉴·줄 안 이름 바꾸기·빈 곳 우클릭 3. 화면 ②: 끌어 옮기기(PC·폰)·되돌리기 4. 화면 ③: 일괄 수정.

### 12.7 전수: 노트 폴더(`note-folders.md`)

노트 폴더는 노트의 `metadata.folder` 이름 하나(한 단계)로 칩 줄에서 거르는 방식이고 폴더 표가 없다. 자료실처럼 나무·끌어 옮기기가 있는 구조가 아니라서 이번 요구가 그대로 필요하지는 않다. 같은 종류 개선(폴더 칩 우클릭 이름 바꾸기, 노트 줄 끌어서 폴더 칩에 놓기)은 가능하지만 노트 폴더는 별도 과제로 두고 이번에는 고치지 않는다(보고만).

## 0. 요약과 추천

1. **읽기만 하는 수집기**: 새 Edge 함수 `outside-feed` 하나가 하루 3번(서울 08·13·18시 근처) GitHub Actions 예약으로 불려, 단체마다 RSS 또는 성명 게시판 목록을 한 번 읽고 새 글만 가져온다. 공유·답글·퍼 나르기 같은 바깥 행동은 어떤 경로로도 하지 않는다(외부 입력 → 외부 행동 자동 연결 금지).
2. **읽을 곳은 서버 코드 안 목록(카탈로그)으로만** 정한다. 화면에서는 그 목록 안의 단체를 켜고 끄기만 한다(서버 저장). 화면이 임의 주소를 넣어 서버가 읽게 하는 길은 만들지 않는다(서버가 아무 주소나 읽게 되는 위험 차단). 새 단체는 명진이 요청함에 올리면 카탈로그에 한 줄 더하는 작은 PR로 넣는다.
3. **보관 경계**: 국내 단체 성명·논평·보도자료는 본문 전체를 Web2 서버에 비공개(작업공간 소유자만)로, 문장 단위로 쪼개 보관한다. 외국 매체는 **제목·링크·한국어 요약·핵심 문장 3개까지(원문 + 번역)**만 보관하고 전문·전문 번역은 저장하지 않는다. 공개 저장소·Web1에는 어느 것도 넣지 않는다.
4. **문장 찾기**: 새 검색 함수 `app_outside_search`(INVOKER, owner RLS 그대로, 기존 `app_search_records`와 같은 모양) — 낱말 일치 + "뜻이 비슷한 문장"은 1단계에서 **AI가 찾는 말을 비슷한 표현 몇 개로 넓혀 함께 찾는 방식**(새 DB 확장 없음). 의미 벡터(pgvector)는 2단계 선택지로 남긴다. 명진 쪽 성명(자료실 종류 '성명·보도자료'의 `app_documents.extracted_text`)도 같은 결과에 함께 나온다.
5. **알림**: 18시 수집 뒤 하루 한 번 저녁 요약 — 홈·위젯에 '새 성명 n건', 폰 알림은 기존 저녁 알림 묶음(phone-notifications 설계의 `evening` 칸)에 한 줄 더한다.
6. **막힌 곳**: 정의당은 robots.txt가 게시판 자동 읽기를 막는다 → 홈페이지는 자동 수집 안 함(결정 Q1), 공개 텔레그램 채널로 읽음(1.4.2, S48-23). 공공운수노조는 명진이 준 성명 게시판 주소(Q2)도 robots.txt 이유로 WebFetch가 거절했다(2026-10-31 S46-32) — 수집기가 실행 때 robots를 직접 읽어 막혀 있으면 건너뛴다(3.4). 전국결집은 leftall.com(Q3), 성명 게시판 없이 공지사항에 [입장]·[연서명] 머리말 글.
7. **결정**: 8절 Q1~Q9 모두 결정됨(명진 2026-10-31 22:35). ② DB는 S46-32 PR(`20261031230000_outside_statements`).
8. **Now 합치기·글 상세·관심사 환류**(2026-11-02): 12절. 메뉴 'Now' 하나 + 소탭, 글을 누르면 상세(요약·주요 문장·나와의 연관·시사점·함께 볼 것), 별표·보관·메모·관심 없음 → AI 관심 주제 후보 → 명진 확정.

## 1. 사이트별 읽는 길 (조사 결과)

표기: [사실] = WebFetch로 직접 확인, [추정] = 주소 모양 등으로 짐작, "확인 못 함" = 이번 세션에서 열지 못함. robots.txt는 웹 세션 도구가 검색에 안 나온 주소(`/robots.txt`)를 여는 것을 거절해 대부분 직접 보지 못했다. 다만 게시판 목록이 WebFetch(robots 준수 도구)로 열렸다는 것은 그 경로가 막히지 않았다는 뜻이다(정의당은 반대로 robots에 걸려 거절됨). **수집기는 실행할 때 robots.txt를 직접 읽고 막힌 경로는 건너뛴다**(3.4).

## 3. 서버 구조

### 3.1 DB 표 (DB PR에서 만듦 — ★정지 지점★)

모두 `workspace_id` 칸 + RLS 켬 + `private.app_is_workspace_owner(workspace_id)` 소유자 정책(기존 Web2 표와 같은 모양). `anon`·`PUBLIC` 권한 없음. 화면이 쓰는 칸은 켜기·끄기·읽음 표시뿐이고, 글 넣기는 Edge(service role)만 한다. **실제 migration: `supabase/migrations/20261031230000_outside_statements.sql`(S46-32)** — 아래는 그 PR에서 고친 모양이다.

| 표 | 칸(요지) | 화면(authenticated) 권한 |
| --- | --- | --- |

- 사람마다 작업공간 하나이므로(AGENTS §5) 같은 단체를 두 사람이 켜면 글이 작업공간마다 따로 들어간다. 수집기는 **한 번 실행에 사이트마다 한 번만 읽고** 켠 작업공간마다 나눠 넣는다(사이트 부담 줄이기). 작업공간 사이 공유 표는 만들지 않는다.
- 저녁 알림의 '새 n건' 기준 시각: 처음엔 `app_profiles.outside_seen_at` 칸을 추천했으나, S46-32에서 **작은 새 표 `app_outside_seen`으로 바꿨다** — 기존 표(`app_profiles`)에 열·열 권한을 더하지 않기 위해서(승인형 DB workflow 확장 규칙의 `grant-existing` 회피, 작업 지시).
- 크기 상한: 글 한 건 본문 6만 자 안쪽(넘으면 자름 + `has_body` 표시), 작업공간마다 2년 지난 글은 문장만 지우고 제목·요약은 남김(결정 Q7, 추천).
- 검색 함수 `app_outside_search(p_query text, p_terms text[], p_sources text[], p_from date, p_to date, p_limit int, p_offset int)`(S46-32에서 `p_include_mine` 뺌): `SECURITY INVOKER`, `authenticated`만 실행, `search_path` 고정. 문장 표에서 ILIKE로 찾고(%·_·\\는 글자 그대로, 기존 `app_search_records`가 pg_trgm 색인을 쓰지 않은 이유와 같음), 원래 말 + 비슷한 말 6개까지, 일치한 문장과 앞뒤 한 문장·글 제목·단체·종류·시각·찾은 말(`matched`)·비슷한 말로 찾았는지(`is_similar`)를 돌려준다. 한 번에 1~100건, 건너뛰기 0~2000.
- '내 성명 함께'는 이 함수에 넣지 않고 화면(⑤)이 **이미 있는 `app_search_records`(자료실 찾기, 같은 owner RLS)를 함께 불러** 종류 '성명·보도자료' 결과만 붙인다 — 같은 목적의 문서 찾기를 새로 만들지 않기(AGENTS §4) + 자료실 표 모양(종류·휴지통)에 이 migration이 묶이지 않게.
- 2년 지난 글(Q7 결정): ③ Edge 수집기가 실행할 때 `published_at`(없으면 `fetched_at`) 2년 지난 글의 문장 행을 지우고 `has_body=false`로 둔다(제목·요약은 남김). DB 쪽 새 함수·예약은 없다.

### 3.2 Edge 함수 `outside-feed` (Edge PR — ★배포 정지 지점★)

- `verify_jwt=false` + 함수 코드 인증(collector-feed·phone-push와 같은 두 입구):
  - **예약 입구** `run`: `x-outside-feed-cron-secret` 헤더를 비밀값 `OUTSIDE_FEED_CRON_SECRET`과 고정 길이 비교, 비밀값 없으면 모두 거절. 누구 작업공간에 넣을지는 서버가 `app_outside_sources.enabled`로 정한다(호출 쪽이 보낸 id를 믿지 않음).
  - **화면 입구** `catalog`(카탈로그 목록 돌려주기)·`expand`(뜻 비슷한 말 넓히기, 3.3)·`read_now`(화면에서 단체를 켜면 그 단체 하나를 그 사람 작업공간에만 바로 한 번 읽기, OUTSIDE-이름·바로읽기: 단체 키만 받음, 그 작업공간에서 켜져 있어야 함, 마지막으로 읽은 지 10분 안이면 건너뜀, 사람마다 하루 30번, 새 글 5건·60초 상한): 사용자 JWT로 확인. 두 입구의 비밀값·JWT가 섞여 오면 거절.
- 카탈로그는 `_shared/outside-catalog.ts`에 코드로 둔다: 키·이름·묶음(민주노총·공공운수노조·정당·사회운동·외국)·읽는 방식(`rss|html`)·주소·허용 호스트·종류 가르는 규칙(제목 머리말 등)·http 허용 여부. 서버는 **카탈로그의 허용 호스트에만** 요청한다(리다이렉트도 같은 호스트만, 응답 2MB·10초 상한).
- 단체별 읽기 코드(목록 HTML 해석)는 단체마다 작은 함수 하나 + 저장해 둔 목록 HTML 견본으로 단위 시험한다(견본은 제목·주소만 남기고 줄여서 저장소에 둠 — 본문 넣지 않음).
- 실행 한 번에: 단체마다 목록 1회 → 새 글만(이미 있는 `url` 제외) 최대 10건 → 글 페이지 1회씩(요청 사이 2초) → 본문 추출 → 문장 나누기 → AI 한 문장 요약(국내) / 한국어 요약·핵심 문장(외국) → 넣기. 단체 하나가 실패해도 다음 단체는 계속, 결과는 `last_ok_at`·`last_error`에.
- AI: 기존 서버 AI 키(OpenAI, `ai-assist`와 같은 공용 모듈)를 쓴다. 글 한 건에 한 번 부름. 사용량은 기존 AI 사용량 줄에 '바깥 성명'으로 더한다.
- User-Agent에 이 서비스 이름과 연락 주소 대신 프로젝트 안내 페이지 주소만(개인정보 넣지 않음).

### 3.3 "뜻이 비슷한 문장" 찾기

- 1단계(추천): 화면이 `expand`로 찾는 말을 보내면 서버 AI가 같은 뜻의 표현 3~6개(예: "구조조정" → "인력 감축", "정원 축소")를 돌려주고, 화면이 원래 말 + 넓힌 말로 `app_outside_search`를 부른다. 결과에 "낱말 같음 / 비슷한 말(인력 감축)"을 구분해 보인다. 새 DB 확장 없음.
- 2단계(선택, 결정 Q8): 문장마다 의미 벡터를 저장하는 pgvector 방식. production에 확장이 켜져 있는지 확인 못 함 + 읽생기와 같은 DB라 확장 추가는 따로 판단.

### 3.4 예약 작업

- 새 워크플로 `outside-feed.yml`: `schedule` UTC 23:07·04:07·09:07(서울 08·13·18시 7분), `workflow_dispatch`. 기존 `library-text-nightly.yml`과 같은 모양(`scripts/ops/` 작은 스크립트가 비밀값 헤더로 Edge `run` 호출, 결과는 건수만 출력). 비밀값 `OUTSIDE_FEED_CRON_SECRET`은 GitHub Actions 비밀값과 Edge 비밀값 두 곳에 같은 값 — **비밀값 등록은 명진이 대시보드에서**(AGENTS §1, 비밀값 변경은 AI가 하지 않음).
- robots.txt: 수집기가 하루 한 번 단체마다 읽어 기억(메모리)하고, 대상 경로가 막혀 있으면 그 단체는 건너뛰고 `last_error='robots'`.

## 13. [문장 찾기] · 저녁 '새 성명 n건' · 성명 초안 연결 (2026-11-02, S48-18 — 7절 ⑤·⑥·⑦)

- **[문장 찾기] 탭**: 지금은 탭 둘 [새로 온 것]·[문장 찾기](탭 줄·탭 상태는 `app/outside-statements.js`, 이 탭 메모리만). 칸 안은 `app/outside-search.js` 하나가 그린다. 12절 Now 합치기(S48-14 ③)가 탭 넷으로 바꿀 때 이 칸을 그대로 옮겨 쓴다(두 벌 만들지 않음). 폰은 좌우 밀기, PC는 ←→ 키.
  - 찾기 칸 + 기간 [1달|6달|1년|전체|날짜(달력 두 칸)] + 단체 묶음 칩 + [비슷한 말]·[내 성명](켬 기본).
  - 비슷한 말: Edge `outside-feed` `expand`(이미 배포된 입구, 사람마다 하루 횟수는 서버). 같은 말은 이 탭 메모리에 기억해 거르기만 바꿀 때는 다시 부르지 않는다. 못 받으면 낱말만 찾고 한 줄로 알림.
  - 결과: 문장마다 찾은 말 칠하기(원래 말은 옅은 바탕, 비슷한 말은 밑줄) + 앞뒤 문장 흐리게 + '단체 · 종류 · 제목 · 날짜 · [원문]' + '비슷한 말: …' 꼬리표 + [초안에 쓰기].
  - 내 성명: 기존 `app_search_records`(종류 document) → 그 자료들의 분류를 owner RLS로 읽어 '성명·보도자료'(와 그 아래 분류)만. 누르면 자료실 그 자료로.

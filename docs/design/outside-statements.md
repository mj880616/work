## 0. 요약과 추천

1. **읽기만 하는 수집기**: 새 Edge 함수 `outside-feed` 하나가 하루 3번(서울 08·13·18시 근처) GitHub Actions 예약으로 불려, 단체마다 RSS 또는 성명 게시판 목록을 한 번 읽고 새 글만 가져온다. 공유·답글·퍼 나르기 같은 바깥 행동은 어떤 경로로도 하지 않는다(외부 입력 → 외부 행동 자동 연결 금지).
2. **읽을 곳은 서버 코드 안 목록(카탈로그)으로만** 정한다. 화면에서는 그 목록 안의 단체를 켜고 끄기만 한다(서버 저장). 화면이 임의 주소를 넣어 서버가 읽게 하는 길은 만들지 않는다(서버가 아무 주소나 읽게 되는 위험 차단). 새 단체는 명진이 요청함에 올리면 카탈로그에 한 줄 더하는 작은 PR로 넣는다.
3. **보관 경계**: 국내 단체 성명·논평·보도자료는 본문 전체를 Web2 서버에 비공개(작업공간 소유자만)로, 문장 단위로 쪼개 보관한다. 외국 매체는 **제목·링크·한국어 요약·핵심 문장 3개까지(원문 + 번역)**만 보관하고 전문·전문 번역은 저장하지 않는다. 공개 저장소·Web1에는 어느 것도 넣지 않는다.
4. **문장 찾기**: 새 검색 함수 `app_outside_search`(INVOKER, owner RLS 그대로, 기존 `app_search_records`와 같은 모양) — 낱말 일치 + "뜻이 비슷한 문장"은 1단계에서 **AI가 찾는 말을 비슷한 표현 몇 개로 넓혀 함께 찾는 방식**(새 DB 확장 없음). 의미 벡터(pgvector)는 2단계 선택지로 남긴다. 명진 쪽 성명(자료실 종류 '성명·보도자료'의 `app_documents.extracted_text`)도 같은 결과에 함께 나온다.
5. **알림**: 18시 수집 뒤 하루 한 번 저녁 요약 — 홈·위젯에 '새 성명 n건', 폰 알림은 기존 저녁 알림 묶음(phone-notifications 설계의 `evening` 칸)에 한 줄 더한다.
6. **막힌 곳**: 정의당은 robots.txt가 게시판 자동 읽기를 막는다 → 자동 수집 안 함(결정 Q1). 공공운수노조·전국결집은 주소를 확인하지 못했다(결정 Q2·Q3).

## 2. 저작권·보관 경계

| 대상 | 서버에 보관 | 보관하지 않음 | 화면에서 |
| --- | --- | --- | --- |
| 국내 단체 글 | 제목·단체·종류·게시 시각·원문 주소·**본문 전체(문장 단위)**·AI 한 문장 요약 | 첨부 파일·이미지(주소만) | 요약 늘 보임, 본문 접기, [원문]은 그 단체 페이지 |
| 외국 매체 글 | 제목(원문)·한국어 제목·링크·저자·게시 시각·한국어 요약(3~5문장)·핵심 문장 3개까지(원문 + 번역, 문장마다 300자 안쪽) | 원문 본문·전문 번역 | 요약 + 핵심 문장, [원문]은 매체 페이지 |
| 명진 쪽 성명 | 이미 있는 자료실 '성명·보도자료'(`app_documents.extracted_text`) — 새로 복사하지 않음 | — | 문장 찾기 결과에 '내 성명'으로 함께 |

- 근거: 국내 성명·논평은 널리 퍼뜨리라고 낸 공개 글이지만 CC 같은 이용 허락 표시는 한 곳도 확인되지 않았다(사실). 그래서 **본인만 보는 비공개 보관 + 원문 링크 + 출처 표시**에 머물고, 다시 공개하는 길(Web1·공유 링크·공개 저장소)은 만들지 않는다(추정: 개인 자료 보관 범위라 위험 낮음).
- Jacobin은 번역을 사전 허가 대상으로 적었다(사실). 따라서 전문 번역은 저장도 즉석 표시도 1단계에서 하지 않고, 요약과 짧은 인용(핵심 문장)만 둔다. "펼칠 때 그 자리에서 번역"은 결정 Q6.
- 단체 글 본문은 AI(기존 Web2 서버 AI, OpenAI)에 요약용으로만 보낸다. 공개 글이라 비밀 정보는 아니다.
- 로그·PR·보고에는 글 제목·본문을 쓰지 않는다(건수·단체 키·HTTP 상태만).

## 3. 서버 구조

### 3.1 DB 표 (DB PR에서 만듦 — ★정지 지점★)

모두 `workspace_id` 칸 + RLS 켬 + `private.app_is_workspace_owner(workspace_id)` 소유자 정책(기존 Web2 표와 같은 모양). `anon`·`PUBLIC` 권한 없음. 화면이 쓰는 칸은 켜기·끄기·읽음 표시뿐이고, 글 넣기는 Edge(service role)만 한다.

| 표 | 칸(요지) | 화면(authenticated) 권한 |
| --- | --- | --- |
| `app_outside_sources` | `workspace_id`, `source_key`(카탈로그 키, 검사 제약으로 형식만), `enabled`, `last_ok_at`, `last_error`(짧은 코드), `created_at` | select·insert·update(`enabled`만)·delete — 자기 작업공간만 |
| `app_outside_posts` | `id`, `workspace_id`, `source_key`, `kind`(`statement|comment|press|article`), `lang`(`ko|en`), `title`, `title_ko`, `url`(유일: workspace+url), `published_at`, `fetched_at`, `summary_ko`, `key_sentences` jsonb(외국만, 3개까지), `has_body` | select만 |
| `app_outside_sentences` | `post_id`, `workspace_id`, `idx`, `text`(500자 안쪽) | select만 (국내 글만 행이 생김) |

- 사람마다 작업공간 하나이므로(AGENTS §5) 같은 단체를 두 사람이 켜면 글이 작업공간마다 따로 들어간다. 수집기는 **한 번 실행에 사이트마다 한 번만 읽고** 켠 작업공간마다 나눠 넣는다(사이트 부담 줄이기). 작업공간 사이 공유 표는 만들지 않는다.
- 저녁 알림의 '새 n건' 기준 시각은 `app_profiles`에 칸 하나(`outside_seen_at`)를 더하는 것을 추천(새 표 늘리지 않기, phone-notifications의 `notify_prefs`와 같은 방식).
- 크기 상한: 글 한 건 본문 6만 자 안쪽(넘으면 자름 + `has_body` 표시), 작업공간마다 2년 지난 글은 문장만 지우고 제목·요약은 남김(결정 Q7, 추천).
- 검색 함수 `app_outside_search(p_query text, p_terms text[], p_sources text[], p_from date, p_to date, p_include_mine boolean, p_limit int, p_offset int)`: `SECURITY INVOKER`, `authenticated`만 실행, `search_path` 고정. 문장 표에서 ILIKE로 찾고(기존 `app_search_records`가 pg_trgm 색인을 쓰지 않은 이유와 같음), 일치한 문장과 앞뒤 한 문장·글 제목·단체·시각을 돌려준다. `p_include_mine`이면 자료실 '성명·보도자료'의 `extracted_text`에서도 찾는다(같은 RLS).

### 3.2 Edge 함수 `outside-feed` (Edge PR — ★배포 정지 지점★)

- `verify_jwt=false` + 함수 코드 인증(collector-feed·phone-push와 같은 두 입구):
  - **예약 입구** `run`: `x-outside-feed-cron-secret` 헤더를 비밀값 `OUTSIDE_FEED_CRON_SECRET`과 고정 길이 비교, 비밀값 없으면 모두 거절. 누구 작업공간에 넣을지는 서버가 `app_outside_sources.enabled`로 정한다(호출 쪽이 보낸 id를 믿지 않음).
  - **화면 입구** `catalog`(카탈로그 목록 돌려주기)·`expand`(뜻 비슷한 말 넓히기, 3.3): 사용자 JWT로 확인. 두 입구의 비밀값·JWT가 섞여 오면 거절.
- 카탈로그는 `_shared/outside-catalog.ts`에 코드로 둔다: 키·이름·묶음(민주노총·공공운수노조·정당·사회운동·외국)·읽는 방식(`rss|html`)·주소·허용 호스트·종류 가르는 규칙(제목 머리말 등)·http 허용 여부. 서버는 **카탈로그의 허용 호스트에만** 요청한다(리다이렉트도 같은 호스트만, 응답 2MB·10초 상한).
- 단체별 읽기 코드(목록 HTML 해석)는 단체마다 작은 함수 하나 + 저장해 둔 목록 HTML 견본으로 단위 시험한다(견본은 제목·주소만 남기고 줄여서 저장소에 둠 — 본문 넣지 않음).
- 실행 한 번에: 단체마다 목록 1회 → 새 글만(이미 있는 `url` 제외) 최대 10건 → 글 페이지 1회씩(요청 사이 2초) → 본문 추출 → 문장 나누기 → AI 한 문장 요약(국내) / 한국어 요약·핵심 문장(외국) → 넣기. 단체 하나가 실패해도 다음 단체는 계속, 결과는 `last_ok_at`·`last_error`에.
- AI: 기존 서버 AI 키(OpenAI, `ai-assist`와 같은 공용 모듈)를 쓴다. 글 한 건에 한 번 부름. 사용량은 기존 AI 사용량 줄에 '바깥 성명'으로 더한다.
- User-Agent에 이 서비스 이름과 연락 주소 대신 프로젝트 안내 페이지 주소만(개인정보 넣지 않음).

### 3.3 "뜻이 비슷한 문장" 찾기

- 1단계(추천): 화면이 `expand`로 찾는 말을 보내면 서버 AI가 같은 뜻의 표현 3~6개(예: "구조조정" → "인력 감축", "정원 축소")를 돌려주고, 화면이 원래 말 + 넓힌 말로 `app_outside_search`를 부른다. 결과에 "낱말 같음 / 비슷한 말(인력 감축)"을 구분해 보인다. 새 DB 확장 없음.
- 2단계(선택, 결정 Q8): 문장마다 의미 벡터를 저장하는 pgvector 방식. production에 확장이 켜져 있는지 확인 못 함 + 읽생기와 같은 DB라 확장 추가는 따로 판단.

### 3.4 예약 작업

- 새 워크플로 `outside-feed.yml`: `schedule` UTC 23:07·04:07·09:07(서울 08·13·18시 7분), `workflow_dispatch`. 기존 `library-text-nightly.yml`과 같은 모양(`scripts/ops/` 작은 스크립트가 비밀값 헤더로 Edge `run` 호출, 결과는 건수만 출력). 비밀값 `OUTSIDE_FEED_CRON_SECRET`은 GitHub Actions 비밀값과 Edge 비밀값 두 곳에 같은 값 — **비밀값 등록은 명진이 대시보드에서**(AGENTS §1, 비밀값 변경은 AI가 하지 않음).
- robots.txt: 수집기가 하루 한 번 단체마다 읽어 기억(메모리)하고, 대상 경로가 막혀 있으면 그 단체는 건너뛰고 `last_error='robots'`.
- 저녁 알림: 18시 실행이 끝난 뒤의 phone-push `evening` 묶음에서 `outside_seen_at` 뒤 새 글 수를 세어 '새 성명 n건' 한 줄. 0건이면 줄 없음.

## 4. 화면 (12:43 시안대로)

- 메뉴: 왼쪽 메뉴(폰은 더보기 메뉴)에 '바깥 성명'. 화면 하나 = 모듈 하나(`app/outside-statements.js`)가 상태 소유·그리기(AGENTS §5 한 영역 한 렌더러). 탭 두 개 [새로 온 것]·[문장 찾기], 폰은 좌우 밀기로 탭 이동.
- **[새로 온 것]**
  - 칩 줄: 전체·민주노총·공공운수노조·정당·사회운동·외국 + 단체 낱개 — 공용 `app/chip-rows.js`(두 줄 + [더보기 ▾], UI-칩줄두줄).
  - 글 한 줄 묶음: 첫 줄 `단체 · 종류(성명/논평/보도자료/글) · 시각`(작게), 둘째 줄 제목, 셋째 줄 한 문장 요약(늘 보임), 그 아래 `<details>` 본문 접기(국내: 본문 문단 / 외국: 한국어 요약 + 핵심 문장 원문·번역), 끝에 작은 [원문] 링크(새 창). 날짜로 묶음 머리('오늘'·'어제'·'10. 29. (목)').
  - 화면 오른쪽 위 ⋯ → '단체 켜고 끄기'(카탈로그 목록에 켬/끔, 단체마다 마지막으로 읽은 시각·실패 표시) — 서버 저장.
  - 들어오면 `outside_seen_at`을 지금으로(서버 저장), 홈 '새 성명 n건'이 사라짐.
- **[문장 찾기]**
  - 찾기 칸 하나 + 거르기 줄(단체 칩, 기간 [1달|6달|1년|전체|날짜 고르기 — 공용 날짜 칸], [내 성명 함께] 켬 기본).
  - 결과: 문장 하나씩, 찾은 말 칠하기(`<mark>`), 앞뒤 한 문장 흐리게, 아래 작은 글 `단체 · 제목 · 날짜 · [원문]`. 비슷한 말로 찾은 것은 칠한 색을 달리하고 '비슷한 말: 인력 감축' 꼬리표.
  - 결과 문장마다 작은 [초안에 쓰기] — 성명 초안 근거로 넘김(5절).
- 홈·위젯: 저녁 요약 뒤 '새 성명 n건' 한 줄(누르면 [새로 온 것]). 위젯 칸은 phone-widget 설계의 기존 줄 목록에 한 종류 더함.
- 크기: 콤팩트(제목 14px·요약 13px·꼬리 12px), 큰 카드·굵은 버튼 없음, 톤다운 색.

## 6. 보안 확인

- 읽기만: 수집기는 GET만, 로그인·글쓰기·댓글·구독 신청 요청 없음. 화면에도 공유·퍼 나르기 버튼을 만들지 않는다([원문] 링크만).
- 서버가 읽는 주소는 코드 카탈로그의 허용 호스트뿐(화면 입력 주소 없음).
- 표는 소유자 RLS, 글 넣기는 service role(Edge)만. `anon`·`PUBLIC` 권한·정책 없음.
- 받은 HTML은 서버에서 글자만 뽑아 저장하고, 화면은 글자로만 그린다(HTML 그대로 넣지 않음).
- 기능 허용: 노조 사람 각자 자기 작업공간에서 쓰는 기능으로 본다(통화·텔레그램 같은 운영자 전용이 아님, 결정 Q9 추천). 다만 MULTI ② 전에는 명진만 작업공간이 있다.

## 9. 완료 기준 (요청함 그대로)

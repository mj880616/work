## 1. 화면

### 1.1 들어가는 길

- 상단 줄 검색칸(UI-상단줄 자리, `app/global-search.js`가 소유)에 문장을 쓴다. 예: "A 사업장 임금교섭 지난번 쟁점 뭐였지?"
- 지금처럼 2글자 이상이면 기록 검색이 돈다(바뀌지 않음). 거기에 더해 **질문처럼 보이면**(물음표로 끝남, 또는 낱말 4개 이상, 또는 '뭐·언제·왜·어떻게·누가·얼마·했나·였지' 같은 물음 말) 결과 창 맨 위에 한 줄이 생긴다.

```
[🔍 A 사업장 임금교섭 지난번 쟁점 뭐였지?          ×]
 ✦ Web2에 물어보기 ↵                       AI · 근거 기록과 함께
 ───────────────────────────────
 업데이트 3 · 회의 2 · 원장 4 · 통화 2 …   (지금 결과 창 그대로)
```

- 질문처럼 보이지 않아도 결과 창 맨 아래 `이 내용으로 Web2에 물어보기`(작은 글자 단추)로 언제든 부를 수 있다.
- AI는 **그 줄을 누르거나 Enter를 칠 때만** 부른다. 글자를 칠 때마다 부르지 않는다(비용·한도).

### 1.2 답 상자

```
Web2에 물어보기                                   10/29 09:12 · [다시 묻기]
A 사업장 임금교섭 지난번 쟁점 뭐였지?
 · 3차 교섭(10/27)에서 기본급 인상률과 성과급 기준이 남은 쟁점임.  [회의 10/27]
 · 회사는 성과급을 개인 평가와 묶자고 했고 우리는 거부함.         [회의 10/27] [통화 10/28]
 · 다음 교섭 전에 인상률 근거 자료를 보내기로 약속함(11/1 기한).  [원장 약속] [텔레그램 10/28]
▸ 근거 7건 — 회의 2 · 원장 2 · 통화 2 · 텔레그램 1
   AI가 찾은 기록을 요약한 것임. 원본을 눌러 확인할 것.
```

- 줄마다 근거 꼬리표(종류·날짜). 누르면 그 기록 자리로 연다(전체 검색 결과 줄과 같은 여는 길, 아래 표).
- `▸ 근거 n건`은 `<details>`로 접힘. 펼치면 근거 줄 전체(종류·날짜·제목·앞뒤 한 줄). 접혀도 건수 요약은 늘 보임(긴 내용 규칙).
- 상자 아래로 지금 결과 창(종류별 묶음)이 그대로 이어진다. 답은 결과를 **대신하지 않고 위에 더할 뿐**이다.
- 답 상자 문구: 맨 아래 흐린 한 줄 "AI가 찾은 기록을 요약한 것임. 원본을 눌러 확인할 것." 하나만(중복 안내 금지).
- 상태 문구(한 줄씩): 찾는 중 "기록 찾는 중…" → "답 쓰는 중…" / 근거 0건 "찾은 기록이 없음. 낱말을 바꿔 볼 것." / 월 한도 "이번 달 AI 한도에 걸림. 아래 검색 결과만 보임." / 하루 한도 "오늘 물어보기 횟수를 다 씀." / 실패 "답을 만들지 못함. [다시 묻기]".
- 폰: 검색은 지금처럼 전체 화면(`#searchView`). 답 상자도 그 안 맨 위. 뒤로가기는 검색 닫기(기존 그대로).
- PC: 상단 줄 결과 창(`gs-panel`) 안. 창 높이를 넘으면 창 안에서 스크롤. [전체 화면으로]는 기존 전용 화면.
- 지난 질문: 검색칸을 비운 채 누르면 결과 창에 "최근 물어본 것" 5줄(결정 4가 ①일 때). 누르면 저장된 답을 다시 띄움(AI 다시 안 부름).

### 1.3 근거를 누르면 여는 곳

전체 검색 결과 줄과 **같은 여는 함수**를 쓴다(`global-search.js`의 `source`별 열기). 새로 더하는 것은 통화·텔레그램·원장 세 가지다.

| 근거 종류 | 여는 곳 |
| --- | --- |
| 업데이트·노트·업무일지·자료·회의·프로젝트·진행 기록·조직 기록·주요 일정 | 지금 검색 결과와 같음(`source` 값 그대로) |
| 원장 | 원장 화면 그 기록(원장 검색 `ledger-browse.js`가 여는 길) |
| 통화 | 통화 메뉴 그 통화 상세(`app/call-feed.js`) |
| 텔레그램 | 텔레그램 소식 그 방·그날 줄(`app/telegram-feed.js`) |

### 1.4 소유권(AGENTS.md §5, ARCHITECTURE)

- 결과 창·전용 화면은 지금처럼 `global-search.js` 하나가 그린다. 답 상자도 이 모듈의 그리는 함수 하나가 그린다(새 렌더러 경쟁·`MutationObserver` 덧칠 금지).
- 질문 판별·답 모양 검사 같은 순수 규칙은 `global-search-model.mjs` 옆 새 모델 파일(`ask-web2-model.mjs`)에 둔다. 서버 호출은 `global-search-data.js`에 함수 하나(`askWeb2`)를 더한다.
- 이 모듈은 지금처럼 검색칸을 처음 쓸 때 늦게 불러온다(시작 화면 무게 그대로).

### 2.2 질문 하나가 처리되는 순서 (서버, ai-assist `kind=ask_web2`)

1. **입력 검사**: `{kind:'ask_web2', question}`만. 질문 4~200자, 한 줄, 제어문자 거절. 비밀번호·키 모양이면 거절(기존 `note-secret` 규칙 재사용).
2. **낱말 뽑기(AI 안 씀)**: 물음 말('뭐였지·언제·어떻게' 등)과 조사(은·는·이·가·을·를·에서·의·로…)를 뗀 2글자 이상 낱말 최대 6개. 담당조직 이름·별칭이 들어 있으면 `org-name-match.mjs`의 `matchOrg` 규칙(서버로 옮겨 같이 씀)으로 조직 하나를 잡는다.
3. **찾기(AI 안 씀, 명진 토큰)**:
   - 낱말 묶음 전체로 한 번(`app_search_records`, `p_per_kind=5`) — 다 들어간 기록.
   - 결과가 적으면(합 10건 미만) 낱말을 하나씩 빼며 다시(최대 4번 더) — "A 사업장 + 쟁점"처럼 일부만 맞는 기록.
   - 원장은 같은 낱말로 `app_ledger_search` 한 번(앞 10건). `validity='superseded'`(대체됨)는 빼고, 대체한 새 기록을 씀.
   - 조직을 잡았으면 그 조직 연결 기록을 앞에 둠(같은 조직 이름이 든 다른 기록보다 먼저).
4. **고르기**: 겹친 낱말 수 → 최근 순으로 근거 최대 **30줄**. 줄마다 `{ref, kind, id, date, title, snippet}`만(본문 통째 아님, snippet 약 80자).
5. 근거가 0줄이면 여기서 끝: AI 안 부르고 `{empty:true}`.
6. **AI 한 번**: 지시문 = "근거 줄에 있는 것만으로 답함. 줄마다 근거 ref를 붙임. 모르면 모른다고 씀. 말투 '~함. ~임.'(공용 `AI_TONE_RULE`)." 답 형식 JSON `{lines:[{text, refs:[ref…]}]}`, 줄 최대 6개·줄당 120자.
7. **답 검사**: refs가 이번 근거에 없는 줄은 버림. refs 0개인 줄은 버림. HTML·연락처·비밀값 모양 줄 버림. 남은 줄이 0이면 "근거로 답을 만들지 못함."
8. 저장(결정 4)·사용량 기록(`app_ai_daily_usage`) 뒤 돌려줌: `{lines, sources, words, org}`.

### 2.3 새 색인·뜻 검색(임베딩)을 만들지 않는 이유

- 기존 검색 함수가 일기 제외·owner 경계를 **함수 안에서** 이미 지킨다. 같은 목적의 새 저장소를 만들지 않는다(AGENTS.md §4).
- `document-ai-index`는 자료만 다루고, 서버 관리자 키로 Drive를 읽으며, 사용자가 고른 자료만 조각낸다. 질문 기능 재료로 넓히면 관리자 키 경로가 질문마다 돌게 된다 → 쓰지 않는다. 자료 본문은 이미 `extracted_text`로 찾는다.
- 뜻 검색(임베딩)은 모든 기록을 미리 AI에 보내 값을 만들어야 해서 비용·민감 기록 노출이 커진다. 1단계는 **낱말 검색 + AI 요약**으로 하고, 낱말이 달라 못 찾는 사례가 쌓이면 그때 따로 판단한다(9절).

### 2.4 Google 일정·할 일은 왜 빠지나

- 일정·할 일 원본은 Google이고, ai-assist는 명진 로그인 토큰만 쓰는 원칙이라 Google을 직접 못 읽는다(#1431과 같은 판단).
- 화면이 이미 가진 할 일·일정 저장본을 질문과 같이 보내는 길(#1431 `schedule_titles` 방식)은 2단계 후보로 둔다. 1단계 답은 DB 기록만 근거로 한다. 답 상자 아래 결과 창에는 지금처럼 Google 일정·할 일 검색 결과가 그대로 보인다.

### 2.5 민감 기록 처리

| 재료 | AI에 보내나 | 근거 링크로 보이나 |
| --- | --- | --- |
| 일기 | 안 보냄(검색 함수가 원래 뺌) | 안 보임 |
| 개인 통화함 | 안 보냄(결정 1 추천) | 안 보임 |
| 업무 통화 | 제목·요약·핵심 줄만(원문 `raw_text` 안 보냄). 전화번호·이메일 가림 | 보임 |
| 텔레그램 소식 | 방 이름·요약·핵심 줄만(원문·보낸 사람 이름 안 보냄 — TG-발언자이름 원칙) | 보임(결정 2) |
| 원장 교섭·전략(S2) | 안 보냄(결정 3 추천 — 원장 자동 기록·재료의 S2 제외 규칙과 같음) | 보임(제목·날짜만, 답 상자 근거 목록에 '교섭·전략' 꼬리표) |
| 노트 `ai_export_allowed=false`·비밀 메모 | 안 보냄(기존 ai-assist 규칙 `note_excluded`) | 검색 결과에는 지금처럼 보임 |

## 3. ai-assist 새 쓰임과 비용

- 새 쓰임 `kind=ask_web2`. 새 Edge 함수 없음(ai-assist에 하나 더함, verify_jwt 그대로).
- 하루 상한 `DAILY_LIMITS.ask_web2 = 30`. 전체 하루 합계 `DAILY_TOTAL_LIMIT 80`(handler.ts)에 같이 셈.

## 4. 저장 위치 (서버)

새 표 하나(이름 안: `app_ask_answers`). 결정 4가 ②(남기지 않음)면 이 표를 만들지 않는다.

| 칸 | 뜻 |

| `sources` (jsonb) | 근거 `[{ref, kind, id, date, title}]` — snippet은 저장 안 함(원본이 바뀌면 원본을 보도록) |

## 9. 범위 밖 발견·나중 후보

- 낱말이 달라 못 찾는 경우(예: '임금'↔'기본급'): 1단계는 낱말 검색이라 놓칠 수 있다. 근거 0건 질문 수를 사용량 기록에 숫자로만 남겨 두고(질문 글은 안 남김), 많으면 AI로 검색어를 넓히는 단계(AI 한 번 더, 약 0.5원)를 따로 판단한다.
- Google 일정·할 일을 근거로 쓰기(2.4): 화면이 저장본을 같이 보내는 방식, 2단계 후보.
- `document-ai-index`는 지금 화면에서 부르는 곳이 없다(`app/`에서 이름 검색 0건, 사실). 남길지 정리할지는 이 기능과 별개로 판단할 일이다.

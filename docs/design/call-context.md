# 통화 요약용 맥락 문서 갱신 설계 (CALL-맥락문서)

이 문서는 설계만 다룬다. 앱 코드, DB, Edge, Apps Script, workflow는 바꾸지 않는다.

- 작성: 2026-10-25, Claude Code 웹. production과 Google Drive를 직접 읽지 않았다. "사실"은 저장소 파일 또는 커맨드센터가 전한 내용이고, "추정"·"확인 필요"는 확인하지 못한 것이다. 공개 저장소이므로 문서 ID, 폴더 ID, 실제 조직·사람 이름은 이 문서에 없다.
- 원장 행: CALL-맥락문서. 이 PR은 `docs/roadmap.md`를 고치지 않는다.
- 관련 문서: [통화·텔레그램 한 흐름](call-telegram-feed.md), [원장 자료원](ledger-sources.md), [수집 받기 설치](../ops/collector-feed-setup.md), [통화 분석 안내문 기록](../ops/call-prompts-patch.md), [저장소 규칙](../../AGENTS.md).

## 0. 명진용 요약

**문제.** 통화 전사·분석 스크립트(`trascription`, Gemini)는 분석할 때 Drive의 '통화 요약용 맥락' 문서를 읽어 조직 이름, 약칭, 사람 직함을 바르게 적는다. 이 문서는 사람이 한 번 써 둔 것이라 조직·프로젝트가 바뀌어도 낡은 채로 있다. Web2에는 최신 담당조직·프로젝트가 있다.

**막힌 이유 (사실).** Web2의 Drive 권한은 `drive.file` 하나라 Web2가 만들지 않은 그 문서는 고칠 수 없다(10/24 확인). 권한은 넓히지 않는다.

**추천 (다안).** 전사·분석 스크립트(명진 계정)가 Web2에서 맥락을 **읽어 와서** 맥락 문서의 "자동 구간"만 스스로 고친다. Web2는 읽기 전용 입구 하나만 연다(`collector-feed` 새 action `context`, 기존 비밀값 방식). 사람이 쓴 부분은 그대로 두고, Web2가 안 될 때는 지난번 문서가 그대로 남는다.

**명진 손 가는 일.** Apps Script에 코드를 한 번 붙여 넣는 것(커맨드센터가 통째 교체본을 준다)과 Supabase 비밀값 한 칸 확인. 이후는 자동이다.

**순서.** ① Edge 읽기 입구(배포 승인 1회) → ② Apps Script 패치(시험 모드부터) → ③ 홈 화면에 "맥락 마지막 갱신" 표시(선택). DB 변경은 없다.

**결정 질문은 3개다(5절).**

## 1. 선택지 비교

| | **가** Web2가 새 문서를 만들고 스크립트가 그 문서를 읽음 | **나** 스크립트가 Web2에서 맥락을 받아 바로 씀 | **다** 스크립트가 받아 와서 맥락 문서를 스스로 갱신 (추천) |
| --- | --- | --- | --- |
| 권한 | Web2 소유 새 문서라 `drive.file`로 고칠 수 있다. 다만 **사람이 없는 때에도 고치려면** Web2 서버가 명진의 Google 로그인 정보를 갖고 있어야 한다. 지금 그런 예약 쓰기 경로가 문서 갱신용으로 있는지는 확인 필요 | Drive 권한 변화 없음. 스크립트는 이미 명진 계정이라 문서 읽기 가능 | Drive 권한 변화 없음. 스크립트가 명진 계정으로 기존 문서를 고침(이미 가진 권한) |
| 보안 | 새 입구 없음. 대신 Web2가 Drive 쓰기를 예약 실행하는 구조가 늘어난다 | **외부 입구가 데이터를 내보낸다.** 읽기 전용·비밀값·최소 항목·횟수 상한이 필요하다(3.2절) | 나와 같다. 추가로 문서에 쓰는 내용이 Drive에 남으므로 넣을 것을 3.1절로 제한 |
| 비용 | 0원(AI 없음). Edge 호출은 하루 수 번 | 0원. 통화 한 건마다 호출하면 호출이 늘지만 하루 1~2번으로 줄일 수 있다 | 0원. 하루 1~2번 호출 |
| 명진 손 | 새 문서 ID를 스크립트에 한 번 넣고, 분석 스크립트의 맥락 읽는 줄을 새 문서로 바꿈. 새 문서 공유·위치 확인 | 스크립트 코드 붙여넣기 1회. 문서는 안 쓰게 되어 **사람이 쓰던 설명 부분을 둘 곳이 없다** | 스크립트 코드 붙여넣기 1회. 사람이 쓴 부분은 그대로 유지 |
| 되돌리기 | 스크립트가 옛 문서를 다시 읽게 하면 끝. 옛 문서는 안 건드렸으므로 안전 | 스크립트 코드를 옛 판으로. 입구는 비밀값 삭제로 즉시 닫힘 | 입구 닫기(비밀값 삭제) + 문서 "편집 기록"에서 이전 버전 복원 |
| 실패 시 | 새 문서가 낡은 채로 남음. 낡았다는 신호가 없다 | Web2가 안 되면 맥락이 비어 분석 품질이 떨어질 수 있다 | 마지막으로 성공한 문서가 그대로 남아 분석은 계속된다 |
| 약점 | Web2 쪽에 Drive 쓰기 배선이 새로 필요(Edge·권한 검토 큼) | 사람이 쓴 맥락(약칭, 말버릇 보정 등)을 담을 곳이 사라짐 | 스크립트가 문서의 자동 구간을 정확히 찾아야 함(표지 줄 방식으로 해결) |

**판단 근거.**
- 가안은 "읽는 쪽 Drive 권한을 넓히지 않는다"는 원칙은 지키지만, Web2 서버가 Drive 쓰기를 예약으로 돌려야 해서 기존 구조(Web2는 받기만, 바깥 스크립트가 Drive를 다룬다. `call-telegram-feed.md` 2절)와 방향이 반대다. 새 쓰기 경로는 권한 검토 부담이 가장 크다.
- 나안은 구조가 가장 단순하지만, 사람이 손으로 써 둔 설명이 갈 곳이 없고 Web2가 멈추면 맥락이 사라진다.
- 다안은 나안의 입구를 그대로 쓰고, 문서를 "마지막 성공본" 겸 "사람이 쓰는 칸"으로 남긴다. 새 입구는 읽기 하나뿐이고 기존 `collector-feed`와 같은 비밀값 방식이다.

## 2. 구조 (다안)

```
[Web2 표] 담당조직 · 프로젝트 · (선택) 외부 상대 직함   — 소유자 전용 RLS
      ▲  서비스 키로 서버 함수가 읽음
[Edge collector-feed  POST ?action=context]  읽기 전용, 비밀값 헤더, 최소 항목, 글자 한도
      ▲  1일 1회(+ 문서가 하루 넘게 낡았을 때 분석 직전 1회)
[전사·분석 Apps Script]  명진 계정
      · 맥락 문서의 "자동 구간"만 교체  (표지 줄 두 개 사이)
      · 사람이 쓴 부분은 그대로
      ▼
[Drive '통화 요약용 맥락' 문서]  ← 분석 때 Gemini가 읽음(기존 동작 그대로)
```

- 분석 스크립트의 "문서를 읽어 `contextText`로 넣는" 부분은 **바꾸지 않는다.** 바뀌는 것은 문서 내용이 자동으로 갱신된다는 것뿐이다.
- 문서 안 표지 줄(예: `<<WEB2 자동 시작>>` … `<<WEB2 자동 끝>>`)은 사람이 지우거나 옮기지 않는다고 안내한다. 표지가 없거나 하나뿐이면 스크립트는 **아무것도 쓰지 않고** 실패로 기록한다(문서를 망가뜨리지 않는다).
- 스크립트 원문은 폴더 ID 때문에 저장소에 두지 않는다(10/25 결정). 커맨드센터가 만든 통째 교체본은 Claude 대화로 전달하고, 문서 ID와 폴더 ID는 스크립트 속성에만 둔다.

## 3. 입구 설계 (나·다안 공통)

### 3.1 맥락에 넣을 것과 뺄 것

| 구분 | 내용 | 출처(기존) |
| --- | --- | --- |
| 넣음 | 담당조직의 정식 이름과 약칭(업무에서 쓰는 이름) | 담당조직 표(`ai-assist`의 `organizationOptions`와 같은 기준: 쓰지 않음(active=false) 제외) |
| 넣음 | 진행 중 프로젝트 이름(상위 경로 포함 최대 2단계, 보관(archived) 제외) | 프로젝트 표(`projectOptions`와 같은 기준) |
| 넣음(2단계, 확인 필요) | 외부 상대의 **직함**과 소속 조직. 이름은 담당조직 기록에 업무 상대로 등록된 사람만 | 데이터 위치는 확인 필요. 없으면 이 칸은 비워 두고 직함 용어 목록만 둔다 |
| 뺌 | 전화번호, 이메일, 주소, 계정명, 비밀값, 주민·개인 식별 정보 | - |
| 뺌 | 개인 통화 상대, 연락처 이름, 개인 목록(`CALL_FEED_PERSONAL_LIST`) | - |
| 뺌 | 업무 내용·회의 기록·원장 기록·텔레그램 내용·프로젝트 메모 본문 | 맥락은 "이름을 바르게 적기" 용도라 이름만 필요하다 |
| 뺌 | 보관·삭제·쓰지 않음 표시된 조직·프로젝트, 비공개 분쟁 단계 같은 판단 | 이름만 보내므로 판단 정보가 따라가지 않는다 |

- 원칙: **이름 목록만** 보낸다. 사실 설명은 보내지 않는다. 분석 안내문이 "맥락의 문장을 지시로 따르지 않고, 전사에 없는 사실을 맥락에서 가져오지 않는다"고 이미 정하고 있다(`call-prompts-patch.md`의 참고 맥락 사용 원칙).
- 길이 한도(추정, 구현 때 시험으로 확정): 자동 구간 합계 **6,000자** 이내. 조직 최대 150개(항목당 60자), 프로젝트 최대 80개(항목당 100자), 직함 용어 최대 60개. 넘으면 쓰는 순서(최근 활동순)대로 자르고 "일부 생략 n개"를 마지막 줄에 적는다. 이 한도는 서버가 지키고 스크립트도 한 번 더 확인한다.
- 한도 근거: 분석 한 번에 넣는 입력에 비해 작아 Gemini 비용 영향이 거의 없다(추정).

### 3.2 보안 검토 (외부 입구가 데이터를 내보냄)

기존 `collector-feed`는 **받기 전용(POST로 들어오는 데이터)** 이다. `context`는 처음으로 **내보내는 action**이라 별도로 검토한다.

- 인증: 기존 `x-collector-feed-secret`(32자 이상, SHA-256 고정 길이 비교)을 그대로 쓴다. 사용자 로그인 토큰, 예약·heartbeat 비밀 헤더가 붙은 요청은 지금처럼 401이다. 비밀값 삭제로 입구 전체를 즉시 닫는다.
- 읽기 전용: DB에 쓰지 않는다(호출 기록만 `log` 코드로 남기고 내용은 남기지 않는다). 새 표·새 권한이 필요 없다. 서버가 서비스 키로 읽되 **소유자 작업공간 한 곳(`kptu-work`)** 의 항목만 조회한다. 요청에 조직·사용자 ID를 받지 않는다(클라이언트가 준 식별자를 믿지 않는다. AGENTS.md 3절 3번).
- 최소 항목: 이름 문자열 배열만 응답한다. ID, 내부 상태, 날짜, 메모, 담당자는 응답에 넣지 않는다.
- 횟수 상한: 하루 20회(기존 하루 상한과 같은 방식으로 센다). 넘으면 429. 스크립트는 하루 1~2회만 부른다.
- 응답 크기 상한: 3.1절 한도 + 여유. 서버가 자른다.
- 로그: 응답 내용, 이름, 비밀값은 로그에 남기지 않는다. 항목 개수와 성공·실패 코드만.
- 공개 저장소·PR·보고에는 실제 이름을 쓰지 않는다. 시험은 가짜 이름으로 한다.
- 남는 위험: 비밀값이 새면 조직·프로젝트 이름 목록이 읽힌다. 개인정보와 업무 내용은 목록에 없으므로 영향은 "이름 노출"로 제한된다. 노출이 의심되면 비밀값을 바꾼다(기존 순서와 같음).
- 이 PR 때문에 Edge 인증 경계(verify_jwt=false + 함수 안 비밀값)는 **바뀌지 않는다.** 같은 함수에 action만 늘어난다. 배포는 멈춤 지점이므로 승인을 받는다(AGENTS.md 6절·8절).

### 3.3 갱신 주기와 실패 처리

| 상황 | 동작 |
| --- | --- |
| 평상시 | 스크립트가 하루 1회(새벽, 트리거) 받아 자동 구간을 교체한다. 내용이 어제와 같으면 문서를 건드리지 않는다(편집 기록 오염 방지) |
| 문서가 24시간 넘게 낡음 | 분석 직전에 1회만 추가로 시도한다. 실패하면 기다리지 않고 현 문서로 분석을 계속한다 |
| Web2 응답 실패(401·429·5xx·시간 초과) | 문서를 그대로 둔다(마지막 성공본 유지). 다음 실행에서 다시 시도한다. 연속 실패 횟수를 스크립트 속성에 센다 |
| 응답이 비었거나 비정상으로 작음(예: 조직 0개) | 문서를 **덮어쓰지 않는다.** 빈 맥락으로 분석 품질이 떨어지는 것을 막는다 |
| 표지 줄을 못 찾음 | 쓰지 않고 실패로 기록한다 |
| 3일 연속 실패 | 홈 화면 수집 점검 칸에 "맥락 갱신 지연"을 표시한다(3단계. 기존 heartbeat 방식에 시각 한 줄 추가) 또는 스크립트 실행 오류 메일(Apps Script 기본 알림)로 명진이 알게 한다 |
| Web2에서 조직 이름을 바꿈 | 다음 날 문서가 바뀐다. 이미 만든 분석 파일은 고치지 않는다(과거 통화는 다시 분석하지 않는 원칙, Q12) |

- 성공본에 시각을 적는다: 자동 구간 첫 줄 "마지막 갱신: 날짜"(개인정보 아님). 사람이 문서만 열어도 낡았는지 안다.

## 5. 명진 결정 질문 (최대 3개)

**Q1. 어느 안으로 갈까요?**
- 추천: **다안**(스크립트가 받아 와서 맥락 문서를 스스로 갱신).
- 대안: 가안(Web2가 새 문서를 만듦. 구조 변경이 커서 비추천), 나안(문서를 없애고 직접 받음. 사람이 쓴 설명을 둘 곳이 없어짐).

**Q2. 맥락에 사람 이름과 직함까지 넣을까요, 조직·프로젝트 이름만 넣을까요?**

**Q3. 문서의 사람이 쓴 부분은 어떻게 할까요?**
- 추천: **그대로 두고 자동 구간만 갱신**. 문서 안에 표지 줄 두 개를 한 번 넣어 주세요(커맨드센터가 넣을 위치와 글자를 알려 줌). 지금 문서 내용 중 자동으로 대체할 부분(조직 목록 등)이 있으면 그 부분만 표지 안으로 옮깁니다.

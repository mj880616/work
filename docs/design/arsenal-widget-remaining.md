## 3. 앞 세션이 멈춘 원인(추정)

사실: S47-43·S47-60 모두 push가 없었다. 저장소에 두 세션 이름의 원격 브랜치도 없다(`git ls-remote` 확인). 아래는 추정이다.

1. **Gradle 빌드·시험 시간**: 폰 앱 시험은 `./gradlew test`(첫 실행 때 안드로이드 SDK·의존성 내려받기)가 필요하다. 클라우드 세션에서 첫 빌드가 수십 분 걸리거나 SDK가 없어 멈췄을 가능성이 가장 크다. 첫 push를 빌드 뒤로 미루면 아무것도 남지 않는다.
2. **요청 범위가 한 PR에 너무 큼**: 4×2·4×1·2×1(·2×2) 세 레이아웃 + 일정 읽기 + 달력 넣기 + 결과 가림 설정 + 중계 자료까지 한 번에 하려 했을 수 있다. 특히 [달력에 넣기]·결과 가림 저장은 정지 지점·W-D2와 걸려 판단에서 멈추기 쉽다.
3. **요청 원문 찾기**: 요청함 파일이 약 40만 자라 한 번에 못 읽는다(이번 세션도 파일로 저장 뒤 찾음). 원문 ④를 못 찾고 헤맸을 수 있다.
4. **같은 파일 겹침**: APP-한칸위젯디자인(1×1 한 칸)과 공용 위젯 파일(`WidgetRefresh.kt`·테마 색 `res/values`)이 겹친다. 11/02 덧붙임으로 두 작업이 합쳐져 범위가 다시 커졌다.

다음 세션 권고: 범위 하나 + Gradle 없이 고칠 수 있는 순수 Kotlin 계산·시험부터, 시작 20분 안에 빈 PR이라도 push, Gradle 시험은 CI(`build-android-app.yml`)에 맡김.

## 5. 명진·CC 결정이 필요한 것

1. **크기**: 10/31 원문은 4×2·4×1·2×1, 11/02 덧붙임은 4×2·4×1·2×2. 2×1(지난 결과·결과 가림)을 2×2로 바꾸는지, 넷 다 두는지. 추천: 원문대로 세 크기(시안 확정본) — 2×2는 시안이 없음.
2. **끝나는 시각**: 킥오프 + 2시간(전후반·휴식·추가시간) 고정으로 계산. 연장·승부차기 가능 경기(컵)는 + 2시간 30분. 추천대로면 결정 불필요.
3. **[달력에 넣기] 방식**: 가) 폰 달력 앱 '일정 추가' 화면이 미리 채워져 열림 → 명진이 [저장] 한 번(서버 쓰기 없음, 정지 지점 아님) / 나) 위젯이 바로 구글 달력에 넣음(서버 쓰기 허용 넓힘, 정지 지점). 추천: 가.
4. **결과 가리기 설정 저장**: 가) 위젯을 놓을 때 고르는 위젯 설정(1×1 '한 칸' 위젯의 기능 고르기와 같은 방식, 경기 자료가 아니라 켬/끔 한 칸) / 나) 서버 프로필 설정에 저장(허용 목록 넓힘, 정지 지점). W-D2는 '위젯 자료'를 폰에 두지 않는 원칙이라 켬/끔 설정이 이에 해당하는지 CC 판단 필요. 추천: 가(1×1 한 칸 위젯이 이미 같은 방식).
5. **중계 채널 출처**: 예약 작업이 국내 중계사를 찾지 못하면 칸을 비우고 위젯은 그 줄을 생략. 추천대로면 결정 불필요.
6. **[FotMob로 보기]**: 경기별 주소 자료가 없으므로 FotMob 아스날 팀 페이지 고정 주소. 추천대로면 결정 불필요.

## 6. 보안·원칙 확인

- 위젯 요청 허용 목록(`WidgetRules.allowed`)은 A~C에서 바꾸지 않는다. 일정 읽기는 이미 허용된 `calendarUrl` 모양만 쓴다.

- 일정 내용은 위젯 화면에만 그리고 로그·시험 출력에 쓰지 않는다.

- 자료: 기존 공개 정적 파일 `app/arsenal/matches.js`(id·subtitle/verdict·goals)만 읽는다. 위젯 요청 허용 목록·폰 저장 방식은 그대로(그림을 받거나 저장하지 않음, W-D2).
- '그 리뷰 열기'는 앱 주소 `?view=arsenal&match=<경기 id>`. 웹 쪽은 기존 자리 기억 길(`app-router.js` `PLACE_PARAMS`)에 `arsenal:['match']`만 더했다 — 새로고침해도 같은 리뷰.
- 크기: 안드로이드 12+는 2×1·2×2(100dp~)·4×1·4×2(100dp~)·4×2 높은 칸(140dp~) 다섯 그림을 함께 주고 홈 화면이 고른다.

# 처음 쓰는 사람 — 시작 화면·빈 화면·메뉴 정리 (MULTI-처음쓰는사람 기획)

- 상태: 기획(설계 문서와 시안만, 코드 변경 없음)
- 요청: 요청함 'MULTI-처음쓰는사람 기획'(11/13), 'MULTI-다른담당자맞춤', 'PRODUCT-노조구독판매 방향'
- 시안: `docs/design/mockups/new-user-start.html` (폰 412 · 폴드 펼침 760 · PC)
- 공개 저장소이므로 사람 이름·메일·조직 이름·작업공간 값은 적지 않는다.

## 0. 원칙

1. **운영자(명진) 계정의 화면·자료는 한 칸도 바뀌지 않는다.** 바뀌는 것은 '아직 아무것도 없는 사람'에게만 보이는 칸, 그리고 운영자 기능이 없는 계정의 메뉴뿐이다(3절에서 하나씩 확인).
2. 빈 화면·연결 안 됨은 **고장이 아니다.** 빨간 오류 글 대신 "무엇을 하면 되는지 한 줄 + 버튼 하나"로 보인다. 진짜 고장(서버 오류)일 때만 지금의 오류 글과 [다시]가 남는다.
3. 숨기기가 아니라 **빼기**. 운영자 전용 메뉴는 서버 답(`app_my_features()`)으로 메뉴 목록에서 뺀다(`docs/design/multi-user-audit.md` 3절 표의 '화면 메뉴' 줄 — 계획만 있고 아직 안 됨). 데이터는 지금처럼 서버가 거절한다.
4. 새 저장소를 만들지 않는다. 담당조직은 있는 표(`app_suborganizations`)와 있는 추가·수정 창(`app/suborganizations.js` `openEdit`)을 쓴다. 묶음·순서는 있는 `view_prefs.org_order`.
5. 장기 방향은 노조 조직담당자 대상 구독 제품(요청함 PRODUCT). 그래서 '명진 전제'가 박힌 글(양식 이름·칸 제목)은 사람마다 바뀌는 설정으로 간다.

## 1. 지금 상태 (11/13, 새 계정으로 폰 412·폴드 760·PC 확인한 사실)

| 화면 | 새 사람에게 보이는 것 | 원인(사실) |
| --- | --- | --- |
| 홈 그날 일정·할 일 | 빨간 "불러오지 못했어요… [다시]" | 구글 캘린더·할 일 연결이 없어서 읽기 실패. 연결 없음과 서버 오류를 구분하지 않음 |
| 일정 | "구글 캘린더 [구글 캘린더 연결]" | 잘 됨 — 홈이 따라 할 본보기 |
| 조직 보고 | "없음 · 참고 묶음", ⋯ 에는 '쟁의 단계 관리'만 | `openEdit`(담당조직 추가·수정 창)는 있으나 여는 버튼이 어디에도 없음(`#soAddOrg`는 포커스 대상 이름으로만 남음) |
| 사업 보고 | "1) 사업요약표 사업명이 없음 2) 주요 사업·회의결과 없음" | 사업영역이 0개. 무엇을 하면 채워지는지 안내 없음 |
| 홈 주간 정리 | 명진 주간보고 칸 제목 그대로, "바탕을 열지 못해…", "분류 목록에 없음" | 주간보고 양식(바탕) 파일이 자료실에 없음. 오류 글이 개발 용어 |
| 파일 | 403 | 운영자 기능 `files`가 없는 계정(서버가 맞게 거절). 메뉴에 남아 있는 것이 문제 |
| 메뉴 판 | 통화·텔레그램 소식·아스날·News·사진·원장 | `app/menu-model.mjs`가 기능 판정 없이 모든 항목을 그림 |
| 하단바 | 홈·잊지 말기·일정·사업 보고·조직 보고 | `DEFAULT_BAR` |
| 프로필 | '보고 설정' 글 상자, 폰 알림 '수집 멈춤·아침 묶음·저녁 묶음', '수집·사용량'(연락 있는 조직 기준) | 운영자 기능용 칸이 판정 없이 보임 |
| 공유 페이지 | [+ HTML] | 처음 사람에게 뜻이 안 닿음 |
| HWP 편집 | '노조 양식으로 새 문서' | 운영자 노조 양식 전제 |
| 일기 | "이 달에는 아직 일기가 없어요. [+]로…" | 좋은 빈 화면 — 다른 빈 화면의 본보기 |
| 폴드 펼침 | 홈이 두 칸으로 잘 나뉨 | 배치 문제 없음. 문제는 내용뿐 |

## 2. 바꿀 것 (화면별)

### 2-1. 메뉴 (운영자 기능이 없는 계정)

- 하단바 기본값: **홈 · 노트 · 일정 · 조직 보고 · 사업 보고** (명진 11/13 15:24). `DEFAULT_BAR`만 바꾼다. 저장된 메뉴 순서(`view_prefs.menu_layout`)가 있는 사람은 그대로 — 명진은 저장값이 있으므로 영향 없음(구현 PR에서 운영 값 존재를 읽기 전용으로 확인).
- 잊지 말기는 메뉴 판 위쪽으로. 홈 업데이트 칸 옆 [잊지 말기] 버튼은 이미 있다.
- 메뉴에서 빼는 것(서버 기능 키가 없을 때): 통화(`calls`), 텔레그램 소식(`telegram`), 파일(`files`), 사진의 구글 드라이브 출처(`gdrive_photos` — 이미 칩 단위로 판정), **아스날·News**(명진 15:26 "내 계정에만"). 아스날·News용 기능 키는 아직 없다 → 허용 표에 키 2개를 넣는 DB 변경이 필요(4절 ③).
- 원장: 원장 자동 기록·내보내기는 모두 자기 것으로 쓴다(MULTI D3) → 남긴다. 다만 처음 사람에게 '원장'이 무엇인지 한 줄 안내(빈 화면).
- 라우터: 빠진 메뉴를 주소로 직접 열면 '없는 화면'으로(데이터는 서버가 어차피 거절).

### 2-2. 홈

| 칸 | 지금 | 바꿈 |
| --- | --- | --- |
| 그날 일정 | 빨간 오류 | 연결 없음이면 "구글 캘린더를 연결하면 그날 일정이 여기 보여요 [구글 캘린더 연결]"(일정 화면과 같은 버튼·같은 흐름). 서버 오류일 때만 지금 글 |
| 할 일 | 빨간 오류 | 연결 없음이면 "구글 할 일을 연결하면…[구글 할 일 연결]". 캘린더 연결과 한 번에 될 수 있으면 버튼 하나 |
| 주간 정리 | 명진 양식 칸·개발 용어 오류 | 양식 없음이면 "주간보고 양식 파일(한글)을 올리면 이 칸이 그 모양으로 바뀌어요 [양식 올리기]". 칸 제목은 양식에서 읽은 것만. 기본 양식은 '빈 3칸(요청·일정·사업)' |

연결 없음 판정은 서버 답으로 한다(예: 캘린더·할 일 Edge가 돌려주는 '연결 없음' 코드 — 구현 PR에서 현재 응답 모양 확인 뒤 정함. 응답에 구분이 없으면 Edge 변경이 필요하고 그때 정지 지점).

### 2-3. 조직 보고 — 담당 조직 직접 넣기

- 목록이 비었을 때: "담당하는 조직을 넣으면 조직별 업데이트·보고가 모여요 [+ 담당 조직 추가]".
- 목록이 있을 때: 맨 위 제목 줄의 작은 [+ 담당조직] 버튼(#2522 시안과 같은 자리, 큰 버튼 아님). 조직 줄 ⋯ 에 [수정][담당 조직에서 제외](명진 15:31 이름).
- 추가 창은 있는 `openEdit` 그대로: 조직 이름 · 줄임말(쉼표) · 종류 · 메모. '종류'는 자유 입력 + 내가 이미 쓴 종류를 고르기로(예: 사람마다 '지부·지회·분회'처럼 다름).
- 묶음(철도·지하철처럼)은 프로필의 담당조직 묶음(#2522 시안: [+ 묶음], ⋮⋮ 끌기)으로. 처음 사람은 묶음 없이 가나다순.
- '담당 조직에서 제외'는 지우기가 아니다: 고르기 창과 목록에서 빠지고, 지난 기록은 남는다. [담당 조직으로 추가]로 되돌린다(`org_order.hidden`).

### 2-4. 사업 보고

- 비었을 때: "사업(예: 임단협, 조직 확대)을 만들면 회의·결과가 사업별로 모여요 [+ 사업 만들기]". 버튼은 지금 ⋯ 안의 사업영역 관리 화면을 연다.

### 2-5. 프로필

- '보고 설정' → 이름을 **'보고 캘린더'**로(명진 15:29 "유지, 보다 직관적 이름"), 글 상자 대신 내 구글 캘린더 목록에서 고르기. 담당조직 묶음은 '담당 조직' 칸으로 옮김(#2522).
- '수집·사용량' → 운영자만: 수집 상태(통화·텔레그램 기준). 다른 사람에게는 칸을 그리지 않음. AI 사용량은 한도가 생기면(PRODUCT ④) 그때 '이번 달 AI 사용'으로 따로.
- 폰 알림 고르기의 '수집 멈춤·아침 묶음·저녁 묶음'은 운영자 기능이 있을 때만.
- 기본 정보 아래 뜻 없는 '없음' 칸: 무엇을 그리는 칸인지 구현 PR에서 확인 뒤 빼거나 이름 붙임.

## 3. 명진 계정 영향 확인 (구현 PR마다)

| 바뀌는 곳 | 명진이 그대로인 이유 | 확인 방법 |
| --- | --- | --- |
| 하단바 기본값 | 저장된 `menu_layout`이 있으면 기본값을 안 씀 | 운영 `app_profiles.view_prefs ? 'menu_layout'` 읽기 전용 확인 |
| 운영자 메뉴 빼기 | 명진 작업공간은 `calls`·`telegram`·`files`·`gdrive_photos`(+ 새 키)가 허용 표에 있음 | `app_my_features()` 결과 확인, 새 키는 DB 적용 뒤 화면 PR |
| 빈 화면·연결 안내 | 명진은 자료·연결이 있으므로 이 칸이 안 그려짐 | E2E: 자료 있는 상태 화면 사진이 이전과 같음 |
| 보고 캘린더 고르기 | 저장값 `report_calendar` 그대로 읽음 | 기존 값이 고르기의 선택으로 보이는지 |

순서 규칙: **새 기능 키를 허용 표에 넣는 DB 적용이 먼저, 메뉴에서 빼는 화면 PR이 나중.** 거꾸로 하면 명진 메뉴에서도 아스날·News가 잠깐 사라진다.

## 4. PR 나누기 (줄 세우기)

| 순서 | 내용 | 정지 지점 |
| --- | --- | --- |
| ① | 조직 보고 [+ 담당 조직 추가]·빈 화면·⋯ [수정][담당 조직에서 제외] (화면만, 있는 창·표) | 없음(화면) |
| ② | 홈 일정·할 일 '연결 없음' 안내 (응답 구분이 없으면 Edge 먼저) | Edge 배포 시 |
| ③ | 허용 표에 `arsenal`·`outside` 기능 키 추가(명진 작업공간 행만), 서버 판정 | DB 적용 |
| ④ | 메뉴 모델 기능 판정 + 하단바 기본값 + 라우터 | 없음(③ 뒤) |
| ⑤ | 프로필 정리(보고 캘린더 고르기·수집 칸 운영자만·폰 알림 칩) | 없음 |
| ⑥ | 주간 정리 양식 없음 안내·기본 3칸 | 없음 |
| ⑦ | 빈 화면 글 일괄(노트·자료실·원장·공유 페이지·HWP) | 없음 |

①과 ④는 같은 파일을 만지지 않으므로 동시에 가능. ④는 ③ 뒤. ⑤는 #2522(담당조직 묶음) 뒤.

## 5. 명진 결정 필요

1. 시안의 안내 글 말투(지금: "~하면 ~가 여기 보여요") 괜찮은지.
2. 아스날·News 말고도 '내 계정만'으로 뺄 메뉴가 더 있는지(사진 전체? 원장?).
3. 주간 정리 기본 3칸(요청·일정·사업)으로 시작할지, 양식을 올리기 전엔 주간 정리 버튼 자체를 감출지.

## 6. 구독 제품 방향과의 연결 (PRODUCT, 결정 대기)

이 기획은 '판매 제품의 첫 화면'의 바탕이다. 판매 전에 따로 필요한 것: 개인정보처리방침·이용약관, 탈퇴·내보내기, 결제(플레이 스토어 앱 안 결제 규칙 확인), 사람별 AI 한도, 노조별 양식. 각각 원장 '결정 대기'로 따로 다룬다.

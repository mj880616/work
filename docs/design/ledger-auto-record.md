설계 문서만 있다. 앱 코드·DB·Edge·Drive는 바꾸지 않았고 운영 DB도 보지 않았다.

- 작성: 2026-10-23, Claude Code 웹. 기준 main `bd8e3eb`(#1069).
- 근거: 2026-10-22 23:27 명진 요청(Web2 요청함). 2026-10-21의 "AI 후보 → 명진 확정" 방식([ledger-web2.md](ledger-web2.md) 4·15·16절)을 대신한다.

## 1. 현재 구조 (사실, main `bd8e3eb`)

### 1.1 표와 함수 (운영 적용 여부는 roadmap 기준)

- 표 10개(`20261021082000_ledger_schema`): 기록 `app_ledger_records`, 출처 `app_ledger_sources`, 기록-출처 `app_ledger_record_sources`, 연결 `app_ledger_links`, 조직·주제, 후보 `app_ledger_candidates`, 감사 `app_ledger_audit`, 가져오기 묶음 `app_ledger_imports`, 번호표 `app_ledger_id_counters`.
- 권한: 모든 표 RLS, 정책은 표마다 owner(`private.app_is_workspace_owner(workspace_id)`) 하나, authenticated만, PUBLIC·anon·service_role 없음. 원장 행 삭제는 "확인 전 가져오기 묶음에서 들어와 고친 적 없는 행"만(제한 정책). 감사 기록은 쌓기만.
- 함수: 검색 `app_ledger_search`, 가져오기 4개(`app_import_ledger_*`), 후보 확정 `app_confirm_ledger_candidate`, Claude 후보 파일 넣기 `app_queue_ledger_candidates`, 확정 되돌리기 `app_unconfirm_ledger_candidate`(20261021234000, 운영 적용 완료). 모두 SECURITY INVOKER·`search_path = ''`.
- 고치면 바뀐 칸의 고치기 전 값이 감사 기록 `row_update`로 쌓인다(트리거). 대체는 `validity = superseded` + `superseded_by` + `supersede_reason`이 짝으로만 들어간다(CHECK).

### 1.2 AI 후보 만들기 (`ai-assist` 쓰임 3 `ledger_candidates`)

- [원장 후보 만들기]를 눌렀을 때만 돈다(자동 실행 없음). 하루 5회, 전체 AI 하루 50회, 월 추정 1만 5천 원 한도.
- 재료: 지난 실행 뒤(처음은 3일, 길어도 7일) 바뀐 업데이트(바구니)·노트·업무일지 한 줄·회의 결과·담당조직 기록·프로젝트 기록. 일기·보관·AI 내보내기 비허용 제외. 최대 150건·6만 자.
- 이미 있는 사건(현재유효·업무·S0~S1, 최근 80건)의 ID·제목을 함께 보내 변화기록을 그 사건에 붙인다.
- AI 답은 믿지 않는 입력으로 다시 검사. S3·개인정보 모양은 버리고 개수만.
- 결과는 **후보 표에만** 넣는다(`origin = web2_ai`, 대기). 원장 기록은 명진 [확정] 때 `app_confirm_ledger_candidate`가 한 거래로 만든다.
- 출처는 서버가 정한다: 위치 `web2:<종류>:<id>`. 같은 위치의 출처는 다시 쓴다(한 회의에서 여러 기록 = 출처 하나). 중복 열쇠 `web2:<종류>:<id>:<제목>`.
- 실행 표시는 감사 기록 `event = note`(숫자·시각만)에 남기고, 그것으로 다음 기준선·하루 횟수를 센다. 실행 잠금은 없다.

### 1.3 화면

## 2. AGENTS 규칙과의 충돌, 개정안 (제안만, 이 PR은 고치지 않음)

### 2.1 충돌

이번 요청은 "명진이 확정하지 않아도 AI가 뽑은 것이 원장에 들어간다"이다. 지금 규칙의 "원장에 들어가는 문은 사용자가 확정하는 하나뿐"과 정면으로 부딪힌다. 또 source-of-truth 문서의 "`ai-assist`는 후보를 스스로 확정하지 않음"과도 부딪힌다.

부딪히지 않는 부분:

- "Claude·개발도구는 Web2·원장에 직접 쓰지 않는다"는 그대로 지킨다. 자동 기록은 Web2 서버 안의 AI(`ai-assist`, OpenAI)가 **명진 로그인 토큰**으로 한다. Claude는 수정안을 글로 줄 뿐이고, 반영은 명진이 Web2에서 누른다.
- 권한(RLS·grant)은 넓히지 않는다(4절).

### 2.2 AGENTS.md §2 개정안 문구

지금:

> - 원장에 들어가는 문은 Web2에서 사용자가 확정하는 하나뿐이며, Claude·개발도구는 Web2·원장에 직접 쓰지 않는다(2026-10-21 변경: ChatGPT 단일 작성자 폐지).

바꿀 문구(제안):

> - 원장에 들어가는 문은 Web2 안의 두 가지뿐이다. ① Web2 서버 AI(`ai-assist`)가 사용자 로그인으로 Web2 기록(업데이트·사업 보고·담당조직 기록·노트)에서 뽑아 자동으로 기록한다. 기록마다 근거(원래 Web2 기록)를 붙이고, 기존 기록을 고치거나 폐기하지 않고 더하기만 한다. ② 사용자가 Web2에서 직접 넣거나 고친다(가져오기, '원장 수정 요청' 반영 포함). Claude·개발도구는 Web2·원장에 직접 쓰지 않는다. Claude의 원장 수정안은 사용자 승인 뒤 사용자가 Web2 '원장 수정 요청'에 넣어 반영하며, 옛 기록은 지우지 않고 '대체됨'으로 남긴다(2026-10-22 변경: AI 후보 → 사용자 확정 방식 폐지).

### 2.3 `docs/ai-work-system-source-of-truth.md` 개정안 문구

- 2026-10-21 변경 상자 둘째 문장 → "원장에 들어가는 문은 Web2 안 두 가지(서버 AI 자동 기록, 사용자 직접 입력·수정 요청 반영)다(2026-10-22 변경, `design/ledger-auto-record.md`)."
- AI 도구별 역할 표, Web2 안의 짧은 AI 행: 역할 "원장 후보 만들기" → "원장 자동 기록(더하기만, 근거 필수)", 하지 않는 일 "후보를 스스로 확정하지 않음" → "기존 원장 기록을 고치거나 폐기하지 않음".
- Claude 행: 하지 않는 일에 "원장 수정은 수정안 글까지만(반영은 사용자가 Web2에서)"을 더함.

### 2.4 순서

규칙 개정(커맨드센터 문서 PR, 명진 승인)은 **자동 기록을 켜는 앱 PR(8절 PR-3)을 merge하기 전**에 한다. DB·Edge PR은 켜지 않은 상태로 먼저 들어가도 규칙 위반이 아니다(자동 기록이 아직 돌지 않음).

## 3. 새 흐름

### 3.1 자동 기록

```
명진이 저장(업데이트·사업 보고·담당조직 기록·노트)
  → 앱이 "원장에 볼 것 생김" 표시만 해 둠(원문은 보내지 않음)
  → 마지막 저장 10분 뒤(처음 저장부터 길어도 30분) 앱이 ai-assist {kind:"ledger_auto"} 한 번
  → 서버가 명진 토큰으로 "아직 안 본 기록"만 읽음 → AI 한 번 → 답 검사
  → DB 함수 하나가 한 거래로 원장에 씀(새 기록 / 기존 사건에 변화로 이어 붙이기 / 기존 기록에 근거만 추가)
  → 원장 바뀜 → Drive 사본 자동 갱신 예약(6절)
```

- 재료 범위: 명진이 말한 넷 — 업데이트(바구니 메모), 사업 보고(회의 결과, 모든 칸), 담당조직 기록, 노트. **업무일지 한 줄과 프로젝트 기록은 넣지 않는다**(요청에 없음, 넣으려면 명진 결정). 일기·보관·AI 내보내기 비허용은 지금처럼 뺀다.
- "아직 안 본 기록" = 처리 표(4.2 `app_ledger_auto_sources`)에 없거나, 마지막으로 본 뒤 고쳐진 기록. 시간 창(3~7일)이 아니라 기록 단위로 센다 → 며칠 Web2를 안 열어도 다음에 열면 밀린 것을 이어서 본다(한 번에 150건·6만 자, 넘으면 다음 실행으로).
- 자동 기록이 할 수 있는 일은 **더하기 셋뿐**: 새 기록, 기존 사건에 변화기록 이어 붙이기(`belongs_to`), 같은 일인 기존 기록에 근거 추가(`add_source`). 기존 기록의 칸을 바꾸거나 대체·폐기하는 일은 하지 않는다(그건 7절 수정 요청만).
- 기록에는 "자동" 꼬리표(`entry_route = auto`)와 실행 번호가 붙는다. 명진이 따로 확인하지 않아도 되지만, AI가 자신 없다고 한 것은 유효상태 '확인필요'(`needs_check`, 기존 값)로 들어가 목록에서 표시된다.
- 시작점: 자동 기록을 켠 날 이후 저장된 기록부터. 켜기 전 기록은 보지 않는다(필요하면 3번 질문 ③과 함께 "지난 기록 한 번 훑기"를 따로 정함).

### 3.2 중복 방지와 이어 붙이기 (질문 ②)

세 겹:

1. **같은 원문·같은 제목**: 열쇠 `web2:<종류>:<id>:<정리한 제목>`이 이미 원장(자동 기록 표시)에 있으면 건너뜀. DB 유일 색인으로 한 번 더 막음.
2. **같은 원문을 고쳐 저장**: AI에게 "이 원문에서 이미 뽑은 기록(ID·제목)"을 함께 보내고, 새로 생긴 사실만 고르게 한다. 원문 고침으로 이미 뽑은 내용이 틀리게 됐다고 AI가 답하면 **자동으로 고치지 않고** 그 기록을 '확인필요'로만 바꾼다(→ 명진이 보거나 Claude 수정 요청으로 고침). 이것이 자동 기록이 기존 기록에 하는 유일한 변경이다.
3. **다른 원문, 같은 사안**: 지금 보내는 "최근 사건 80건" 대신 **같은 담당조직·프로젝트에 걸린 최근 현재유효 기록(사건·결정·약속, 최근 90일, 최대 80건) ID·제목**을 보낸다. AI가 `same_as: <ID>`로 답하면 새 기록 대신 그 기록에 근거만 추가, `event: <ID>`면 변화기록으로 그 사건에 이어 붙임. 서버·DB가 그 ID가 실제로 있고 현재유효인지 확인(없으면 새 기록).

S2 기록 제목은 지금처럼 AI에게 보내지 않는다(그 기록과는 이어 붙지 않고 새 기록이 될 수 있음 → 위험 9절).

### 3.3 근거 연결과 원문 열기

- 출처 위치는 지금처럼 `web2:<종류>:<id>`(종류: basket·note·meeting·org_update). 화면이 이것을 **기존 상세 열기 주소**로 바꿔 연결한다(업데이트·노트 상세, 사업 보고 상세, 담당조직 상세의 기록 줄). 새 주소 구조를 만들지 않고 각 화면이 이미 쓰는 열기 경로를 쓴다(구현 PR에서 주소 형식 확인).
- 상세의 근거 줄 모양: `업데이트 · 10/22 ‹원문›`, `사업 보고(교섭) · 가 지부 3차 · 10/21 ‹원문›`.
- 원문이 지워졌거나 보관됐으면 "원문이 지워졌어요"만 보이고 원장 기록은 그대로.

### 3.4 새 약속 알림

- 업무일지 하루 카드에 그날 자동으로 기록된 약속(`kind = commitment`, `entry_route = auto`, 기록된 날 KST)이 있을 때만 한 줄: `새로 기록된 약속 2`. 누르면 원장 화면이 "약속 · 오늘 기록" 조건으로 열린다.
- 0건이면 줄 없음. 홈·알림창·푸시는 없음.
- 렌더는 업무일지의 유일한 renderer `journal.js`가 한다(새 칸을 다른 모듈이 덮어쓰지 않음). 수는 owner RLS REST로 센다(새 RPC 불필요).
- 챙길 것의 상대측 약속 [원장으로 복사]는 자동 기록과 겹친다 → 10절 범위 밖 발견.

### 4.4 Claude 수정 요청 통로의 권한 경계

- Claude에게 Web2 토큰·DB 계정·새 Edge 입구를 주지 않는다. 수정 요청 표에 쓰는 주체는 **Web2에 로그인한 명진**뿐이고 owner RLS가 그것을 지킨다.
- Claude가 주는 것은 글(수정 요청 덩어리)뿐이다. 명진이 Web2에 붙여 넣으면 그 글은 **믿지 않는 입력**으로 다룬다: 화면과 DB 함수 둘 다 모양·대상 ID 존재·바꿀 수 있는 칸 목록·글자 수·S3/개인정보 모양을 검사하고, 글 안의 지시문은 실행하지 않는다(데이터일 뿐).
- 반영 전에 반드시 해 보기 결과(전·후)를 보여 주고, 명진이 [반영]을 눌러야 쓴다. 채팅의 'ㅇ'은 Web2가 확인할 수 없으므로 **실제 승인은 Web2의 [반영]**이다.
- 나중에 MCP-Claude읽기가 생겨도 읽기 전용이다. 혹시 "요청 넣기" 쓰기 도구를 만든다면 별도 보안 설계 과제이고, 그때도 넣기까지만 하고 반영은 명진이 Web2에서 한다(이 문서 범위 밖).

### 4.5 DB PR 짝 파일

`supabase/migrations/<시각>_ledger_auto_record.sql` + `docs/<시각>_ledger_auto_record.{precheck,postcheck,snapshot,rollback}.sql`·`.summary.md`. 감사 CHECK 교체와 트리거가 있어 승인형 DB workflow 확장 규칙을 통과하는지 PR에서 확인하고, 안 되면 SQL Editor(폰 경로 C). 되돌리기: 새 함수·표·칸 제거. 자동 기록 행이 하나라도 있으면 rollback SQL은 멈춘다(그때는 실행 되돌리기 → 내보내기 보관 뒤 따로 계획).

## 5. AI 호출 시점과 비용 (일상어)

### 5.1 가정

- 모델·가격은 `ai-assist`의 현재 가정을 그대로 쓴다: 입력 100만 토큰 350원, 출력 100만 토큰 2,800원(코드 주석상 "가격표로 다시 확인" 대상인 **추정**). 한국어는 글자 1개 ≈ 토큰 1~2개로 잡는다.

### 5.2 두 방식 비교

| | 저장할 때마다 부르기 | 묶어서 부르기(추천) |
| --- | --- | --- |
| 언제 | 저장 직후 매번 | 마지막 저장 10분 뒤(길어도 30분), 앱을 닫거나 가릴 때 남은 것 바로, 앱을 열 때 밀린 것 |

| 하루 | 약 250~300원 | 약 70~120원 |
| 한 달(30일) | **약 7,500~9,000원** | **약 2,000~3,500원** |

## 6. Drive 사본 자동 갱신

- 원장이 바뀌면(자동 기록 실행 `done`에서 1건 이상, 수정 요청 반영, 실행 되돌리기) 앱이 기존 `drive-summary ?action=ledger_export`를 **10분 묶어 한 번** 부른다. 한 시간에 한 번을 넘지 않는다. 앱을 열 때 마지막 성공이 하루 넘었고 그 뒤 원장이 바뀌었으면 한 번.
- 서버 함수는 바꾸지 않는다(같은 날짜 JSON은 같은 파일에 덮어쓰기, 읽기용 문서 1개 교체 — 이미 그렇게 동작). Edge 재배포 없음.
- 원장은 예약 실행으로 읽을 수 없는 구조(서버 키 권한 없음)를 유지한다. 그래서 Web2를 며칠 안 열면 사본도 그만큼 늦다 → 매주 점검 workflow 기준을 8일에서 3일로 줄이는 것을 제안(선택, 같은 PR-3에서 숫자만).
- 화면: [지금 Drive로 내보내기] 버튼과 칸을 없애고, 원장 화면 맨 위 한 줄 상태만:
  - 평소: `Claude용 사본 10/23 14:20 갱신` (작은 회색 글자)
  - 멈춤(마지막 실패가 성공보다 최근, 또는 원장이 바뀐 뒤 하루 넘게 성공 없음): `⚠ Claude용 사본이 10/21부터 멈췄어요 · 다시 시도` (다시 시도는 이 경고 때만 보이는 글자 링크)
- S2(교섭·전략) 기록은 읽기용 문서에 제목만 — 지금 그대로(질문 ①).

## 7. 고치기: 원장 수정 요청

### 7.1 흐름

```
Claude와 대화 중 명진: "EVT-09xx 날짜 틀렸어, 10/21이야"
  → Claude: 수정안 설명 + 붙여 넣을 덩어리 하나(복사용)
  → 명진 'ㅇ'
  → 명진이 Web2 원장 화면 [원장 수정 요청] 칸에 붙여 넣기
  → 화면이 해 보기: "EVT-09xx 기준일 10/20 → 10/21, 옛 기록은 '대체됨'" 미리보기
  → [반영] 한 번 → 새 기록(EVT-09yy, "명진 지적으로 수정 · 2026-10-23") + 옛 기록 대체됨
```

- 붙여 넣는 덩어리 모양(제안): `{"format":"kptu-ledger-fix","version":1,"items":[{"target":"EVT-09xx","do":"replace","set":{"date_start":"2026-10-21"},"reason":"날짜 오기"}]}`. Claude가 만들고, 명진은 내용을 몰라도 붙여 넣기만 하면 된다. 화면은 이 덩어리를 일상어 미리보기로만 보여 준다.
- `do` 세 가지:
  - `replace` 고쳐 바꾸기: 옛 기록 칸을 복사해 고친 칸만 바꾼 **새 기록**을 만들고, 옛 기록은 `superseded`(대체됨) + 대체 이유 "명진 지적으로 수정: <이유>". 근거·연결 줄은 새 기록에 복사(옛 기록 줄도 그대로).
  - `retire` 틀린 기록 폐기: `retired` + `change_note` "명진 지적으로 폐기 · 날짜: <이유>". 지우지 않음.
  - `add_source` 근거 추가: 기존 출처 ID 또는 Web2 원문 위치.
- 바꿀 수 있는 칸: 제목·요지·종류별 칸(결정유형·상대측·이행상태·후속확인일 등)·기준일·주제·민감도(S0~S2)·중요도·범위. 종류·고정 ID·들어온 길은 못 바꿈.
- 한 요청 최대 20개 항목. 대상 ID가 없거나 이미 대체·폐기면 그 요청 전체를 거절(부분 반영 없음).
- 반영 직후 알림 옆 [되돌리기](10초)와 수정 요청 목록의 ⋯ [반영 취소](`app_undo_ledger_fix`).

### 7.2 대체됨 이력

- 옛 기록은 지우지 않는다. 목록은 기본으로 현재유효만 보이고, 새 기록 상세에 `명진 지적으로 수정 · 2026-10-23 · 이전 기록 EVT-09xx ›`, 옛 기록 상세에 `대체됨 → EVT-09yy · 이유`.
- 고치기 전 값은 기존 감사 트리거(`row_update`)에도 남는다. 감사 기록은 지우지 않는다.
- 이어서 또 고치면 사슬(EVT-09xx → 09yy → 09zz)로 남고, 상세에서 한 단계씩 따라간다.

### 7.3 Claude 쪽 준비 (개발 아님)

- Claude가 원장을 읽는 길은 지금 Drive 사본(6절)이다. 수정안은 사본에 보이는 고정 ID로 대상을 집는다. S2 기록은 사본에 제목만 있으므로 요지 고침은 명진이 내용을 말해 줘야 한다.
- Claude 프로젝트 지침에 "원장 수정 요청 덩어리 모양"을 한 번 적어 두는 일은 커맨드센터 몫(이 PR 아님).

## 9. 위험과 되돌리기

### 9.1 자동 기록이 틀릴 위험

| 위험 | 줄이는 법 |
| --- | --- |
| 없는 사실·날짜를 만들어 냄 | 지시문 "재료에 없는 것 만들지 않음" + 근거 원문 연결 필수(근거 없는 항목은 서버가 버림) + 자신 없으면 '확인필요' + 상세에서 ‹원문› 한 번에 대조 |
| 같은 일을 두 번 기록 | 3.2절 세 겹. 그래도 생기면 수정 요청 `retire` 또는 [틀린 기록으로 표시] |
| 민감도를 낮게 매김(S2를 S1로) → Drive 사본에 요지가 실림 | 사업 보고 칸이 '교섭'이면 서버가 최소 S2로 올림, 담당조직의 교섭 관련 기록도 같은 규칙 검토. 지시문 "애매하면 높게". 사본은 명진 Drive 비공개(공유 검사 그대로) |
| 개인정보·S3 | 지금처럼 기록에도 남기지 않고 개수만(L9) |
| 원문 속 지시문(프롬프트 주입) | 재료는 데이터로만, 답 모양·참조·글자 수 서버 검사. 자동 기록은 더하기만 할 수 있어 기존 기록을 망가뜨리지 못함 |
| 원문을 고치거나 지움 | 고침 → 3.2-2(확인필요만). 지움 → 기록은 남고 근거에 "원문이 지워졌어요" |
| 확정 단계가 없어 명진이 원장을 안 봄 | 업무일지 약속 한 줄, 원장 목록 "자동" 꼬리표, 매주 사본으로 Claude가 함께 봄. 명진이 원한 방식이라 수용 |

### 9.2 되돌리기

- 기록 하나: 상세 ⋯ [틀린 기록으로 표시] → 폐기(이유 선택). 지우지 않음.
- 실행 하나: [이번 자동 기록 취소] → `app_ledger_auto_undo`(4.3).
- 수정 요청 하나: [반영 취소] → `app_undo_ledger_fix`.
- 기능 전체 끄기: 앱이 `ledger_auto`를 부르지 않게 되돌리는 앱 PR(또는 `ai-assist` 이전 소스 재배포 → 서버가 `unsupported_kind`로 거절). 이미 들어간 자동 기록은 "자동" 꼬리표로 남고, 필요하면 실행 단위로 취소.
- DB: 짝 rollback SQL(자동 기록 행이 있으면 멈춤).
- 원장 행 완전 삭제는 여전히 없다(제한 정책을 넓히지 않음).

### 9.3 그 밖의 위험

- **시트 이전 전에는 자동 기록이 쌓이지 않음**: 번호표 접두어가 없으면 거절(4.3). 처리 표가 그대로라 이전 뒤 밀린 것을 처리하지만, 한 번 150건·6만 자 상한이라 여러 번에 나뉜다.
- **Web2를 안 열면 자동 기록도 멈춤**: 예약 실행이 원장을 쓸 수 없는 구조(서버 키 권한 없음)를 유지하기 때문. 열면 이어서 처리.
- **두 기기 동시**: `app_ledger_auto_begin` 잠금(2분)으로 한 번만 돈다.
- **비용 추정의 불확실성**: 가격은 코드의 가정값, 저장 수는 가정. 월 한도(1만 5천 원)가 위에서 막는다.
- **S2 사건과 이어 붙지 않음**: S2 제목을 AI에 보내지 않아 같은 교섭 사안이 새 사건으로 따로 생길 수 있음 → 수정 요청으로 합침(`retire` + `add_source`).

## 12. 범위 밖 발견 (고치지 않음)

- 챙길 것(`todo-radar`)의 상대측 약속 [원장으로 복사]는 옛 "쓰기요청" 문구를 복사한다. 자동 기록이 켜지면 같은 약속이 원장에 자동으로 들어가므로 이 버튼은 겹친다 → 정리 과제 후보.

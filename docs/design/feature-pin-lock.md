# 기능별 PIN 잠금 (SEC-기능PIN잠금)

명진 11/19 18:33 요청 "보안 기능 추가해줘. 네 자리 숫자 핀 번호를 기능별로 추가할 수 있게. 예를 들어 일기라든지. 껐다 켤 수 있는 거를 메뉴 안에다가 넣어 줘. 일단 시안부터." → CC 시안 확인 뒤 19:59 "ㅇㅇ".
확정: PIN은 서버에 알아볼 수 없게(해시) 저장해 폰·폴드·PC가 같은 PIN, 다시 잠그기 기본 5분.

## 1. 무엇인가 — 화면 가림이다

- 잠금은 **같은 기기를 다른 사람이 잠깐 볼 때 그 화면을 가리는 편의 장치**다. 자료 자체의 접근 권한은 지금 그대로다(작업공간 owner 경계·RLS·Edge 인증, AGENTS.md 3·5절). 이 기능은 그 경계를 넓히지도 좁히지도 않는다.
- 그래서 AI 재료(주간 보고·업무일지 초안·'이런 기록은 어때요?' 등 내 작업공간 서버 처리)는 잠금과 무관하게 지금대로 돈다.
- 잠긴 동안 그 기능의 화면은 **자료를 불러오지도 그리지도 않는다**. 가림막을 덮는 방식(display:none 덮기)이 아니라, 라우터가 그 화면으로 가기 전에 잠금 화면으로 보낸다(한 화면 영역 한 주인, ARCHITECTURE 5절).

## 3. 서버 (PR① — DB 함수, Edge 없음)

- 새 표 `public.app_feature_locks`(사람마다 한 줄): `pin_hash`(bcrypt 60자), `features`(위 4가지 안), `relock`(`now`·`5m`·`30m`·`close`), `fail_count`, `block_level`, `blocked_until`. RLS 켬·정책 없음·API 역할 표 권한 없음.
- 함수는 모두 SECURITY DEFINER·빈 search_path·`auth.uid()` 필수·authenticated만 실행. 사람 id는 받지 않는다.

| 함수 | 하는 일 |
|---|---|
| `app_lock_read()` | PIN이 있는지·잠근 기능·다시 잠그기·남은 횟수·막힌 끝 시각(해시 없음) |
| `app_lock_setup(pin, features, relock)` | 처음 PIN 정하기(이미 있으면 `LOCK_PIN_EXISTS`) |
| `app_lock_check(pin)` | 풀기. `{ok, left, blocked_until}` |
| `app_lock_save(pin, features, relock)` | 켜기·끄기·다시 잠그기 바꾸기. 지금 PIN이 맞아야 함 |
| `app_lock_pin_change(pin, new_pin)` | PIN 바꾸기 |
| `app_lock_pin_renew(new_pin)` | 잊음: 이 요청 세션이 최근 10분 안에 로그인했을 때만(JWT `amr` 로그인 시각) |

- **해시 근거**: Supabase에 이미 있는 pgcrypto `crypt(pin, gen_salt('bf', 10))`(bcrypt, 사람마다·바꿀 때마다 새 소금, 일부러 느림). PBKDF2·scrypt·argon2는 Postgres 안에 없고 Edge로 가면 새 함수·배포·비밀값 없는 service 경로가 하나 더 생긴다. RPC면 PIN이 HTTPS로 PostgREST까지만 가고, 함수 인자는 기록되지 않는다(시험 DB는 `log_statement=none`, 운영 기본도 DDL만).
- 4자리 PIN은 경우의 수가 1만이라 해시만으로는 막을 수 없다. 진짜 막는 것은 **서버가 세는 횟수**다: 연속 5번 틀리면 15분 막힘, 막힘이 끝나고 또 5번이면 30분·1시간…(두 배, 최대 24시간), 맞히면 0. 막힌 동안에는 맞는 PIN도 대조하지 않는다. 15분×두 배면 하루에 시도할 수 있는 수가 수십 번으로 줄어 1만 경우를 다 해 보는 데 몇 달이 걸린다.
- 틀림은 예외가 아니라 결과로 돌려준다(예외면 횟수 증가까지 취소됨).
- 로그에는 숫자·코드만(`LOCK_*` 이유 코드). PIN·해시는 어떤 응답·로그에도 없다.

## 4. 화면 (PR② — 적용 뒤)

- 입구: 계정 메뉴(PC 오른쪽 위·폰 [메뉴] 계정 칸)의 '메뉴 수정'·'화면 색' 같은 설정 줄 근처 **[잠금]** 한 줄 → `?view=lock`(새 화면, `updates`와 같은 방식). 근거: 왼쪽 메뉴는 화면 이동만 두고, 사람별 설정은 계정 메뉴에 모여 있다(`topbar-actions.js`).
- 잠금 화면: 기능마다 켜기/끄기 스위치 · '다시 잠그기'(바로·5분·30분·앱 닫을 때, 기본 5분) · [PIN 바꾸기].
- 처음 스위치를 켤 때 PIN 정하기(두 번 입력). 켜기·끄기·다시 잠그기 바꾸기는 PIN 확인 뒤.
- 잠긴 기능을 열면 그 화면 자리에 자물쇠 + 'PIN 4자리' + 점 4개 + 숫자 판(1~9·잊음·0·지우기). 4자리면 바로 서버 대조, 틀리면 흔들림 + 남은 횟수. PC는 키보드 숫자도.
- '잊음' → 구글 로그인을 다시 하고 돌아오면 PIN을 새로 정할 수 있다(서버가 최근 로그인 확인).
- 풀림 상태는 **화면 메모리에만**: 새로고침·앱 다시 열기면 다시 잠김. localStorage 등 브라우저 저장소에 PIN·풀림 상태를 두지 않는다. 한 번 풀면 잠근 기능 모두가 함께 풀린다(PIN이 하나라서).
- 다시 잠그기: `now` = 잠근 기능을 떠나면 바로, `5m`·`30m` = 잠근 기능을 마지막으로 본 뒤 그 시간이 지나면, `close` = 앱을 닫거나 다른 앱으로 가면(화면이 숨겨지면).
- 폰 앱(WebView)도 같은 웹 화면이라 앱 코드는 바꾸지 않는다.

## 7. 노트 폴더 잠금 (S67-14)

명진 11/19 20:37 "노트는 특정 폴더만 잠금 가능하게".

- 서버(`20261119233000_note_folder_lock`, 앞 단계 파일은 고치지 않고 더하기만): 새 표 `public.app_note_folder_locks`(사람·노트 폴더 한 쌍마다 한 줄, 폴더가 지워지면 함께 지워짐, RLS 켬·정책 없음·API 역할 표 권한 없음)와 함수 2개.

| 함수 | 하는 일 |
|---|---|
| `app_lock_note_folders()` | 내가 잠근 폴더 id 목록(지금도 내 작업공간 폴더만). 이름·내용 없음 |
| `app_lock_note_folder_set(pin, folder, locked)` | 폴더 하나 잠그기·풀기. 폴더 주인은 서버가 폴더 줄의 작업공간으로 확인(남의 폴더·없는 폴더는 같은 `LOCK_FOLDER_FORBIDDEN`, 횟수도 쓰지 않음) → 같은 PIN 대조(`private.app_lock_try`, 같은 틀린 횟수·막힘) → 50개까지(`LOCK_FOLDER_LIMIT`) |

- PIN이 아직 없으면 화면이 먼저 PIN 정하기(`app_lock_setup`, 잠근 기능 없이)를 한 뒤 잠근다.
- 풀림·다시 잠그기는 기능 잠금과 하나다: PIN 한 번이면 잠근 기능·폴더가 함께 풀리고, 같은 '다시 잠그기' 규칙으로 함께 잠긴다(화면 메모리에만).
- 잠긴 폴더와 그 안의 하위 폴더 노트는 어디서도 제목·내용 대신 '잠김'(화면 PR에서 처리할 곳을 전수 표로).
- 되돌리기: 화면 PR을 먼저 되돌린 뒤 짝 rollback(`docs/20261119233000_note_folder_lock.rollback.sql`, SQL Editor 전용). 잠근 폴더 목록만 사라지고 노트·폴더·PIN은 그대로다.

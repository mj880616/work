확정: PIN은 서버에 알아볼 수 없게(해시) 저장해 폰·폴드·PC가 같은 PIN, 다시 잠그기 기본 5분.

## 1. 무엇인가 — 화면 가림이다

- 잠금은 **같은 기기를 다른 사람이 잠깐 볼 때 그 화면을 가리는 편의 장치**다. 자료 자체의 접근 권한은 지금 그대로다(작업공간 owner 경계·RLS·Edge 인증, AGENTS.md 3·5절). 이 기능은 그 경계를 넓히지도 좁히지도 않는다.
- 그래서 AI 재료(주간 보고·업무일지 초안·'이런 기록은 어때요?' 등 내 작업공간 서버 처리)는 잠금과 무관하게 지금대로 돈다.
- 잠긴 동안 그 기능의 화면은 **자료를 불러오지도 그리지도 않는다**. 가림막을 덮는 방식(display:none 덮기)이 아니라, 라우터가 그 화면으로 가기 전에 잠금 화면으로 보낸다(한 화면 영역 한 주인, ARCHITECTURE 5절).

## 3. 서버 (PR① — DB 함수, Edge 없음)

- 새 표 `public.app_feature_locks`(사람마다 한 줄): `pin_hash`(bcrypt 60자), `features`(위 4가지 안), `relock`(`now`·`5m`·`30m`·`close`), `fail_count`, `block_level`, `blocked_until`. RLS 켬·정책 없음·API 역할 표 권한 없음.
- 함수는 모두 SECURITY DEFINER·빈 search_path·`auth.uid()` 필수·authenticated만 실행. 사람 id는 받지 않는다.

| 함수 | 하는 일 |
|---|---|
| `app_lock_read()` | PIN이 있는지·잠근 기능·다시 잠그기·남은 횟수·막힌 끝 시각(해시 없음) |
| `app_lock_setup(pin, features, relock)` | 처음 PIN 정하기(이미 있으면 `LOCK_PIN_EXISTS`) |
| `app_lock_check(pin)` | 풀기. `{ok, left, blocked_until}` |
| `app_lock_save(pin, features, relock)` | 켜기·끄기·다시 잠그기 바꾸기. 지금 PIN이 맞아야 함 |
| `app_lock_pin_change(pin, new_pin)` | PIN 바꾸기 |
| `app_lock_pin_renew(new_pin)` | 잊음: 이 요청 세션이 최근 10분 안에 로그인했을 때만(JWT `amr` 로그인 시각) |

- **해시 근거**: Supabase에 이미 있는 pgcrypto `crypt(pin, gen_salt('bf', 10))`(bcrypt, 사람마다·바꿀 때마다 새 소금, 일부러 느림). PBKDF2·scrypt·argon2는 Postgres 안에 없고 Edge로 가면 새 함수·배포·비밀값 없는 service 경로가 하나 더 생긴다. RPC면 PIN이 HTTPS로 PostgREST까지만 가고, 함수 인자는 기록되지 않는다(시험 DB는 `log_statement=none`, 운영 기본도 DDL만).
- 4자리 PIN은 경우의 수가 1만이라 해시만으로는 막을 수 없다. 진짜 막는 것은 **서버가 세는 횟수**다: 연속 5번 틀리면 15분 막힘, 막힘이 끝나고 또 5번이면 30분·1시간…(두 배, 최대 24시간), 맞히면 0. 막힌 동안에는 맞는 PIN도 대조하지 않는다. 15분×두 배면 하루에 시도할 수 있는 수가 수십 번으로 줄어 1만 경우를 다 해 보는 데 몇 달이 걸린다.
- 틀림은 예외가 아니라 결과로 돌려준다(예외면 횟수 증가까지 취소됨).
- 로그에는 숫자·코드만(`LOCK_*` 이유 코드). PIN·해시는 어떤 응답·로그에도 없다.

## 4. 화면 (PR② — 적용 뒤)

- 입구: 계정 메뉴(PC 오른쪽 위·폰 [메뉴] 계정 칸)의 '메뉴 수정'·'화면 색' 같은 설정 줄 근처 **[잠금]** 한 줄 → `?view=lock`(새 화면, `updates`와 같은 방식). 근거: 왼쪽 메뉴는 화면 이동만 두고, 사람별 설정은 계정 메뉴에 모여 있다(`topbar-actions.js`).
- 잠금 화면: 기능마다 켜기/끄기 스위치 · '다시 잠그기'(바로·5분·30분·앱 닫을 때, 기본 5분) · [PIN 바꾸기].
- 처음 스위치를 켤 때 PIN 정하기(두 번 입력). 켜기·끄기·다시 잠그기 바꾸기는 PIN 확인 뒤.
- 잠긴 기능을 열면 그 화면 자리에 자물쇠 + 'PIN 4자리' + 점 4개 + 숫자 판(1~9·잊음·0·지우기). 4자리면 바로 서버 대조, 틀리면 흔들림 + 남은 횟수. PC는 키보드 숫자도.
- '잊음' → 구글 로그인을 다시 하고 돌아오면 PIN을 새로 정할 수 있다(서버가 최근 로그인 확인).
- 풀림 상태는 **화면 메모리에만**: 새로고침·앱 다시 열기면 다시 잠김. localStorage 등 브라우저 저장소에 PIN·풀림 상태를 두지 않는다. 한 번 풀면 잠근 기능 모두가 함께 풀린다(PIN이 하나라서).
- 다시 잠그기: `now` = 잠근 기능을 떠나면 바로, `5m`·`30m` = 잠근 기능을 마지막으로 본 뒤 그 시간이 지나면, `close` = 앱을 닫거나 다른 앱으로 가면(화면이 숨겨지면).
- 폰 앱(WebView)도 같은 웹 화면이라 앱 코드는 바꾸지 않는다.

## 8. 고르기 창과 쓰던 것 붙들기 (S67-23)

- 증상(2026-11-20 요청): 잠금 켠 하루 기록 수정 창에서 [사진]·[넣기 ▾ › 파일]로 폰 고르기 창을 열었다 돌아오면 숫자 판이 뜨고, PIN을 넣으면 수정 창이 아니라 달력으로 돌아와 고른 파일·쓰던 글이 사라졌다.
- 원인(사실): 고르기 창이 뜨면 페이지가 숨겨진다(`visibilitychange` hidden — 폰 앱은 `onShowFileChooser`가 안드로이드 고르기 창을 띄워 WebView가 뒤로 감). `feature-lock.js`가 이를 '다른 앱으로 감'으로 보고 '바로'·'앱 닫을 때'면 곧바로 잠가 `guard` → `go('lock')`. 이때 하루 기록의 `kptu:before-view-change`가 수정 창을 닫아(바뀐 것이 없으면 묻지 않고 닫음) 세션이 버려졌고, PIN 뒤에는 `enter()`가 달력을 새로 그렸다. 바뀐 글이 있으면 반대로 '나갈까요?' 물음이 잠금 이동을 멈춰, 잠겨야 할 수정 창이 그대로 보이는 문제도 있었다(E2E로 재현).
- 고르기 창: 파일 고르기 칸(`input type=file`)을 누르면(문서 전체 누름 듣기 한 곳, `feature-lock.js`) 3초 안의 화면 숨김은 고르기 창으로 보고 잠그지 않는다. 사진 편집기(`phone-photos.js` edit)·공유 창(`app-share.js` out:go, `navigator.share`)은 열기 직전에 `stepOut()`을 부른다. 고르기 창을 연 채 오래 떠나 있었으면(다시 잠그기 시간, '바로'·'앱 닫을 때'는 3분) 돌아왔을 때 원래대로 잠근다. 고르기 창이 닫히면(다시 보이면) 바로 원래 규칙이다.
- 붙들기(hold): 다시 잠길 때 문지기는 `go('lock', {hold:true})`로 보내고, 라우터는 `before-view-change`·`view-changed` detail에 `hold`를 실어 보낸다. 잠금 이동은 쓰던 화면이 막거나 물을 수 없다. 하루 기록은 수정 창을 버리지 않고(화면째 숨겨짐), PIN 뒤 `go(view, {hold:true})`로 돌아오면 그대로 보이고 뒤로가기 겹만 다시 연다. PIN 없이 다른 화면에 갔다 와도 문지기가 다시 숫자 판으로 보낸다(`held`).
- 노트 폴더: 잠긴 폴더 노트를 고치던 중(저장 안 한 글) 다시 잠기면 닫지 않고 `askNotes(…, {hold:true})`로 정리함째 잠금 화면 뒤에 숨긴다(`retainBasketDraft`). 큰 쓰기 창이 떠 있으면 숨길 수 없어 지금처럼 닫는다. 숫자 판 [취소]면 붙들기를 놓고, 정리함에 돌아오면 잠긴 노트는 닫는다(자료를 남기지 않음).
- 폰 앱(안드로이드) 코드는 바꾸지 않는다(고르기 창은 웹 칸 누름에서 시작하므로 웹 쪽 판정으로 충분). 앱 새 판 필요 없음.

## 9. 앱 전체 잠금 (S69-08)

사용자 11/24 07:44 "잠금 기능 중에서 앱 전체를 잠그는 기능도 있었으면 좋겠는데 어 이것도 켜고 끌 수 있도록".

- 잠금 설정 화면 스위치 줄 **맨 위에 '앱 전체'** 한 줄(켜기·끄기). 같은 PIN, 같은 '다시 잠그기'(바로·5분·30분·앱 닫을 때). 처음 켤 때 PIN이 없으면 PIN 정하기, 켜기·끄기는 PIN 확인 뒤(다른 스위치와 같은 길).
- 서버(`20261124080000_app_lock_whole_app`, 앞 단계 파일은 고치지 않고 더하기만): 잠글 수 있는 이름에 `app` 하나를 더한다 — 표 `app_feature_locks`의 `features` 검사(4 → 5가지)와 private 목록 도우미 `app_lock_clean_features`(같은 서명·invoker·빈 search_path·실행권 없음)만 고친다. 표 권한·RLS·정책·공개 함수 6개·노트 폴더 함수·자료는 그대로. 되돌리기: 화면 PR을 먼저 되돌린 뒤 짝 rollback(`docs/20261124080000_app_lock_whole_app.rollback.sql`, SQL Editor 전용) — 켠 사람 줄에서 `app` 한 이름만 빠지고 PIN·다른 잠금은 그대로.
- **시작 순서**: 세션 확인 → 로그인 → 작업공간 확인 → 사람별 설정(이름 고침·화면 색) → **앱 잠금 확인** → 첫 화면. `loader-v2.js`가 잠금 설정을 읽고(4초까지 기다림), 앱 전체가 잠겼으면 첫 화면 프로그램·자료를 받기 전에 잠금 화면만 연다(`feature-lock.js` `startGate`, 그리기는 `lock-ui.js` 하나). 주소는 원래 화면 그대로 두고, 맞는 PIN이면 시작 순서가 그 화면을 연다. 잠금 화면이 떠 있는 동안 나가는 요청은 로그인·작업공간 확인·사람별 설정·기능 목록·잠금 함수뿐이다(E2E `tests/app-e2e/app-lock-whole.spec.mjs`가 요청 목록으로 본다).
- 앱 안에서 잠기면(다시 잠그기) 라우터 문지기가 지금처럼 화면째 잠금 화면 뒤에 붙든다(hold, 8절). 잠긴 동안 메뉴·주소·뒤로 가기로 다른 화면에 가도 잠금 화면 그대로(라우터 `go()`·`view-loader.load()`가 같은 `locked()`를 묻는다).
- 다시 잠그기: 시계는 기능 잠금과 따로다. 앱 전체는 **앱을 떠난 때(화면 숨김)부터** 잰다 — '바로'·'앱 닫을 때' = 앱을 떠나면 바로, 5분·30분 = 떠난 뒤 그 시간이 지나 돌아오면. 앱 안에서 화면을 옮겨 다니는 것은 재지 않는다. 고르기 창 예외(8절)도 같다.
- 풀림: PIN 하나라 한 번 맞히면 앱 전체와 잠근 기능·폴더가 **함께 풀린다**(4절의 지금 규칙). 그 뒤 기능 잠금은 기능 잠금 시계대로 따로 다시 잠긴다(앱 전체가 풀려 있어도 하루 기록은 떠난 뒤 5분이면 다시 잠김).
- 잠금 화면(앱 전체가 잠긴 동안): 전체화면 숫자 판, 제목 '앱 잠김'. 나갈 화면이 없으므로 왼쪽 위 [✕] 대신 맨 아래 **[로그아웃]**(갇히지 않게·다른 계정). **PIN 잊음**은 지금 길 그대로(최근 로그인이면 새 PIN 정하기, 아니면 구글로 다시 로그인 — 돌아온 주소 `?view=lock&renew=1&for=…`는 시작 순서가 돌아갈 화면 주소로 바꾸고 새 PIN 정하기를 연다).
- 설정 읽기: 실패(서버 오류·연결 실패)면 켜 두었는지 모르므로 앱 전체를 가리고 잠금 화면에 [다시](잠근 기능 화면의 지금 규칙과 같음). 4초 넘게 늦으면 앱을 멈춰 세우지 않고 열고, 늦게 온 설정이 앱 전체 잠금이면 그때 바로 잠금 화면으로 옮긴다. 작업공간 확인 요청이 먼저 성공해야 여기까지 오므로 오프라인에서 열어 잠금을 건너뛰는 길은 없다.
- 잠금은 여전히 **화면 가림**이다. 자료 권한은 서버 owner 경계 그대로이고, 풀림 상태는 탭 메모리에만 둔다(기기 저장소 없음). 폰 앱(WebView)도 같은 웹 시작 순서라 앱 코드는 바꾸지 않는다. 폰 지문 풀기는 이번에 하지 않는다(제안만).

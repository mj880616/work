### 1.3 공유 링크 길(남아 있는 유일한 바깥 길)

- AGENTS.md 5절: Web2 공개·게시·공유 경로는 없앴다. 남은 것은 공유 페이지 `share/`(`work.bokdoong.com/work/share/`)이고, "밖에 보여 줄 일은 원본을 Web2에 두고 Web2 공유 링크로".
- 표: `app_share_pages`(status draft/published/archived·휴지통), `app_share_page_links`(토큰은 DB가 만듦, 읽기는 `token_hash`=sha256으로만, `expires_at`·`disabled_at`), `app_share_page_slugs`(짧은 주소 `이름-8글자`), `app_share_page_html`(HTML 판), `app_share_page_media`(사진, 비공개 버킷). 모두 owner RLS, anon 권한 없음.
- 읽기: Edge `share-page-read`(verify_jwt=false). 토큰/짧은 주소 → 지문 → 링크(꺼짐·기한) → published 페이지 → 내용. 그 밖은 모두 같은 404. no-store·noindex, CORS는 공유 화면 주소만.
- 노트 게시(`docs/design/note-publish.md`): 짝 표 `app_note_share_pages`(페이지 ↔ 노트), 게시 멈춤 = status `draft`, 노트 사진은 **주인이 로그인한 화면이** `share-page-media`로 다시 그려 올림(받는 사람 요청 때 서버가 주인 Drive를 대신 읽지 않음).
- 받는 화면: `share/index.html` — CSP `default-src 'none'; script-src 'self'`, `robots noindex,nofollow,noarchive`, no-referrer. `?t=`는 바로 `#t=`로 옮김. HTML 판은 sandbox iframe(allow-same-origin 없음, `share/frame.html`).
- 짧은 주소: Worker가 `bokdoong.com`·`nojoplus.com`·`workonplus.com`의 `/s/<이름-8글자>`를 공유 화면으로 302(`cloudflare/bokdoong-router.mjs`).

## 2. 무엇을 게시하나

- **보드 하나 = 게시본 하나.** 게시 때 그 보드의 주제·가지 선·관계선·글자·도형·선·사진·노트 카드(별명 또는 제목)·재료 칩 제목을 찍어 **정적 자료(JSON) 한 벌**로 저장한다.
- 원본 보드는 비공개 그대로다. 게시본은 원본을 다시 읽지 않으므로, 게시 뒤 원본을 고쳐도 게시본은 안 바뀐다(노트 게시는 지금 글을 읽지만, 보드는 여러 표·Drive 사진·재료를 모으는 일이라 읽을 때마다 모으면 원본 권한 길이 바깥에 열린다).
- **[다시 게시]** = 지금 보드를 새로 찍어 같은 주소의 게시본을 바꾼다(주소·비밀번호·만료일 그대로). 이전 게시본은 남기지 않는다(덮어씀, 사진도 새 게시본에 없는 것은 지움).
- **[게시 멈추기]** = 즉시 내림(그 순간부터 404, 받아 둔 사진 주소도 404). 같은 보드를 다시 게시하면 **같은 주소가 다시 살아난다**(노트 게시와 같음). 주소를 바꾸고 싶으면 [새 주소로 바꾸기](옛 주소는 영구 404).
- 원본 보드를 지우면 게시본도 내린다(멈춤과 같음). 게시본만 남는 일은 없다.
- 왜 #3073 HTML 내보내기를 그대로 올리지 않나: 그 HTML은 화면 모양(계산된 스타일)을 그대로 붙인 것이라 (1) 받는 화면이 그 HTML을 믿고 그려야 하고(sandbox iframe 안 — 찾기·미니맵·자리 링크를 바깥 화면이 다룰 수 없음), (2) 멀리 보기·접기를 하려면 다시 짜임 자료가 필요하고, (3) 서버가 안을 들여다보고 거를 수 없다. 그래서 게시본은 **짜임 자료(JSON)** 로 두고, 받는 화면이 글자만(`textContent`) 그린다. 계산 부품(자리·선 모양)은 #3073·S71-52와 같은 파일을 쓴다.

### 2.1 게시본 자료 모양(제안, ① 단계에서 S71-52~54 결과에 맞춰 확정)

```
{ "v": 1,
  "title": "보드 이름(게시 창에서 고칠 수 있음)",
  "at": "2026-11-26T20:00:00+09:00",          // 찍은 때(받는 화면 맨 아래 '○월 ○일 기준')
  "box": [x0, y0, x1, y1],                      // 전체 범위(처음 열 때 전체 보기)
  "topics":  [ { "id":"t1", "parent":null, "x":0, "y":0, "w":180, "h":40, "text":"…", "kind":"topic",
                 "look":{ "color":2, "shape":"round", "font":3 }, "collapsed":false,
                 "depth":0, "mats":["m1","m2"] } ],
  "cards":   [ { "id":"c1", "x":…, "y":…, "w":…, "h":…, "text":"별명 또는 노트 제목", "mat":"m3" } ],
  "lines":   [ { "id":"l1", "kind":"branch|relation|free", "from":"t1", "to":"t4", "shape":"curve",
                 "dash":false, "ends":"end", "label":"…", "color":3, "width":2 } ],
  "photos":  [ { "id":"p1", "x":…, "y":…, "w":…, "h":…, "media":"share:<사진 id>" } ],
  "mats":    [ { "id":"m1", "type":"note|file|url", "title":"…", "body":null | {doc…}, "file":null | "share:<파일 id>", "url":null | "https://…" } ]
}
```

- `id`는 게시본 안에서만 쓰는 새 번호다(`t1`·`c1`…). **원본 상자·노트·Drive 파일 번호는 게시본에 남기지 않는다**(노트 게시의 사진 지문 규칙과 같음).
- 가지 자리는 게시 때 `layoutMindmap`으로 계산한 값을 싣는다(받는 화면이 자동 배치를 다시 하지 않음 — 원본과 똑같이 보임).
- 한도(제안): 칸 합계 3,000개, 자료 2MB, 사진 200장, 내용 포함 재료 100개. 넘으면 게시 창이 무엇을 줄일지 한 줄로 알린다.

## 3. 재료(노트·자료실 자료·웹 링크) 처리

| 재료 | 기본(내용 포함 꺼짐) | '게시본에 내용 포함'을 켜면 | 원본 권한 |
| --- | --- | --- | --- |
| 노트 | 제목(또는 카드 별명)만 칩으로 | 그 노트 **글 사본**(편집기 서식 `ed1`, 노트 게시와 같은 모양) — 노트 안 사진은 게시본 사진으로 다시 그려 올림, 파일 칸은 이름·크기만 | 그대로(노트 표 RLS·공유 설정 안 바뀜) |
| 자료실 자료 | 자료 이름·종류만 | 그 파일 **사본**을 게시본 저장소에 복사(PDF·그림만 — 제안, 9절) | 그대로(Drive 파일 공유 설정을 바꾸지 않음) |
| 웹 링크 | 제목 + 주소 그대로(받는 사람이 누르면 새 탭, `rel=noopener noreferrer`) | 해당 없음(주소가 곧 내용) | — |

- 켜는 단위(제안): **주제마다**(그 주제에 달린 재료 모두) + 재료마다 따로 끄기. 게시 창에 '내용이 함께 나가는 재료 n개' 목록을 늘 보인다.
- 사본은 게시본 쪽에만 산다. 원본 노트를 고쳐도 게시본은 [다시 게시] 때만 바뀐다. 게시 멈춤·주소 바꾸기·원본 보드 지우기 때 사본도 지운다.

### 3.1 어떤 경우에도 못 들어가는 것 — 서버가 거름

화면이 빼는 것만 믿지 않는다. ① 단계의 게시 서버(5절)가 **주인 로그인 토큰으로 원본을 직접 읽어** 게시본을 만들고, 아래를 거른다. 화면이 보낸 게시본 자료를 그대로 받지 않는다.

| 막는 것 | 서버가 하는 일 |
| --- | --- |
| 잠근 폴더의 노트 | 카드는 자물쇠 자리만(제목·별명도 '잠긴 노트'), 재료 내용 포함 불가 |
| 가족 기록·일기·업무일지 | 노트 종류가 `note`가 아니면 재료가 될 수 없음(카드도 자리만) |
| 통화·텔레그램·운영자 전용 기능 자료 | 그 자료에서 온 노트·재료는 제목조차 넣지 않음(서버 허용 표와 무관하게 게시본에는 늘 거절, AGENTS.md 5절 '어떤 공유로도 열리지 않음'과 같은 줄) |
| 휴지통·보관한 노트 | 넣지 않음 |
| 다른 작업공간 것 | 주인 RLS로만 읽으므로 처음부터 안 보임. 함께 보기(묶인 사람 공유)로 보이는 남의 자료도 게시본에는 **넣지 않음**(재료 칩 자리만, '내 자료 아님') |
| 주민등록번호·카드·계좌 번호 모양 글자 | 게시본 글에서 가림(●●●). 전화번호·메일 모양은 게시 창이 '이런 글이 있어요' n개를 미리 보여 주고 주인이 고르게(7절 결정 5) |
| 사진 정보(EXIF·위치) | 사진은 다시 그려 올리고 서버가 정보 칸을 거절(노트 게시와 같은 `inspectJpeg`) |

## 5. 주소·접근

| 항목 | 제안 |
| --- | --- |
| 주소 | 기존 공유 링크 길: `work.bokdoong.com/work/share/?t=<64자>`(DB가 만든 토큰, 서버는 지문만 봄). 짧은 주소(`workonplus.com/s/<이름>-<8글자>`)는 선택(7절 결정 4) |
| 비밀번호 | 선택. 서버가 PBKDF2(소금·반복)로 지문만 저장, 원문은 어디에도 남기지 않음. 틀린 횟수는 게시본마다 세어 5번 틀리면 10분 잠금(이 링크만) — `share-page-read`에 공용 시도 제한이 없어서(사실) 게시본 쪽에 따로 둔다 |
| 검색 엔진 | `noindex,nofollow,noarchive`(받는 화면 머리·응답 머리 둘 다, 지금 공유 화면과 같음), 미리보기 카드는 보드 제목만(비밀번호가 걸린 게시본은 제목도 안 냄) |
| 만료일 | 선택. 기존 링크의 `expires_at`을 그대로 씀. 지나면 404(내용·사진 사본은 다음 정리 때 지움) |
| 본 횟수 | 게시본마다 숫자 하나(하루 단위로 더함). **누가·어디서·언제 봤는지는 모으지 않는다**(주소·기기·쿠키 없음) |
| 주인 화면에서 | 보드 머리 한 줄 '게시 중 · 본 횟수 n · 링크 복사 · ⋯'(⋯ = 다시 게시·비밀번호·만료일·게시 멈추기·새 주소로 바꾸기) |

- `?t=`는 지금처럼 바로 `#t=`로 옮겨 서버 기록·다른 사이트로 가는 주소에 남지 않게 한다.
- '이 자리' 정보(④)는 `#` 뒤에만 붙인다: `…/work/share/#t=<64자>&at=<x>,<y>,<배율>` 또는 `&topic=t12`. `#` 뒤는 서버로 가지 않는다. 비밀번호는 어떤 경우에도 주소에 넣지 않는다.

## 6. 보안 경계

- 원본 표(`app_notes`·`app_note_board_texts`·`app_note_board_links`·자료실 표)의 RLS·권한은 **한 줄도 바꾸지 않는다.** anon·PUBLIC 권한 없음, 새 공개 RPC 없음, 공개 버킷 없음.
- 게시본은 **따로 저장**한다: 게시본 자료는 새 표(owner RLS, API 역할 직접 쓰기 없음), 사진·파일 사본은 기존 비공개 버킷 `share-page-media`(페이지 소속 기록만, 5분 서명 주소).
- 게시 만들기·다시 게시·멈추기·비밀번호·만료일은 **로그인한 주인만**: 새 Edge `board-publish`(verify_jwt=true, 코드에서도 로그인 다시 확인, 위임 토큰 거절 — `share-page-media`와 같은 틀). 주인 확인은 호출자 토큰으로 DB(owner RLS)가 한다. 클라이언트가 보낸 작업공간·주인 번호는 믿지 않는다(AGENTS.md 3절 3).
- 서버가 게시본을 만든다: `board-publish`가 **호출자 토큰으로** 보드 표·노트 카드·재료를 읽어(그러니 주인 것만 보임) 3.1절 거름을 거친 뒤 게시본 자료를 저장한다. 서버 키(service_role)는 게시본 표 쓰기·비공개 버킷 쓰기에만.
- 사진·자료 파일 사본은 노트 게시와 같이 **주인 화면이** 주인 로그인으로 받아(`basket-files`, 주인만) 다시 그려 올린다. 받는 사람 요청 때 서버가 주인 Drive를 대신 읽는 길은 만들지 않는다(AGENTS.md 5절).
- 읽기는 기존 공개 문 하나(`share-page-read`, verify_jwt=false)에 보드 길을 더한다(새 공개 함수를 늘리지 않음). 읽는 칸은 게시본 표의 필요한 칸만 SELECT, 그 밖은 같은 404.
- 받는 화면은 받은 글을 `textContent`로만 그린다. 노트 글은 기존 `ed-render.mjs`(공유 화면에서 이미 쓰는 것). 웹 링크는 `https:`·`http:`만, 그 밖(`javascript:` 등)은 글자로만.
- 운영자도 게시본 내용을 보지 않는다(AGENTS.md 3절 '남의 기록 안 보기'). 운영 확인은 게시본 개수·크기 합계 같은 숫자만.

## 7. 사용자에게 물을 결정(일상어, 추천 ★)

1. **비밀번호 기본** — (가) 끔: 링크만 있으면 누구나 봄(링크 글자가 64자라 짐작은 불가능) ★ / (나) 켬: 게시할 때마다 비밀번호를 정하고 받는 사람에게 따로 알려 줘야 함.
   - 추천 까닭: 설명용으로 여러 사람에게 보내는 일이 많아 보이고, 링크 자체가 비밀번호 역할을 한다. 민감한 보드만 그때 켠다.
2. **재료 내용 기본** — (가) 제외: 제목만 보이고, 내용은 주제마다 켤 때만 나감 ★ / (나) 포함: 붙인 노트 글·자료가 기본으로 함께 나감.

3. **만료 기본** — (가) 없음(멈출 때까지) / (나) 30일 ★ / (다) 7일. 게시 창에서 바꿀 수 있고, 만료 전날 앱 알림 한 줄.

- 공유 화면 미리보기 카드(Worker)가 보드 제목을 쓰는지 ③에서 확인하고, 비밀번호 걸린 게시본은 제목을 내지 않게 한다(Worker 변경이 필요하면 따로 PR).

## 9. 남은 결정·위험

- **자료 파일 사본 종류**: PDF·그림만 받을지, 한글·워드 파일도 받을지. 한글·워드는 받는 화면이 미리보기를 못 하므로 [내려받기]만 — 받는 사람 기기에서 열리는 파일이 된다. 제안: ①은 PDF·그림만, 그 밖은 '제목만' 칩.
- **용량**: 게시본마다 사진·파일 사본이 비공개 버킷에 쌓인다. 게시본 하나 100MB 한도·전체 한도를 ①에서 정한다. 멈춤·만료·주소 바꾸기 때 지우는 정리는 ①에 넣는다.
- **휴지통 줄**: 게시본의 짝 페이지 행이 휴지통 '공유 페이지' 줄에 섞일 수 있다(노트 게시 짝 페이지와 같은 문제). ②에서 짝이 있는 줄은 빼거나 '보드 게시본'으로 보이게 한다.
- **아주 큰 보드**: '무한정 뻗어나가는' 보드는 칸 3,000개 한도를 넘을 수 있다. 넘으면 게시 창이 접힌 가지를 빼고 게시할지 묻는 안을 ②에서 시안으로 보인다.
- **시도 제한**: 비밀번호 잠금은 게시본마다다. 여러 게시본을 두루 두드리는 시도는 막지 못한다(토큰 64자라 실익 없음). 공용 시도 제한 장치는 이번 범위 밖.
- **S71-54 재료 저장 위치**를 보고 서버가 재료를 읽는 길이 정해진다. 재료가 노트 `metadata`에 있으면 노트 표 하나만 읽으면 되고, 새 표면 그 표의 owner RLS로 읽는다 — 어느 쪽이든 RLS는 넓히지 않는다.

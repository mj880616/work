## 1. 요구 정리 (원장 그대로)

- 원드라이브의 **지정 폴더**에 있는 사진을 **찍은 날짜별로 읽어** 일기 날짜 아래 [전체] 보기에 보여 준다.
- 사진에 ☆를 누르면 [별표] 보기에 모인다. 별표는 Web2에 저장하고 직접 올린 사진도 함께 쓴다.
- 구글 포토는 2025-03 이후 외부 앱의 라이브러리 읽기가 막혀 쓰지 않는다.
- 화면 자리는 1차에서 이미 있다([전체|별표] 전환, 연결 전 [별표] 안내, 크게 보기 ☆ 자리). 2차는 그 자리를 동작시키는 일이다.
- 필요한 것(원장): 마이크로소프트 앱 등록(사용자) · 로그인 연결 · 새 Edge 함수(AGENTS.md §6 정지 지점, §8 신규 배포 절차).

**정보 원본 원칙과의 관계.** "자료 원문 = Drive(Google)"은 업무 문서·첨부 원문에 대한 원칙이다. 일기 사진의 원본은 이미 명진의 원드라이브에 있다. 이 설계는 그 사진을 **복사하지 않고 읽기만** 하므로 원본이 둘로 갈라지지 않는다(원드라이브가 원본, Web2는 보는 창 + 별표 기록). 직접 올린 일기 사진은 지금처럼 Google Drive "Web2 바구니"에 남는다.

**A로 설계한다.**

## 3. 연결 구조: 기존 Google Drive 연결과 비교

코드로 확인한 기존 구조(`supabase/functions/_shared/drive-upload.ts`):

- 연결 정보 한 행을 DB 표 `public_policy_drive_config`(id=1)에 둔다: Google 클라이언트 id·비밀·**갱신 토큰**.
- Edge 함수가 service role로 그 행을 읽고, 갱신 토큰으로 짧은 접근 토큰을 받아 Drive를 부른다. 접근 토큰은 저장하지 않는다.
- 갱신 토큰이 막히면(`invalid_grant`) "연결 만료"(424)로 알린다.

원드라이브도 **같은 방식**을 쓴다. 달라지는 점만 정리한다.

| 항목 | Google Drive (기존) | 원드라이브 (이 설계) |
| --- | --- | --- |
| 앱 id·비밀 | DB 행 안 | **Supabase 비밀값**(`ONEDRIVE_CLIENT_ID`, `ONEDRIVE_CLIENT_SECRET`, `ONEDRIVE_REDIRECT_URI`, 선택 `ONEDRIVE_TENANT`). DB에는 두지 않는다 |
| 갱신 토큰 | 한 행 | 새 표 `app_onedrive_connections` 작업공간당 1행. **화면용 권한 0**(로그인한 나도 못 읽음), service role만 읽고 씀 |
| 토큰 갱신 | 같은 토큰 계속 | 마이크로소프트는 갱신 때마다 **새 갱신 토큰**을 줄 수 있어, 받으면 바로 바꿔 저장한다 |
| 연결하는 법 | 운영자가 한 번 만든 행 | 화면의 [원드라이브 연결] 버튼 → 마이크로소프트 로그인 → Web2로 돌아옴 → 서버가 코드를 열쇠로 바꿈(5절) |

## 4. 권한 범위 (가장 좁게)

요청하는 권한은 **`Files.Read` + `offline_access`** 두 가지다(위임 권한, 내 원드라이브 파일 읽기 + 로그인 유지).

- `Files.ReadWrite.AppFolder`는 쓰지 않는다. 그 권한은 앱 전용 폴더("앱" 폴더)만 보여서 카메라 앨범 같은 기존 폴더를 읽을 수 없다. 이 요구에 맞지 않는다.
- `Files.ReadWrite*`·`Files.Read.All`은 요청하지 않는다. 함수는 로그인 응답의 허용 범위에 `ReadWrite`나 `.All`이 섞여 있으면 **저장하지 않고 거절**한다(시험으로 고정).
- 솔직한 한계: 마이크로소프트의 `Files.Read`는 "이 폴더 하나만"으로 좁힐 수 없다. 토큰 자체는 원드라이브 전체를 읽을 수 있다. 그래서 (1) 토큰을 화면·로그·응답에 절대 내보내지 않고 service role 전용 표에만 두며, (2) 서버가 **고른 폴더 밖 사진은 거절**(경로 경계 검사)한다. 최악의 유출도 "사진을 읽을 수 있음"에 그치고 쓰기·삭제는 불가능하다.
- 연결을 완전히 끊으려면 Web2의 [연결 끊기](열쇠 삭제) 뒤 마이크로소프트 계정의 앱 권한 화면에서 이 앱을 지우면 된다(9절 명진 할 일).

## 6. Edge 함수 `onedrive-photos`

- **verify_jwt = true.** 부르는 쪽은 로그인한 Web2 화면뿐이고, 사진은 화면이 로그인 토큰을 붙여 받은 바이트를 그림으로 바꿔 보여 주므로 로그인 없는 주소가 필요 없다. 함수 안에서도 Auth `getUser` + 작업공간 owner 확인을 다시 한다(`basket-files`와 같은 방식). 요청 값의 작업공간·사용자는 믿지 않는다.
- 요청은 모두 `POST` JSON `{ "action": ... }`. 큰 본문(16KB 초과)·JSON 아님은 거절.

| action | 하는 일 | 입력 | 주요 응답·오류 |
| --- | --- | --- | --- |
| `status` | 연결 상태. 비밀값이 없으면 `configured:false` | - | `{configured, connected, folder:{name}\|null, connected_at}` (토큰 없음) |
| `auth-start` | 마이크로소프트 로그인 주소 만들기 | - | `{url}`. `state`는 서버가 HMAC 서명(사용자·작업공간·10분 만료). 브라우저 저장소 불필요 |
| `auth-finish` | 돌아온 코드를 서버가 열쇠로 바꿔 저장 | `code`, `state` | `{connected:true}`. state 위조·만료·다른 사용자 400, 허용 범위가 읽기 전용이 아니면 400 |
| `folders` | 폴더 고르기용 하위 폴더 목록 | `parent_id`(없으면 맨 위) | `{folders:[{id,name}]}` |
| `folder-set` | 사진을 읽을 폴더 지정 | `folder_id` | 폴더가 아니거나 원드라이브 맨 위(루트)면 400 |
| `photos` | 한 달치 사진 목록(찍은 날짜별, 서울 시간) | `month` `YYYY-MM` | `{days:{"YYYY-MM-DD":[{id,name,taken_at,approx}]}, truncated}`. 사진 아닌 파일 제외. 찍은 시각이 없으면 파일 생성 시각으로 대신하고 `approx:true` |
| `photo` | 사진 한 장(작게 480px / 크게 1600px) 바이트 | `id`, `size` | 지정 폴더 밖이면 403. 8MB 초과·이미지 아님 502 |
| `disconnect` | 저장한 열쇠 지우기 | - | `{connected:false}` |

- **비밀값 없으면 안전하게 멈춤**: `ONEDRIVE_CLIENT_ID`·`ONEDRIVE_CLIENT_SECRET`(16자 이상)·`ONEDRIVE_REDIRECT_URI`(https)가 하나라도 없으면 `status`는 `configured:false`, 나머지는 `424 onedrive_not_configured`. 네트워크 호출·DB 쓰기 없음(시험으로 고정).
- 마이크로소프트로 보내는 주소는 고정 호스트뿐이다. 다음 쪽 주소(`@odata.nextLink`)는 `graph.microsoft.com`일 때만 따라가고, 사진 임시 주소는 https·이름 있는 호스트만 받으며(IP·localhost 거절) 그 요청에는 토큰을 붙이지 않는다. 리다이렉트는 따라가지 않는다.
- 한 번에 읽는 양을 제한한다(요청 40회, 항목 5000개, 하위 폴더 3단계). 넘치면 `truncated:true`.
- 로그에는 오류 코드만 남기고 토큰·주소·파일 이름은 남기지 않는다. 응답에도 토큰이 없다(시험으로 확인).
- **배포 절차(§8 신규 함수)**: 먼저 DB 적용 → 비밀값 등록(명진) → 승인형 `edge-function-deploy.yml`에 `function=onedrive-photos`, `first_deploy=true`, `verify_jwt=true`, `expect_unauth_401=true`. `docs/web2-env6b-edge-source.md` 5절 표 **37행을 이 PR에서 사전 등록**했다(배포 대기, `true`). 배포 후 정확히 1개·JWT 정책·유효한 version·비로그인 POST 401·OPTIONS 200/204를 workflow가 확인한다. 이전 버전이 없으므로 되돌리기는 "화면이 이 함수를 아직 쓰지 않는 상태 유지"이고, 필요하면 비밀값을 지워 입구를 닫는다. 함수 삭제는 사용자가 대시보드에서 판단한다(자동 삭제 없음).
- 성능 메모: 월 목록은 폴더를 훑어 만들기 때문에 사진이 수천 장이면 느릴 수 있다. 1단계는 단순하게 만들고, 실제 계정으로 재 본 뒤 필요하면 4단계에서 월 요약 캐시(별도 DB 제안)를 더한다. 접근 토큰은 함수 안에서 1시간 가까이 재사용해 갱신 호출을 줄였다.
- 미확인(실제 계정이 있어야 확인 가능): 휴대폰 HEIC 사진의 썸네일 형식, `c1600x1600` 크기 지정이 모든 사진에서 받아지는지, 폴더 경로의 한글 인코딩 형태. 경로 검사는 안 맞으면 **거절 쪽으로** 멈추도록 만들었고(열어 주지 않음), 실제 연결 뒤 2단계 시작 때 확인한다.

## 8. 명진이 직접 하는 일: 마이크로소프트 앱 등록

PC 브라우저 권장. 화면 글씨는 마이크로소프트가 가끔 바꿔서 조금 다를 수 있다. 다르면 캡처를 보내 주면 된다. **비밀번호·열쇠 값은 채팅에 보내지 않는다.**

1. 브라우저에서 `https://entra.microsoft.com`(또는 `https://portal.azure.com`)을 열고, 원드라이브를 쓰는 **그 마이크로소프트 계정**으로 로그인한다. 처음이면 "디렉터리 만들기" 같은 안내가 나올 수 있다. 기본값으로 진행한다(돈 드는 구독은 필요 없다).
2. 왼쪽 메뉴에서 **앱 등록**(영어 "App registrations")을 누른다. 안 보이면 위 검색창에 "앱 등록"을 입력한다.
3. **+ 새 등록**을 누른다.
4. **이름**: `Web2 일기` (아무 이름이나 된다).
5. **지원되는 계정 유형**: **"모든 조직 디렉터리의 계정 및 개인 Microsoft 계정"** 을 고른다(개인 계정 원드라이브도 쓰려면 이 항목이어야 한다).
6. **리디렉션 URI**: 지금은 **비워 둔다**(2단계에서 정확한 주소를 알려 드린다). **등록**을 누른다.
7. 만들어진 화면(개요)에서 **애플리케이션(클라이언트) ID**를 복사해 둔다. 이 값은 비밀이 아니지만 채팅에는 보내지 않아도 된다. 아래 11번에서 쓴다.
8. 왼쪽 **API 사용 권한**을 누르고 **+ 권한 추가** → **Microsoft Graph** → **위임된 권한** → 검색창에 `Files.Read`를 입력해 **Files.Read** 하나만 체크 → **권한 추가**. 같은 방식으로 `offline_access`도 체크한다. 기본으로 있는 `User.Read`는 그대로 둬도 된다. **`ReadWrite`가 들어간 것, `.All`이 붙은 것은 고르지 않는다**(고르면 함수가 연결을 거절한다).
9. 왼쪽 **인증서 및 비밀**을 누르고 **+ 새 클라이언트 암호**. 설명 `Web2`, 만료 **24개월**(가장 길게)을 고르고 **추가**.
10. 새로 생긴 줄의 **값**(Value)을 바로 복사한다. **이 값은 지금 한 번만 보인다.** 화면을 벗어나면 다시 못 본다(못 봤으면 새로 만들면 된다). 채팅·메모·저장소에 붙여 넣지 않는다. 만료일(24개월 뒤)을 달력에 적어 둔다. 만료되면 연결이 끊긴다.
11. Supabase 대시보드(`supabase.com/dashboard`)에서 이 프로젝트를 열고 **Edge Functions → Secrets**(또는 Project Settings → Edge Functions)로 가서 비밀값 두 개를 추가한다.
    - 이름 `ONEDRIVE_CLIENT_ID` / 값: 7번에서 복사한 클라이언트 ID
    - 이름 `ONEDRIVE_CLIENT_SECRET` / 값: 10번에서 복사한 암호 값
12. `ONEDRIVE_REDIRECT_URI`(돌아올 주소)는 2단계에서 주소가 정해지면 같은 곳에 추가하고, 마이크로소프트 앱 등록의 **인증 → 플랫폼 추가 → 웹**에도 같은 주소를 넣는다. 지금은 하지 않는다.

비밀값 12번까지 끝내기 전에는 화면에 아무 변화가 없고, 함수는 "연결 준비 안 됨"으로 안전하게 멈춘다. 나중에 연결을 완전히 끊고 싶으면: Web2 [연결 끊기] 후 마이크로소프트 계정의 "앱 및 서비스" 권한 화면에서 `Web2 일기`를 제거하고, 앱 등록의 암호를 삭제한다.

## 9. 범위 밖·남는 위험

- 화면(버튼·폴더 고르기·돌아오는 페이지·[전체]에 합치기·☆)은 2~3단계. 이번에는 만들지 않았다(1차의 안내 문구·자리는 그대로).
- 토큰은 암호화 없이 권한 0 표에 둔다(기존 Google 연결과 같은 수준). 강화는 별도 제안.
- 휴대폰이 사진을 원드라이브에 올리는 방식(원본 크기·HEIC·업로드 지연)에 따라 보이는 시점·모양이 다를 수 있다.
- 사진이 매우 많은 폴더의 월 목록 속도는 실제 연결 뒤에 잰다(6절 성능 메모).

## 10. 2단계 결정 (2026-10-27): 지우기·스와이프 별표·맥락

명진 결정 4가지와 그에 따른 바뀜. 위 0~9절과 다르면 이 절이 맞다.

### 10.1 결정

| # | 결정 | 설계 |
| --- | --- | --- |
| 1 | 일기 글과 직접 올린 사진은 지금처럼 Web2(구글 드라이브)에 둔다 | 바뀜 없음. 원드라이브 사진은 복사하지 않고 보기만 한다 |
| 2 | **Web2에서 원드라이브 사진을 지울 수 있다** | 권한을 `Files.ReadWrite`로 올린다(아래 10.2). 지우기는 **원드라이브 휴지통으로 보낸다**(영구 삭제 아님, 원드라이브 앱의 휴지통에서 되살릴 수 있다). 지우기 전에 "원드라이브에서도 지워져요" 확인 한 줄. 별표 기록은 남긴다 |
| 3 | 사진 많은 날은 **스와이프로 별표** | 크게 보기에서 좌우로 넘기며 ☆를 누른다. 별표 상태는 넘겨도 바로 보이고, 누르면 서버(`app_diary_stars`)에 즉시 저장한다. 폰 우선 |
| 4 | 사진의 **맥락**은 명진이 가져온다 | 이번엔 설계 제안만 한다(10.6). 구현은 명진 확인 뒤 |

### 10.2 권한

- 요청 범위: **`Files.ReadWrite offline_access User.Read`** (위임 권한). Azure 앱 등록에는 User.Read·Files.Read·Files.ReadWrite·offline_access가 이미 있다.
- `.All`(`Files.ReadWrite.All` 등), `AppFolder`, `Selected`는 계속 거절한다. 로그인 응답의 허용 범위에 이런 것이 섞여 있거나 `Files.ReadWrite`가 없으면 **저장하지 않고 거절**한다. DB 검사(`app_onedrive_connections_scope_check`)도 같은 글자를 거절한다.
- 솔직한 한계: 마이크로소프트에는 "이 폴더 하나만 쓰기" 권한이 없다(개인 계정에서 `Files.ReadWrite.Selected`는 쓸 수 없다). 토큰 자체는 원드라이브 전체에 쓸 수 있다. 그래서 (1) 토큰은 service role 전용 표에만 두고 화면·로그·응답에 내지 않으며 (2) **서버가 고른 폴더 안 사진만** 읽고 지운다. 폴더 밖, 폴더 자체, 사진이 아닌 파일은 지우기를 거절한다(경로 경계 검사, 시험으로 고정).
- 최악의 유출은 이제 "원드라이브 파일 읽기·쓰기"까지다. 그래서 연결 끊기와 마이크로소프트 앱 권한 제거(9절 끝)가 더 중요하다.

### 10.3 Edge `onedrive-photos` 추가 동작

- 새 action `photo-delete`: 입력 `{id, confirm:true}`. 순서: 로그인·owner 확인(기존과 같음) → 연결·고른 폴더 확인 → 허용 범위에 `files.readwrite`가 있는지 확인(없으면 424 다시 연결) → 항목 조회 → 사진인지·폴더 안인지 확인(아니면 404/403) → Graph `DELETE /me/drive/items/{id}` (휴지통 이동) → `{deleted:true}`. 이미 없으면 404.
- `confirm`이 `true`가 아니면 거절한다(화면 확인을 건너뛴 호출 방지).
- 별표 기록(`app_diary_stars`)은 건드리지 않는다. 지운 사진의 별표는 남지만 [별표] 보기는 목록에 있는 사진만 그리므로 보이지 않는다.
- verify_jwt는 그대로 `true`, 5절 표 37행 설명만 "읽기·지우기"로 고친다.

### 10.4 돌아올 주소 (redirect URI)

- **`https://desk.bokdoong.com/work/app/onedrive-return.html`** (비밀값 아님). `ONEDRIVE_REDIRECT_URI`와 Azure **인증 → 플랫폼 추가 → 웹**에 같은 글자를 넣는다.
- 왜 Edge 주소가 아닌가: Edge 함수는 로그인 토큰(verify_jwt=true)이 있어야 열리는데, 마이크로소프트가 돌려보내는 브라우저 이동에는 토큰을 붙일 수 없다. 돌아오는 곳은 Web2의 정적 페이지로 두고, 로그인된 화면이 `auth-finish`를 부른다(1단계 설계와 같음).
- 왜 앱 첫 화면(`/work/app/`)이 아닌가: 앱 시작 코드(`auth-bootstrap.js`)가 `?code=`가 붙은 첫 화면을 읽생기로 넘기는 규칙이 있어 부딪친다. 전용 페이지가 코드와 확인값을 **주소의 `#` 뒤**(서버에 전달되지 않음)로 옮겨 `?view=diary`로 보낸다. 화면은 읽는 즉시 주소에서 지운다.
- 마이크로소프트는 등록 주소와 **글자 하나까지 같아야** 한다. 주소를 바꾸면 비밀값과 Azure를 함께 바꾼다.

### 10.5 화면 (일기)

- 머리줄 `원드라이브` 작은 버튼 → 접히는 한 줄 패널: 연결 전 [원드라이브 연결], 연결 뒤 폴더 고르기(하위 폴더 따라 내려가며 [이 폴더 쓰기]), 고른 뒤 `폴더명 · 폴더 바꾸기 · 연결 끊기`. 함수 비밀값이 아직 없으면(configured:false) 버튼 자체를 그리지 않는다.
- 날짜 상세: 원드라이브 사진은 [전체]에 직접 올린 사진과 같은 격자로 합쳐 보인다(찍은 날짜 기준, 서울 시간). 사진만 있고 일기 글이 없는 날도 열린다. [별표]는 그날 별표한 사진(원드라이브 + 직접 올린)만 모아 보인다.
- 크게 보기: 기존 일기 크게 보기(좌우 스와이프 띠, `3 / 8`)를 그대로 쓴다. 바에 ☆(누르면 ★)와 ⋯(원드라이브 사진만: 지우기)가 있다. 키보드는 ←/→ 이동, S 별표. 지운 뒤에는 다음 사진으로 넘어간다.
- 별표는 즉시 저장(실패하면 되돌리고 한 줄 안내). 지우기는 "원드라이브에서도 지워져요. 휴지통으로 보냅니다." 확인 뒤에만 실행한다.
- 월 목록은 달을 열 때 한 번 받아 메모리에만 둔다(브라우저 저장 없음). 지우면 그 달을 다시 받는다.
- 달력 칸: 원드라이브 사진만 있는 날은 작은 점(일기 글 점과 구분되는 색)으로 표시한다. 미리보기 그림은 칸마다 받지 않는다(속도).

### 10.6 맥락 제안 (구현은 명진 확인 뒤)

사진 날짜의 "그날 무슨 일이 있었나"를 **새 저장 없이** Web2에 이미 있는 기록에서 붙여 보이는 안이다.

- **붙일 것(기존 읽기 경로 재사용)**: 그날 일정(Google Calendar 일정 읽기), 회의, 끝낸 할 일, 바구니 메모·노트, 업무일지 "오늘 한 줄" — 업무일지 화면이 이미 날짜별로 모으는 읽기 함수(`app/journal-data.js`)를 그대로 부른다. 새 표·새 Edge 함수 없음.
- **어디에**: 날짜 상세의 사진 격자 아래 접힌 한 줄 `그날 맥락 · 일정 2 · 메모 1`(펼치면 제목 목록, 각 줄을 누르면 해당 화면으로). 크게 보기에서는 사진의 **찍은 시각**과 일정 시간을 맞춰 "14:20 ○○ 회의 중" 한 줄을 캡션 자리에 보인다(시각이 없는 사진은 생략).
- **하지 않는 것**: AI가 사진 내용을 읽어 설명하지 않는다(외부 입력 분석과 외부 행동을 한 흐름으로 잇지 않는 원칙). 일기 글에 자동으로 쓰지 않는다. 맥락은 보여 주기만 한다.
- **명진이 정할 것**: ① 붙일 종류(일정·회의·할 일·메모 중 무엇) ② 크게 보기 캡션에 시각 맞춤 표시를 쓸지 ③ 사진 없는 날에도 맥락만 보여 줄지.

### 10.7 적용 순서 (2단계)

1. 설계·DB 파일 PR → merge (코드 영향 없음).
2. DB `20261026140000` 적용(승인형 workflow dry-run → apply, 되돌리기 짝 SQL 있음). 운영 미적용 상태에서 같은 판 번호 파일을 고쳤으므로, 적용 전 사전 확인에서 "새 migration absent"가 `예`인지 본다.
3. 비밀값 `ONEDRIVE_REDIRECT_URI` 등록 + Azure 웹 리디렉션 주소 등록(명진).
4. Edge 첫 배포(`first_deploy=true`, `verify_jwt=true`).
5. 화면 PR merge → Pages 배포 확인.
6. 명진: 일기 → `원드라이브` → 연결 → 폴더 고르기.

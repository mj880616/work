## 0. 한눈 요약

1. 웹 화면(Web2)은 보안상 PC 드라이브를 직접 읽지 못한다. PC에 깔린 **바구니 PC 앱이 그 PC 안에서만 열리는 작은 문(127.0.0.1)** 을 열고, Web2 [파일]이 그 문에 "C: 목록 줘", "이 파일 보내 줘"를 묻는다.
2. **PC 파일 목록과 내용은 서버에 남지 않는다.** 목록은 브라우저 화면 메모리에만 있고, 클라우드로 복사할 때만 파일 바이트가 지금 올리기와 같은 길(Edge)을 지나 원드라이브·구글 드라이브에 저장된다(지나가기만, 서버 보관 없음).
3. 문은 **기본 꺼짐**, 트레이 메뉴에서 켠다. 켜져 있어도 ① 그 PC 안에서만(바깥 기기 접속 불가) ② Web2 주소에서 온 요청만 ③ 바구니 앱과 **같은 계정으로 로그인한 Web2**만 받는다. 시스템 폴더는 보이지 않고, 지우기는 휴지통으로만.
4. 화면은 '이 폰'과 같은 모양: 위 줄 출처 아이콘 [내 PC], 나무 맨 위 줄 '내 PC › C: · D:', [최근] 섞기(결정 D3), 복사는 같은 전송 줄.
5. 단계: ① PC 앱 새 판(보기·열기만) → ② Web2 화면('내 PC' 출처·나무·목록, 시안 고른 뒤) → ③ 복사(PC↔클라우드) → ④ 이름 바꾸기·새 폴더·휴지통. PC 앱 PR과 Web2 PR은 나눈다.

| 길 | 내용 | 판단 |
| --- | --- | --- |
| **A. PC 앱이 그 PC 안 문(127.0.0.1)을 열고 Web2가 직접 부름** | 브라우저 → `http://127.0.0.1:<포트>` → PC 앱이 목록·파일을 돌려줌 | ★ 추천. PC 파일이 서버를 거치지 않는다(복사로 클라우드에 넣을 때만 지나감). 빠르다. |

| C. 브라우저에서 폴더 한 번 허용(요청함 '가') | 크롬 폴더 열기 허락(File System Access) | 명진이 '나'를 골라 쓰지 않음. 드라이브 전체가 아니라 고른 폴더만, 매번 허락. |
| D. 브라우저 확장 + 네이티브 메시징 | 확장을 따로 깔아야 함 | ✗ 깔 것이 하나 더 늘고 크롬·엣지마다 다름. |

### A의 브라우저 쪽 조건 [추정 — ① 단계에서 실제 크롬·엣지로 확인]

- https 페이지가 `http://127.0.0.1`을 부르는 것은 크롬·엣지가 '같은 PC는 믿을 만한 곳'으로 보고 허용한다(섞인 내용 막기 예외).
- 최근 크롬(2025 하반기~)은 공개 사이트가 같은 PC·집 안 기기를 부를 때 **'로컬 네트워크 접근' 허락 창**을 처음 한 번 띄운다. 명진이 한 번 [허용]을 눌러야 한다(결정 D5).
- 그 전 단계 규칙(Private Network Access)으로 미리 묻기(OPTIONS)에 `Access-Control-Allow-Private-Network: true`를 답해야 할 수 있다. PC 앱이 이 답을 한다.
- Web2 CSP: `connect-src`에 `http://127.0.0.1:<포트>` 몇 개를 더해야 한다(`cloudflare/web2-csp.mjs`, Web2 화면 PR에서). 이미지 미리보기는 `img-src`에 같은 주소 또는 blob으로.

## 3. 경로 (A안)

```
[Web2 화면, 그 PC의 크롬]                [바구니 PC 앱, 같은 PC]                 [클라우드]
  [파일] '내 PC' 출처
   ├─ 목록 GET /v1/drives, /v1/list ───▶ 127.0.0.1:4762x (그 PC 안만)
   │       ◀── 이름·크기·바뀐 날(메모리)
   ├─ 열기 POST /v1/open ──────────────▶ 윈도우 기본 프로그램으로 그 PC에서 엶(바이트는 브라우저로 안 옴)
   ├─ 미리보기 GET /v1/thumb (사진만, 작게)
   ├─ PC→클라우드 복사:
   │    GET /v1/read (조각) ◀────────────  파일 바이트
   │    └─ 지금 올리기 길(Edge)로 ─────────────────────────────────────────▶ 원드라이브·구글 드라이브
   └─ 클라우드→PC 받기:
        Edge media(지금 '이 폰'과 같음) ──▶ 브라우저 ──▶ POST /v1/write (조각) ─▶ PC 폴더(임시 파일 → 크기 맞으면 이름 바꿈)
```

- 문 번호: 로그인용 47615~47617과 겹치지 않는 고정 후보 3개(예: 47620~47622). 화면은 후보를 차례로 `/v1/hello`로 두드려 찾는다.
- 글 모양은 '이 폰'과 같은 목록 모양(이름·종류·크기·바뀐 날)으로 맞춰, Web2 화면 코드가 출처만 바꿔 쓰게 한다.
- 클라우드→PC 받기의 같은 이름·임시 파일·크기 확인 규칙은 '이 폰'(`pfiles:save`)과 같게: 숨긴 임시 파일에 쓰고 크기가 맞을 때만 '이름 (2)' 규칙으로 바꾼다. 같은 이름은 화면이 한 번 묻는다.
- 클라우드 사이(원드라이브↔구글)는 지금처럼 서버 `across`. PC가 끼는 복사만 브라우저가 중간에서 나른다.

## 4. 권한·보안 (요청 ②)

### 4-1. 누가 문을 두드릴 수 있나

| 막는 것 | 방법 |
| --- | --- |
| 다른 기기(같은 와이파이의 폰·남의 PC) | 문을 `127.0.0.1`에만 연다(`0.0.0.0`·랜 주소 금지). 윈도우 방화벽 예외를 만들지 않는다. **열린 포트를 바깥에 노출하지 않음.** |
| 같은 PC의 다른 웹사이트 | 요청의 `Origin`이 정확히 `https://desk.bokdoong.com`일 때만 받는다(CORS 답도 그 주소만). 그 밖은 403. |
| 주소 바꿔치기(DNS rebinding) | `Host` 머리가 `127.0.0.1:<포트>`가 아니면 거절. |
| 다른 계정의 Web2(같은 PC를 여러 사람이 쓸 때) | 요청마다 Web2 로그인 토큰(`Authorization: Bearer`)을 받고, PC 앱이 Supabase `auth/v1/user`로 그 토큰의 사용자 id를 확인해 **PC 앱에 로그인한 사용자 id와 같을 때만** 받는다(확인 결과 몇 분 메모리 보관). 토큰은 화면·로그에 남기지 않는다. |
| 같은 PC의 다른 프로그램 | 위 토큰 확인으로 막는다(유효한 Web2 토큰 없이는 못 씀). 이 PC에 이미 악성 프로그램이 있으면 그 프로그램은 어차피 파일을 읽을 수 있으므로 이 문이 위험을 늘리지 않게만 한다 [추정]. |
| 꺼 둔 상태 | 트레이 [Web2에서 이 PC 보기]가 꺼져 있으면 문을 아예 열지 않는다(기본 꺼짐, 결정 D1). PC 앱이 로그아웃 상태여도 열지 않는다. |

인증 우회·운영자 예외·시험용 열쇠는 두지 않는다. 서버 쪽 권한(RLS·Edge 검사)은 그대로이고, 클라우드에 넣는 일은 지금 올리기 Edge의 소유자 확인을 그대로 지난다.

- 안 보이는 곳(목록에서 빼고 직접 경로로 와도 거절): `C:\Windows`, `C:\Program Files*`, `C:\ProgramData`, 각 사용자 `AppData`, `$Recycle.Bin`, `System Volume Information`, 숨김+시스템 속성 파일·폴더, 바구니 앱 자기 폴더(대기열·설정).

## 5. 화면 (요청 ③, 시안은 결정 뒤)

- 위 줄 출처 아이콘에 [내 PC](모니터 모양). **그 PC의 브라우저에서 문이 응답할 때만** 보인다. 폰·다른 PC에서는 안 보인다.
- 나무 맨 위 줄: `원드라이브 · 구글 드라이브 · 내 PC` → '내 PC' 아래 `C:` `D:` …(이름표가 있으면 '로컬 디스크 (C:)'처럼). 문 응답이 없으면 '내 PC'는 흐리게 + 한 줄 안내("바구니 PC 앱 트레이에서 [Web2에서 이 PC 보기]를 켜 주세요").
- 목록·위치 줄은 '이 폰'과 같은 부품: `내 PC › C: › 문서 › …`, 줄마다 작은 출처 점.
- [최근] 섞기는 결정 D3.
- 복사: 고르기 → [복사] → 받을 곳(나무에 '내 PC' 포함) → 아래 전송 줄. 두 칸 보기(PC 1440)에서 왼쪽 '내 PC' → 오른쪽 구글 드라이브로 끌어 복사.
- 시안: 폰 412는 해당 없음(그 PC에서만 보임), PC 1440 두 장(한 칸·두 칸) + 문이 꺼져 있을 때 한 장. 명진이 고른 뒤 ② 구현.

## 7. 남은 위험·확인할 것

- [추정] 크롬·엣지의 '로컬 네트워크 접근' 허락 창 모양·시점과, 회사 PC 정책이 이를 막는지. ①에서 실제로 확인한다.
- [추정] 삼성 인터넷 PC판 등 다른 브라우저는 안 될 수 있다. 크롬·엣지만 지원으로 적는다.
- 같은 PC를 여러 사람이 윈도우 계정 하나로 쓰면, 바구니 앱에 로그인한 사람의 Web2만 열린다(4-1). 다른 사람은 바구니 앱에서 로그아웃·로그인을 바꿔야 한다.
- 노트북을 들고 나가 공용 와이파이에 붙어도 문은 `127.0.0.1`만이라 바깥에서 안 보인다. 그래도 쓰지 않을 때는 꺼 두기를 권한다(결정 D1).
- 바이러스 백신이 '로컬 서버를 여는 프로그램'으로 경고할 수 있다 [추정].

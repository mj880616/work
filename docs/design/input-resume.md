# 다른 앱에 갔다 와도 입력 창 그대로 (S71-20, 결정 장부 A1)

2026-11-26 17:20 명진: "사업보고 입력 화면 띄워놓고 다른 앱 갔다 오면 화면이 닫혀있네 유지됐으면. 마찬가지로 나머지 화면도".

## 1. 무엇이 창을 닫나 — 사실

다른 앱에 갔다 오면 창이 닫히는 길은 세 가지로 나눠 봤다.

| 길 | 확인 방법 | 결과 |
| --- | --- | --- |
| (나) 웹 화면이 돌아올 때 하는 일(visibilitychange·focus·pageshow 처리기)이 창을 닫음 | `tests/app-e2e/keep-open-on-resume.spec.mjs` — 폰 390에서 [+ 추가] 여섯 창(사업 보고·잊지 말기·노트·할 일·일정·하루 기록)에 글을 쓰고 화면 숨김 → 보임을 두 번 | 여섯 창 모두 창·글·같은 칸·주소·화면 그대로, 사업 보고 창 안 스크롤 자리도 그대로. 닫는 처리기 없음 |
| (가) 돌아올 때 웹 화면이 스스로 다시 열림(새로고침) | 앱 코드 전수: `location.reload`를 부르는 곳은 [최신화]·당겨서 새로고침(쓰던 글 확인 `KPTUReloadGuard`)·로그인한 사람이 바뀜·뒤로가기 캐시 복원(`pageshow` persisted)·[다시 시도]뿐. 새 판 안내(`version-notice.js`)는 줄만 띄우고 누를 때만 다시 열며 쓰던 글이 있으면 묻는다. 위 시험도 돌아온 뒤 문서 이동 0회 | 다른 앱에 갔다 오는 것만으로 다시 여는 길 없음 |
| (가) 폰 앱 껍데기가 돌아올 때 다시 엶 | `android-app/.../MainActivity.kt`: `onResume`·`onStart`는 바 색·위젯·알림 지우기·앱 새 판 확인만 하고 웹 화면을 다시 열지 않는다. 아이콘으로 다시 들어오면(`onNewIntent`) 보던 화면 그대로 둔다. 알림·링크로 들어오면 화면 안에서 자리만 옮긴다(`openInPlace`) | 다른 앱에 갔다 오는 것만으로 다시 여는 길 없음 |
| (다) 안드로이드가 뒤에 있던 앱 또는 화면 엔진을 메모리 때문에 끔 | `MainActivity.onCreate`: 저장 상태가 있으면 `webView.restoreState` → 같은 주소를 새로 불러옴(앱 기록 종류 `restore`). `onRenderProcessGone` → `recreate()`(종류 `engine`). 폰 브라우저(삼성 인터넷·크롬)도 뒤에 둔 탭을 메모리 때문에 비우면 돌아올 때 새로 불러온다 | **창이 닫히는 길은 이것뿐.** 새 문서라 메모리에 있던 창·글이 남지 않는다 |

결론: 웹 화면과 폰 앱 껍데기에는 고칠 닫기가 없다(시험으로 지킨다). 명진이 본 증상은 (다) — 폰이 뒤에 둔 앱(또는 화면 엔진)을 끄고 돌아올 때 새로 연 것으로 본다. 기기에서 직접 확인하려면 앱 메모리의 '다시 연 기록'(종류·시각만, `ReopenRules.kt`, 웹 `reopen:list`)이 `restore`/`engine`인지 보면 된다(화면 칸은 11/04에 지움).

## 2. 입력 창 전수 — 돌아올 때 규칙

| 창 | 돌아올 때 다시 읽기 | 쓰는 중이면 | 확인 |
| --- | --- | --- | --- |
| 사업 보고 쓰기 창(`#meetingModal`) | 없음 | — | A1 시험(창·글·스크롤) |
| 잊지 말기·업데이트 큰 창(`#edWindow`, `ed-window.js`) | 없음 | — | A1 시험 |
| 노트 큰 창(`#edWindow`, `note-window.js`) | 없음 | — | A1 시험 |
| 할 일·일정 창(`#eventModal`) | 달력 상태(`calendar-health.js`)·저장 대기 확인(`calendar-persistence.js`) — 창은 안 건드림 | — | A1 시험 |
| 하루 기록 쓰기(`#diaryView`) | 원드라이브 사진 받기 멈춤·이어 받기(`diary-onedrive.js`) — 글 칸은 안 건드림 | — | A1 시험 |
| 사업 상세 기록 상자(`biz-detail-window.js`) | 사업 기록 다시 읽기 | 고치는 중이면 다시 읽지 않고 표시만(`ctl.stale`), 다음에 붙일 때 | 코드(`quiet()`) |
| 조직 기록 창(`record-window-view.js`) | 조직 기록 다시 읽기 | 고치는 중·저장 중이면 다시 읽지 않음 | 코드(`quiet()`) |
| 새 판 안내(`version-notice.js`) | 운영자에게 줄만 | [최신화]를 눌러도 쓰던 글이 있으면 묻는다 | `version-notice.spec.mjs` |

같은 부품: 새 창은 공용 창(`.modal`·`ed-window.js`)을 쓰면 위 규칙을 그대로 받는다. 돌아올 때 다시 읽기를 새로 붙이는 화면은 창을 닫거나 다시 그리지 말고 데이터만 맞추며, 쓰는 중이면 미룬다(한 영역 한 주인, 늦은 덮어쓰기 금지).

알고 둘 것(이 작업 밖):
- 폰 알림을 눌러 들어오면 그 알림 자리로 화면을 옮긴다(`openInPlace`). 다른 화면으로 옮기면 열린 창은 닫힌다 — 알림을 누른 뜻대로다.
- 앱 전체 잠금 '바로'·'앱 닫을 때'는 돌아오면 잠근다. 이때 열린 창이 잠금 화면 위에 남는 문제는 PR 본문 '범위 밖 발견사항'.

## 3. (다) 대비 설계 제안 — 쓰던 글 서버 임시 저장

지금은 입력 창 쓰던 글을 서버에 두는 공용 임시 저장(초안) 구조가 없다(있는 것: 업무일지 AI 초안 `app_journal_drafts`·주간 보고 내 양식 `app_weekly_own_drafts`는 다른 목적, `ed-window.js` `onClose`는 이 탭 메모리만). 명진 원칙(저장은 서버, 한 기기에만 남는 localStorage 금지)에 맞춰 아래를 제안한다. **DB 변경이라 명진 결정·CC 승인형 DB workflow 뒤에 만든다.**

- 표 `app_input_drafts`: `workspace_id`, `kind`(사업 보고·업데이트·노트·할 일·일정·하루 기록 등 고정 목록, check), `target_id`(고치는 기록 id, 새 글이면 null), `body jsonb`(창 칸 값, 크기 상한 예: 256KB check), `updated_at`. (workspace_id, kind, target_id) 하나만.
- 권한: RLS 켬, 주인만(`private.app_is_workspace_owner`), anon·PUBLIC 권한 없음. 공유 기능으로 열리지 않음. 운영자도 내용을 보지 않음(AGENTS.md 3절 '남의 기록 안 보기'). AI에 보내지 않음.
- 화면 공용 부품 하나(`input-draft.js`): 창이 열려 있고 글이 바뀌면 몇 초 쉬었다 저장, 화면 숨김 때 바로 저장(keepalive), [저장]·[취소]·닫기 → 지움. 창마다 따로 만들지 않고 공용 창(`.modal`·`ed-window.js`)에 붙인다.
- 복구 길: 새로 열렸을 때 남은 초안이 있으면 공용 알림 줄(`notice-bar.js`)에 "쓰던 사업 보고가 있어요 [이어 쓰기] [버리기]" 한 줄. [이어 쓰기]는 같은 창을 열고 칸을 채운다. 한 번에 한 줄, 여러 개면 "쓰던 글 2개" → 고르기.
- 정리: 7일 지난 초안은 서버 예약 작업이 지운다(내용을 열지 않고 날짜로만).
- 시험: 창에 글 → 화면 숨김 → 새 문서로 다시 열기(`page.reload`) → 알림 줄 → [이어 쓰기] → 같은 글.

명진 결정 필요: 이 임시 저장을 만들지(만들면 쓰던 글이 몇 초마다 서버에 올라감), 대상 창 범위, 보관 기간(제안 7일).

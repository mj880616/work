# UI-PC스크롤묶음 전수 표 (S56-43, 2026-11-10)

PC 틀(761px~, 폴드 펼침 884px 포함)의 스크롤을 한 가지로 맞춘 기록. 화면마다 따로 고치지 않고 공용 틀(`desktop-ui.css`·`base-ui.css`·`follow-pane.js`·`accessibility-dialog.js`)에서 고쳤다.
시험: `tests/app-e2e/pc-scroll-one.spec.mjs`. 사진: `docs/design/screens/s56-43/`.

## 원인과 고친 곳

| 번호 | 증상(요청함) | 원인(파일·줄) | 고침 |
| --- | --- | --- | --- |
| ① | 스크롤하면 맨 위 줄(뒤로·검색·+ 추가)이 사라지는 화면과 남는 화면이 갈림 | `desktop-ui.css` `#appView>.app-topline`이 보통 격자 칸이라 문서와 같이 올라감. 달력·할 일은 화면 높이에 맞춰 그려 문서가 안 내려가서 남아 보였을 뿐 | CC 결정 '늘 보임': 맨 위 줄을 `position:sticky`(바탕색·아래 간격 그림자). 화면 안에서 위에 붙는 줄은 공용 값 `--kptu-stick-top` 아래에 붙음. 녹음 띠·알림 줄이 떠 있으면 `--kptu-fixed-top`만큼 내려감 |
| ② | 조직 보고 오른쪽 상세 칸 위 휠이 안 먹음(칸에 굴릴 내용이 없을 때) | `desktop-ui.css` `.kptu-follow-pane{overscroll-behavior:contain}` — 크롬은 넘칠 것 없는 스크롤 틀도 contain이면 휠을 막는다(작은 시험 페이지로 확인) | contain 뺌. 칸이 짧거나 칸 끝이면 휠이 문서로 넘어감. 붙는 자리는 `follow-pane.js` `stickTop()`이 맨 위 줄 높이를 더함 |
| ③ | 창이 떠 있을 때 바깥 휠로 뒤 화면이 움직임 | 공용 `.modal` 바탕이 휠을 받는 틀이 아니어서 휠이 문서로 넘어감. `<dialog>` 창은 바탕(::backdrop) 휠이 문서로 감 | `base-ui.css` `.modal:not([role="region"]){overflow:hidden;overscroll-behavior:contain}`, `dialog:modal{overscroll-behavior:contain}`, `accessibility-dialog.js` 바탕 위 휠 막기. 칸 안에 놓인 창(role=region)은 제외 |
| ④ | 사업 보고·달력 주간 스크롤 두 겹 | (가) `desktop-ui.css` 사이드바 `grid-row:1 / span 40` — 크롬이 빈 줄 38칸에 약 10px씩 높이를 줘서 모든 화면이 약 380px 더 내려감. (나) 사이드바 높이(화면-24px)가 화면 줄 높이를 정하고 본문 아래 여백 76px이 더해져, 내용이 화면에 다 들어와도 64~80px 더 내려감. 달력 주간 시간표·사업 보고 결과 칸(안에서 스크롤)과 문서 스크롤이 겹침 | 사이드바는 두 줄만 차지(`grid-template-rows:auto 1fr`), 칸 높이 계산에서 빠짐(`margin-bottom:-100vh`, 보이는 크기 그대로), 본문 아래 여백 12px 공용(할 일 화면 전용 규칙을 공용으로) |
| ⑤ | 사업 보고 3칸 결과 칸 글 왼쪽 잘림(884px) | #2320(3칸 폭 고침) 판에서 884·1280px, 긴 글 30건 가짜 데이터로 재현 안 됨(결과 칸 안 요소가 칸 왼쪽 밖으로 나간 것 0개, 가로 넘침 0) | 고치지 않음. 실제 데이터에서 다시 보이면 사진과 함께 알려 주면 이어서 고침 |

## 화면 전수(1280·884px, 가짜 데이터, 고친 뒤)

'문서 더 내려감'은 내용이 화면에 다 들어오는데도 문서가 더 내려가는 px(고치기 전 → 뒤). 고치기 전 값은 사업 보고 가짜 데이터 실측 454px(빈 줄 38칸 × 약 10px + 본문 아래 여백 76px)이고, 같은 틀이라 다른 화면도 같은 크기로 본다. '맨 위 줄'은 문서 끝까지 내렸을 때 줄의 화면 위 위치(0 = 붙어 있음, 문서가 안 내려가는 화면은 그대로 12).

## 남은 것

- 사업 보고처럼 붙은 칸이 화면 아래 끝(12px 띄움)까지 차는 화면은, 칸을 감싼 카드의 아래 안쪽 여백(약 16px)만큼 문서가 조금 더 내려간다. 칸 높이 계산(`followMax`)이 칸 아래 카드 여백을 모르기 때문. 'UI-상세칸고정'(긴 칸은 칸 안에서 스크롤) 결정은 그대로 두었다.
- 폰(~760px)은 맨 위 줄이 없어 이번 변경 대상이 아니다.

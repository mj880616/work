## 고를 것 (사용자)

1. **파일 상세 칸 모양: 가안 / 나안**
   - 가안: 아이콘+글자 작은 버튼(28px, 얇은 선) 한 줄 `[↗ 열기][↓ 받기][자료실로] … [⋯]`. 버튼인 게 분명하다.
   - 나안: 선 없는 글자 버튼 한 줄 `열기 | 받기 | 자료실로 보내기 … [⋯]`. 가장 가볍다.
   - 둘 다: 위쪽 [새 폴더]·[업로드]보다 크지 않고, 늘 한 줄이고, 공유·이름 바꾸기·복사·옮기기·휴지통은 [⋯] 안(휴지통은 맨 아래 빨간 글자).
2. **같은 규칙을 앱 전체에 한 번에 적용할지** — 아래 '규칙 제안'을 UI-버튼기준에 더하고, 전수 표의 '고칠 곳'을 같은 부품으로 한꺼번에 바꾼다(추천). 아니면 파일 상세 칸만 먼저.
3. **밖에 둘 버튼 3개** — 파일은 열기·받기·자료실로 보내기(추천). 공유를 더 자주 쓰면 자료실로 대신 공유.

## 규칙 제안 (UI-버튼기준에 더할 안 — 'UI-버튼묶음')

기존 값(32px 작은 버튼·28px 작은 높이·44px 누르는 범위, UI-버튼6가지)은 그대로 두고 '묶음'에 대한 규칙만 더한다.

1. **머리줄보다 크지 않게**: 상세 칸·카드·줄 안 동작 버튼 묶음의 보이는 높이는 그 화면 머리줄 버튼 이하다. 기본 `--ds-compact-height-sm`(28px)·글자 `--ds-text-meta`(12px). 누르는 범위는 44px(`::after`) 그대로.
2. **늘 한 줄**: 버튼 묶음은 줄바꿈(`flex-wrap:wrap`)하지 않는다. 밖에는 자주 쓰는 2~3개만, 나머지는 줄 끝 [⋯](공용 작은 메뉴) 안. 폭이 모자라면 줄을 늘리지 않고 밖 버튼을 ⋯로 더 넣는다(폰 390 기준 밖 최대 3개 + ⋯).
3. **위험 동작은 채움 빨강 금지**: 휴지통·삭제·빼기는 ⋯ 안 맨 아래 빨간 글자(공용 메뉴의 위험 줄). 꼭 밖에 둬야 하면 줄 맨 끝 빨간 글자 버튼(바탕 없음). 빨간 채움은 '지우기를 확인하는 창'의 주 동작 하나뿐(UI-창아래버튼통일 그대로).
4. **한 묶음 = 한 모양**: 같은 묶음 안 버튼은 같은 종류·같은 높이·같은 글자 크기. 아이콘이 있으면 모두 있고, 없으면 모두 없다. 폭이 제각각인 버튼이 두 줄로 쌓이는 모양(들쭉날쭉)은 없다.
5. **예외(각자 규칙 그대로)**: 창 아래 [삭제]…[취소][저장] 줄(UI-창아래버튼통일), 보기 바꾸기 탭(⑤), 거르기 칩 줄(④), 여러 개 고른 막대(공용 고르기 막대 `.kptu-selbar`·`.kptu-actbar`), 서식 줄.
6. **재발 방지(구현 PR에서)**: 화면 시험이 주요 상세 칸에서 '묶음 한 줄 · 높이 ≤ 머리줄 · 빨간 채움 0'을 재고, CSS 검사가 버튼 묶음 클래스의 `flex-wrap:wrap`을 기준표보다 늘리지 못하게 막는다.

원인(사실): 공용 `app/base-ui.css` 89행 `.danger{background:var(--kptu-danger);color:…}`가 빨간 **채움**이 기본이고, 흰 바탕+빨간 글자로 바꾸는 규칙은 창(`.modal`)·창 아래 줄·잊지 말기·프로젝트 상세 안에만 있다(`app/ui-standard.css` 53·155·442·2032행). 그래서 창 밖 화면(파일 상세 칸 등)의 `button.danger`만 빨간 채움으로 보인다. UI-버튼6가지 ②의 '지우기만 빨강'(흰 바탕·빨간 선/글자) 정의와 다르다. 구현 때 공용 기본을 6가지 정의로 맞추는 것을 제안한다(창 안 확인 버튼 모양은 지금과 같음).

## 전수 표

### 조사 방법

- 도구: `docs/design/button-groups-measure.js`(앱 코드 아님). 시험 브라우저에 끼워 넣어 화면이 바뀔 때마다 '같은 부모 아래 버튼 3개 이상'인 묶음을 재고 모은다. 보기 탭·탭·목록 줄·나무·메뉴 안 항목·서식 줄·아래 탭·왼쪽 메뉴는 묶음이 아니라 뺀다.
- 돌린 화면: 상세 칸·창·카드를 여는 기존 화면 시험 58개 파일(시험 571번, 폭 360~1440 사이 20가지: 390·412·599·640~760·870~900·1024·1199·1200·1280·1440 등)과 기본 화면 12개·파일 상세 칸(390·700·1280). 모두 시험용 가짜 자료(사용자 자료 아님). 시험 결과 570 통과 · 1 실패(노트 큰 창 첨부 시험 하나, 기계가 바빠 생긴 시간 초과로 보임 — 이 조사와 상관없음).
- 머리줄 = 그 화면(또는 창)의 맨 위 56px 안 글자 버튼 높이. '큼' = 묶음 버튼이 머리줄보다 높다.
- 눈으로 확인: 파일 상세 칸 390·700·1280 화면 그림. 일정 머리줄(390)은 재는 값에 '3+1 두 줄'로 나왔으나 그림으로 보니 [일정 등록]이 따로 떠 있는 버튼이라 들쭉날쭉이 아니어서 뺐다.

# PHOTO-정보고치기 — 웹2에서 사진 정보(EXIF) 고치기 + 여러 장 한꺼번에

요청함 [11/03 00:29] "웹2 사진에서 사진 정보 exif 수정 가능하게 일괄 수정도". 명진 결정(11/03 11:57 "추천대로"):
E1 고칠 칸은 찍은 날·시각과 위치 둘만(카메라·렌즈는 보기만), E2 폰 사진은 파일 자체를 고친다(EXIF + 사진첩 목록 DATE_TAKEN, 갤러리 순서도 바뀜).

## 1. 왜 둘을 함께 고치나

직전 PHOTO-찍은시각EXIF(취소)에서 확인한 것: 파일 EXIF만 고치면 폰 사진첩 목록(MediaStore `DATE_TAKEN`)이 옛 값이라
삼성 갤러리·웹2 폰 사진 순서가 그대로다. 웹2가 고칠 때는 앱이 **파일 EXIF와 사진첩 목록 칸을 한 번에** 고친다.

## 2. 화면

- 사진을 꾹 눌러(PC는 클릭) 고른 뒤 사진 ⋯(PC 우클릭) → **[정보 고치기…]**. 한 장만 고르면 그 한 장. 폰 앱 0.4.15+에서만 보인다.
- 창 위쪽: 고른 장수 + 카메라·렌즈(보기만, 여러 종류면 "여러 가지").
- 고치는 방법(한 번에 하나만 고른다):
  - **시각 밀기**: `모두 [+|−] n시간 n분 밀기` (소니 시계가 틀린 경우처럼 한꺼번에 몇 시간 어긋난 경우).
  - **이 날짜로**: `모두 이 날짜·시각으로`(달력 입력). 여러 장이면 원래 순서·간격은 지키고 첫 장을 그 시각에 맞춘다.
  - **이 장소로**: `모두 이 장소로`(위도·경도 입력, 지도에서 고르기는 [지도 열기]로 확인) 또는 `위치 지우기`.
- 저장 전 **앞 → 뒤 미리 보기 표**(한 줄에 한 장: 이름 · 앞 시각 → 뒤 시각 · 위치). 못 고치는 사진(HEIC·동영상·옛 앱)은 표에 "못 고침"으로 보이고 빠진다.
- [저장] → 안드로이드 수정 허락 창 **한 번**(여러 장은 묶어서 한 번, '미디어 관리 허용'이 켜져 있으면 창 없음).
- 끝나면 알림 `12장 고쳤어요 · [되돌리기]`. 나중에도 이 창 맨 아래 `지난번 고친 12장 · [되돌리기]`로 묶음 통째 되돌린다.
- 한 번에 최대 200장. 자동 변경 없음(명진이 고른 사진만).

## 3. 폰 앱(0.4.15, versionCode 55)

다리 메시지(앱 상태 `photos:state`에 `meta:true`):

| 웹 → 앱 | 앱 → 웹 |
| --- | --- |
| `photos:meta:read:[번호…]` | `photos:meta:{ok, items:[{id, taken, lat, lon, make, model, lens, can}], error}` |
| `photos:meta:write:{items:[{id, taken?, loc?}]}` | `photos:metadone:{ok, count, failed:[번호], error}` |

- 읽기: `MediaStore.setRequireOriginal` + `ACCESS_MEDIA_LOCATION`(위치 칸이 가려지지 않게, 대화창 없이 사진 권한에 딸린 허락)로 원본 EXIF를 읽는다.
- 쓰기: `MediaStore.createWriteRequest`(허락 창 한 번) → 장마다 `rw`로 열어 androidx `ExifInterface`로
  `DateTimeOriginal`·`DateTimeDigitized`·`DateTime`·`OffsetTime*`(폰 시간대) 또는 GPS 칸만 다시 쓴다(사진 화질·그림 바이트는 그대로) →
  닫은 뒤 `DATE_TAKEN`을 같은 시각으로 고친다(사진첩이 다시 읽어도 같은 값).
- 고칠 수 있는 종류: JPEG·PNG·WebP. HEIC·동영상은 `can:false`(읽기만).
- 로그에 사진 이름·시각·위치를 쓰지 않는다(실패 종류·예외 클래스 이름만). 서버로 사진·EXIF를 보내지 않는다.
- 규칙(메시지 해석·시각 글자 만들기·한도)은 `PhotoMetaRules.kt`, 단위 시험 `PhotoMetaRulesTest.kt`.

## 4. 되돌리기 기록(서버)

새 표 `public.app_photo_info_edits`(DB `20261103140000_photo_info_edits`): 한 줄 = 고친 사진 한 장.
`batch_id`, `source`('phone'), `item_key`('ms:<번호>'), 앞 시각·위치, 뒤 시각·위치, `undone_at`.
- 작업공간 주인만 읽기·넣기·`undone_at` 고치기(owner RLS 정책 하나, anon·PUBLIC·service_role 없음). 지우기 없음.
- 위치는 민감하므로 이 표는 화면 주인만 읽는다. 사진 이름·내용은 넣지 않는다.
- [되돌리기] = 그 묶음의 앞 값으로 다시 쓰기(같은 다리 `photos:meta:write`) → 성공한 줄에 `undone_at`.
- 표가 아직 없으면(DB 적용 전) 고치기는 하되 되돌리기 기록 없이 "이번 화면에서만 되돌릴 수 있어요"로 알린다.

## 5. 원드라이브·구글 드라이브 사진

원드라이브 Graph의 `photo.takenDateTime`·`location`은 읽기 전용이라 "원드라이브 쪽 정보만" 고칠 칸이 없다.
고치려면 원본 파일 EXIF를 다시 써서 새 판으로 올려야 한다(원본 덮어쓰기 전 확인, 원드라이브 판 기록에 옛 판이 남음).
이것은 Edge `onedrive-photos` 올리기 동작이 필요해 **다음 단계(PHOTO-정보고치기 ②)**로 나눈다. 이번 판 창에서는
원드라이브·구글 드라이브 사진이 섞이면 "폰 사진만 고쳐요(원드라이브는 다음 판)"로 빼고 알린다.

## 6. 완료 기준

웹2(폰 앱)에서 사진 12장을 골라 '모두 −8시간' 한 번 → 웹2 폰 사진과 삼성 갤러리 둘 다 시각·순서가 바뀜, [되돌리기]로 원래대로.

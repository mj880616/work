## 2. 단계 목록 (명진이 직접 관리)

고정 목록이 아니다. 명진이 단계를 추가·이름 수정·삭제·순서 바꾸기 할 수 있고, 아래는 **처음 넣어 두는 기본 목록 11개**다(소유자가 처음 쓸 때 앱이 한 번 채움).

| 순서 | 기본 이름 | 투쟁 중으로 봄 | 끝남 | 뜻 |
| --- | --- | --- | --- | --- |
| 1 | **교섭 시작 전**(기본 단계) | 끔 | 끔 | 쟁의 없는 평상시, 새 조직의 처음 자리. 이름은 바꿀 수 있고 지울 수 없음 |
| 2 | 교섭 중 | 끔 | 끔 | 임단협 교섭 진행 |
| 3 | 쟁의발생 결의 | **켬** | 끔 | 교섭 결렬 선언·쟁의발생 결의를 한 상태 |
| 4 | 조정 신청 | **켬** | 끔 | 노동위원회에 조정 신청 |
| 5 | 조정 종료 | **켬** | 끔 | 조정이 끝남(중지·불성립 포함) |
| 6 | 파업 찬반투표 | **켬** | 끔 | 쟁의행위 찬반투표 |
| 7 | 쟁의중 | **켬** | 끔 | 파업·태업·집회 등 쟁의행위 중 |
| 8 | 잠정합의 | **켬** | 끔 | 잠정합의안 마련(아직 투쟁 중) |
| 9 | 임단협 찬반투표 | **켬** | 끔 | 잠정합의안 찬반투표 |
| 10 | **협약체결** | 끔 | **켬** | 합의로 끝남 |
| 11 | **종료** | 끔 | **켬** | 합의 없이 끝남 등 그 밖의 끝 |

- **기본 단계**: '교섭 시작 전'. 업무공간마다 하나뿐이고 지울 수 없다. 두 표시(투쟁 중·끝남)는 켜지 못한다. 이력이 없는 조직(새 조직 포함)은 이 단계에 있는 것으로 읽는다(5절).
- **투쟁 중으로 봄**: 단계마다 켜고 끌 수 있는 표시. 켠 단계에 있는 조직이 주간보고 투쟁 사업장 표 자동 채움 대상이다. 기본은 쟁의발생 결의~임단협 찬반투표(7개) 켬.
- **끝남**: 단계마다 켜고 끌 수 있는 표시. 켠 단계로 바뀐 주에는 표에 그 주 한 번 `협약체결(날짜)`·`종료(날짜)`로 보이고 다음 주부터 빠진다. 기본은 협약체결·종료 켬. **한 단계에 '투쟁 중으로 봄'과 '끝남'을 동시에 켜지 못한다**(DB 검사로도 거절).
- 코드값(영어)은 두지 않는다. 단계는 단계 id로 가리키고, 이름은 명진이 바꿀 수 있는 글자일 뿐이다(판정은 이름이 아니라 위 두 표시와 기본 단계 표시로 한다).
- 순서는 목록에서 보이는 순서일 뿐 입력 순서를 강제하지 않는다. 입력 때 아무 단계나 고를 수 있다.
- **지우기**: 지금 어느 조직이 그 단계에 있으면 먼저 `○○지부 외 N곳이 이 단계예요`로 알린다. 명진이 그래도 지우면 그 조직들은 기본 단계(교섭 시작 전)로 옮기고(이력 한 줄 추가) 단계를 지운다. 지난 이력의 글자는 그때 이름 사본으로 남는다. 이름 바꾸기도 지난 이력 글자는 그때 이름 그대로 남는다. 기본 단계는 지울 수 없다.

## 3. 담당조직 화면

- 위치: 조직 상세 맨 위 이름 줄 바로 아래 한 줄(`쟁의 단계 [쟁의발생결의 ▾] [10.20]`). 목록 줄에는 투쟁 중인 조직과 이번 주 끝난 조직에만 단계 이름을 작은 글씨로 덧붙인다(평시 조직은 아무것도 안 붙임 — 줄이 길어지지 않게).
- 입력: 단계는 한 줄 선택 칸(`select`, 폰에서 기본 선택창) 하나. 고르면 오른쪽에 날짜 칸(달력 입력, 기본값 오늘)이 나타난다. [저장] 버튼은 그 줄 끝 작은 기본 버튼 하나. 담당조직 추가·수정 창에는 넣지 않는다(상세에서만 — 창이 길어지지 않게).
- '교섭 시작 전'으로 되돌릴 때도 날짜를 받는다(이력에 한 줄이 남는다). 같은 단계를 다시 저장하면 날짜만 고친 것으로 본다.
- 한 줄 요약 아래에 접힘 '단계 이력'(평소 닫힘)에 날짜·단계 목록 3~5줄.
- 단계 고르는 칸의 선택지는 명진이 관리하는 단계 목록(2절)이다. 목록 줄 표시는 '투쟁 중으로 봄' 켠 단계와 이번 주 '끝남' 단계(협약체결·종료)에만 붙는다.
- 단계 관리: 담당조직 화면 오른쪽 위 ⋯ 메뉴의 '쟁의 단계 관리' 한 곳(결정). 줄마다 이름·투쟁 중 켬/끔·⋯(이름 바꾸기·지우기·끝남 켬/끔)·끌어 순서 바꾸기, 맨 아래 작은 [+ 단계]. 기본 단계 줄은 이름 바꾸기만. 시안 (다).
- 크고 굵은 버튼·카드·안내문 없음. 색은 기존 `--kptu-*`·`--ds-kind-*` 토큰 중 톤다운 색만(투쟁 중 = 기존 '챙길 것' 주황 계열 연한 바탕).

## 4. 변경 이력

남긴다(추천). 이유: 주간보고에서 "언제부터 이 단계인지"를 매주 쓰고, 단계가 잘못 눌렸을 때 되돌릴 근거가 필요하다. 별도 이력 표 하나를 **유일한 원본**으로 하고, 현재 단계 = 그 조직의 가장 나중 줄(단계 날짜 → 입력 시각 순)로 읽는다. 조직 표에 '현재 단계' 칸을 따로 두면 저장이 두 곳이라 어긋날 수 있어 두지 않는다. 잘못 넣은 줄은 이력에서 지우면 이전 단계로 돌아간다(데이터 삭제는 그 줄 하나뿐).

이력 줄은 **단계 id와 그때의 이름 사본**을 같이 저장한다. 나중에 단계 이름을 바꾸거나 단계를 지워도 지난 이력 글자는 그대로 남는다. 현재 단계의 투쟁 중·끝남 판정은 단계 id로 목록 표를 찾아 읽고, 단계가 지워져 id가 비어 있으면(이력에만 쓰였던 단계) 투쟁 중 아님·끝남 아님으로 읽는다. 단계를 지울 때는 그 단계에 있던 조직을 기본 단계로 옮기므로, 지금 단계의 id가 비어 있는 조직은 새로 생기지 않는다.

## 5. 주간보고 투쟁 사업장 표 자동 채움 규칙

1. 대상: `my-organizations.js`의 내 담당 조직 중 현재 단계가 **'투쟁 중으로 봄' 켬**인 조직만(기본: 쟁의발생 결의~임단협 찬반투표 7개).
2. 표 줄: 조직명 칸은 조직 이름(보고서 표기 규칙은 기존 그대로), 현황 칸 첫 줄에 `- {단계 이름}({M.D})`. 그 아래는 직전 확정본의 그 조직 현황 줄을 그대로 이어 사람이 고친다(기존 동작 유지, 앱이 현황 문장을 지어내지 않음).
3. 투쟁 중이 아닌데 직전 확정본에 줄이 있던 조직: 초안에서 줄을 지우자고 제안(기존 `remove` 고침 항목)하고, 화면 '고칠 목록'에서 명진이 확인한다. 자동으로 말없이 지우지 않는다.
4. 현재 단계가 '끝남' 켬이고 그 단계 날짜가 이번 보고 주간 안이면 그 주 한 번만 `- 협약체결(M.D)`·`- 종료(M.D)`(단계 이름)로 보여 주고 다음 주부터 뺀다. 끝남 표시가 켜진 단계가 목록에 하나도 없으면 이 규칙은 없는 것으로 읽는다.
5. 단계가 안 정해진 조직(이력 없음) = 기본 단계(교섭 시작 전) = 표에 안 나옴. 조회 실패 시 기존처럼 직전 확정본 줄을 그대로 쓰고 화면에만 "단계를 불러오지 못했어요" 한 줄.
6. 외부 행동 없음: 읽기만 하고, 보고서는 지금처럼 명진이 확인 후 받는다.

## 6. DB 변경 (DB PR `20261024100000_org_dispute_stage_db`, 운영 적용 전 정지)

새 표 두 개와 함수 하나. 기존 표·정책·권한은 건드리지 않는다.

```
app_dispute_stages                       -- 단계 목록(업무공간별)
  id            uuid pk default gen_random_uuid()
  workspace_id  uuid not null references app_workspaces(id) on delete cascade   -- 소유자 칸: 기존 소유자 정책(task12a_owner_all)과 같은 칸·방식
  name          text not null check (char_length(btrim(name)) between 1 and 20), unique (workspace_id, name)
  sort_order    integer not null default 0
  is_struggle   boolean not null default false   -- 투쟁 중으로 봄
  is_ending     boolean not null default false   -- 끝남
  is_default    boolean not null default false   -- 기본 단계(교섭 시작 전). 넣을 때만 정하고 고칠 수 없음
  check (not (is_struggle and is_ending))
  check (not is_default or (not is_struggle and not is_ending))
  unique index (workspace_id) where is_default    -- 업무공간마다 하나

app_suborganization_dispute_stages       -- 이력(유일한 원본)
  id              uuid pk default gen_random_uuid()
  organization_id uuid not null references app_suborganizations(id) on delete cascade
  stage_id        uuid references app_dispute_stages(id) on delete set null   -- 단계가 지워지면 비움
  stage_name      text not null          -- 저장 당시 이름 사본(1~20자)
  stage_date      date not null
  created_by      uuid references auth.users(id) on delete set null default auth.uid()   -- 로그인에서만 채움(넣기 권한 밖의 칸)
  created_at      timestamptz not null default now()
  index (organization_id, stage_date desc, created_at desc)
```

- RLS: 두 표 모두 켠다. 단계 목록은 `private.app_is_workspace_owner(workspace_id)`(소유자만, `for all to authenticated`, using/with check 동일), 이력은 `private.app_is_owner_organization(organization_id)`. 모든 정책 `to authenticated` 명시. anon·PUBLIC 권한 없음, 권한 확대 없음. 공유 페이지·Edge는 이 표들을 읽지 않는다.
- 좁히기 전용(restrictive) 정책 둘: (1) 이력 넣을 때 단계가 그 조직과 같은 업무공간의 단계이고 이름 사본이 그 단계의 지금 이름과 같아야 한다(`stage_id` 비움 불가, 남의 단계 id·가짜 이름 거절). (2) 단계 지울 때 기본 단계이거나 지금 어느 조직이 그 단계에 있으면 거절(함수를 거치지 않은 직접 지우기도 막음).
- 열 권한: 단계 목록은 넣기 6칸·고치기 5칸(이름·순서·두 표시·갱신 시각, 기본 표시·id·업무공간은 고칠 수 없음)·읽기·지우기. 이력은 넣기 4칸(조직·단계·이름 사본·날짜)·읽기·지우기만(고치기 없음 — 잘못 넣은 줄은 지워서 이전 단계로 되돌린다).
- `app_dispute_stage_delete(p_stage_id, p_move_organizations default false)`: INVOKER·search_path 고정·authenticated만 실행. 기본 단계 → `DEFAULT_STAGE`, 있는 조직이 있는데 확인 없음 → `ORGS_AT_STAGE`(조직 id 목록·개수 반환, 변경 없음), 확인했으면 그 조직들을 기본 단계로 옮기고(이력 한 줄, 날짜는 오늘(서울)과 그 조직의 지금 줄 날짜 중 나중) 같은 트랜잭션에서 단계를 지운다. 기본 단계가 없으면 `NO_DEFAULT_STAGE`.
- 기본 11단계 채움은 migration이 아니라 소유자가 처음 열 때 앱이 소유자 권한으로 넣는다(production 데이터를 migration이 건드리지 않음, 빈 표 생성). 기본 단계 줄(`is_default`)을 가장 먼저 넣는다.
- 적용: 승인형 DB workflow 확장 규칙(mode `apply`, version `20261024100000_org_dispute_stage_db.sql`), 짝 파일 5개. 되돌리기 = rollback SQL로 함수·두 표 삭제(SQL Editor 전용, 단계·이력 줄이 있으면 멈춤, preserve로 먼저 보관).
- 기존 조직은 모두 '이력 없음 = 기본 단계'.

## 7. PR 순서

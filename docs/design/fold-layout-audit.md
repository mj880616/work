# 폭별 화면 깨짐 전수 조사 (LAYOUT-폭별검사, 2026-11-28)

사용자 요청(2026-11-28 14:10): 폴드 펼친 화면에서 노트 화면이 완전히 깨졌던 것 같은 일이 다른 화면에도 있는지 조사해 체크.

배경: 폴드 펼침에서 노트 폴더를 누르자 노트 목록 제목 칸이 한 글자 폭(실제로는 0폭)으로 줄고, 머리 줄 '제목'과 '폴더'가 겹쳤다(#3239·#3277 뒤 회귀). 이 노트 목록은 S73-38(브랜치 `fix-note-fold-list`)이 고치는 중이라 이 조사에서는 고치지 않고 시험 표에만 넣었다.

## 1. 어떻게 쟀나

- 시험: `tests/app-e2e/width-layout.spec.mjs` (폭 표 × 화면 표, 칸마다 새로 열어 잼, 가짜 서버·지어낸 자료만).
- 재는 자: `tests/app-e2e/helpers/width-audit.mjs`
  - `overflow` — 문서 가로 넘침, 또는 굴림 상자 없이 화면 밖으로 나간 요소(줄 밀기로 일부러 민 줄은 옮기기 전 자리로 잰다).
  - `narrow` — 글 칸이 0폭으로 눌림, 80px보다 좁은데 4글자도 안 보이게 잘림, 3줄 넘게 접힘, 한 줄에 2글자 이하.
  - `textover` — 서로 다른 글 칸의 글자가 포개짐(같은 층끼리).
  - `pane0` — 두 칸 화면에서 내용 있는 칸이 40px보다 좁게 눌림.
  - `overlap` — 같은 층에서 단추 가운데를 다른 것이 덮음. `covered` — 떠 있는 창 안 단추를 하단바·상단 줄이 덮거나, 창 안을 굴려도 닿지 않게 화면 아래로 잘림.
- 폭 표(`WIDTHS`): 폴드 접힘 344 · 폰 360·412 · 경계 599|600 · 폴드 펼침 세로 673 · 경계 760|761 · 폴드 펼침·태블릿 세로 768 · 폴드 펼침 가로 884 · 경계 1023|1024 · PC 1280. 경계 폭은 앱 CSS 구간(`@media` 600·761·1024)과 두 칸 전환 폭 양쪽이다.
- 화면 표(`SCREENS`, `helpers/width-screens.mjs`): 메뉴 화면 전부(홈·잊지 말기·달력·할 일·하루 기록·조직 관리·사업 관리·사업영역 관리·브리핑 룸·파일·자료실·읽을 거리·저장한 글·통화·텔레그램 소식·아스날·사진·메뉴) + 상세(노트 폴더·노트 열기·조직 상세·사업영역 상세·일정 열기·파일 폴더·자료실 폴더·설정·설정 수집 상태·찾기·운영자 업데이트 기록·가입 관리·의견함) + 동작(노트 폴더 누르기·들어가기·폴더 메뉴 열기·줄 밀기 왼쪽/오른쪽, 잊지 말기 줄 누르기·줄 밀기). 37칸 × 13폭 = 476개.
- 새 화면은 `SCREENS`에 줄 하나, 새 기기 폭은 `WIDTHS`에 줄 하나만 더한다.

## 3. 공통 원인 묶음

- **가. 칸 수를 화면 폭으로 정함** — 노트 목록은 칸(폴더·태그·날짜·첨부)을 화면 폭 `@media(min-width:600px)`로 켠다. 그런데 [폴더] 보기에서는 목록이 나무 옆 좁은 칸이라 화면 폭과 목록 칸 폭이 다르다. 칸 자기 폭(container query) 기준으로 바꿔야 한다. 같은 모양(화면 폭 `@media`로 칸 수를 정하는 목록)은 이번 표에서 노트 목록 말고는 걸리지 않았다. 고치기는 S73-38.
- **나. 폴더 나무 줄의 개수 글자가 이름을 밀어냄** — 공용 `app/folder-tree.css`. 예전 LIB-나무이름잘림(S70-59)은 칸이 아주 좁을 때만(이름 단추 7.5em 이하) 개수를 숨겼는데, 칸이 넉넉해도 개수 글자가 길면(고른 폴더 '폴더 1 · 파일 3') 같은 일이 났다. 개수·표시 글자를 `flex:none` 대신 이름보다 100배 먼저 줄어들고 '…'로 끝나게 바꿨다(파일·자료실·노트·사진 나무 모두 이 줄을 쓴다). 폭 하드코딩·숨김 없음.
- **다. 입력 줄 폴더 칩 폭 상한** — 폰 노트 입력 줄 폴더 칩이 6.5em 상한이라 이름이 두 글자. 칩을 넓힐지, 그림만 둘지는 화면 결정이라 제안으로 남긴다.

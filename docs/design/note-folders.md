# 노트 폴더 설계 (UI-노트폴더)

📱 폰 가능 — 이 문서는 설계·조사만 한다. 앱 코드·DB·Edge·권한 변경 없음.

- 작성: 2026-10-20, Claude Code 웹. 기준 main `183b9fa`.
- 원장 행: `docs/roadmap.md`의 UI-노트폴더(진행중, 설계 문서). 같은 묶음: UI-노트고정(완료, #755), UI-프로젝트화면정리(대기).
- 앞 설계: [journal-memo-diary-design.md](journal-memo-diary-design.md)(노트 종류 `kind=note`를 만든 설계).
- 표기: **사실**은 저장소 코드·migration에서 확인한 것(파일 위치를 붙임). **추정**은 그렇게 표시했다. 운영 DB는 이 세션에서 볼 수 없어(AGENTS.md §1, 웹 세션) 실제 노트 수·연결 수는 확인하지 않았다.
- 이름: 지금 기록 종류는 **업데이트·노트·일기·일지** 네 가지다(옛 "메모"는 업데이트). 이 문서의 "노트"는 바구니 탭 [노트] 쪽 글(`app_notes.kind = 'note'`)만 뜻한다.
- 공개 저장소라 예시는 "A 폴더", "B 프로젝트"처럼 일반 이름만 쓴다.

## 명진이 정할 것

### 결정 1. 폴더를 어디에 저장할까

| 선택지 | 내용 |
| --- | --- |
| ① 새 폴더 표를 만든다 | 폴더가 따로 저장됨. 빈 폴더, 폴더 순서, 이름 한 번에 바꾸기가 깔끔함. 대신 DB 변경이라 승인·적용 단계(§6·§7)가 있고 되돌리기 SQL을 따로 준비해야 함 |
| ② 노트에 이미 있는 '부가 정보' 칸(`metadata`)에 폴더 이름만 적는다 (**추천**, 1단계) | 노트 고정(`metadata.pinned_at`)과 같은 방식. DB 변경 없음, 코드만 바꾸면 끝. 대신 노트가 하나도 없는 빈 폴더는 둘 수 없고, 폴더 이름을 바꾸면 그 폴더 노트를 하나씩 고쳐 씀 |
| ③ 프로젝트를 폴더처럼 쓴다 | 이미 있는 노트 → 프로젝트 연결을 폴더로 보여 줌. DB·저장 없음. 대신 노트 하나가 프로젝트 여러 개에 걸릴 수 있어 "노트당 한 폴더"가 안 되고, 프로젝트가 아닌 주제(예: 참고 자료 모음)는 넣을 곳이 없음 |

추천 이유: 폴더가 정말 손에 맞는지 먼저 써 보는 게 중요하고, ②는 승인 단계 없이 바로 만들고 되돌리기도 쉽다(코드만 되돌리면 폴더 표시가 사라지고 노트는 그대로). 몇 주 써 보고 "빈 폴더를 미리 만들고 싶다", "폴더 순서를 정하고 싶다"가 생기면 2단계에서 ①로 옮긴다. 옮길 때는 노트에 적힌 폴더 이름을 그대로 새 표로 옮기는 SQL 한 번이면 된다(7절).

### 결정 2. 폴더와 기존 프로젝트·조직 연결의 관계

| 선택지 | 내용 |
| --- | --- |
| ① 서로 따로 둔다 (**추천**) | 폴더 = 노트 탭 안에서 찾기 쉽게 정리하는 곳. 연결 = 이 노트가 어느 프로젝트·조직 일인지 표시(노트 줄의 색 꼬리표). 한 노트가 "A 폴더"에 있으면서 B 프로젝트에 연결될 수 있음 |
| ② 폴더를 고르면 프로젝트 연결도 자동으로 | 폴더마다 프로젝트를 하나 정해 두고 옮기면 연결도 생김. 편하지만 폴더를 옮길 때 연결을 지울지 남길지 매번 헷갈리고, 연결은 다른 화면(업무일지·주간보고 재료)에도 영향을 줌 |
| ③ 폴더 대신 연결만 쓴다(결정 1의 ③) | 새 기능 없이 꼬리표로 거르기만. "노트당 한 폴더", "프로젝트 아닌 주제" 요구를 못 채움 |

추천 이유: 두 가지가 하는 일이 다르다. 폴더는 내 노트 정리, 연결은 다른 화면과 이어 주는 길이다. 묶어 버리면 폴더를 옮기는 가벼운 손질이 다른 화면 기록까지 흔든다. 대신 목록 위 거르기 줄에서 폴더와 함께 "연결로 거르기"를 나란히 둘 수 있다(5절, 나중 과제).

### 결정 3. 폴더 모양

추천안 하나로 묶음(원장 제안 그대로):
- 폴더는 **한 단계만**(폴더 안 폴더 없음).
- 노트 하나는 **폴더 0개 또는 1개**. 폴더가 없는 노트는 "폴더 없음"에 보인다.
- 폴더 이름 1~20자, 최대 30개(자료실 분류 목록과 같은 기준, `app/document-categories.js`).
- 폴더는 노트(`kind=note`)에만. 업데이트·일기·일지에는 두지 않는다.

### 결정 4. 노트 고정과 폴더를 함께 쓸 때

| 선택지 | 내용 |
| --- | --- |
| ① 고정은 폴더와 상관없이 그대로: "전체"에서도, 그 노트의 폴더 안에서도 맨 위 (**추천**) | 고정 정보(`metadata.pinned_at`)를 하나만 둠. 지금 고정 기능을 바꿀 일 없음 |
| ② 폴더마다 따로 고정 | 같은 노트를 "전체"에선 고정 안 하고 폴더 안에서만 고정 가능. 고정 정보가 폴더 수만큼 늘고 화면 설명이 길어짐 |

추천 이유: 고정한 노트는 어디서 보든 맨 위에 있으면 된다. 지금 정렬 함수(`sortNotes`)를 고치지 않고, 폴더로 거른 뒤 그대로 쓰면 된다(6절).

### 결정 5. 폴더를 지우면 안에 있던 노트는

| 선택지 | 내용 |
| --- | --- |
| ① 노트는 남고 "폴더 없음"으로 (**추천**) | 폴더만 사라짐. 확인 문구 "A 폴더를 지울까요? 노트 N개는 '폴더 없음'으로 가요" |
| ② 노트도 같이 지움 | 실수 한 번에 노트 여러 개가 사라짐 |

### 결정 6. 화면 모양(PC·폰)

| 선택지 | 내용 |
| --- | --- |
| ① PC·폰 모두 검색칸 아래 **가로 폴더 줄**(전체 · A 폴더 · B 폴더 · 폴더 없음) (**추천**, 1단계) | 자료실·바구니에서 쓰는 거르기 줄(`app/filter-chips.js`)을 그대로 씀. 폰에서는 옆으로 밀어 봄 |
| ② PC는 왼쪽 세로 폴더 목록 + 오른쪽 노트 목록, 폰은 ① | PC 넓은 화면을 잘 씀. 대신 화면 틀을 새로 짜야 하고, UI-PC화면개선(PC 화면 정리 묶음)과 겹침 |

추천 이유: 1단계는 기존 부품만으로 PC·폰을 같이 맞춘다. PC 왼쪽 목록은 UI-PC화면개선 때 다른 PC 화면과 같이 시안으로 비교한다.

### 결정 7. 순서

UI-노트폴더 1단계는 **UI-프로젝트화면정리와 동시에 진행 가능**하다(추천). 노트 폴더는 `app/basket-notes.js`·`app/basket-data.js`, 프로젝트화면정리는 `app/project-system-v3.js`로 고치는 파일이 다르다. 겹치는 것은 이름(기록·노트·업데이트) 하나뿐이라, 이 문서는 "노트·폴더"라는 이름만 쓰고 프로젝트 화면 이름은 건드리지 않는다. 동시 진행 2개 제한(AGENTS.md §2) 안에서 커맨드센터가 정한다.

## 1. 목표와 범위 밖

### 목표

- 노트가 늘어도 한눈에 찾을 수 있게, 노트를 폴더로 나눠 본다.
- 폴더 고르기·옮기기는 노트 ⋯ 메뉴에서 한 번에, 폰·PC 똑같이.
- 기존 노트·고정·연결·첨부·검색은 그대로 둔다.

### 범위 밖

- 폴더 안 폴더(여러 단계), 노트 하나를 여러 폴더에 넣기.
- 업데이트(바구니)·일기·일지에 폴더 두기.
- 폴더를 다른 사람과 나누기·공개하기(Web2는 소유자 한 사람만 씀, AGENTS.md §5).
- 프로젝트·조직 연결 방식 바꾸기, 프로젝트 상세 화면 손질(UI-프로젝트화면정리 몫).
- PC 왼쪽 폴더 목록 같은 화면 틀 바꾸기(UI-PC화면개선 몫, 결정 6).
- 끌어서 옮기기(드래그). 1단계는 ⋯ 메뉴로만.

## 2. 지금 노트가 저장·표시되는 구조

### 2.1 저장 (사실)

| 무엇 | 어디 | 근거 |
| --- | --- | --- |
| 노트 본문 | `public.app_notes` 한 행. `kind='note'`, `title`(1~200자 한 줄, 노트만 필수), `raw_text`(10만 자까지) | migration `20261017052234_journal_memo_notes_kind.sql` |
| 같은 표의 다른 종류 | `kind`가 `basket`(업데이트)·`work`(일지)·`diary`(일기). 화면마다 한 종류만 읽음 | 같은 migration, `app/basket-data.js` `readKind` |
| 부가 정보 | `metadata` jsonb. DB는 "객체일 것"만 검사(`app_notes_metadata_check`). 지금 쓰는 칸: `pinned_at`(노트 고정), `tasks`(업데이트에서 만든 할 일) | migration `20261010120000_basket1_notes_links.sql`, `app/basket-data.js` `setNotePinned`, `app/basket-note-tasks.js` |
| 첨부·보관 | `attachments`(Drive 파일 목록), `archived_at` | `20261010120000_basket1_notes_links.sql` |
| 권한 | RLS 켜짐, anon·PUBLIC 권한 없음, 정책 하나 `notes_owner_all`(`private.app_is_workspace_owner(workspace_id)`) | `20260927103344_task_impl2_notes_record_links.sql`, `20261017052234` 사전·사후 검사 |

### 2.2 연결 (사실)

- 노트 → 프로젝트·담당조직·회의·자료실 연결은 `public.app_record_links` 한 행씩(`note_id` + 대상 하나). 같은 owner 정책(`record_links_owner_all`)이 노트와 대상이 같은 작업공간인지 검사한다.
- 노트 하나에 연결이 **여러 개** 생길 수 있다(대상마다 한 행, 고유 조건은 같은 대상 중복만 막음).
- 노트 화면은 확정된 연결을 줄마다 색 꼬리표로 보여 준다(`app/basket-notes.js` `chips`).
- **프로젝트·조직 상세의 🧺 기록에는 업데이트만 나온다.** `readLinkRecords`가 `note.kind=eq.basket`으로 거르기 때문(`app/basket-link-records.js` 38줄). 즉 노트를 B 프로젝트에 연결해도 B 프로젝트 상세에는 안 보이고, 노트 목록의 꼬리표로만 보인다. → 결정 1의 ③(프로젝트를 폴더처럼)이 약한 이유 중 하나.

### 2.3 목록 화면 (사실, `app/basket-notes.js`)

- 바구니 탭 위 [업데이트 | 노트] 전환은 `app/basket.js`가, 노트 쪽 그리기는 `basket-notes.js`(`mountNotes`) 하나가 맡는다. PC 왼쪽 메뉴 [바구니] 아래 [업데이트]·[노트]도 같은 전환을 연다(`app/topbar-actions.js`).
- 위에서부터: 검색칸 + [+ 노트] → 개수 줄 → 노트 줄들. 줄마다 [복사]·[⋯]·본문 버튼(고정 표시, 제목, 미리보기, 고친 날, 첨부 수, 연결 꼬리표).
- 정렬: 고정한 노트 먼저(최근 고정 순) → 나머지는 고친 날 최신순(`app/basket-data.js` `sortNotes`).
- 검색: 제목+본문 글자(화면 안에서 거름, 서버 요청 없음).
- ⋯ 메뉴: [고정/고정 풀기]·[수정]·(열린 노트에서만 [연결하기]·[바구니로 돌리기])·[삭제]. 목록 줄과 열린 노트가 같은 메뉴 하나를 씀.
- 노트 전체를 한 번에 읽어(100개씩 나눠 끝까지) 화면에서 거르고 정렬한다(`readNoteDocs` → `readKind`).

### 2.4 노트 고정이 한 방식 (사실, UI-노트고정 #755)

- 새 칸 없이 `metadata.pinned_at`(시각)만 적는다. 다른 `metadata` 칸은 그대로 둔다.
- 고정은 "고친 것"이 아니라서 `updated_at`(고친 날)을 바꾸지 않는다.
- 저장 직전 그 노트를 다시 읽고, 읽은 때와 같을 때만 고친다(`updated_at`·`pinned_at` 조건). 다른 곳에서 그사이 바꿨으면 "노트가 그사이 바뀌었어요" 안내.
- 폴더(결정 1 ②)도 이 방식을 그대로 따라 한다.

### 2.5 노트를 읽는 다른 곳 (사실)

- 업무일지: 그 주에 고친 노트 제목만 읽음(`app/journal-data.js` `readChangedNotes`, `kind=eq.note`). 폴더와 무관.
- 바구니·AI 복사·Drive 요약·🧺 기록: `kind=eq.basket`만 읽음. 노트·폴더가 섞이지 않음.
- [바구니로 돌리기]: `kind`를 `basket`으로, 제목을 비움. `metadata`는 그대로 남는다(지금도 `pinned_at`이 남음 — 업데이트 쪽은 이 값을 안 씀).

## 3. 폴더 방식 후보 비교

권한을 넓히거나 RLS를 느슨하게 하는 방식은 후보에서 뺐다. 세 후보 모두 **기존 소유자 전용 경계(`private.app_is_workspace_owner`)를 그대로** 쓴다.

| | ① 새 폴더 표 | ② `metadata.folder`에 이름 적기 (**추천 1단계**) | ③ 프로젝트를 폴더처럼 |
| --- | --- | --- | --- |
| DB 변경 | **필요**: 새 표 `app_note_folders` + `app_notes.folder_id` 칸 | 없음 | 없음 |
| 권한(RLS) | 새 표에 RLS 켜고, anon·PUBLIC 권한 걷고, authenticated에 4가지만, 정책은 `notes_owner_all`과 같은 모양(`app_is_workspace_owner`). `app_notes` 정책은 안 고침 | 기존 `notes_owner_all` 그대로 | 기존 `record_links_owner_all` 그대로 |
| "노트당 한 폴더" | DB가 지켜 줌(칸 하나) | 화면이 지킴(값 하나) | **못 지킴**(연결 여러 개 가능) |
| 빈 폴더 | 가능 | 불가(노트가 하나라도 있어야 폴더가 보임) | 프로젝트가 있으면 가능 |
| 폴더 순서 | 저장 가능 | 이름순 고정 | 프로젝트 순서 따름 |
| 이름 바꾸기 | 한 행만 고침 | 그 폴더 노트를 하나씩 고침(중간 실패 시 일부만 바뀜 → 다시 누르면 이어서) | 프로젝트 이름 바꾸기(다른 화면도 바뀜) |
| 프로젝트 아닌 주제 | 가능 | 가능 | 불가 |
| 되돌리기 | rollback SQL(칸·표 지우기) + 그 전에 폴더 배정 사본 저장. 승인 단계 | 코드만 되돌림. 노트에 남은 `folder` 값은 해가 없음(아무도 안 읽음) | 코드만 되돌림 |
| 만드는 양 | DB 1회 적용(정지 지점) + 코드 | 코드만(`basket-data.js`·`basket-notes.js`) | 코드만, 대신 프로젝트 고르기 화면을 폴더용으로 고쳐야 함 |
| 다른 화면 영향 | 없음 | 없음 | 연결이 업무일지·주간보고 재료에 쓰이므로 폴더 정리가 그쪽을 흔듦 |

### 3.1 ① 새 폴더 표 — 모양 제안(적용은 별도 PR·승인)

- `app_note_folders`: `id`, `workspace_id`, `name`(1~20자 한 줄), `position`(순서), `created_at`. 같은 작업공간에서 이름 겹침 금지.
- `app_notes.folder_id`: 폴더 표를 가리킴. 폴더를 지우면 `null`(노트는 남음, 결정 5 ①).
- 다른 작업공간의 폴더를 못 고르게 하는 것은 **`app_notes` 정책을 고치지 않고** `(workspace_id, folder_id)` 두 칸을 함께 가리키는 참조로 막는다(추정: 이 방식이면 정책 변경 없이 같은 작업공간만 허용됨. 폴더를 지울 때 `workspace_id`까지 비우지 않도록 `on delete set null (folder_id)`처럼 폴더 칸만 비우는 형태여야 하며, 운영 PostgreSQL 판이 이를 지원하는지 적용 PR에서 확인).
- 폴더는 노트에만: 검사 조건 `folder_id is null or kind = 'note'`. 이 경우 [바구니로 돌리기]가 폴더를 먼저 비워야 하므로 그 코드도 같이 고친다.
- 새 함수·Edge·권한 확대 없음. 적용 SQL은 기존 migration처럼 사전 검사(정책·권한 모양이 지금과 같을 때만) → 변경 → 사후 검사 → `schema_migrations` 1행 → `commit;`.

### 3.2 ② `metadata.folder` — 모양 제안

- 노트의 `metadata.folder`에 폴더 이름(1~20자, 앞뒤 공백 없음, 줄바꿈 없음)을 적는다. 없으면 "폴더 없음".
- 폴더 목록 = 지금 노트들에 적힌 이름을 모아 이름순(화면에서 계산, 따로 저장하지 않음).
- 옮기기: 고정과 똑같이 그 노트를 다시 읽고 → 다른 `metadata` 칸은 그대로, `folder`만 바꿔 → 읽은 때와 같을 때만 저장. `updated_at`은 안 바꿈(폴더 옮기기는 고친 것이 아님).
- 이름 바꾸기·지우기: 그 이름을 가진 노트를 하나씩 위 방식으로 고침. 중간에 실패하면 "N개 중 M개만 바뀌었어요. [다시 시도]" — 다시 누르면 남은 것만 이어서 고친다.
- DB가 이름 규칙을 검사하지 않는다. 화면이 검사하고, 그리기는 지금처럼 글자로만(escape) 하므로 이상한 값이 들어와도 표시가 깨지는 정도에서 그친다(소유자 한 사람만 쓰는 표).
- [바구니로 돌리기]는 `folder`를 지우고 돌린다(업데이트에는 폴더가 없음).

### 3.3 ③ 프로젝트를 폴더처럼 — 왜 추천하지 않나

- 노트 하나가 여러 프로젝트에 연결될 수 있어 "어느 폴더에 있나"가 하나로 정해지지 않는다.
- 연결된 노트는 프로젝트 상세에 안 보인다(2.2) — 폴더처럼 쓰려면 그 화면도 고쳐야 해서 UI-프로젝트화면정리와 겹친다.
- 프로젝트 목록은 상위·하위로 많고, 노트 정리용으로 프로젝트를 만들면 프로젝트 목록·주간보고 묶음이 지저분해진다.
- 다만 "B 프로젝트 노트만 보기"는 유용하다. 이는 폴더와 별개로 목록 거르기에 "연결" 거르기를 더하는 나중 과제로 남긴다(결정 2 ①).

## 4. 화면 흐름

### 4.1 폴더 고르기·옮기기

- 노트 ⋯ 메뉴에 [폴더 옮기기] 한 줄을 [고정] 다음에 넣는다(목록 줄·열린 노트 모두).
- 누르면 기존 고르기 창(`app/choice-sheet.js` `createChoiceSheet`)이 열린다: 폴더 이름들 + "폴더 없음" + 맨 아래 [+ 새 폴더](이름 입력). PC에서는 ⋯ 아래 작은 목록, 폰에서는 아래에서 올라오는 창 — 지금 고르기 창이 PC·폰에서 하는 그대로.
- 고르면 바로 저장, 알림 "A 폴더로 옮겼어요." 실패하면 그 자리 안내 줄(고정과 같은 문구 방식).
- 새 노트 만들 때: 폴더 하나를 보고 있는 중이면 그 폴더에 넣어 저장한다(추정: 쓰기 창 `write-window.js` 저장 뒤 한 번 더 고치는 방식이 아니라 처음 저장 값에 넣는 편이 안전. 1단계 PR에서 확인).

### 4.2 폴더 관리

- 폴더 줄 끝에 작은 [⋯ 폴더] 버튼 → [이름 바꾸기]·[지우기]만. 지금 고른 폴더에 대해서만 동작("전체"·"폴더 없음"을 고른 때는 숨김).
- 지우기 확인 문구: "A 폴더를 지울까요? 노트 N개는 '폴더 없음'으로 가요."

## 5. 목록 화면 안

### 5.1 폰(좁은 화면)

```
[ 노트 검색                    ] [+ 노트]
( 전체 )( A 폴더 )( B 폴더 )( 폴더 없음 ) [⋯]   ← 옆으로 밀림
12개 노트
📌 고정한 노트 제목 …
•  노트 제목 …            A 폴더 · B 프로젝트
```

- 폴더 줄은 검색칸 아래 한 줄. 고른 쪽은 회색, 안 고른 쪽은 흰 바탕(앱 공통 규칙, UI-선택표시통일).
- "전체"에서는 노트 줄에 폴더 이름을 작은 글자로 붙인다(연결 꼬리표 앞). 폴더 하나를 고른 때는 붙이지 않는다.
- 검색은 고른 폴더 안에서만 찾는다. 찾는 노트가 없으면 "이 폴더에 찾는 노트가 없어요 · [전체에서 찾기]".
- 노트를 연 뒤 "‹ 노트"로 돌아오면 보던 폴더·스크롤 그대로(지금 뒤로가기 구조 그대로).

### 5.2 PC(넓은 화면)

- 1단계는 폰과 같은 폴더 줄(결정 6 ①). 넓은 화면이라 대부분 밀지 않고 한 줄에 다 보임.
- PC 왼쪽 메뉴 [바구니] 아래 [노트]는 그대로. 폴더를 왼쪽 메뉴에 더 늘어놓지 않는다(메뉴가 길어짐).
- PC 왼쪽 폴더 목록 + 오른쪽 노트 목록은 UI-PC화면개선에서 시안 비교(결정 6 ②).

### 5.3 고른 폴더 기억

- 마지막에 본 폴더는 이 브라우저에만 기억한다(새로 열면 그 폴더로). 기억 못 하면(개인정보 보호 창 등) "전체"로. 같은 화면 상태 하나가 정하고(`basket-notes.js` 안), 다른 곳에서 덮어쓰지 않는다(AGENTS.md §5 "한 칸에 한 주인").

## 6. 노트 고정과의 관계

- 고정은 그대로 하나(`metadata.pinned_at`), 폴더와 따로(결정 4 ①).
- 정렬은 지금 `sortNotes` 그대로: 고른 폴더로 먼저 거르고 → 고정 먼저 → 고친 날 순. 정렬 함수는 안 고친다.
- 고정과 폴더가 같은 `metadata` 안에 나란히 있다. 둘 다 "다시 읽고 → 다른 칸 그대로 → 읽은 때와 같을 때만 저장" 방식이라 서로 지우지 않는다. 1단계 시험에서 "고정한 노트를 옮겨도 고정 유지", "폴더에 있는 노트를 고정해도 폴더 유지"를 확인한다.
- 결정 1에서 ①(새 표)을 고르면 폴더는 `folder_id` 칸, 고정은 `metadata`로 저장 위치가 갈린다. 동작은 같다.

## 7. 단계 계획

### 1단계 — ② 방식, 코드만 (DB·Edge 변경 없음)

- `app/basket-data.js`: `noteFolder(note)`(값 읽기·검사), `setNoteFolder(note, name)`(고정과 같은 다시 읽기·조건 저장), `noteFolders(notes)`(목록 계산), 폴더 이름 검사. [바구니로 돌리기]에서 `folder` 지우기.
- `app/basket-notes.js`: 폴더 줄(`filter-chips.js`), ⋯ 메뉴 [폴더 옮기기], 고르기 창, [⋯ 폴더] 이름 바꾸기·지우기, 고른 폴더 기억.
- `app/basket.css`(필요한 만큼). 새 공용 부품 만들지 않음.
- `app/ARCHITECTURE.md`: 노트 목록 문단에 폴더 한 줄.
- 시험: 단위(`tests/basket-data.test.mjs`: 이름 검사, 다른 `metadata` 칸 보존, `updated_at` 안 바꿈, 조건 저장 실패 안내), 화면(`tests/app-e2e/basket-note-folder.spec.mjs` 새로: 옮기기·거르기·이름 바꾸기 중간 실패 이어하기·지우기·고정과 함께·폰/PC 폭·키보드만으로 조작). 예시는 가짜 이름만.
- 되돌리기: PR revert. 노트에 남은 `folder` 값은 아무도 읽지 않아 해가 없다.

### 2단계(필요할 때만) — ① 새 폴더 표로 옮기기

빈 폴더·순서·한 번에 이름 바꾸기가 필요해졌을 때만. **DB 변경이라 정지 지점**(AGENTS.md §6·§7).

- 2-1 설계 보완 PR: 적용 SQL·확인 SQL·rollback SQL 초안(`docs/design/sql/`), 일상어 3줄(무엇이 바뀌나 / 잘못되면 / 되돌리는 방법).
  - 적용 SQL 안에서 노트의 `metadata.folder` 이름들로 폴더 행을 만들고 `folder_id`를 채운다(같은 트랜잭션). `metadata.folder`는 지우지 않고 남겨 둔다(되돌리기 대비).
  - rollback: `folder_id` 칸·검사 조건·폴더 표 지우기. `metadata.folder`가 남아 있으므로 1단계 화면으로 되돌아가도 폴더가 그대로 보인다.
- **⏸ 정지 지점**: 커맨드센터 승인 → 명진이 SQL Editor(또는 폰 경로 C)에서 실행 → 결과 확인. AI는 실행하지 않는다.
- 2-2 코드 PR: 읽기·쓰기를 `folder_id`로 바꿈. 2-1 적용 확인 뒤에만 merge.

### 결정 1에서 ①을 바로 고르면

1단계가 "1-1 DB(정지 지점) → 1-2 코드"로 바뀐다. 1-1은 위 2-1과 같지만 옮길 `metadata.folder` 값이 없다.

## 8. 위험

- **이름 바꾸기 중간 실패(②)**: 노트 여러 개를 하나씩 고치므로 일부만 바뀔 수 있다. 결과 개수를 보여 주고 [다시 시도]로 이어서 고친다. 이름이 두 개로 갈려도 노트는 사라지지 않는다.
- **`metadata` 덮어쓰기**: 폴더·고정·할 일이 같은 칸을 쓴다. 다른 칸을 지우지 않는지 단위 시험으로 고정한다(고정 기능과 같은 방식).
- **폴더 수가 많아짐**: 30개 제한, 폰에서 줄이 길어짐. 30개 넘게 원하면 그때 ①·PC 왼쪽 목록을 함께 검토.
- **폴더와 연결 혼동**: 둘 다 노트 줄에 작은 글자로 보인다. 폴더는 글자만, 연결은 지금처럼 색 점 꼬리표로 구분한다.
- **DB가 이름을 검사 안 함(②)**: 소유자 한 사람만 쓰는 칸이고 화면이 글자로만 그리므로 위험은 표시가 어긋나는 정도. ①로 가면 DB가 검사한다.

## 9. 조사 중 알게 된 것(범위 밖, 보고만)

- 노트를 프로젝트·조직에 연결해도 그 상세 화면의 🧺 기록에는 나오지 않는다(`readLinkRecords`가 업데이트만 읽음, 2.2). 의도인지(노트는 오래 두는 문서라 기록 줄에 안 섞음) 빠뜨린 것인지 원장에 기록이 없다. UI-프로젝트화면정리에서 "프로젝트 상세에 연결된 노트를 보여 줄지"를 함께 정하면 좋다.
- [바구니로 돌리기] 뒤에도 `metadata.pinned_at`이 업데이트 행에 남는다(2.5). 지금은 아무 화면도 안 읽어 해는 없다. 1단계에서 폴더를 지울 때 고정도 같이 지울지는 그 PR에서 판단(이 문서 범위 밖).

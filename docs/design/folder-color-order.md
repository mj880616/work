## 0. 한눈 요약

1. 폴더를 쓰는 곳은 **다섯 갈래**다(노트 / 자료실 / [파일] 클라우드 / 사진 폴더 / 사진 앨범). 순서 값을 이미 서버에 가진 곳은 노트·자료실뿐이고, 색을 고를 길은 어디에도 없다.
2. 저장은 **두 가지 길 하나씩**: 우리 표가 있는 폴더(노트·자료실)는 그 폴더 표에 `color` 칸 하나를 더한다. 클라우드 폴더([파일]·사진 폴더)와 앨범은 폴더 표가 우리 것이 아니므로 새 표 `app_folder_prefs` 하나(주인만, 폴더 키 → 색·순서)에 둔다. `view_prefs`는 쓰지 않는다(이유 3절).
3. 화면은 **공용 부품 둘**: 순서·색을 계산하는 순수 모듈 `app/folder-look-model.mjs`(색 번호→색 이름·정렬·끌기 판정)와 폴더 아이콘·꼬리표를 그리는 `app/folder-look.js`. 모든 폴더 화면이 이 둘만 부른다. 색 값은 `theme-tokens.css` 한 곳.
4. 끌기: 줄 **가운데 = 폴더 안으로 넣기**, 줄 **사이 = 순서 바꾸기**(가운데 50%만 '넣기', 위·아래 25%는 '사이'). 폰은 꾹 눌러 끌기(`reorder-drag.js` 공용 부품), 메뉴 [위로][아래로]는 끌기가 어려울 때의 같은 동작.
5. 노트 순서: 정렬 기준에 **'내가 정한 순서'**를 더하고, 그 기준일 때만 끌 수 있다. 다른 기준(고친 날 등)에서는 끌기 손잡이를 숨기고 [위로][아래로]도 비활성.
6. PR은 셋: ① 이 설계 + 시안(이번) → ② 노트(DB `color` 칸 + 화면 + 공용 부품) → ③ 자료실·[파일]·사진(+`app_folder_prefs`).

## 2. 저장 자리 [결정]

### 2-1. 우리 표(노트·자료실·앨범): `color` 칸 하나

- `app_note_folders`, `app_library_folders`, `app_photo_tags`에 각각 `color smallint null` 추가, 검사 `color is null or color between 1 and 8`. null = 기본(안 고른 폴더, 지금 모양 그대로).
- 순서 값이 없는 `app_photo_tags`는 같은 migration에서 `sort_order integer not null default 0`도 더한다(없으면 이름순 유지, 끌어 바꾼 뒤부터 값 사용).
- 열 권한: 기존 정책(주인만)은 그대로. `grant update (color)`(·`sort_order`) 한 줄씩만 더한다. 정책·RLS·anon·PUBLIC 변경 없음.
- 순서 쓰기는 지금처럼 `sort_order`를 PATCH. 끌어 옮기면 이웃 사이 값(간격 1024, `nextSortOrder`)을 쓰고, 간격이 다 차면 그 형제 전체를 다시 매긴다.

### 2-2. 클라우드 폴더([파일]·사진 폴더·폰 앨범): 새 표 `app_folder_prefs` [결정]

- 칸: `id`, `workspace_id`, `source`('od'|'gd'|'phone'), `folder_key`(그 출처의 폴더 id — [사실] `app_cloud_items.item_id`·`app_onedrive_folders` id 와 같은 값), `color smallint null`, `sort_order integer null`, `updated_at`. 유일키 `(workspace_id, source, folder_key)`.
- RLS 켜고 주인만(`private.app_is_workspace_owner`) 한 정책, anon·PUBLIC 권한 없음. 쓰기는 `insert/update`에서 위 칸만 열 권한. 클라우드에서 폴더가 지워지면 남는 줄은 화면이 무시하고, 맞추기 때 지우거나(후속) 그대로 둬도 해가 없다.
- 순서는 **같은 부모 안**에서만 의미가 있으므로 `sort_order`는 '같은 부모 안 상대 순서'로 쓴다. 값이 없는 폴더는 지금처럼 이름순으로 뒤에 붙는다(정해진 순서 폴더 → 이름순 폴더).
- 클라우드 실제 폴더 이름·순서는 건드리지 않는다(색·순서는 Web2 안에서만 보이는 꾸미기). 이 점을 폴더 ⋯ 메뉴에 한 줄로 알린다("이 색·순서는 이 앱에서만 보여요").

### 2-3. 왜 `view_prefs`가 아닌가

- `view_prefs`는 `app_profiles`의 한 칸에 모든 화면 설정을 JSON으로 두고, 칸 이름을 늘릴 때마다 CHECK 제약을 통째로 다시 만든다(최근 20261104190000까지 35~36개) [사실]. 폴더가 수백 개면 JSON이 커지고 한 폴더만 바꿔도 전체를 쓰며, 기기 두 대가 동시에 바꾸면 덮어쓴다.
- 폴더 하나에 한 줄인 표가 읽기·쓰기·충돌 모두 단순하다. 그래서 하나로 정한다: **우리 표는 칸, 나머지는 `app_folder_prefs`**. `view_prefs`에는 폴더 색·순서를 넣지 않는다.
- 노트의 '내가 정한 순서' 정렬 기준 선택값 자체(화면 설정)는 지금처럼 `view_prefs`의 기존 정렬 칸에 값 하나를 더하는 일이라 칸 추가가 아니라 허용값 추가이며, 구현 PR에서 main 최신 판(지금 `20261104190000_profile_view_prefs_files_two`) 위에 얹는다.

### 3-2. 끌기와 '안으로 넣기' 구분

- 폴더 줄 높이를 4등분: **위 25% = 이 줄 앞에 놓기, 가운데 50% = 이 폴더 안으로 넣기, 아래 25% = 이 줄 뒤에 놓기**. 가운데에서는 줄 전체가 연한 파란 바탕, 위·아래에서는 줄 사이에 파란 선 하나(시안의 선). 선과 바탕이 동시에 나오지 않는다.
- 노트를 끌 때는 폴더 줄 가운데 = 그 폴더로 옮기기(지금과 같음), 노트 줄 위·아래 = 순서(노트 목록에서만).
- 폴더를 자기 안·자기 아래로는 넣을 수 없다(지금 규칙 그대로, `library-tree.js`).
- 키보드·터치 대안: ⋯ 메뉴 [위로][아래로](한 칸씩), [폴더로 옮기기…] 창은 지금처럼.
- 판정 함수는 순수 모듈에 두고(`dropZone(rowRect, y)` → 'before'|'inside'|'after') 단위 시험한다. 끌기 UI는 `reorder-drag.js`의 `mountReorder`(폰 `LONG_MS` 450ms 꾹 누르기, 마우스 손잡이)를 쓰되, '가운데=넣기'가 필요한 곳을 위해 `onDrop`에 `zone`을 더하는 확장을 **구현 PR에서 한 번만** 한다(다른 사용처 `menu-edit.js` 등은 기존 동작 그대로).

### 3-3. 노트 정렬 기준

- 노트 목록 정렬 기준에 **'내가 정한 순서'**를 추가한다. 기본값은 지금처럼 '고친 날'. '내가 정한 순서'에서만 노트 줄에 끌기 손잡이·[위로][아래로]가 보이고, 고정 노트는 맨 위에 그대로(고정 안 노트끼리만 끌기).
- 노트 순서 값은 노트 행의 `metadata.order`(정수, 폴더 안 간격 1024) 하나. 이미 노트마다 `metadata`에 `folder_id`·`board`·`pinned`를 두는 방식과 같다 [사실: `basket-data.js`]. 값이 없는 노트는 고친 날 순으로 뒤에 붙는다. 새 칸·새 표 필요 없음.
- 한 줄 요약: **정렬이 '내가 정한 순서'일 때만 끌 수 있고, 값은 `metadata.order`에 서버 저장한다.**

## 4. 색 [결정, 명진이 시안에서 고름]

## 6. 보안·DB 규칙 (구현 PR용)

- DB는 migration 짝 파일(`.sql`+rollback+snapshot) + `schema_migrations` 기록 줄. 시험 적용 먼저, 실패하면 멈춤(자동 되돌리기 없음). 지금 설계에서 DB가 바뀌는 곳: ② `color`(·`app_photo_tags.sort_order`) 칸 추가, ③ `app_folder_prefs` 새 표. 기존 정책·RLS·권한을 넓히지 않는다.
- 노트·자료실·앨범 `color`는 열 권한 `update (color)`만 추가하고, 검사로 1~8 외 값을 서버에서 거절한다(화면만 믿지 않음).
- `app_folder_prefs`는 새 표라 RLS 주인만, anon/PUBLIC 없음, 정책 하나. 클라이언트가 보낸 `workspace_id`를 믿지 않고 주인 검사를 서버(RLS)에서 한다.
- 기기 저장(localStorage) 쓰지 않는다. 색·순서 모두 서버. 다른 기기에서는 목록을 다시 읽을 때(화면 열기·창으로 돌아올 때) 같은 값이 보인다.
- RTW(`rtw_*`)·Web1·공개 경로 변경 없음.

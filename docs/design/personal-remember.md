## 0. 명진이 정할 것 (한 번에 고르기)

각 항목에서 **굵은 것이 추천**이다. "전부 추천대로"라고만 답해도 된다.

1. **저장 위치** — **가. 원문은 개인 노트북에만 + Web2에는 정리한 요점만 새 비공개 표(소유자 전용)에(추천)** · 나. 노트북에만(Web2 화면 없음, 노트북에서 파일로만 봄) · 다. 노트북 + 개인 Drive 비공개 폴더. 근거 3절.
2. **Web2에 원문도 올릴까** — **가. 요점만(추천)**: 항목마다 "무슨 내용인지 한두 줄 + 근거 날짜". 원문 문장을 그대로 옮기지 않는다(짧은 인용도 넣지 않음). · 나. 원문도 함께(새 표 하나 더, 보관량·유출 시 피해가 훨씬 큼).
3. **AI 분석을 어디서 돌릴까** — **가. 노트북에서(추천)**: 원문이 노트북 밖으로 나가는 곳은 AI 회사 한 곳뿐. · 나. 서버(Edge)에서: 원문이 Supabase를 거쳐야 함.
4. **AI 열쇠** — **가. 이 기능 전용 새 열쇠 1개, 월 사용 한도 걸기, 노트북의 동기화 안 되는 폴더에만(추천)** · 나. Web2 서버 열쇠(`WEB2_OPENAI_API_KEY`)를 같이 씀(섞이면 업무 비용·기록과 구분이 안 됨).
5. **노트북 → Web2 보내는 길** — **가. 이 기능 전용 새 Edge 함수 하나 + 전용 비밀값, "쓰기만 되고 읽기는 안 되는" 입구(추천)** · 나. 노트북에 명진 로그인 정보를 두고 직접 쓰기(노트북을 잃으면 Web2 전체 권한이 샘).
6. **원문 백업** — **가. 노트북 디스크 암호화 확인 + 한 달에 한 번 암호 걸린 압축 파일을 개인 외장 저장장치에(추천)** · 나. 백업 없음(노트북 고장·분실 때 원문 영구 손실) · 다. Google Drive에 백업(업무 Drive와 같은 계정이라 Claude Drive 검색에 걸릴 수 있음 — 비추천).
7. **Web2 입구** — **가. [계정 ▾] 메뉴 안 [개인 기록] 한 칸(내 프로필과 같은 위치·방식, 업무 메뉴·홈·업무 검색에 안 보임)(추천)** · 나. 왼쪽 메뉴의 [일기] 옆.
8. **삭제 방식** — **가. 항목 지우기 = 내용은 즉시 비우고 '지웠다는 표시'(항목 번호만)를 남겨 노트북이 같은 항목을 다시 올리지 못하게(추천)** · 나. 행을 완전히 지움(다음 날 노트북이 다시 보내면 되살아날 수 있음).

10. **최초 소급 분석 방식** — **가. 한 달치씩 나눠 분석한 뒤 주제별로 합치기(추천, 중간에 멈춰도 다시 이어 감)** · 나. 전부 한 번에.

### 1.2 Web2에 개인 전용 공간·비공개 영역 설계가 있나

- **ME-보관함**(사실: `docs/roadmap.md` 대기 행, `docs/basket-design.md`): 개인 **문서** 비공개 보관함. Web2 개발 종료 뒤 착수, 착수 전 DB·RLS·Storage 조사 필수. 설계 문서는 아직 없다. → 이번 기능은 대화 요점 목록이라 성격이 달라 **ME-보관함에 합치지 않는다**. 나중에 ME-보관함이 생기면 같은 [계정 ▾] 아래 이웃 칸으로 둔다.
- **일기**(사실: `docs/design/journal-memo-diary-design.md`, migration `20261017052234`): `app_notes` 안 `kind='diary'` + DB가 `ai_export_allowed=false` 강제. 업무 검색(`app_search_records`)은 함수 안 허용 목록(basket·note·work)으로 일기를 뺀다.
  - 교훈: **같은 표에 종류만 다르게 넣으면 읽는 곳마다 종류 필터를 빠뜨리지 않았는지 지켜야 한다**(일기 설계 문서가 "필터 누락 검사"를 따로 둠). 이번 기능은 **처음부터 새 표**로 두어 기존 읽는 곳이 이름조차 모르게 한다(4절).
- Web2 전체 구조(사실: AGENTS.md §5): 로그인 1명(소유자)만 쓰는 비공개 시스템, 데이터 접근은 `private.app_is_workspace_owner`로 소유자만. 개인 공간도 이 경계 안에 둔다(권한 새로 넓히지 않음).

### 1.4 Drive 사본 경로

- Claude가 읽는 사본(사실: `supabase/functions/drive-summary/README.md`): 내 Drive 최상위 "Web2 읽기용 사본" 폴더 + 조직·프로젝트 문서 2개 + 원장 내보내기. 앱이 만든 파일만 다루는 `drive.file` 권한.
- 업무 수집 결과 폴더: 텔레그램 `messages/<YYYY-MM>/`, 통화 `통화 녹음 → 전사`(사실: 점검 신호 안내 문서).
- **위험(추정)**: 이 프로젝트의 Claude에는 Google Drive 검색 연결이 붙어 있어, **Drive 어디에든 원문을 두면 Claude 대화에서 검색으로 읽힐 수 있다**. → 원문은 Drive에 두지 않는다(3절).

## 2. 전체 흐름 (추천안 기준)

```
[개인 노트북]
  ① 개인 수집기: 가족 1:1 대화 1개만 → 노트북 로컬 폴더(동기화 안 되는 곳)에 원문 저장
  ② 글자 수 세기(숫자만 출력) ──► 명진에게 비용·시간 보고 ──► (정지) 승인
  ③ AI 분석(노트북의 전용 열쇠) → 항목(분류·주제·요점·근거 날짜) 만들기
  ④ 항목만 전용 Edge 입구로 보냄(비밀값, 쓰기만)
                      │
[Supabase]            ▼
  Edge personal-remember-ingest ─► 새 표 app_personal_remember_items (소유자 전용 RLS)
                      │
[Web2]                ▼
  [계정 ▾] → [개인 기록] 화면: 분류·주제별 목록, 주제 안 날짜순(변화 흐름), 검색, 지우기, 내보내기, 전체 지우기
```

- 원문은 ①의 노트북 폴더(와 결정 6의 개인 백업)에만 있다.
- 업무 수집기(회사 PC)·업무 Drive 폴더·Web2 업무 화면·업무 AI·Claude 사본은 이 흐름 어디에도 끼지 않는다.

## 3. 저장 위치 비교

| | 가. 노트북 원문 + DB 요점(추천) | 나. 노트북만 | 다. 노트북 + 개인 Drive 비공개 폴더 |
| --- | --- | --- | --- |
| Web2에서 목록·검색 | 됨 | **안 됨**(웹 화면은 노트북 파일을 못 읽음) | **안 됨**(사실: Web2는 `drive.file` 권한이라 노트북이 만든 Drive 파일을 못 읽음. 넓히는 것은 금지) |
| 원문이 있는 곳 | 노트북 1곳 | 노트북 1곳 | 노트북 + Google 계정 |
| 유출 경로 | 노트북 분실(디스크 암호화로 줄임), Web2 계정 탈취 시 **요점만** | 노트북 분실 | 노트북 분실, Google 계정 탈취, **Claude Drive 검색**, 공유 실수 |
| 업무 쪽 섞임 위험 | 낮음(새 표, 읽는 곳 없음) | 없음 | 중간(업무 Drive와 같은 계정·같은 검색) |
| 요청 충족 | 전부 | 'Web2 개인 공간에서 보기' 불충족 | 'Web2에서 보기' 불충족 + 제약(Claude용 사본에 안 들어가게) 위반 위험 |

**추천: 가.** 요청의 "Web2에서 보기·검색"을 지키면서 원문은 노트북 밖으로 나가지 않는다(AI 회사로 보내는 분석 요청 제외).

### Web2에 요점만 vs 원문도 (결정 2)

- 요점만(추천): 유출돼도 원문 문장이 없다. 검색은 요점·주제 글자로 한다. 근거 날짜가 있으므로 원문이 필요하면 노트북에서 그 날짜를 연다.
- 원문도: 검색이 넓어지지만 DB에 상대의 말 전부가 쌓인다. 백업(Supabase 자체 백업)에도 남는다(**추정**: 요금제별 보관 기간 동안). 추천하지 않는다.

## 4. 업무 쪽에서 절대 안 읽히게 하는 장치

| 장치 | 내용 |
| --- | --- |
| 별도 표 | `app_notes`에 종류를 더하지 않고 새 표. 기존 읽는 곳(1.3)이 이 표 이름을 모른다 |
| 표 권한 | RLS 켬, 정책은 소유자 1개(`private.app_is_workspace_owner(workspace_id)`) — 기존 Web2 표와 같은 모양. `anon`·`PUBLIC` 권한 없음. `service_role`은 **INSERT만**(SELECT·UPDATE·DELETE 없음) — 입구 Edge가 써 넣기만 하고 읽지 못함 |
| 업무 검색 제외 | `app_search_records`는 바꾸지 않는다. "종류 목록에 개인 기록이 없다"를 테스트로 고정 |
| Edge 분리 | 전용 함수 `personal-remember-ingest` 하나. `ai-assist`·`drive-summary`·`basket-files`에 개인 기능을 넣지 않는다. 이 함수는 다른 표를 읽지도 쓰지도 않는다 |
| 이름 울타리 테스트 | 저장소 전체에서 새 표·새 함수 이름이 나오는 파일을 허용 목록(개인 화면 모듈·migration·Edge·테스트)으로 고정. 업무 파일이 이름을 부르면 CI 실패 |
| 로그에 본문 금지 | Edge는 실패 코드·건수만 기록(기존 `ai-assist` 로그 모양). 노트북 스크립트도 화면·로그 파일에 건수·날짜·실패 코드만. 요청·응답 본문을 출력하지 않는다 |
| 화면 분리 | 업무 메뉴·홈·업무 검색·업무일지에 들어가지 않음. 시작 로더(`loadAll`)에 넣지 않고 처음 열 때만 불러옴 |
| 브라우저 저장 금지 | 항목을 `localStorage`·`sessionStorage`·IndexedDB에 두지 않음(화면 메모리만). 서비스워커는 이미 저장 안 함 |
| 시험은 지어낸 자료만 | 단위·E2E 시험 자료는 "(예시) 주말 일정" 같은 지어낸 문구. 실제 대화·실제 날짜 일화로 시험하지 않음. 노트북 분석 시험도 지어낸 대화 파일로 |
| Drive·공유 금지 | 원문·요점 어느 것도 Drive·공유 링크·Web1·Claude 사본에 보내지 않음. 개인 화면에 공유 버튼을 만들지 않음 |
| 노트북 폴더 | 원문 폴더는 Google Drive·OneDrive 등 **동기화 폴더 밖**에. 업무 수집기의 출력 폴더와 다른 곳 |
| 업무 수집기 쪽 확인 | 회사 PC 업무 수집기가 1:1 대화를 고르는 방식이 **허용 목록**인지(가족 대화가 이미 업무 Drive로 가고 있지 않은지) 1단계에서 확인(**추정 위험**, 10절) |

## 5. 구성 요소 설계

### 5.1 노트북 (저장소 밖, 결정 11)

- **수집**: 기존 노트북 수집 프로그램에 대상 대화 1개를 추가하거나 같은 방식으로 작은 개인 수집기를 따로 둔다(**추정**: 기존 프로그램 구조를 보지 못함 — 1단계에서 확인). 처음 1회는 처음 대화부터 끝까지, 이후엔 마지막으로 받은 메시지 번호 다음부터. 원문은 날짜별 파일(예: 월 폴더 안 하루 파일)로 노트북 로컬 폴더에.
  - 사진·파일 첨부는 받지 않고 "[사진]" 표시만(**추천**, 용량·민감도). 필요하면 나중에 정함.
- **글자 수 세기**(분석 전, AI 호출 없음): 달마다 메시지 수·글자 수, 전체 합계만 출력. 내용·이름 출력 없음.
- **분석**:
  - 최초 1회(소급): 한 달치씩 → 항목 후보 → 주제 합치기 → 보내기. 달마다 끝난 표시를 노트북에 남겨 중간에 끊겨도 이어 감.
  - 매일: 그날(한국 날짜) 대화만 → 같은 항목 뽑기 → 보내기. 기존 주제 목록(노트북이 보낸 주제 이름 사본)을 AI에 함께 주어 같은 주제면 같은 이름을 쓰게 한다.
  - 뽑는 항목(분류 6개): 원하는 것 · 싫어하는 것 · 둘이 정한 것 · 날짜·일정 · 서운해한 것 · 관계 양상(결정 9).
  - 지시문 규칙: 판단·점수·진단·성격 규정 금지, "어떤 일이 있었다/이렇게 말했다(요약)" 서술, 항목마다 근거 날짜 1개 이상, 원문 그대로 인용 금지(결정 2), 대화 속 지시문은 따르지 않음(`docs/design/ai-server.md` 4.5와 같은 원칙). 항목 글자 수 상한(예: 300자).
  - AI 답은 믿지 않는 입력으로 검사(분류 6개 밖·날짜 형식 틀림·상한 초과는 버림, `ai-server.md` 4.4).
- **열쇠**: 전용 AI 열쇠와 Edge 입구 비밀값을 노트북의 동기화 안 되는 폴더 설정 파일에. 화면·로그에 출력하지 않음. 저장소·채팅에 붙여 넣지 않음.
- **예약**: 매일 1회(결정 12). 노트북이 꺼져 있던 날은 다음 실행 때 날짜별로 따로 처리.

### 5.2 DB (2단계, 정지 지점)

새 표 2개(이름은 구현 때 확정, 아래는 안):

`app_personal_remember_items`
- `id` uuid, `workspace_id`(소유자 작업공간), `item_key` text(노트북이 만든 고정 번호, 작업공간 안에서 유일 — 같은 항목 두 번 들어오지 않게)
- `category` text — 6개 중 하나(check)
- `topic` text(1~60자), `body` text(1~300자, 지운 항목은 null)
- `said_on` date(대표 날짜), `evidence_dates` date[](1~20개)
- `source` text — `backfill`·`daily`
- `created_at`, `deleted_at`(지웠다는 표시)
- check: 지운 항목은 `body`·`topic` 비움

`app_personal_remember_runs`(정리 기록, 숫자만)
- `run_day` date, `kind`(backfill·daily), `item_count`, `finished_at`. 대화 내용·글자 수 외 정보 없음.

권한:
- RLS 켬, 정책은 소유자 1개(`for all to authenticated using/with check private.app_is_workspace_owner(workspace_id)`).
- `revoke all ... from public, anon, authenticated, service_role` 뒤 `authenticated`에 select·update·delete, `service_role`에 **insert만**(두 표). 소유자 화면은 새로 쓰지 않으므로 `authenticated` insert는 주지 않는다.
- migration은 기존 규칙대로 짝 파일 5개(precheck·snapshot·postcheck·rollback·summary) + `schema_migrations` 기록 1행. 권한 확대 모양이 아니므로 사용자 승인형 DB workflow로 적용 가능(**추정**: 확장 규칙 판정은 구현 PR에서 확인).

### 5.3 Edge `personal-remember-ingest` (3단계, 정지 지점)

- 새 함수, `verify_jwt=false`(로그인 없는 노트북 호출이라), 함수 안에서 `x-personal-remember-secret` 헤더를 새 비밀값과 고정 길이 비교(사실: `drive-summary`의 예약 비밀값 비교와 같은 방식). 틀리면 401, 다른 인증으로 넘어가지 않음.
- 받는 것: 항목 배열(최대 200개/회) + 정리 기록 1개. 키 이름·글자 수·분류·날짜를 서버에서 다시 검사.
- 하는 것: `insert ... on conflict (workspace_id, item_key) do nothing`. 지운 항목(표시만 남은 행)은 같은 번호라 되살아나지 않음.
- 돌려주는 것: `{ok, inserted, skipped}` 숫자만. 항목·주제 목록을 돌려주지 않는다(비밀값이 새도 읽을 수 없음).
- 로그: 실패 코드·건수만. 요청 본문을 기록하지 않음.
- 호출 상한: 하루 몇 번 이상이면 거절(예: 1시간 10회). 소급 분석 날만 넉넉히.
- `docs/web2-env6b-edge-source.md` 5절 표에 새 함수 행 추가(`first_deploy=true`, `verify_jwt=false` 명시).

### 5.4 Web2 개인 공간 화면 (4단계)

- 입구: [계정 ▾] → [개인 기록](결정 7). `?view=remember`(안). `view-loader.js`에서 `profile`처럼 처음 열 때만 모듈을 불러옴. `loadAll`·홈·업무 메뉴·업무 검색에 없음.
- 화면 하나가 그리는 주인(AGENTS §5 한 영역 한 렌더러).
- 보기: 위에 분류 칩(전체·원하는 것·싫어하는 것·둘이 정한 것·날짜·일정·서운해한 것·관계 양상) → 주제별 묶음, 주제 안은 근거 날짜 오래된 것부터(변화 흐름). 맨 위 "마지막 정리: 날짜"(runs 표).
- 검색: 화면에 읽어 온 항목의 주제·요점 글자에서 찾기(화면 안 검색, 노트 검색과 같은 방식). 서버 검색 함수를 새로 만들지 않음.
- 지우기: 항목 ⋯ → [지우기](확인 → 내용 비우고 표시만 남김). 주제 ⋯ → [이 주제 모두 지우기].
- 내보내기: [내보내기] → 지금 항목 전체를 글 파일(주제별)·JSON 중 골라 기기에 저장(브라우저에서 만들어 바로 받기, 서버·Drive 거치지 않음).
- 전체 지우기: [모두 지우기] → 안내("노트북 매일 정리를 먼저 끄세요") → 확인 글자 입력 → 두 표 행 전부 삭제(지운 표시까지). 노트북 원문 지우기는 6절 안내.
- 보안: 소유자 로그인·RLS만 사용. 공유 버튼·링크 없음. 화면 메모리에만 둠.

## 7. 비용 추정 방법 (글자 수 세기만)

- 노트북 세기 스크립트가 출력하는 것: 달별 `메시지 수 · 글자 수`, 전체 합계, 첫 달·마지막 달. 내용·이름·대화방 번호 출력 없음.
- 계산(**추정** 계수, 실제 실행 전 보고서에 다시 적음):
  - 입력 토큰 ≈ 글자 수 × k (한국어 k는 모델·토크나이저마다 다름 — 지어낸 예시 글로 같은 모델 토큰 수를 한 번 재서 k를 정함)
  - 소급 분석 = 원문 입력 토큰 + 지시문(달마다) + 출력 토큰(항목) + 주제 합치기 1~2회
  - 비용 = 토큰 × 그 시점 공식 단가표(문서에 단가를 고정해 쓰지 않음)
  - 시간 = 달 수 × 한 달 분석 시간(지어낸 한 달 분량으로 1회 측정)
- 매일 비용 = 하루 평균 글자 수로 같은 계산 × 30.
- **정지 지점**: 위 표를 명진에게 보고 → 승인 → 소급 분석 실행. 승인 전에는 AI를 한 번도 부르지 않는다.

## 9. 일상어 3줄 (DB·Edge 단계 공용 초안)

- 무엇이 바뀌나: Web2에 "개인 기록" 표 2개와, 노트북이 정리한 요점을 넣기만 하는 입구 하나가 생긴다. 업무 표·화면은 그대로다.
- 잘못되면 어떤 일이 생기나: 입구 비밀값이 새면 누군가 엉뚱한 항목을 넣을 수 있다(읽지는 못함). 표 권한이 잘못되면 다른 로그인 사용자가 볼 수 있으므로 적용 직후 비소유자·비로그인 거절을 확인한다.
- 되돌리는 방법: 비밀값 삭제로 입구를 즉시 닫고, 표는 rollback SQL로 지운다(행이 있으면 먼저 [모두 지우기]).

## 10. 위험·범위 밖 발견사항

- **(추정) 업무 수집기와의 섞임**: 2026-10-20 이후 업무 1:1 대화도 수집 범위에 들어갔다면, 회사 PC 수집기가 대상을 고르는 방식이 허용 목록이 아닐 경우 가족 대화가 이미 업무 Drive `messages/`에 있을 수 있다. 1단계 첫 일로 확인하고, 있으면 업무 Drive에서 지운다(저장소 밖, 명진 PC 작업).
- **(추정) Claude Drive 검색**: 이 프로젝트 Claude에 Drive 검색 연결이 있어 Drive에 둔 개인 파일도 읽힐 수 있다. 원문·내보낸 파일을 Drive에 두지 않는다.
- 노트북 분실·고장: 원문 유일 사본. 디스크 암호화 확인·개인 백업(결정 6).
- AI 회사로 원문이 나감: 분석 요청마다 원문이 AI 회사에 간다. 상대 동의 범위에 이 점이 포함되는지 명진이 한 번 더 확인(사용자 확인 사항, 저장소에 기록하지 않음).
- 같은 텔레그램 계정 로그인 세션 파일이 노트북에 있음: 이 파일이 새면 계정 전체 대화가 샌다. 동기화 폴더 밖·디스크 암호화.
- 범위 밖(고치지 않음, 기록만): `docs/design/mcp-claude-read.md` M8 제외 목록에 "개인 기록 표"를 더해야 함(MCP 구현 때). ME-보관함 설계 시 같은 [계정 ▾] 아래 이웃 칸으로 맞출 것.
- 권한 확대·RLS 약화·anon 권한: 이 설계에 없음. `service_role` 권한은 새 표 INSERT로만 좁힌다.

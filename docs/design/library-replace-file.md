📱 폰 가능. PR 3개(DB → Edge → 화면)로 나눈다. DB·Edge는 적용·배포 직전에 멈춘 상태로 올린다.

- 요청: 2026-10-23 11:48 사용자(요청함). 접수 메모의 추천안 "옛 파일은 Drive에 남기고 [이전 파일 ▾]"을 그대로 진행.
- 바탕: 자료실 ⋯ 메뉴 [정보 수정]을 [수정]으로 바꾸고, 수정 창에서 제목·날짜·종류와 함께 파일 자체도 바꾼다.

## 2. 저장 구조 판단 (DB 필요)

기존 `app_documents`에는 "옛 파일" 기록 칸이 없다. 확인한 것:

- 파일을 가리키는 칸은 `file_id`·`drive_url`·`file_name`·`mime_type`·`file_size` 하나씩뿐이다(이력 구조 없음). `extracted_text` 등 글자 칸은 현재 파일 것 하나만 둔다.
- HWP 편집기의 `hwp-overwrite`는 같은 Drive 파일 번호 안에서 내용을 덮어쓰고 백업을 "Web2 편집 백업" 폴더에 두지만, 그 백업 위치를 자료 행에 적지 않는다(교체 = 새 파일 번호로 바뀌는 이 작업과 다름).
- 옛 파일을 따로 적을 다른 표도 없다(자료 변경 이력 표 없음).

그래서 DB를 바꾼다(첫 PR). 새 표를 만들지 않고 같은 자료 행에 칸 두 개를 더한다:

| 칸 | 모양 | 뜻 |
| --- | --- | --- |
| `previous_files` | jsonb 배열, 기본 `[]`, 최대 50개·64 KiB | 옛 파일 목록(오래된 순). 항목: `file_id`(Drive 번호 모양 검사), `file_name`, `mime_type`, `file_size`, `drive_url`, `replaced_at` |
| `reclassify_needed` | boolean, 기본 false | 파일이 바뀌어 AI 분류를 한 번 다시 해야 한다. 서버가 켜고, 분류가 끝나면 끈다 |

- 권한은 그대로다(기존 소유자 정책 `task12a_owner_all`, anon 없음, grant·정책·함수·트리거 변경 없음).
- 시간 창(올린 지 1시간)에 기대지 않는 이유: 교체한 자료는 대개 오래된 자료라 기존 `fill`(막 올린 자료만)에 해당하지 않고, 창을 닫거나 AI가 바빠도 다음에 자료실을 열 때 한 번 다시 보게 하려면 "해야 함" 표시가 필요하다.

## 3. 서버 (Edge)

- `library-files`(올리기)에 교체 분기를 더한다: 같은 multipart 요청에 `replace_document_id`가 있으면 새 행을 만들지 않고 그 자료의 파일만 바꾼다. 소유자·업무공간은 서버가 DB에서 확인하고, 새 파일은 같은 Drive 자료실 폴더에 올린다. 자료 행 갱신은 "지금 파일 번호가 읽을 때와 같을 때만"(겹친 교체·삭제 방지), 실패하면 방금 올린 새 파일만 정리한다. 옛 파일은 지우지 않는다.
  바꾸는 칸: `file_id`·`drive_url`·`file_name`·`mime_type`·`file_size`, `previous_files`에 옛 파일 한 항목 추가, `reclassify_needed = true`, 글자 칸 비움, `updated_at`. **안 바꾸는 칸**: 제목·분류·출처·날짜·설명·태그·프로젝트·사업 보고·담당조직·칸별 기록·분류 메모.
- `ai-assist` `library_fill`의 `tidy`가 `reclassify_needed`인 자료를 "올린 지 오래됐거나 시도 기록이 있어도" 한 번 다시 보게 한다(규칙은 그대로, 끝나면 표시를 끈다). 새 모드·새 비밀값 없음.
- 옛 파일 열기·내려받기는 Edge 변경이 필요 없다: Drive 파일 번호만 있는 첨부(바구니 등)와 같은 길(`file-actions.js` 내려받기 `uc?export=download`, Drive 보기 주소)을 쓴다.

## 4. 적용 순서와 정지 지점

| 순서 | 무엇 | 방법 | 되돌리기 |
| --- | --- | --- | --- |
| 1 | DB `20261024030000_library_replace_file` | 승인형 `db-migration-apply` mode apply, 사용자 승인 한 번 | `docs/…rollback.sql`(SQL Editor, 화면·Edge 먼저 되돌린 뒤. 교체한 자료가 있으면 멈춤) |
| 2 | Edge `library-files`, `ai-assist` (verify_jwt는 현재 값 유지, 5절 표 기준) | `edge-function-deploy` 함수마다 한 번씩, 사용자 승인 | 각 함수의 배포 전 운영 ref 재배포 |
| 3 | 화면 | Pages(merge = 배포) | revert PR |

- 화면은 DB 칸이 행에 없으면(`previous_files` 없음) [파일 교체]를 보이지 않는다. 그래서 어느 순서로 나가도 깨지지 않는다.
- Edge가 DB보다 먼저 나가면 교체 요청은 서버가 거절한다(칸 없음 → 실패 응답, 파일은 올리지 않음).

## 5. 다른 화면 조사 (보고만, 이번엔 자료실만)

- 담당조직 상세 [자료]·프로젝트 상세 [자료]·사업 보고 자료: 모두 같은 `app_documents` 행을 읽어 줄로 보여 줄 뿐 편집 창이 없다(열기·내려받기·연결 해제 정도). 자료실에서 파일을 교체하면 그 줄들은 자동으로 새 파일을 가리킨다(행의 `file_id`가 바뀌므로). 이 화면들에 따로 교체를 넣을 필요는 없고, 필요하면 자료실 [수정] 창으로 보내는 것이 한 곳 규칙에 맞다.
- 바구니 노트 첨부(`app_notes.attachments`, `basket-files`)·할 일 첨부(Google Tasks 첨부): 자료 행이 아니라 노트·할 일 안의 첨부 목록이라 구조가 다르다(첨부 추가·삭제만). 교체는 "새로 첨부 + 옛 것 삭제"로 이미 가능하다. 같은 Drive 원본을 바구니 첨부와 자료실이 함께 가리키는 자료(`register-basket-attachment`)는 자료실에서 교체하면 자료실만 새 파일을 가리키고 바구니 쪽은 옛 파일을 계속 가리킨다(옛 파일을 지우지 않기 때문에 깨지지는 않는다).
- 성명·보도자료(`press/`)는 별개(PRESS-자료실편입).

## 8. 이전 파일 30일 뒤 자동 정리 (LIB-이전파일정리, 2026-10-27 명진 결정)

- 결정: 교체해서 밀려난 이전 파일은 **교체한 지 30일이 지나면 하루 한 번 Drive 휴지통으로** 옮기고 [이전 파일 ▾]에서 뺀다. 영구 삭제는 없다(Drive가 휴지통을 30일 뒤 스스로 비운다). 줄마다 작은 'N일 뒤 삭제'와 [계속 보관](누르면 '보관', 다시 누르면 해제 — 해제하면 그날부터 새로 30일).
- 대상은 `previous_files` 항목뿐이다. 자료 줄 자체와 지금 쓰는 파일(`file_id`)은 건드리지 않는다.
- DB 변경 없음: 항목(JSON)에 칸을 더한다. `keep_at`(계속 보관 누른 시각)·`unkeep_at`(해제한 시각)·`pruned_at`·`prune_result`(`trashed` 휴지통으로 옮김 | `list_only` 목록에서만 뺌). 기존 모양 검사(`app_documents_previous_files_check`)는 다른 칸을 허용한다. 휴지통으로 옮긴 기록(어느 파일을 언제)이 이 칸들이다. 자료 행의 `updated_at`은 바꾸지 않는다.
- 서버 작업: drive-summary `POST ?action=library_prev_prune[&dry_run=1]`(크론 비밀값만). 매일 GitHub 예약(`.github/workflows/library-prev-prune.yml`, 저장소 변수 `LIBRARY_PREV_PRUNE_ENABLED=true`일 때만)이 부른다. 하룻밤 최대 50개. 첫 실행 전 수동 실행(dry_run 기본 켜짐)으로 개수를 본다.
- 휴지통으로 옮기는 조건: 내 소유 + 자료실 폴더 바로 아래(Web2가 올린 파일) + 다른 기록(다른 자료의 지금·이전 파일, 노트 첨부(앱 휴지통 노트 포함), 할 일 첨부)이 같은 파일을 쓰지 않음. Web2가 올린 파일이 아닌 것(원래 Drive에 있던 파일을 등록한 경우 등)은 Drive를 건드리지 않고 목록에서만 뺀다. 네트워크·서버 오류는 아무것도 바꾸지 않고 다음 날 다시 한다.
- 권한: 기존 Drive 연결(`drive.file`)로 이 앱이 만든 파일만 옮길 수 있다. 권한을 넓히지 않는다.
- [계속 보관]은 library-files의 JSON 요청 `{action:'previous-keep', document_id, file_id, keep}` 로 서버에 저장한다(로컬 저장 없음). 이미 정리된 항목은 보관할 수 없다(Drive 휴지통에서 복원).
- 되돌리기: 휴지통으로 간 파일은 Drive 휴지통에서 복원(30일 안). 자동 작업은 변수를 끄거나 workflow를 끄면 멈춘다. Edge는 이전 ref 재배포.

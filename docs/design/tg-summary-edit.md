# TG-요약고치기 (텔레그램 소식 요약을 명진이 직접 고치기)

요청함 2026-10-27 16:35. 시안은 명진이 보고 승인함.

## 규칙
- 고친 값은 AI 값과 따로 서버에 둔다: `app_feed_summary_edits`(PK workspace_id+target, vals jsonb), 고친 기록 `app_feed_summary_edit_history`(추가만). 쓰기는 `public.app_feed_summary_edit` 하나(소유자 확인, SECURITY DEFINER). 마이그레이션 `20261027200000_tg_summary_edit`.
- AI 값(`app_feed_items.summary`, `app_feed_room_days.parts`)은 고치지도 지우지도 않는다. 다시 요약하거나 채워 넣어도 고친 값을 덮지 못한다(수집기는 새 줄을 넣거나 묶음을 덧붙일 뿐이다).
- target: 소식 한 줄 `item:<id>`(summary), 그날 요약 `day:<방>|<날짜>`(headline = 목록에 보이는 한 줄, lines = 요약 줄).
- [AI 원래 요약으로] = `reset` 으로 고친 값을 비운다. 기록 표에 AI 원본이 남는다.
- 입구: 그날 요약 상자의 ✎(복사 단추 옆), 소식 줄 ⋯ 메뉴의 [요약 고치기]. 고친 것은 제목 옆에 작게 '고침'.
- 고친 값이 보이는 자리: 소식 줄, 고정 띠, 요약 복사, 그날 요약 상자, 방 목록의 한 줄, 보관함·휴지통 줄. 서버에서 이 요약을 읽는 곳은 없다(홈의 텔레그램 숫자는 `app_feed_days`, 원장·주간보고는 텔레그램 요약을 읽지 않음).
- 표를 읽지 못하면(마이그레이션 적용 전) 고치기 입구를 보이지 않는다.

## 아직 손으로 고칠 수 없는 AI 요약 (고치지 않고 조사만)
| 자리 | AI가 쓰는 것 | 손고치기 |
|---|---|---|
| 통화 | 제목·핵심내용 | 가능 (CALL-손고치기) |
| 텔레그램 소식 | 소식 한 줄, 그날 요약 | 이번에 가능 |
| 자료실 | 자료 한두 줄 요약, 요약 칸 | 불가 (자료 칸은 직접 고칠 수 있으나 AI 요약 값과 따로 보관하지 않음) |
| 연결 요약(기록에 연결할 때) | 업무보고형 한 줄 | 연결 상자에서 쓰기 전에 고침 (저장 후 따로 고치는 곳 없음) |
| 산하 조직 현황 요약 | 주간보고 재료 | 불가 |
| 회의 AI 초안 | 결정·정보 | 초안을 열어 고친 뒤 저장하는 방식 |
| 원장 자동·후보·보정 | 요약 칸 | 원장 기록 화면에서 직접 고침 (AI 값과 분리 보관 아님) |
| 문서 색인 요약 | 검색용(화면에 안 보임) | 해당 없음 |

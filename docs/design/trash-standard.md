# TRASH-공통: 휴지통 전수 조사와 공통 디자인 (설계만)

- 상태: 설계(1단계). 코드·DB·Edge 변경 없음. DB·Edge는 제안과 짝 파일 목록만 적는다(AGENTS.md 4·6절).
- 요청(2026-11-27 사용자): "휴지통이 있어야 되는데 없는 곳들도 휴지통 만들어 주고 디자인을 좀 공유해 줘."
- 기준 모양: 노트 휴지통 얇은 줄·[휴지통 비우기](PR #3237 `NOTE-휴지통줄슬림`, `app/note-trash.js`). 이 문서는 그 PR head 위에서 썼다.
- 따르는 장부: `docs/design/standard-interactions.md`(R1·K1·P5·S8·W2·W3), `docs/design-decisions.md`(TRASH-삭제휴지통·TRASH-다른삭제·UI-고르기막대), `docs/design/ui-words.md`(삭제·되돌리기·되살리기).

## 0. 한눈에

1. 서버 휴지통은 따로 된 표가 없다. 표마다 `deleted_at` 칸 + DELETE를 가로채는 트리거 + 숨김 정책(restrictive, authenticated) + RPC 3개(`app_trash_list`·`app_trash_restore`·`app_trash_purge`)다. 지금 종류는 6개: `project`·`organization`·`report`·`library_folder`·`note`(노트·업데이트)·`share_page`. **새 휴지통은 이 틀에 종류를 더하는 것으로만 만든다**(새 휴지통 표·새 저장소 없음).
2. 자동 비움은 없다(DB). 사진(원드라이브)만 Edge가 30일 뒤 원드라이브 휴지통으로 보낸다.
3. 휴지통도 되돌리기도 없이 **확인창 한 번으로 영구 삭제**되는 업무 자료가 남아 있다: 조직 기록·조직 메모·조직 타임라인, 사업 기록 줄, 사업영역 진행 기록·진행상황, 저장한 글(직접 넣은 글), 브리핑. 자료실 자료는 6초 되돌리기 뒤 자료 행(제목·분류·연결·브리핑)이 영구로 지워지고 Drive 원본만 Drive 휴지통에 간다.
4. 화면 휴지통은 5곳인데 줄 모양·단추 이름·비우기 유무가 제각각이다. 노트 휴지통(#3237) 모양을 공용 부품으로 빼서 모두 같은 모양으로 맞춘다.
5. 원본이 Google(일정·할 일)·Drive·원드라이브·폰인 것은 **그쪽 휴지통이 책임**이다. 앱이 사본을 따로 들고 있지 않는다.

## 1. 지울 수 있는 자료 전수 표

결과 뜻: **휴지통** = 앱 서버 휴지통(`deleted_at`, 되살리기 화면 있음) / **영구** = DB 행 바로 삭제 / **숨김** = `hidden_at`·상태 칸 / **바깥 휴지통** = Google·Drive·원드라이브·폰·윈도우 휴지통.
"실수하면" 뜻: ◎ 앱에서 되살림 / ○ 짧은 되돌리기 알림만(알림이 사라지면 끝) / △ 바깥 휴지통에서만 / ✕ 못 되돌림.

## 2. 휴지통이 필요한 곳 — 우선순위와 방식

순서는 **실수 비용이 큰 순**(업무 기록이 다시 못 쓰는 형태로 사라지는가 → 되돌리기 알림조차 없는가 → 얼마나 자주 지우는가). 만드는 순서는 3절 끝의 '바꾸는 양'도 함께 본다.

| 순위 | 대상 | 왜 | 가장 적게 흔드는 방식 |
| --- | --- | --- | --- |
| 1 | **조직 기록·조직 메모·조직 타임라인** | 손으로 쓴 업무 기록, 확인창 한 번 뒤 ✕ | 기존 틀에 종류 `org_record` 하나 더함: 세 표에 `deleted_at` + `*_a_trash_before_delete` 트리거 + `*_trash_hidden` 정책, `app_trash_list/restore/purge`에 분기. 화면 삭제 호출(REST DELETE)은 그대로 — 트리거가 휴지통으로 바꾼다(노트와 같은 길). 되살리기 때 그 조직이 휴지통이면 `TRASH_PARENT_IN_TRASH`로 거절 |
| 2 | **사업 기록 줄·사업영역 진행 기록·진행상황** | 같은 이유(사업 쪽) | 종류 `project_record` 하나로 세 표를 묶음. 방식은 1과 같음. 사업영역이 휴지통이면 되살리기 거절 |
| 3 | **자료실 자료**(자료까지 삭제 포함) | 제목·분류·연결·브리핑·AI 요약이 한꺼번에 사라짐, Drive에 파일만 남음 | 종류 `document`. 휴지통으로 옮길 때 Drive 원본은 **건드리지 않고**, 영구 삭제(또는 자동 비움) 때 지금처럼 Drive 휴지통으로 보냄. 6초 되돌리기는 그대로(그 뒤는 휴지통). **주의: `app_documents`를 읽는 Edge 함수가 33곳**이라(service_role은 숨김 정책을 건너뜀) 각 함수에 `deleted_at is null` 거르기를 전수로 더해야 한다 → 별도 설계·여러 PR |
| 4 | **저장한 글(직접 넣은 글)** | 직접 모은 글, ✕ | 종류 `reading`(`app_reading_items` 하나, Edge 1곳). 방식은 1과 같음 |
| 5 | **브리핑만 삭제** | AI로 다시 만들 수는 있으나 비용 | 휴지통 대신 K1처럼 **되돌리기 알림 + 알림이 닫힐 때 서버 삭제**(하루 기록과 같은 길). DB 변경 없음 |
| 6 | **할 일: 수정 창·다른 화면 줄 ⋯ 삭제** | Google에 휴지통이 없어 ✕ | 앱 휴지통은 만들지 않는다(원본 Google). 목록과 같은 `queueDelete` 5초 '삭제 대기 [되돌리기]'를 모든 삭제 길에 쓰게 맞춤. DB·Edge 변경 없음 |
| 7 | **통화 기록 숨김**(운영자만) | 되돌리기 알림이 사라지면 볼 길 없음 | 새 칸 없이 기존 `hidden_at`을 쓰는 '숨긴 통화 N' 선반(텔레그램 휴지통 선반과 같은 모양). DB 변경 없음(읽기 조건만, RLS 그대로) |
| 8 | 노트 폴더·뉴스 폴더·사진 앨범·노트 보드·설정 값 | 안의 자료는 남음, 묶음만 잃음 | 휴지통 만들지 않음. 확인창이 있는 것 중 되돌릴 수 있는 것은 K1 되돌리기 알림으로(노트 폴더처럼) |
| — | 일기·업무일지 | 하루 1행 고유 색인 | 지금 그대로(되돌리기 알림 → 닫힐 때 삭제) |
| — | 일정·Drive·원드라이브·폰·PC | 원본이 바깥 | 바깥 휴지통 그대로. 앱 휴지통·사본 없음. 확인창에 '되돌리기는 ○○ 휴지통에서' 한 줄(지금 [파일]과 같은 글) |

같이 고칠 작은 어긋남(새 휴지통 아님, 모양 맞추기 PR에서):

- 업데이트는 사업 관리 탭에서만 되살릴 수 있다 → 업데이트 화면 ⋯에도 '휴지통 N' 입구(같은 `note` 종류, `note_kind 'basket'`만 거름).
- 텔레그램 휴지통 안내 "직접 비우기 전까지 남아요" → 비우기를 넣거나 글을 "되살리기 전까지 남아요"로(서버에 영구 삭제 함수가 없으므로 글을 고치는 쪽이 작음).
- 사진 [바로 삭제]는 실제로는 원드라이브 휴지통으로 보냄 → 이름을 '원드라이브 휴지통으로'로.
- 되살리기 이름: 보관 탭 '복구'·조직·텔레그램 '꺼내기'는 **보관에서 꺼내기**라 그대로, 휴지통에서는 모두 '되살리기'(ui-words.md).

### 2-1. DB 쪽 제안(이 PR은 적용하지 않음, 짝 파일 목록만)

종류 하나를 더하는 migration마다 `docs/ops-db-workflow.md` 짝 파일 5개(적용·rollback·snapshot·사전 확인·사후 확인)를 둔다. 확장 규칙에 걸리지 않게:

- 새 정책은 **restrictive + authenticated + `deleted_at is null`** 뿐(권한을 넓히지 않음). anon·PUBLIC 권한 없음.
- RPC 3개는 기존 정의를 `create or replace`로 분기만 더함(SECURITY DEFINER·`search_path=''`·`private.app_is_workspace_owner` 그대로, 실행 권한 authenticated만).
- 그 표를 service_role로 읽는 Edge 함수에 거르기를 더하는 PR이 **DB 적용보다 먼저** 배포돼야 한다(Expand → Deploy → Verify 순서).
- 비우기용 `app_trash_purge_all(p_kind)`는 선택 사항: 지금처럼 줄마다 `app_trash_purge`를 불러도 서버가 줄마다 주인을 다시 확인하므로 안전하다. 몇백 개가 넘을 때만 더한다.
- 자동 비움(4-5절, 결정 시): cron 한 개 `web2_trash_auto_purge`(고정 이름, 하루 한 번), 명령은 `private` 함수 하나를 부르는 것뿐이고 그 함수는 `deleted_at < now() - interval 'N days'`인 행만 지운다. 이미 휴지통인 행이라 트리거가 실제 삭제를 통과시킨다. 공유 페이지는 파일이 남아 있으면 건너뜀(Edge가 파일을 먼저 지워야 함). 자료실 자료는 Drive 휴지통 보내기가 필요하므로 SQL이 아니라 Edge 예약으로 따로.

## 3. 휴지통 공통 디자인

### 3-1. 들어가는 길

- **그 자료를 쓰는 화면 안**에 입구를 하나 둔다. 새 메뉴·새 창을 만들지 않는다.
  - 폴더 나무가 있는 화면(노트·자료실·사진): 나무(폰은 첫 화면 폴더 상자) **맨 아래 '휴지통 N' 줄** — 공용 `ftTrashRowHtml`(#3237 노트와 같음).
  - 나무가 없는 화면(조직 관리·사업 관리 상세·저장한 글·업데이트·텔레그램·통화): 그 화면 머리 **⋯ 메뉴 맨 아래 '휴지통 N'**. 건수가 0이면 줄 글자를 흐리게(숨기지 않음 — 빈 휴지통도 열 수 있어야 '없음'을 확인).
- 사업 관리 › 사업영역 관리 › 보관 창 [휴지통] 탭은 지금처럼 **여러 종류 모아 보기**로 남긴다(이미 쓰는 길). 같은 서버 목록(`app_trash_list`)을 읽는 보기 두 개일 뿐 상태 주인은 서버 하나다.
- 바깥 휴지통(일정·Drive·원드라이브)은 입구 줄 대신 지금 [파일] 휴지통 시트·확인창 안내 한 줄 그대로.

### 3-2. 머리(한 줄)

`[휴지통 그림] 휴지통  N            [휴지통 비우기]`

- 건수 N은 그 휴지통 줄 수(바깥 휴지통은 표시하지 않음 — 모르는 수를 쓰지 않는다).
- [휴지통 비우기]: 테두리·바탕 없는 작은 글자 단추(`row-act`), 글자색만 경고색. PC는 건수 옆 오른쪽 끝, 폰은 목록 맨 위 오른쪽(#3237과 같음). 줄이 0이면 단추 없음.
- 자동 비움을 정하면 머리 아래 작은 회색 한 줄: '30일 지나면 저절로 지워져요'(정하지 않으면 줄 없음 — 지금 사업 관리 탭의 "자동으로 비우지 않으며…" 긴 글은 지움).

### 3-3. 줄 모양(#3237 기준)

- 높이 44px 이하 한 줄: **이름**(없으면 본문 앞부분·'제목 없음') · 작은 회색 **지운 날짜** · (모아 보기에서만) 종류 작은 글자('노트'·'사업 보고'…) · (있으면) '하위 N개'.
- 오른쪽: 테두리 없는 작은 글자 **[되살리기]** + **⋯**(보이는 크기 32px, 누르는 범위 44px). ⋯ 안: **[영구 삭제]**(경고색). PC 우클릭 = 그 줄 ⋯ 열기(공용 `context-menu.js`).
- 폰 왼쪽 밀기: **[되살리기][영구 삭제]** 칸만 열림(P5 — 끝까지 밀어도 바로 하지 않음). 오른쪽 밀기: 그 줄 고르기(W3).
- 고르기 막대(S8 한 줄): [전체 선택] · [되살리기] · (결정 시) 맨 끝 경고색 [영구 삭제].
- 위가 휴지통인 줄(하위 사업영역·하위 폴더·조직이 지워진 기록): [되살리기] 잠김 + 날짜 자리에 '위 항목을 먼저 되살려 주세요'.
- 크고 굵은 단추·카드·테두리 단추(`mini`)·네모 ⋯(`icon-btn` 테두리)를 쓰지 않는다.

- 일기·업무일지(하루 1행)를 휴지통에 넣지 않는다.

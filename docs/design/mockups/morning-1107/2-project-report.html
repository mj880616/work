2. 프로젝트를 사업 보고로 합치기

합치기 1~3단계는 이미 운영에 들어가 있다(프로젝트 메뉴 없앰, 사업 보고에 사업영역 꼬리표·다음 할 일, 사업영역 관리 창). 남은 것은 옛 이름 표시와 마지막 정리 두 가지다.

지금 어디까지 됐나 (조사한 사실)
  • 1단계 DB(사업 보고에 꼬리표·다음 할 일 칸) 10/28 운영 적용, 2·3단계 화면 #1402·#1411·#1436·#1502·#1523 merge.
  • 옛 프로젝트 표를 그대로 사업영역 표로 씀 → 옛 프로젝트 이름은 사업영역 이름으로 이미 그대로 남아 있음. 옛 진행 기록은 지우지 않고 보존(화면에서는 안 보임, 10/28 결정 ⑥).
  • 아직 남은 것: 자료실 안 '프로젝트' 글자(폴더 틀 이름), 4단계 정리(옛 진행 기록을 읽는 코드 걷기 — 설계상 "몇 주 써 본 뒤").
  • A안·정리·글자 바꾸기는 DB 변경 없음. B안만 사업영역 표에 '옛 이름' 칸 하나가 필요(DB 한 번, 시험 적용 먼저). 설계 메모: docs/design/project-into-report.md 15절.

명진이 고를 것

  1. 옛 프로젝트 이름을 어디에 남길지 — A: 지금처럼 사업영역 이름 그 자체(따로 표시 없음) / B: 이름을 바꾼 사업영역은 관리 창에 흐리게 "(옛 이름: …)" 한 줄. 추천 A
  2. 마지막 정리(옛 진행 기록 읽는 코드 걷기) — ㅇ: 이번 주에 정리 / ㄴ: 몇 주 더 두고 보기. 추천 ㄴ(옛 주 보고서가 달라질 수 있어 대조표 먼저)
  3. 자료실 폴더 틀 '프로젝트' 글자 → '사업영역' — ㅇ/ㄴ. 추천 ㅇ

답 예: "1 A, 2 ㄴ, 3 ㅇ"

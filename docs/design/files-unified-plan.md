## 0. 한눈 요약

1. 지금 [파일]은 "원드라이브·구글 드라이브를 서버 목록(색인)으로 보는 탐색기"까지 와 있다. 폰 저장 공간은 [사진]에서 사진·동영상만 닿고, 파일 전체에는 닿지 않는다.
2. [최근]이 '불러오지 못했습니다'인 것은 **[최근]을 읽는 서버 함수가 내 파일 전체를 한 줄씩 권한 검사·정렬하다 시간 제한(8초 [추정])에 걸린 것**으로 본다(A-4). 폴더 보기는 한 폴더만 읽어 빨라서 된다.
3. 목표 화면: 맨 위 줄에 **저장소 아이콘 3개(원드라이브·구글 드라이브·이 폰)** 를 켜고 끄고, 폴더 나무는 세 저장소를 탐색기처럼 맨 위 줄로 나란히. 폴드를 펼치거나 PC에서는 **두 칸**으로 열어 왼쪽→오른쪽으로 복사·옮기기.
4. 복사·옮기기는 한 흐름: 고르기 → [복사]/[옮기기] → 받을 곳 → 아래쪽 **전송 줄**(진행) → 끝 알림. 같은 이름·실패·큰 파일 처리는 한 군데(전송 목록)에서.
5. 폰 저장 공간은 **명진이 고른 폴더만** 앱이 읽고 쓰는 방식(안드로이드 '폴더 열기 허락')으로. '모든 파일 접근' 권한은 쓰지 않는 쪽을 추천(E절).
6. 단계: 1단계 [최근] 고침 + 출처 켜고 끄기·세 저장소 나무(S49-21 그대로 씀) → 2단계 복사·두 칸·전송 목록 → 3단계 폰 저장 공간(폰 앱 새 판).

### A-4. [최근]이 '불러오지 못했습니다'가 되는 길 (추정 원인 — 고치지 않음)

코드 길 [사실]:

1. 폰 첫 화면은 [최근](F9) → `setWhere({shelf:'recent'})` → `loadList()`.
2. `loadList`가 `rpc('app_cloud_find', {p_query:null, p_shelf:'recent', p_limit:200})`를 부른다(`app/files.js` 122줄).
3. 실패하면 `state.failed = codeOf(e)` → `paintList`가 `failHtml({retry, text: errorText(code)})`. `errorText`는 아는 코드(권한·연결·바쁨·없음)가 아니면 모두 **'불러오지 못했습니다'** 를 낸다(`files-model.mjs` 270~279줄). 실패 까닭 글자(`reason`)는 넘기지 않아 화면에서는 이유가 안 보인다.

`app_cloud_find`의 [최근] 길이 무거운 까닭 [사실 + 추정]:

- 작업공간을 칸으로 걸러 주지 않는다. 걸러 주는 것은 표의 읽기 규칙(RLS)인데, 그 규칙은 줄마다 `private.app_is_workspace_owner(...)`·`private.app_workspace_has_feature(...)` 두 함수를 부른다. 그래서 `(workspace_id, modified_at desc)` 색인을 못 타고 **내 파일 전체(수만~수십만 줄 [추정])를 한 줄씩 함수 검사 → 전부 정렬 → 200줄** 이 된다.
- 같은 단계에서 줄마다 별표 확인과 `app_documents` 짝 찾기(lateral)를 정렬 **전에** 다 계산할 수 있다. `app_documents(workspace_id, file_id)` 색인은 저장소 migration에서 찾지 못했다 [사실: 검색 결과 없음 / 운영 색인 여부는 추정].
- 로그인 사용자의 DB 시간 제한(Supabase 기본 8초 [추정]) 또는 화면 요청 제한(15초, `runtime-client.js`)에 걸리면 실패 → 위 3번 문구.
- 폴더 보기(`app_cloud_list`)는 `(workspace_id, source, parent_id)` 한 폴더만 읽고 5000줄 상한이라 같은 권한 검사를 해도 빨리 끝난다 → "폴더는 되는데 최근만 안 됨"과 맞다.

다른 가능성(덜 유력): 구글 드라이브 처음 훑기가 끝나지 않아 색인이 크게 늘던 중 / `files` 기능 행이 없어 403(이 경우는 '쓰지 않는 기능입니다'가 나와야 하므로 아님).

CC가 운영에서 확인할 것(읽기만):

1. Supabase 로그(Postgres)에서 `statement timeout` + `app_cloud_find` 찾기, API 로그에서 `/rpc/app_cloud_find`의 상태(500/408 등)와 걸린 시간.
2. SQL Editor(select만): `select source, count(*), count(*) filter (where trashed) from public.app_cloud_items group by source;` — 줄 수 규모.
3. `select source, index_done_at, synced_at, last_error, next_page is not null as more from public.app_cloud_sync;` — 구글 훑기가 끝났는지, 오류 코드.
4. `select indexname, indexdef from pg_indexes where tablename = 'app_documents';` — `file_id` 색인 여부.
5. (선택) `explain` — 로그인 역할로 바꿔 보기는 SQL Editor에서 번거로우므로 1·2로 충분.

고치는 방향(1단계 PR에서): [최근]·[큰 파일]·[별표] 묶음은 "내 작업공간 id를 먼저 한 번 구해 칸으로 거른 뒤 색인 순서대로 200줄만 → 그 200줄에만 경로·별표·자료실 표시"로 다시 쓴다. 권한 경계(owner + `files`)는 그대로, 함수 안 첫 줄에서 한 번만 검사. 화면은 실패 까닭 코드를 작은 글자로 붙인다(`failHtml`의 `reason`, 이미 있는 부품).

### A-5. 구글 드라이브가 보이는 조건 [사실]

`cloud-files`의 `status`에서 구글은 다음이 모두 맞아야 '연결됨'이다: ① 로그인 ② 그 사람이 작업공간 주인 ③ 로그인 토큰으로 본 `app_my_features()`에 `files` ④ `files`가 허용된 **단 하나의** 작업공간 = Drive 연결 작업공간(운영자 작업공간) ⑤ 프로젝트 전체 Drive 설정(`public_policy_drive_config` id=1)에 갱신 토큰이 있음. 하나라도 어긋나면 화면엔 원드라이브만 보인다(오류 없이). 명진 말 "기본적으로 OneDrive만"은 ④·⑤ 또는 구글 첫 훑기 미완 [추정] — 위 확인 3번 결과와 `status` 응답의 `gd.connected`로 CC가 판정.

### A-6. 폰 앱이 폰 저장 공간에 닿는 범위 [사실]

- 폰 앱 `android-app`(현재 0.4.15, versionCode 55). 권한: `READ_MEDIA_IMAGES`·`READ_MEDIA_VIDEO`·부분 허용·`ACCESS_MEDIA_LOCATION`·`MANAGE_MEDIA`(지울 때 묻지 않기)·옛 기기 `READ_EXTERNAL_STORAGE`(32까지).
- `PhoneMedia.kt`: 화면이 `__phone/<열쇠>/…`를 부르면 앱이 **사진첩(MediaStore) 사진·동영상**만 읽어 답한다. 사진첩 안 폴더 옮기기·휴지통·편집 저장까지 된다. 목록은 메모리 30초, 서버로 보내지 않음.
- 그 밖: 파일 고르기 창(`onShowFileChooser`)으로 한 번씩 올리기, 공유 받기·보내기(`ShareOut`).
- **없는 것**: 문서·HWP·PDF·음성 같은 일반 파일 폴더 읽기, 폴더 나무, 폰으로 받기 폴더 지정. 즉 '폰 저장 공간 = 사진첩'까지만.

## B. 목적

원드라이브 · 구글 드라이브 · 이 폰 저장 공간을 **한 화면**에서 보고, 서로 **복사·옮기기**. 그 밖에 이름 바꾸기 · 지우기(휴지통) · 새 폴더 · 올리기 · 받기 · 공유(폰 공유 창) · 미리보기.

성공 기준(명진 눈으로): ① 들어가면 바로 최근 파일이 뜬다(3초 안). ② 세 저장소가 한 나무에 다 보인다. ③ 폰 파일을 원드라이브로, 원드라이브 파일을 구글로 '고르고 두 번 누르기'로 보낸다. ④ 진행과 끝이 눈에 보이고, 실패하면 원본은 그대로.

## D. 화면 구성안 (시안 참고)

### D-1. 공통 부품

- **저장소 아이콘 줄**: 위 줄 오른쪽 작은 아이콘 3개 `[원드라이브][구글 드라이브][이 폰]`. 사진 화면 출처 아이콘과 같은 부품(`source-chips.css`·`od-link.js`, S49-21이 이미 [파일]에 붙임). 누르면 켜고 끄기, 연결 안 된 것은 흐리게 + 누르면 연결 안내 한 줄. '이 폰'은 폰 앱에서만 보인다.
- **나무**: 맨 위 묶음 [최근][별표] → 줄 하나 띄고 켜진 저장소 3개가 맨 위 줄(▸ 펼치기). 각 저장소 뿌리 옆에 작게 '맞춤 3분 전'. 폰 저장 공간은 명진이 허락한 폴더들이 그 아래 줄(예: 문서, 받은 파일)과 맨 끝 '+ 폴더 허락'.
- **줄**: `[종류 아이콘] 이름 …… 출처 점 · 바뀐 날 · 크기`. 출처 점은 [최근]·[별표]·찾기처럼 섞어 보일 때만.
- **고른 것 막대**(고르면 위 줄 자리를 바꿈): `3개 · [복사] [옮기기] [이름] [휴지통] [⋯] ✕`.
- **전송 줄**(하단바 바로 위, 얇게): `↗ 2/5 보내는 중 · 48% ▸` — 누르면 전송 목록 창(하단바 위로 열림). 다 끝나면 '5개 보냄 · 1개 실패 [보기]' 알림 후 사라짐.

### D-2. 폰 접힘(412, 한 칸)

1. **최근**(첫 화면, F9 그대로): 위 줄(찾기 칸 + 저장소 아이콘 3개), 종류 칩 한 줄, 날짜 묶음('오늘·어제·이번 주') 줄 목록. 세 저장소가 섞이고 줄마다 출처 점.
2. **폴더**: 세 저장소 나무(한 화면, S49-21과 같음). 폴더 이름 누르면 그 폴더 목록, 맨 위 ‹ 나 뒤로가기로 나무.
3. **고르기**: 꾹 누르기로 고르기 시작 → 위 막대로 바뀜. 동작 이름은 글자 버튼.
4. **받을 곳 고르기**: [복사] 누르면 아래에서 반쯤 올라오는 창(하단바 위). 같은 나무, 맨 위에 '최근 보낸 곳' 3개. 폴더를 열고 [여기에 복사]. 같은 이름이 있으면 한 번만 묻기.
5. **전송**: 하단바 위 전송 줄 → 누르면 전송 목록(파일별 진행·실패 까닭·[다시]).

좌우 밀기: [최근] ↔ [폴더] ↔ [별표]. 뒤로가기: 받을 곳 창 → 고르기 풀기 → 위 폴더 → 나무 → 이전 화면 순.

### D-3. 폴드 펼침(884, 두 칸)

- 기본은 **두 칸**: 왼쪽·오른쪽이 각자 위치 줄을 가진 목록. 나무는 각 칸 위치 줄의 ▾(누르면 나무가 그 칸 위로 내려옴)로 대신해 폭을 아낀다.
- 왼쪽에서 고르면 막대가 `[→ 오른쪽에 복사] [→ 옮기기]`로 바뀐다(받을 곳 = 반대 칸의 지금 폴더, 따로 고르지 않음). 끌어서 반대 칸에 놓아도 된다(놓을 때 '복사/옮기기' 작은 고르기).
- 지금 칸은 위 줄 테두리 색으로 표시. 칸을 누르면 그 칸이 '지금 칸'.
- 한 칸으로 쓰고 싶으면 위 줄 [두 칸] 끄기(서버 화면 설정에 기억).

### D-4. PC(1440)

- 기본: 나무(240) · 목록 · 미리보기(320) — 지금 구조 그대로.
- [두 칸] 켜면: 나무(220) · 왼쪽 목록 · 오른쪽 목록(미리보기는 Space로 덮는 칸). 단축키 F5 반대 칸에 복사, F6 옮기기, Ctrl+C/X/V, Tab 칸 바꾸기.
- 바탕화면(윈도 탐색기)에서 파일을 끌어 놓으면 그 폴더로 올리기(⑥). 목록에서 바탕화면으로 끌어 받기는 브라우저 한계로 **안 됨** → [받기].
- 전송 목록은 오른쪽 아래 작은 칸(접기).

### D-5. 복사·옮기기 흐름

```
고르기(여러 개) → [복사]/[옮기기] → 받을 곳(폴드·PC 두 칸이면 반대 칸, 아니면 받을 곳 창)
 → 같은 이름 검사(한 번에 묻기) → 전송 목록에 줄 추가 → 하나씩/조금씩 동시에 보냄 → 끝 알림
```

| 경우 | 누가 옮기나 | 방법 |
| --- | --- | --- |
| 같은 클라우드 안 옮기기 | 클라우드 자체 | 부모 바꾸기(있음, 빠름) |
| 같은 클라우드 안 복사 | 클라우드 자체 | 원드라이브 copy(뒤에서 진행, 끝나길 기다림)·구글 files.copy — 새 action |
| 원드라이브 ↔ 구글 | 서버(Edge) | 받으며 보내기(있는 `across`를 **복사 겸용**으로) + 큰 파일은 조각 이어 보내기를 서버 작업표로 여러 번에 나눠(2단계) |
| 폰 → 클라우드 | 폰 앱 | 서버가 '이어 올리기 자리'만 열어 주고, 앱이 파일을 조각으로 직접 보냄(앱 안 네트워크라 브라우저 CORS 걱정 없음) |
| 클라우드 → 폰 | 폰 앱 | 서버 중계(`media`)로 받아 앱이 허락된 폴더에 씀 |
| 폰 ↔ 폰 | 폰 앱 | 허락된 폴더 사이 복사·옮기기 |

- **옮기기 = 복사 확인 뒤 원본 휴지통**(지금 `across` 규칙 그대로: 크기·해시가 맞을 때만). 폰 원본은 폰 휴지통(안드로이드 11+ 휴지통 [추정 — SAF 문서는 휴지통이 없을 수 있어 그때는 '옮기기' 대신 '복사 후 원본 남김' 안내]).
- **같은 이름**: 한 번에 묻기 `[둘 다 두기(이름 (2))] [건너뛰기] [바꾸기(옛것은 휴지통)]` + '남은 것 모두 같게'. 기본 선택은 둘 다 두기.
- **큰 파일**: 200MB 넘으면 2단계 작업표로 이어 보내기. 1개 상한은 결정 H-4.
- **실패**: 줄마다 까닭 한 줄(연결 끊김·공간 부족·이름 규칙·너무 큼) + [다시]. 원본은 손대지 않는다.
- **폴더 통째**: 같은 클라우드 안은 클라우드가 해 줌. 다른 저장소로는 결정 H-5.

### D-6. 최근·별표·찾기를 세 저장소 함께

- 클라우드 둘은 서버 색인에서 한 번에(켜진 출처만 **서버가 거름** — 지금 S49-21은 받은 200줄을 화면에서 거르므로 원드라이브 줄이 많으면 구글 줄이 묻힐 수 있다).
- 이 폰은 앱이 그 자리에서 읽은 목록(메모리만)을 화면이 바뀐 날 순으로 섞는다. 폰 파일 목록은 서버로 보내지 않는다.
- 별표: 클라우드는 `app_cloud_stars`(있음). 폰 파일 별표는 폰마다 다르므로 **두지 않음**(별표가 필요하면 클라우드로 복사).

## E. 폰 저장 공간

### E-1. 안전한 방법: 고른 폴더만 허락(Storage Access Framework)

- 앱이 안드로이드 '폴더 열기' 창을 띄우고, 명진이 고른 폴더(예: 문서, 받은 파일 하위 폴더)만 계속 읽고 쓸 수 있게 허락을 받는다(앱을 지우거나 [허락 끊기] 전까지 유지).
- 장점: 고른 곳 밖은 못 봄 → 화면 코드에 문제가 생겨도 폰 전체가 열리지 않음. 별도 위험 권한 없음.
- 한계 [사실: 안드로이드 11부터의 규칙]: **내부 저장소 맨 위, '다운로드(Download)' 폴더 자체, Android/data** 는 고를 수 없다(그 안 하위 폴더는 됨). 다운로드에 바로 쌓인 파일은 이 방식으로 못 본다.
- 보완: 사진·동영상은 지금처럼 사진첩(MediaStore) 권한으로, 앱이 받은 파일은 `다운로드/Web2` 폴더(앱이 만든 파일은 권한 없이 됨)에 둔다.

### E-2. '모든 파일 접근' 권한(MANAGE_EXTERNAL_STORAGE)

- 폰 전체(다운로드 포함)를 읽고 쓸 수 있다. 우리 앱은 플레이 스토어 밖 설치라 스토어 심사 제한은 없다 [추정].
- 그러나 앱 화면은 웹(WebView)이고, 화면 코드가 폰 전체에 닿는 다리를 갖게 된다 → 화면 쪽 취약점 하나가 폰 전체 노출로 이어진다. **추천하지 않음**(H-1).

### E-3. 폰 앱 새 판 범위(3단계)

1. 새 다리 `__phone/<열쇠>/files/…`(지금 `PhoneMedia`와 같은 열쇠·Origin 검사): 허락 폴더 목록, 폴더 안 목록, 썸네일, 원본 읽기, 쓰기(조각), 이름·새 폴더·휴지통.
2. 폴더 허락 받기/끊기 창.
3. 전송 일꾼: 앱이 화면이 꺼져도 이어 보내도록 안드로이드 '포그라운드 작업'(알림줄에 진행 표시). 클라우드 이어 올리기 주소는 서버가 열어 주고 앱은 그 주소로만 보냄(토큰은 앱에 없음).
4. 로그에 파일 이름 안 남김, 목록 서버 전송 없음(지금 원칙 그대로).
- 판: 0.5.0(새 권한은 없음, 기능 추가). 설치·실기기 확인은 명진.

### E-4. 웹(브라우저)에서 안 되는 것

- 삼성 인터넷·크롬 웹에서는 폰 저장 공간 폴더를 볼 수 없다. '이 폰' 아이콘은 폰 앱에서만 보인다.
- 웹에서 되는 것: 파일 하나씩 올리기(고르기 창·끌어 놓기), 받기(다운로드 폴더로), 공유 창.
- PC 크롬의 '폴더 열기'(File System Access)는 삼성 인터넷에 없고 탭을 닫으면 끊겨 이번 범위에서 뺀다. PC 폴더가 필요하면 바구니 PC 앱 쪽에서 나중에 따로.

## F. 보안·구조 원칙

- **권한 경계 그대로**: 운영자 기능 `files`(서버 허용표) · 작업공간 주인 검사 · 구글은 Drive 연결 작업공간만 · 토큰은 서버에만. 화면 숨김을 권한으로 쓰지 않는다.
- **넣지 않는 것**(files-explorer.md 3절 그대로): 영구 삭제, 휴지통 비우기, 외부 공유 링크·권한 만들기, 소유자 바꾸기.
- **서버 저장**: 출처 켜고 끄기·두 칸 켬·최근 보낸 곳·클라우드 전송 작업은 서버. 화면 메모리는 열린 동안만. 단, 폰 파일 목록·폰 전송 진행은 그 폰의 것이라 앱 메모리(서버로 내보내지 않는 것이 개인정보에 더 안전).
- **쓰기는 사람이 누른 것만**(`confirm:true`), 자동·예약 쓰기 없음. 클라우드 전송 작업표의 이어 하기도 사람이 시작한 작업만.
- **땜질 금지**: 출처 거르기를 화면에서 덮어 거르지 말고 서버 함수에서. 실패 문구를 바꾸는 대신 실패 원인(느린 함수)을 고친다.

### J-1. 200MB 넘는 파일이 옮겨지는 방식(명진 설명용)

- 클라우드 → 클라우드(원드라이브↔구글): 폰·노트북을 거치지 않고 **서버가 원래 클라우드에서 10MB씩 받아 받을 클라우드의 '이어 올리기 자리'(원드라이브 upload session·구글 resumable upload)에 차례로 붙인다.** 서버 한 번 실행 시간이 짧아서(수 분) 일감을 '몇 조각까지 했는지' 작업표에 적어 두고 다음 실행이 그 뒤부터 잇는다. 중간에 끊겨도 처음부터가 아니라 끊긴 조각부터. 다 붙인 뒤 크기·지문(해시)으로 같은지 확인하고 끝 알림. 폰 데이터는 쓰지 않는다. 1GB에 대략 몇 분~십여 분 [추정].
- 폰 → 클라우드: 서버가 '이어 올리기 자리'만 열어 주고 **폰 앱이 그 자리로 조각을 직접 올린다**(파일이 서버를 거치지 않음, 폰 데이터 사용 — 와이파이 권장 안내). 화면이 꺼져도 알림줄 작업으로 계속.
- 노트북 → 클라우드(올리기): 브라우저가 조각으로 올리고, 화면을 닫으면 일시 정지, 다시 열면 남은 조각부터.

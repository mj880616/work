## 명진이 정할 것

### 결정 1. 글 속에서 챙길 것을 누가 찾을까 (1단계)

| 선택지 | 내용 |
| --- | --- |
| ① 복사 → ChatGPT → 붙여넣기 (**추천**) | [챙길 것 찾기 복사]를 누르면 새 재료와 요청문이 복사됨 → ChatGPT에 붙여 넣음 → 답을 Web2 [찾은 결과 넣기]에 붙여 넣음. 바구니 [AI에게 맡기기]와 같은 방식 |
| ② Web2가 직접 AI 호출 | 버튼 하나로 끝. 대신 서버 함수 + OpenAI 키 등록(운영 비밀값, 승인 단계)이 필요하고 글이 OpenAI API로 감 |
| ③ AI 없이 낱말로 찾기 | "까지", "부탁", "회신" 같은 낱말·날짜를 찾음. 비용 0원이지만 놓치는 것·헛잡는 것이 많음 |

추천 이유: 추가 비용·키·서버가 없고, 이미 쓰는 바구니 흐름과 손에 익은 순서가 같다. 써 보고 매일 누르는 게 번거로우면 BASKET-AI자동정리에서 OpenAI 키를 등록할 때 ②로 바꾼다(찾은 결과 형식이 같아서 확인 화면은 그대로 씀).

### 결정 2. 텔레그램·통화 전사는 어떻게 들여올까 (2단계)

| 선택지 | 내용 |
| --- | --- |
| ① Web2가 Drive 폴더를 직접 읽기 | 지금 Web2의 Drive 권한(`drive.file`)으론 **Web2가 만들지 않은 파일을 못 읽음**. 넓은 읽기 권한(Google "제한" 등급)을 새로 받아야 함 → 권한 확대라 후보에서 뺌 |
| ② 예약 ChatGPT가 매일 Drive를 읽고 "챙길 것 후보"를 정해진 형식으로 써 둠 → 명진이 복사해 Web2에 붙여넣기 (**추천**) | 예약 ChatGPT는 이미 이 폴더들을 읽고 있음(사용자 설명). Web2 쪽은 1단계의 [찾은 결과 넣기]를 그대로 씀. 새 권한·서버 없음 |
| ③ Web2에 "받기 전용 입구"(서버 함수 + 전용 비밀값)를 만들고 예약 AI가 직접 보냄 | 손이 안 가지만 새 서버 함수(승인 단계)와, 예약 AI 쪽에 비밀값을 맡겨야 함. ChatGPT 예약이 이런 호출을 할 수 있는지는 확인 안 됨(추정: 어려움) |

추천 이유: 이미 도는 예약 정리를 재활용하고 권한을 넓히지 않는다. ③은 ②를 몇 주 써 본 뒤 "붙여넣기가 정말 번거롭다"면 따로 판단(비밀값을 어디에 맡길지가 핵심 위험).

### 결정 3. 찾은 후보를 저장할까

| 선택지 | 내용 |
| --- | --- |
| ① 저장 안 함 | 붙여 넣은 그 자리에서 바로 [할 일로]/[무시]. 바구니 분류 확인 화면과 같음. DB 변경 없음. 대신 홈에 계속 띄워 둘 수 없고, 나중에 처리할 수 없음 |
| ② 후보만 담는 작은 표를 새로 만듦 (**추천**) | 처리 안 한 후보를 홈·업무일지에 계속 띄움. [무시]한 것은 다시 안 뜸. 폰·PC 똑같이 보임. DB 변경이라 승인 단계(§6·§7)가 있음 |

추천 이유: "홈에 띄워 놓고 놓치지 않기"가 이 기능의 목적이라 ①로는 목적을 못 채운다. 표에는 **처리 전 후보만** 두고, [할 일로] 누르면 실행 상태는 Google 할 일이 맡는다(원본 경계 유지, 4절).

### 결정 4. 화면 어디에 띄울까

| 선택지 | 내용 |
| --- | --- |
| ① 홈 오른쪽 '주요 일정' 아래 칸 + 업무일지에는 그날 나온 후보 기록 (**추천**) | 홈 = 처리 안 한 후보 전체(5개 + 더 보기). 업무일지 하루 카드 위 = 그날 재료에서 나온 후보와 처리 결과(할 일로 갔는지, 무시했는지) |
| ② 업무일지 하루 카드 위에만 | 날짜를 눌러야 보여서 "놓치지 않기"엔 약함 |
| ③ 홈에만 | 업무일지에 "그날 무엇을 챙겼나" 기록이 안 남음 |

추천 이유: 놓치지 않으려면 매일 처음 보는 홈에 있어야 한다. 폰(좁은 화면)에서는 홈 오른쪽 칸이 없으므로 **빠른 입력 바로 아래, '오늘 일정' 위**를 추천(지금 '주요 일정'이 폰에서 들어가는 자리와 같은 방식, 5절).

### 결정 5. 이미 할 일·일정에 있는 마감도 챙길 것에 다시 띄울까

| 선택지 | 내용 |
| --- | --- |
| ① 다시 띄우지 않음 (**추천**) | 홈에 이미 '오늘 할 일'·'회의 후속'·'주요 일정' 칸이 있음. 챙길 것은 **글 속에 숨어 있고 아직 할 일·일정이 아닌 것**만 |
| ② 모두 모아 한 칸에 | 한눈에 보이지만 같은 줄이 홈에 두 번 나오고, 후보(확인 전)와 확정된 할 일이 섞임 |

추천 이유: 같은 정보를 두 칸에서 보여 주면 어느 쪽을 믿을지 헷갈린다. 챙길 것은 "아직 아무 데도 안 적힌 것"을 할 일로 옮기는 입구로만 쓴다.

### 결정 6. 상대방이 하기로 한 약속(COM)은 어떻게

| 선택지 | 내용 |
| --- | --- |
| ① Web2에 저장하지 않고 [원장으로 복사]만 (**추천**) | 확인 화면에서 "상대 약속"으로 나온 후보는 [할 일로] 대신 [원장으로 복사](쓰기요청 문구)를 줌. ChatGPT(원장 단일 writer)에 붙여 넣으면 원장에 등록. Web2 후보 표에서는 지움 |
| ② Web2 후보 표에 두고 추적 | 원장과 Web2 두 곳에서 약속을 추적하게 됨 → 원본 경계 결정(약속은 원장이 원본, Web2에 약속 추적 기능을 만들지 않음)과 충돌 |

추천 이유: 2026-10-01 원본 경계 결정 그대로. **내가(우리 쪽이) 할 일**만 Web2 → Google 할 일로, **상대·제3자 약속**은 원장으로.

### 결정 7. 민감한 내용(사람 이름 등) 처리

추천안 하나로 묶음:
- 바구니에서 "AI 제외"로 표시한 메모, 일기는 찾기 대상에서 늘 뺀다(기존 규칙 `ai_export_allowed`, `app_notes_diary_private_check`).
- 후보에는 **한 줄 요약 + 출처 링크 + 짧은 근거(200자 안)** 만 저장하고 원문을 통째로 복사하지 않는다.
- 사람 이름은 Web2 안(본인만 보는 비공개)에서는 그대로 둔다. 지우면 "누구에게 답해야 하는지"를 잃는다.
- 홈 빠른 표시용 브라우저 사본(홈 캐시)에는 후보 **개수만** 넣고 글은 넣지 않는다.
- 저장소·시험·문서에는 실제 이름을 쓰지 않는다(가짜 이름만).

### 결정 8. 순서

JOURNAL-주간보고허브 1단계(업무일지가 프로젝트·조직·회의 기록을 읽는 함수) **뒤에** 착수하는 것을 추천. 챙길 것이 같은 재료 읽기를 그대로 쓰므로 먼저 만들면 같은 읽기를 두 번 만들게 된다(AGENTS.md §4 중복 금지). 두 작업이 같은 파일(`app/journal-data.js`)을 고치므로 동시에 하지 않는다.

## 1. 목표와 범위 밖

### 목표

- 흩어진 기록 속 "내가 챙겨야 할 것"을 한곳에 모아 놓치지 않게 한다.
- 챙길 것의 종류(예시): 답해야 할 요청("A 사업장에서 자료 회신 요청"), 내가 하기로 한 일, 마감("금요일까지 의견 제출"), 준비할 자료("C 회의 자료 준비"), 참석 요청("B 위원장 참석 요청").
- AI가 찾은 것은 **후보**로만 보이고, 명진이 [할 일로] 또는 [무시]로 확인한다. 바구니 분류와 같은 원칙(`docs/basket-design.md` 5절: "제안만으로 … Google 할 일이 바뀌지 않는다").

### 범위 밖

- 후보를 자동으로 할 일·일정으로 만들기. 외부 글(텔레그램·통화)을 읽은 결과로 바로 쓰기 행동을 하지 않는다(`ai-work-system-source-of-truth.md` "외부 입력과 실행의 분리").
- 상대·제3자 약속의 이행 추적(원장 COM 몫, 결정 6).
- 장기기억 원장 읽기·쓰기. Web2는 원장에 쓰지 않는다.
- 알림(푸시·메일). 필요하면 별도 과제.
- 주간보고 초안 만들기(JOURNAL-주간보고허브·WEEKLY-자동화 몫).
- 할 일 화면·Google 할 일 쪽 동작 변경. [할 일로]는 기존 만들기 경로를 그대로 부른다.

### Drive 권한에 관한 사실 (중요)

- Web2가 받은 Drive 권한은 `drive.file` **하나**이고, 이 권한은 **Web2가 직접 만들거나 올린 파일만** 읽고 고칠 수 있다(사실. `docs/design/drive-tree-permission-check.md` 1절, `supabase/functions/public-policy-drive/index.ts`).
- 텔레그램·전사 파일은 바깥 프로그램이 만든 파일이므로 **지금 권한으로는 Web2 서버도 못 읽는다**(추정이지만 위 문서·`docs/basket-design.md` 7.1과 같은 판단).
- 이 사실은 원장의 **BASKET-수집연동**(Drive 두 폴더를 정기적으로 바구니로)에도 그대로 걸린다. 그 행에는 "새 정기 실행 서버 함수 필요"만 적혀 있고 권한 문제는 적혀 있지 않다 → 착수 전에 커맨드센터가 같이 정리해야 함(아래 9절).

## 3. 찾는 방식 비교

전제: 아래는 **해법 후보에서 처음부터 뺀다** — 서버 관리자 키(service role)를 바깥 AI·브라우저에 주기, 로그인 없이 쓰기 허용(anon 쓰기, RLS 약화), Drive 전체 권한 등 권한 확대(AGENTS.md §3).

| | 가. 낱말 규칙 | 나. 복사 → ChatGPT → 붙여넣기 | 다. 앱 안 AI 호출 | 라. 예약 AI → Web2 기록 |
| --- | --- | --- | --- | --- |
| 어떻게 | 화면 코드가 "까지/부탁/회신/요청"·날짜를 찾음 | [챙길 것 찾기 복사] → ChatGPT → 답을 [찾은 결과 넣기] | 버튼을 누르면 Web2 서버 함수가 OpenAI에 물어봄 | 예약 실행 AI가 정해진 시간에 찾아 Web2로 보냄 |
| 비용 | 0원 | 추가 0원(쓰는 ChatGPT Plus) | 작은 모델이면 월 수백~수천 원(추정). Web2 AI 전체 월 1만 원대 예산 안(2026-10-16 결정) | ChatGPT 예약 = 추가 0원. 단 Plus 예약 5개 한도를 이미 다 씀(원장 머리) → 기존 예약에 섞어야 함 |
| 서버·DB | 없음(저장은 결정 3) | 없음(저장은 결정 3) | 새 Edge 동작 + `OPENAI_API_KEY` 등록(운영 비밀값, §6 정지). 아직 미등록(원장 BASKET-AI자동정리) | 받는 길에 따라 다름 ↓ |
| 권한 | 기존 owner 읽기 | 기존 owner 읽기·쓰기 | Edge가 로그인한 owner만 허용(기존 함수와 같은 방식) | 받는 길: ⓐ Drive 파일을 Web2가 읽기 → 권한 확대라 **제외**. ⓑ 사람이 복사·붙여넣기 → 나와 같음. ⓒ 받기 전용 입구 + 전용 비밀값 → 새 Edge 함수(§8 신규 배포), 비밀값을 바깥에 맡기는 위험 |

- AI 답은 **믿지 않는 입력**으로 다룬다. 엄격한 형식 검사(크기·개수·글자 수 상한), 화면에는 글자로만 표시(HTML로 해석 안 함). 바구니 분류 파서(`app/basket-classification.js`)와 같은 방식 재사용.

## 4. 후보 → 확인 흐름

1. **찾기**: [챙길 것 찾기 복사]는 "지난번 찾기 이후 새로 생기거나 고친 재료"만 복사(바구니 주간넘기기의 기준선 방식과 같음). 재료: 바구니 메모(AI 제외 빼고), 한 줄, 프로젝트 기록, 담당조직 기록, 회의 결과. 각 재료에 종류·ID·날짜를 붙인다.
2. **넣기**: ChatGPT 답(또는 2단계의 예약 정리 결과)을 [찾은 결과 넣기]에 붙여 넣음 → 형식 검사 → 확인 화면.
3. **확인 화면**(줄마다):
   - 종류 표시(요청·내 할 일·마감·준비·참석), 한 줄 요약, 기한(있으면), 출처(누르면 원래 메모·기록·회의로).
   - [할 일로]: 제목·기한을 고친 뒤 기존 `google-tasks` `create`로 Google 할 일 생성. 출처가 프로젝트·조직·회의면 같은 연결을 붙인다(기존 기능). 출처가 바구니 메모면 메모의 할 일 출처(`metadata.tasks`)에도 남김(기존 기능).
   - [무시]: 다시 안 뜸.
   - "상대 약속"으로 나온 줄: [할 일로] 대신 [원장으로 복사](결정 6).
   - [나중에]: 그대로 두면 홈에 계속 보임(결정 3 ②일 때).
4. **같은 후보 거르기**: 같은 출처 + 비슷한 제목은 다시 넣지 않음. 이미 같은 제목의 미완료 할 일이 있으면 "이미 할 일에 있어요" 표시.
5. **할 일로 간 뒤**: 후보는 닫히고, 끝냈는지·기한은 **Google 할 일이 원본**. 후보 표가 할 일 상태를 따로 추적하지 않는다(두 번째 할 일 목록을 만들지 않음).

### 후보 표(결정 3 ② 채택 시, 제안만 — 적용은 별도 PR·승인)

- 칸(안): 종류, 한 줄 요약, 기한, 출처 종류·출처 ID·출처 날짜, 짧은 근거, 상태(열림·할 일로·무시), 만든 할 일 ID, 만든 때·처리한 때.
- 권한: 기존 Web2 표와 같은 owner 전용 경계(`private.app_is_workspace_owner`, 로그인한 사용자에게 필요한 동작만 허용, 비로그인 권한 없음).
- 무시·처리한 후보는 일정 기간 뒤 정리(기간은 착수 때 정함, 추천 30일).
- 다른 안으로 기존 `app_notes`에 새 종류를 더하는 길도 있으나(이것도 DB 규칙 변경), 메모와 성격이 달라 바구니 목록·AI 복사 흐름에 섞일 위험이 있어 추천하지 않는다.

## 8. 위험

- **놓침 착각**: 후보가 안 보이면 "챙길 것 없음"으로 믿기 쉽다. 칸에 "마지막 찾기: ○월 ○일"을 늘 표시하고, 2일 넘으면 [찾기 복사]를 눈에 띄게.
- **헛잡음 피로**: 후보가 너무 많으면 안 보게 된다. 요청문에 "확실한 것만, 하루 최대 N개" 기준을 두고, 무시 비율을 보고 요청문을 고친다.
- **외부 글 속 지시**: 텔레그램·전사 글이 AI에게 지시처럼 읽힐 수 있다. 자동 실행이 없고(후보만), 형식 검사가 엄격해 피해는 "이상한 후보 한 줄"로 제한된다.
- **두 번째 할 일 목록**: 후보 표가 커지면 할 일 원본이 둘이 될 위험. 후보는 처리 전 임시 상태만, 처리 뒤 상태는 Google 할 일(4절 5).
- **민감 정보 위치 늘어남**: 후보 표에 사람 이름이 들어간다. owner 전용 표라 기존 메모와 같은 보호지만, 근거 글 길이 제한·원문 비복사·홈 사본 개수만으로 늘어나는 양을 줄인다.
- **ChatGPT 예약 한도**: 2단계는 예약을 새로 만들지 않고 기존 정리 예약에 섞어야 한다(Plus 5개 한도, 원장 머리 2026-10-16). 섞으면 그 예약 결과가 길어짐.

- 한 항목 두 줄: 윗줄 제목, 아랫줄 회색 작은 글자로 출처·제안 기한(예: `조직 기록 · 제안 기한 10.23 ▾`). 근거 문장은 ▾를 눌러 펼친다. 종류 꼬리표(준비·참석·요청·내 할 일)와 '대기' 글자는 뺐다.
- 오른쪽 작은 버튼 셋(보이는 28px, 누르는 높이 44px): ✓ 바로 할 일로(기한 = AI 제안 기한, 없으면 오늘) / ✎ 고쳐서 넣기(그 자리에서 제목 고치고 기한 [오늘·내일·제안 기한·기한 없음] → [넣기] [취소]) / ✕ 무시(5초 [되돌리기]).
- 처리한 항목은 흐리게 줄 긋고 `할 일로 넣음 · 10.23`·`무시함`으로 남기며, 미처리 아래 `처리함 N ▸`에 접는다. 제목 옆 건수는 남은 것만.
- 처음 4건만, 나머지는 `N건 더 ›`. [다시 찾기]는 글자 버튼.
- 홈은 남은 것 + **오늘(한국 날짜) 처리한 것**을 읽는다(`readHomeCandidates`, `or=(status.eq.open,decided_at.gte.오늘 0시)`). 업무일지는 그날 출처의 후보 전체(기존 주간 읽기 그대로).
- 넣은 기한은 따로 저장하지 않는다(칸 없음). 이 탭에서 넣은 것은 그때 고른 기한을, 다시 연 뒤에는 할 일 화면이 가진 Google 할 일 사본(`peekTasks`)의 기한을 보여 준다. 사본에 없으면 `할 일로 넣음`만 보인다.

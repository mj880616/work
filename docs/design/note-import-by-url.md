## 1. 한 줄 결론

뉴스 본문 읽기 부품이 이미 거의 다 있다. **읽기(`_shared/feed-fetch.ts`) + 한 페이지 읽기(`news-feed/page.ts`의 `readArticlePage`) + 본문 뽑기(`_shared/feed-extract.ts`)를 그대로 쓰고, 빠진 것 세 가지(주소 허용 판정 함수, 저자 읽기, 새 Edge 함수 입구)만 더한다.** DB 표 변경은 필요 없을 가능성이 높다(노트의 `metadata` 칸에 원문 정보를 둠). 화면 쪽은 기존 노트 저장 길을 그대로 쓴다.

## 2. 화면(시안 요약)

1. 넣는 자리: 새 노트 창 제목 아래 작은 한 줄 [🔗 주소 | 가져오기](안 A), 또는 본문에 주소만 붙이면 아래에 뜨는 제안 줄(안 B).
2. 가져오는 중: 'UX-먼저묻고뒤에처리'(`docs/design-decisions.md`)를 따른다. 누르면 노트 줄이 목록에 바로 생기고 창은 닫아도 된다. 원문 링크는 바로 보이고 제목·본문 자리는 회색 막대. 끝·실패는 공용 작은 알림. 처리 중에 또 눌러도 거절하지 않고 줄 세운다.
3. 가져온 뒤: 제목 = 글 제목, 아래 저자·날짜·폴더, 맨 위 작은 한 줄에 원문 링크(+가져온 날), 본문은 문단 그대로(고쳐 쓸 수 있음).
4. 실패: 노트는 '주소만' 남고 위에 안내 한 줄 + [다시 시도][주소만 두기]. 빨간 큰 오류 창 없음.

## 3. 서버가 바깥 페이지를 읽는 안전 범위

서버가 사용자가 넣은 주소를 대신 열기 때문에(SSRF 위험) 아래를 모두 지킨다. 칸마다 '이미 있음'은 기존 부품이 하는 일이고, '새로'는 이번 작업에서 더할 것이다.

| 항목 | 규칙 | 상태 |
| --- | --- | --- |
| 누가 | 로그인한 사람만(Edge `verify_jwt=true`), 코드에서도 작업공간 owner를 서버가 다시 확인. 클라이언트가 보낸 작업공간·소유자 값은 믿지 않음(AGENTS.md 3절 3번). 운영자 전용 기능 아님 — 노조 사용자 누구나 자기 작업공간에서 | 새로(방식은 `news-feed`의 `authorizeUser`와 같게) |
| 주소 모양 | http·https만. 길이 2000자 이하, 아이디·비밀번호·포트가 든 주소 거절, 숫자 IP·IPv6·`localhost`·점 없는 이름·내부 이름(`.local` `.internal` `.lan` `.corp` `.arpa` 등)·Supabase 도메인 거절. 국제 도메인은 punycode로만 | 일부 있음: `news-url.ts`의 `openArticleUrl`이 이 규칙을 이미 한다. 단 **https만** 허용하므로 http 허용 여부는 아래 4번 결정 |
| 리다이렉트 | 사람이 넣은 주소만이 아니라 **리다이렉트 때마다** 같은 판정을 다시 한다(최대 3번, 안 되면 `redirect_outside`) | 이미 있음(`feed-fetch.ts` `follow`) |
| 크기 | 응답 2 MB 초과면 중단(`FETCH_MAX_BYTES`), 선언된 길이와 실제 읽은 길이를 둘 다 봄 | 이미 있음 |
| 시간 | 요청 10초 제한(`FETCH_TIMEOUT_MS`) | 이미 있음 |
| 보내는 것 | 쿠키·인증 헤더 없음(`credentials: "omit"`), 정직한 User-Agent | 이미 있음 |
| 받는 것 | 글자 판(html·xhtml·text)만. 그림·영상·압축 파일 등은 본문으로 읽지 않음 | **새로**(지금 `feed-fetch.ts`의 읽기는 content-type을 돌려줄 뿐 거르지 않음 — 사실) |
| 막힌 곳 | `robots.txt`가 막으면 읽지 않고 우회하지 않음. 봇 확인 화면·유료벽도 우회하지 않고 실패(또는 앞부분만) 처리 | 이미 있음(`robotsAllows`, `looksLikeBotCheck`, `paywallMark`) |
| 저장 | HTML은 저장하지 않는다. 글자와 `https` 사진 주소·캡션만 뽑는다. 노트 글자 상한(20000자) 안으로 자른다 | 이미 있음(`feed-extract.ts` 머리말) + 노트 상한 자르기는 새로 |
| 횟수 | 작업공간별 하루 횟수 상한 | 새로(아래 5번) |
| 기록 | 로그에 주소·본문을 남기지 않고 코드·숫자만 | 기존 규칙 그대로 |
| 외부 입력의 뒤처리 | 가져온 글은 **저장만** 한다. 가져온 글을 AI에 넘기거나 발송·공유로 자동 이어 가지 않는다(프로젝트 보안 원칙) | 지킴(이번에 AI 없음) |

**남는 위험(사실)**: 주소의 이름이 나중에 내부 주소로 풀리는 경우(DNS 재바인딩)는 이름 검사만으로 못 막는다. `openArticleUrl` 머리 주석도 "Edge 런타임의 사설망 차단에 기댐"이라고 적고 있다. 구현 PR에서 Edge 런타임이 풀어 낸 IP를 검사할 방법이 있는지(예: DNS 조회 API 사용 가능 여부) 먼저 확인하고, 없으면 이 위험을 PR에 그대로 적어 명진이 알고 정하게 한다. 이 메모는 그 확인을 하지 못했다(웹 세션에서 Edge 런타임을 볼 수 없음).

## 4. 뉴스 본문 읽기 부품을 다시 쓸 수 있나 — 조사 결과

| 부품 | 하는 일 | 다시 쓰기 | 손볼 것 |
| --- | --- | --- | --- |
| `_shared/feed-fetch.ts` `makeFeedReader` | 주소를 안전하게 읽음(리다이렉트 재검사, robots, 크기·시간, 출처별 간격) | **그대로 쓴다.** `allow(주소)`만 바꿔 끼우는 구조라 노트용 판정 함수를 넘기면 됨 | `allow` 함수만 새로(`news-url.ts`의 `openArticleUrl`을 바탕으로, http 허용을 정하면 거기만 수정). 출처별 간격(`gapMs`)은 한 번에 한 주소라 영향 없음 |
| `news-feed/page.ts` `readArticlePage` | 한 페이지 HTML → 제목(`og:title`)·사이트 이름(`og:site_name`)·발행일(메타·JSON-LD·`<time>`)·언어·본문 블록, 봇 확인·유료벽 판정 | **그대로 쓴다.** 규칙 입력을 안 주면 이미 '열린 주소' 규칙(`OPEN_ARTICLE_RULE`)으로 동작하고 `news-feed`의 채널 기사 열기가 같은 길로 쓰고 있음 | **저자는 못 읽는다**(`author`·byline 읽는 곳 없음 — 사실). 저자는 `<meta name="author">`·JSON-LD `author.name`을 읽는 작은 순수 함수를 새로 더함. 못 읽으면 칸을 비움 |
| `_shared/feed-extract.ts` `extractBlocks` | 본문 칸을 골라 문단·소제목·인용·사진 블록으로 뽑음. 순수 함수, 네트워크·DB 없음 | `readArticlePage`가 이미 부름. 그대로 | 블록 → 노트 본문 변환은 새로(소제목·인용·문단 → 노트 편집기 글. 이미 있는 `ed-markdown.mjs` `plainToDocKeep` 같은 변환을 먼저 확인) |
| `outside-feed/parse.ts` `decodeBody` | 글자 인코딩 판별(UTF-8·EUC-KR·windows-1252) | 그대로 | 없음 |
| `news-feed`의 `open` 동작 | 기사 하나 열기 | **못 쓴다.** `app_news_items`의 줄 id를 받는 동작이라 노트와 맞지 않음. 하루 횟수·소유 확인 방식(`authorizeUser`, `useDaily`)은 본뜬다 | 노트용 새 입구가 필요 |

정리: 새로 만드는 것은 ① 노트용 `allow` 판정 ② 저자 읽기 ③ 글자 판만 받기 검사 ④ 입구(Edge) ⑤ 블록 → 노트 본문 변환뿐이다. 본문 뽑기 규칙 자체를 새로 쓰지 않는다(같은 규칙을 두 벌 두지 않음 — AGENTS.md 4절).

## 5. 필요한 서버·DB 변경

### Edge 함수 — 새 입구 하나

| 선택지 | 내용 |
| --- | --- |
| ① 새 함수 `note-import` (**추천**) | `verify_jwt=true`, 동작은 한 가지(`import`: `{url}` → `{state, title, site, author, published_at, lang, blocks, reason}`). 읽기 전용(DB에 쓰지 않음). 안전 범위가 이 함수 하나에만 걸려 검토가 쉽고, 매체 수집(`news-feed`)의 예약·키 경계와 섞이지 않음. 대신 신규 함수라 `first_deploy=true` + `verify_jwt` 명시 + `docs/web2-env6b-edge-source.md` 5절 표 사전 등록이 필요(AGENTS.md 8절) |
| ② `news-feed`에 동작 추가 | 함수 수는 늘지 않지만, 예약 호출·`CRON` 키 동작과 한 함수에 섞여 인증 경계(예약 키 vs 사용자 로그인)가 복잡해짐. 사용자 동작 목록(`userActions`)에 더하는 방식이라 가능은 함 |

추천 이유: 인증 경계를 단순하게 두는 편이 안전하다. 신규 함수 배포는 §8 승인형 workflow로 하고, 되돌리기는 '화면이 아직 이 함수를 쓰지 않는 상태 유지'이다.

### 서버는 읽기만, 쓰기는 기존 노트 저장 길

- 입구는 읽은 결과만 돌려준다. **노트 저장은 화면이 기존 길(`createNoteDoc` + `finishNewNote`, 노트 창과 같은 뒷일)로 한다.** 새 쓰기 길·새 서버 권한을 만들지 않는다. 노트 본문·첨부 저장의 소유 확인은 지금 길이 이미 한다.
- '창을 닫아도 끝까지'는 화면의 뒤처리 줄(공용 `upload-progress.js`·`meeting-drop-queue.mjs` 모양)이 맡는다. 요청 하나가 10초 안쪽이라 앱을 통째로 닫지 않는 한 끝난다. 앱을 닫아 끊기면 노트는 '주소만' 상태로 남고 [다시 시도]로 이어 간다(노트를 먼저 만든 뒤 읽기 때문에 쓴 것이 사라지지 않음).

### DB — 표 변경 없음이 1순위

- 원문 정보 저장 위치: `app_notes.metadata`(jsonb 객체, 이미 있음 — `20261010120000_basket1_notes_links.sql`, 검사는 객체 여부만). 모양 예: `metadata.source = {url, site, author, published_at, fetched_at, state, reason}`. `state`는 `fetching | ok | failed`. 노트 고정(`pinned_at`)·폴더가 같은 `metadata`를 쓰는 방식과 같다.
- 구현 때 확인할 것: 노트를 고치는 길(`note-window.js`·`basket-data.js`)이 `metadata`의 모르는 키를 지우거나 덮어쓰지 않는지, 노트 읽기 화면의 원문 링크 줄을 **한 곳에서만** 그리는지(단일 renderer, AGENTS.md 5절).
- 하루 횟수: 작업공간별 하루 사용량 표 `app_news_days`(`news-days.ts`)에 `fetch_n` 칸이 있다. 방법 둘: (a) `fetch_n`을 뉴스 기사 열기(`OPEN_DAILY=60`)와 함께 쓰되 노트용 상한을 따로 정함 — **DB 변경 없음, 추천(1단계)**, (b) 새 칸 `import_n` 추가 — migration 필요(§6 정지 지점, 승인형 DB workflow). (a)로 시작하고 모자라면 (b).
- 노트 검색이 `metadata`를 보지 않으면 원문 주소·사이트 이름으로는 못 찾는다. 1단계에서는 제목·본문으로만 찾고, 주소 검색은 후속(DB 변경 없이 화면 검색 칸에서 `metadata`를 더 읽는 방법을 후속 PR에서 조사).
- 가져온 글은 바깥 사람의 글이다. 노트의 `ai_export_allowed`(기본 켜짐)와 노트 AI 마스크 설계(`docs/design/note-ai-mask.md`)에 따라 AI 재료로 가는 길이 있는지 구현 PR에서 확인하고, 이번 범위에서는 AI에 넘기는 길을 새로 만들지 않는다.

## 7. 사용자가 고를 것

시안 쪽(PR 댓글에도 같은 목록):

1. 주소 넣는 자리: 안 A(제목 줄 아래 주소 칸) / 안 B(본문에 주소만 붙이면 제안 줄) / 둘 다
2. 가져오는 중: 노트 줄이 바로 생기고 창은 닫아도 됨(추천) / 창이 열린 채 기다림
3. 사진: 1단계는 글자만(추천) / 사진도 화면에 함께 띄움
4. 실패했을 때: 노트는 '주소만' 남김(추천) / 노트를 만들지 않음

서버 쪽:

5. `http` 주소: 막음(지금 부품 그대로, 추천) / 받되 `https`로 바꿔 한 번 시도. 대부분 사이트가 `https`라 막아도 불편이 작고, 막으면 부품을 고치지 않아도 됨
6. 입구: 새 함수 `note-import`(추천) / `news-feed`에 동작 추가
7. 하루 횟수: 뉴스 기사 열기와 같은 칸 `fetch_n` 공유(추천, DB 변경 없음) / 새 칸(DB 변경)

## 8. 열린 질문·남은 위험

- DNS 재바인딩(3절): 구현 PR 첫 조사 항목. 막을 방법이 없으면 위험을 적고 명진이 정함.
- `robots.txt` 존중은 뉴스 수집과 같은 부품이라 그대로 따라온다. 사람이 직접 한 번 넣는 가져오기에도 같은 규칙이 맞는지(막힌 사이트는 못 가져옴) — 이 메모는 '우회하지 않음'을 기본으로 둠. 다르게 하려면 명진 결정이 필요함.
- 유료 기사는 앞부분(리드)만 들어오거나 실패함. 우회하지 않음.
- 저작물을 노트로 복사하는 일이라, 가져온 글을 밖으로 공유(Web2 공유 링크)하는 길을 열지 않는다는 점은 기존 규칙(Web2는 비공개 내용만)을 그대로 따른다. 이 메모는 새 공유 길을 만들지 않는다.
- 읽생기 쪽 글을 노트로 옮기는 일(RTW-노트일원화)과 이 작업은 별개다. 읽생기 사이트 닫기 순서는 `docs/design/rtw-close-plan.md`를 따른다.

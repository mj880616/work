## 2. 할 일

1. 칸 머리에 출처 고르기를 둔다(시안 A: "원드라이브 ▾" 이름 → 목록, 시안 B: 아이콘 4개). 고르면 그 칸만 그 출처의 맨 위로 간다. 양쪽을 같은 출처로 고를 수 있다(두 폴더 나란히).
2. 쓸 수 없는 출처(폰 앱이 아닌데 '이 폰', PC 앱 문이 꺼졌는데 '내 PC', 연결 안 된 클라우드)는 목록에서 흐리게 + 이유 한 줄.
3. 위 줄 출처 끄기(`files_sources`)와의 관계: 위 줄에서 끈 출처는 칸 머리 목록에서도 흐리게(보기에서 뺀 것과 같은 뜻). [추정] 명진 확인 필요 없음 — 같은 규칙 하나.

## 3. DB가 필요한가

- **기억하지 않으면(시안 2-B) DB 변경 없음.** 칸 머리 고르기는 화면 메모리만 바꾼다.
- **기억하면(시안 2-A, 추천) DB 한 번 필요.** `files_two`는 칸 값이 참·거짓만이라 출처를 넣을 수 없다. `app_profiles_view_prefs_check` 제약을 다시 만들어 새 칸 하나를 허용한다.
  - 새 칸 예: `files_panes = {app|phone|pc: [칸0 출처, 칸1 출처]}`, 출처는 `od`·`gd`·`ph`·`pc` 넷 중 하나, 배열 길이 2. 폴더 위치(폴더 id)는 넣지 않는다(맨 위에서 시작 — 폴더 id를 오래 들고 있으면 지워진 폴더 처리가 늘어남).
  - 방식은 그동안의 `view_prefs` 칸 더하기와 같다(앞 migration 정의를 그대로 옮기고 칸 하나만 더함, 권한·정책 변경 없음, `schema_migrations` 1행).
- 일상어 3줄(2-A를 고를 때):
  - **무엇이 바뀌나** — 내 보기 설정에 "두 칸 각각 어느 출처를 띄웠나" 한 칸이 더 저장될 수 있게 된다.
  - **잘못되면** — 보기 설정 저장이 거절되어 [파일] 화면 모양 기억(두 칸 켬 등)이 잠깐 저장되지 않을 수 있다. 자료·파일은 영향 없음.
  - **되돌리는 법** — 앞 판 제약 정의(`20261106200000`)로 다시 만드는 되돌리기 SQL을 함께 둔다(새 칸 값이 저장된 행이 없을 때만 바로 되돌림).

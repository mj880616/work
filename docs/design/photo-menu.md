## 1. 화면 구조

### 1.1 자리와 주소

- 주소 `?view=photos` (서브 칩은 `&tab=all|calendar|folders|albums|map|trash`). 메뉴 id `photos`. 메뉴 순서·하단바 기억(`view_prefs.menu_layout`, #1347)의 id 규칙(`^[a-z][a-z0-9_-]{0,29}$`)에 맞아 **DB 변경 없이** 메뉴 편집으로 하단바에 옮길 수 있다.
- 처음 자리는 '메뉴' 창 안(`rest` 목록 끝). 아이콘은 기존 아이콘 세트에서 고른다.
- 원드라이브가 연결 안 됐으면 사진 메뉴는 한 줄 `원드라이브 연결 뒤 쓸 수 있어요 [연결]`만 보인다(일기와 같은 연결 흐름 재사용, 돌아올 주소는 그대로 `onedrive-return.html`이고 돌아온 뒤 `?view=photos`로 보낸다 — 돌아올 화면만 `#` 뒤에 담는다).

### 1.2 위 칩 줄

`[사진] [달력] [폴더] [앨범] [지도] [휴지통]` — 알약 칩 32px(UI-버튼기준). 폰은 칩 줄 가로 스크롤 + **본문 좌우 스와이프로 칩 이동**(명진 취향, 사진 격자 안의 좌우 끌기는 선택 모드일 때만 '여러 장 고르기'로 쓰므로 부딪치지 않는다). 뒤로가기는 이전 칩(주소 `tab` 기록).

칩 줄 오른쪽 끝(사진·달력·폴더·앨범 보기에서만): 거르기 `전체 ▾`(전체·★·동영상·스크린샷)과 썸네일 크기 `[－][＋]`(다른 세션 부품, 칸 수 폰 3~6·PC 5~12, 핀치도 같음). 거르기·칸 수는 서버 저장(`view_prefs.photo_view`, 2절 DB 변경 ①).

### 1.4 여러 장 고르기 (자료실 선택 모드와 같은 부품)

- 시작: 사진을 **길게 누르기**(0.5초). 들어갈 때 0.2초 살짝 흔들림, 위에 강조색 줄 `✕ · n개 골랐음`, 아래 작업 줄. **뒤로가기 = 선택 해제**(화면 이동 아님). 모두 자료실 세션의 공용 부품이다.
- 고른 채 손가락을 떼지 않고 끌면 지나간 칸을 모두 고른다(첫 칸이 고름이면 고르기, 해제면 해제로 끌기). 화면 끝에 닿으면 천천히 자동 스크롤. 끄는 동안만 `touch-action:none`.
- 날짜 머리줄 ○ = 그날 전체 고르기/풀기.
- 아래 작업 줄(작은 32px 아이콘+글자): `[☆ 별표] [# 태그] [⇪ 공유] [⤓ 받기] [🗑 지우기] [⋯]`, ⋯ 안 `폴더로 옮기기`. 폰 390px에 다섯 개 + ⋯가 한 줄에 들어간다(시안). PC는 ⋯ 없이 여섯 개 다 보인다.
- 휴지통 보기의 선택 줄은 `[되살리기] [바로 지우기]`.
- 키보드(PC): 칸에 초점 후 Space = 고르기, Shift+클릭 = 범위, Esc = 해제.

### 1.6 일기 날짜 화면 스위치 (요청 ⑫)

### 2.2 DB 변경 (단계별, 모두 정지 지점)

승인형 DB workflow 확장 규칙의 `grant-existing`(이번 파일에서 만들지 않은 기존 표에 권한 추가)은 **거절**된다. 그래서:

- `app_onedrive_connections`에는 **칸을 더하지 않는다**(칸 단위 권한이라 새 칸에 service_role 권한을 주려면 기존 표에 권한 추가가 필요 → 거절). 휴지통 폴더 id 같은 연결 단위 값도 폴더 표에 둔다.
- `app_onedrive_photos`·`app_onedrive_folders`는 service_role이 **표 단위** 권한을 이미 가져서, `alter table … add column`(확장 규칙 허용)만으로 새 칸을 쓸 수 있다. 권한 문장 없음.
- 새 표(태그)는 같은 파일에서 RLS를 켜고 authenticated owner 정책·권한을 준다(확장 규칙 허용, `app_diary_stars`와 같은 모양).
- `view_prefs` 칸 추가는 검사(`app_profiles_view_prefs_check`)를 같은 이름으로 다시 만드는 기존 방식(#1338 등과 같음).

- 노트 해시태그(10/28 주소 이전 ③)와는 **입력 모양만** 맞추고 저장은 따로다.

### 2.3 휴지통 기준

- 확인한 사실: Microsoft Graph의 "지운 항목 되살리기"(`POST /me/drive/items/{id}/restore`)는 개인 계정에서 **`Files.ReadWrite.All` 권한을 요구**한다(Microsoft 문서). 지금 권한 `Files.ReadWrite`로는 Web2가 원드라이브 휴지통에서 되살릴 수 없다. 원드라이브 휴지통 목록을 읽는 기능도 Graph v1.0에 없다.
- 권한은 넓히지 않는다(요청 확인 사항). 그래서 두 안이 있다.

| 안 | 지우기 | Web2 휴지통 보기 | 되살리기 | 좋은 점 / 아쉬운 점 |
| --- | --- | --- | --- | --- |
| A. 원드라이브 휴지통 바로 | 지금처럼 `DELETE`(원드라이브 휴지통으로) | Web2가 지운 기록(이름·날짜·폰 보관 작은 그림)만 보여 줌 | **Web2에서 못 함.** `원드라이브 휴지통 열기 ↗` 링크로 명진이 원드라이브에서 되살리면 다음 색인 때 다시 나타남 | DB 변경 적음 / 요청 ⑨의 '되살리기'가 반쪽 |
| **B. Web2 휴지통 폴더 (추천)** | 고른 맨 위 폴더 안 숨은 폴더 `.Web2 휴지통`으로 **옮기기**(같은 `Files.ReadWrite`, 폴더 안 이동) | 그 폴더 사진 격자(실제 그림) | Web2에서 원래 폴더로 다시 옮김. 30일 지나면 서버가 `DELETE`(원드라이브 휴지통 30일 더) | 권한 그대로 · 진짜 되살리기 / 원드라이브 앱에서는 그 폴더가 보인다(이름이 점으로 시작해 맨 위로 모임) |

- B안 세부: 휴지통 폴더는 처음 지울 때 서버가 만든다(`role='trash'`). 이 폴더는 폴더 보기·일기·사진 격자에서 빠진다. 30일 비우기는 사진 메뉴를 열 때 서버가 한 걸음씩(오래된 것 20장까지) 한다 — 새 예약 작업 없음. `[모두 비우기]`·`[바로 지우기]`는 작은 확인창 한 번.
- 폴더 지우기(요청 ②): 폴더째 휴지통 폴더로 옮긴다. 확인창 `사진 n장도 같이 휴지통으로 가요` (n = 색인의 아래 전체 장수, 기존 `folders-tree`의 `total`).

### 2.4 지도 위치 정보 출처

- 원드라이브 항목의 `location`(위도·경도·고도) 값. 휴대폰 사진의 EXIF 위치를 원드라이브가 읽어 둔 것이다. 색인 받을 때(`delta`) `$select`에 `location`을 더해 `lat`·`lon` 칸에 적는다. **사진 파일을 내려받아 직접 읽지 않는다**(속도·용량).
- 미확인(실제 계정 필요): 개인 원드라이브가 모든 사진에 `location`을 채우는지, 동영상에도 채우는지. 없으면 그 사진은 지도에 안 나올 뿐 다른 곳은 그대로다. ①단계 첫 색인 뒤 `위치 있는 사진 n장`을 폴더 보기 아래 한 줄로 보여 확인한다.
- 위치는 민감할 수 있다: 화면 역할에 바로 열지 않고 Edge `map` 동작으로만 돌려준다(작업공간 owner 확인 뒤). 공유·원본 받기 때 파일 안의 EXIF는 원본 그대로 간다(Web2가 지우지 않음) — [⇪] 판에 작은 글씨 `원본에 위치 정보가 들어 있을 수 있어요`.

### 2.5 동영상 재생 주소

- 원드라이브 항목의 `@microsoft.graph.downloadUrl`은 **짧게 사는(약 1시간) 사전 인증 주소**다. 토큰이 주소에 들어가지 않고, 범위 요청(Range)을 받아 `<video src>`로 바로 재생·넘겨보기가 된다. 기존 `photo-urls`가 돌려주는 썸네일 주소와 같은 종류다.
- 새 Edge 동작 `media-url`(한 장, `purpose: play|download`)이 폴더 안·사진/동영상인지 확인한 뒤 그 주소만 돌려준다. 화면은 메모리에만 두고 50분 뒤 다시 받는다. 저장하지 않는다.
- 색인: 지금은 `image/*`만 색인한다. ①에서 `video/(mp4|quicktime|3gpp|webm)`을 더하고 `video.duration`(밀리초)·`width`·`height`를 적는다. 동영상 썸네일은 원드라이브가 만든 썸네일을 `photo-urls`로 그대로 받는다.
- 일기 날짜 화면은 ①에서 `kind='photo'`만 계속 보이게 한다(동영상을 일기에 넣을지는 나중에).
- 아쉬운 점: 아이폰 HEVC(.mov) 동영상은 PC 크롬에서 안 나올 수 있다. 그때는 `이 기기에서 재생 못 해요 [원본 받기]` 한 줄. 서버 변환은 하지 않는다.
- 원본 받기(요청 ⑦): 같은 `media-url`의 `download` 주소로 브라우저가 바로 받는다(파일이 Edge를 거치지 않음, 크기 제한 없음). 여러 장은 차례로(한 번에 20장까지, 넘으면 작은 알림).

## 3. 서버 동작 목록 (Edge `onedrive-photos`에 더함)

모두 기존 함수 안의 새 action이다. 새 함수 없음, `verify_jwt=true` 그대로, 권한 `Files.ReadWrite offline_access User.Read` 그대로. 공통 검사: 로그인·owner 확인 → 연결·맨 위 폴더 확인 → **대상과 목적지가 모두 고른 맨 위 폴더 안**(색인 폴더 트리 + Graph `parentReference.path` 이중 확인, 안 맞으면 거절 쪽) → 허용 범위에 `files.readwrite`가 없으면 424(다시 연결).

| action | 단계 | 하는 일 | 입력 | 거절 |
| --- | --- | --- | --- | --- |
| `library` | ① | 최신순 사진 쪽 읽기(켠 폴더만) | `cursor`, `filter`(all·star·video·shot), `folder_id`·`tag_id`(선택), `limit≤200` | 형식 틀림 400 |
| `months` | ① | 달별 장수(빠른 이동 막대·달력 표시) | `filter` | - |
| `days` | ① | 한 달의 날별 장수·대표 1장(달력 보기) | `month` | - |
| `media-url` | ① | 재생·받기용 짧게 사는 주소 1개 | `id`, `purpose` | 폴더 밖 403, 사진·동영상 아님 404 |
| `photo-delete` | ① 고침 | 동영상도 받음, 여러 장(`ids` ≤ 50) | `ids`, `confirm:true` | confirm 없음 400 |
| `folder-create` | ② | 새 폴더 | `parent_id`, `name` | 부모가 폴더 밖 403, 이름 규칙(원드라이브 금지 글자 `"*:<>?/\|`, 1~200자) 400, 같은 이름 409 |
| `folder-rename` | ② | 폴더 이름 바꾸기 | `folder_id`, `name` | **맨 위 폴더 자체는 거절**(연결 기준이 바뀜) |
| `folder-move` | ② | 폴더를 다른 폴더 아래로 | `folder_id`, `parent_id` | 자기 아래로 옮기기 400, 맨 위 폴더 거절 |
| `folder-delete` | ②(B안은 ③) | 폴더째 휴지통 | `folder_id`, `confirm:true` | 맨 위 폴더 거절 |
| `photos-move` | ② | 여러 장 폴더로 옮기기(원드라이브에서도 실제 이동) | `ids` ≤ 50, `parent_id` | 하나라도 폴더 밖이면 전부 거절 |
| `map` | ③ | 위치 있는 사진(id·위도·경도·날) | `bbox`(선택) | - |
| `trash-list`·`trash-restore`·`trash-empty` | ③ | B안 휴지통 | `ids`, `confirm` | - |
| `dupes` | ③ | 정리 도우미 묶음: 같은 `sha1`(같은 파일) · 같은 폴더에서 2초 안에 3장 이상(연사) | - | - |

- 옮기기·이름 바꾸기·만들기는 Graph `PATCH /me/drive/items/{id}`(`parentReference`·`name`)·`POST …/children`, `@microsoft.graph.conflictBehavior: fail`(덮어쓰지 않음). 여러 장은 Graph `$batch`(20개씩). 성공한 것만 색인 표를 바로 고치고, 나머지는 다음 `delta`가 맞춘다.
- 태그·별표는 Edge를 거치지 않고 화면이 owner RLS 표에 직접 쓴다(`app_diary_stars`와 같음). 여러 장 태그는 한 번의 insert(≤ 200행).
- **AI는 사진 내용을 읽지 않는다**(정리 도우미는 해시·시각·폴더만). 외부 공유는 명진이 공유창에서 직접 고른다(자동 발송 없음).
- 로그에는 오류 코드만(파일 이름·주소·위치 없음). 응답에 토큰 없음.

## 5. 화면 세부 기준

- 버튼은 UI-버튼기준: 칩·작업 줄 32px, 안내 줄 안 버튼 28px 글자 버튼, 누르는 범위 44px. 채운 큰 버튼 없음.
- 팝업·아래 판은 하단바 위에 뜬다(하단바에 가리지 않음, `--kptu-mobile-tab-height`만큼 띄움).
- 색은 `--kptu-*` 토큰만, 선택 표시는 강조색(`--kptu-primary`) 테두리 + 오른쪽 위 작은 체크.
- 중복 제목 없음: 칩 줄이 곧 제목. 안내문은 빈 상태에서만 한 줄.
- 사진 상태는 화면 하나가 소유(`photos-view.js` 가칭 한 곳)하고 렌더러도 하나다(AGENTS.md 5절). 일기와 공용인 것은 `diary-onedrive.js`의 호출·썸네일 부품뿐.
- 브라우저 저장은 썸네일 사본(#1362, 이미 있음)만. 거르기·칸 수·스위치는 서버 저장.

## 7. 범위 밖·남는 위험

- 권한은 넓히지 않는다. 그 대가로 원드라이브 휴지통에서의 되살리기는 Web2가 못 한다(2.3).
- 지우기·옮기기·폴더 바꾸기는 **실제 원드라이브 파일**을 바꾼다. 원드라이브 앱·다른 기기에도 바로 반영된다. 실수는 B안 휴지통(30일) + 원드라이브 휴지통(30일)으로 되살린다. 폴더 옮기기에는 되돌리기 작은 알림을 둔다.
- 사진이 아주 많을 때(수만 장) 첫 색인 다시 받기가 오래 걸린다. 받는 동안에도 기존 칸으로 그린다.
- 위치 `location`·동영상 길이·`sha1`이 개인 원드라이브에서 늘 채워지는지는 실제 계정으로 ① 뒤에 확인한다(채워지지 않으면 해당 기능만 빈다).
- 범위 밖 발견: 없음(이번 세션은 문서만).

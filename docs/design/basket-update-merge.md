## 0. 명진이 정할 것

일상어로 정리한다. 각 항목에 추천과 이유를 붙였다.

### 결정 U1. 합치는 깊이 — "화면만" 먼저 할까, "저장 장소까지" 한 번에 할까

- **가. 화면만 합치기(추천)**: 편집 창·이름·저장 버튼은 하나로 통일한다. 조직·프로젝트를 고르면 지금처럼 각 조직·프로젝트 기록 칸에 저장되고, 안 고르면 바구니에 미분류로 저장된다. 데이터 옮기기 없음.
- 나. 저장 장소까지 합치기: 조직 기록·프로젝트 기록도 모두 바구니 쪽 저장소 하나로 모으고, 기존 기록을 옮긴다.
- **추천 이유**: 명진이 원하는 "어디서 들어가도 같은 창, 고르면 거기 쌓이고 안 고르면 바구니"는 화면만 합쳐도 그대로 된다. 저장 장소를 합치려면 DB 변경·기존 기록 옮기기·주간보고 재료·Drive 읽기용 사본·홈 "이번 주 업데이트"를 한 번에 바꿔야 해서 위험과 작업량이 크다. 옛 결정(2026-10-09, 담당조직 기록을 바구니로 옮겨 통합 — 원장 BASKET-2b)은 그대로 두고, 필요하면 나중에 따로 한다.

### 결정 U2. 이름 — "메모"를 "업데이트"로 바꿀까

- **가. 바꾼다(추천)**: 바구니 탭 위 전환을 [업데이트 | 노트]로, 쓰기 창의 [메모 | 노트]도 [업데이트 | 노트]로. 홈 입력창의 [업데이트]와 같은 말이 된다.
- 나. 지금 그대로 [메모 | 노트].
- **추천 이유**: 같은 글을 홈에서는 "업데이트", 바구니에서는 "메모"라고 부르는 혼란이 없어진다. 이름만 바뀌고 저장된 내용은 그대로다.
- 주의: 바구니 탭 이름 "바구니" 자체는 그대로 둘 것을 추천(폰 하단 탭·주소가 이미 쓰는 이름).

### 결정 U3. 홈 입력창 탭 구성

- **가. [업데이트] [할 일] 두 개(추천)**: [바구니] 탭을 없애고 [업데이트]가 그 역할을 한다. 업데이트에서 조직·프로젝트를 안 고르면 바구니에 미분류로, 고르면 그 조직·프로젝트 기록으로.
- 나. 지금처럼 [바구니] [할 일] [업데이트] 세 개 유지.
- **추천 이유**: 지금 [바구니]와 [업데이트]의 차이는 "어디를 골랐냐"뿐이라 두 탭이 같은 일을 한다. 하나로 합치면 고민할 게 줄어든다.
- 기본으로 선택될 탭: [업데이트](지금 기본 [바구니]와 같은 동작 — 아무것도 안 고르면 바구니).

### 결정 U4. 조직·프로젝트를 고르고 저장한 업데이트가 바구니에도 보일까

- **가. 안 보인다(추천, 지금과 같음)**: 고른 업데이트는 그 조직·프로젝트 기록에만 쌓인다. 바구니는 "아직 어디로 갈지 안 정한 것" 모음으로 남는다.
- 나. 바구니 [분류] 쪽에도 같이 보인다(저장 장소까지 합쳐야 가능, U1-나 필요).
- **추천 이유**: 가는 DB 변경 없이 된다. 나는 같은 글이 두 군데 생기지 않게 하려면 저장 장소를 합쳐야 한다.

### 결정 U5. 큰 창에서 저장한 뒤

- **가. 저장하고 닫는다(추천)**: 지금 메뉴 [쓰기]의 큰 창 동작과 같다. 닫힌 뒤 "바구니에 저장했어요 / ○○ 기록에 저장했어요 / 노트로 저장했어요" 안내.
- 나. 저장하고 창에 머문다("저장됨" 표시).
- **추천 이유**: 업데이트는 짧게 쓰고 끝내는 경우가 많다. 노트를 오래 고칠 때는 나중에 "노트 고치기 중 중간 저장"을 따로 둘 수 있다(이번 범위 밖).

### 결정 U6. PC 사이드바 바구니 하위 메뉴 이름

- **[업데이트] [노트](추천)** — U2와 같은 이름. U2를 "그대로"로 고르면 [메모] [노트].

### 결정 U7. 작업 순서

- **추천**: PR 1(이름 바꾸기·홈 탭 정리) → PR 2(편집 창 하나 + 저장할 곳 고르기) → PR 3(PC 사이드바 하위 메뉴, UI-PC사이드바와 함께). DB 변경 없음. UI-노트편집버튼 ②(큰 창 저장)는 PR 2에 흡수.

### 1.2 바구니 메모와 조직·프로젝트의 연결

- 바구니 메모를 조직·프로젝트로 보내는 것은 **원문을 옮기지 않고 연결 표(`app_record_links`)에 한 줄**을 만든다: `note_id → organization_id` 또는 `project_id`, `status`(`suggested` 제안 / `confirmed` 확정), `summary`(기록에 보일 요약, 최대 2,000자). 저장 함수는 `app_basket_confirm_links`(SECURITY INVOKER, 본인 권한으로 실행).
- 조직 상세(`app/workplace-detail.js`)와 프로젝트 상세(`app/project-system-v3.js`)는 **자기 표의 기록 + 🧺 연결 기록**을 날짜순으로 섞어 한 목록으로 보여 준다. 🧺 줄을 누르면 원래 바구니 메모가 열린다.
- 즉 지금도 "조직·프로젝트 기록 목록"은 두 출처(직접 쓴 기록, 바구니에서 연결된 기록)를 이미 한 화면에 합쳐 보여 준다.

### 1.3 분류 상태(바구니 [미분류] [분류] [보류])

- 저장된 상태 칸은 없고 화면이 계산한다(`app/basket-data.js` `noteState`·`noteClassified`·`visibleNotes`).
  - **미분류**: 보류 아님 + 확정 연결 없음 + [자료로 넣기]·할 일 만든 적 없음. (제안만 있으면 미분류 쪽에 "정리 제안 있음"으로 남음)
  - **분류**: 확정 연결이 있거나, 첨부가 프로젝트·조직 자료로 들어갔거나, 할 일을 만들었음.
  - **보류**: `archived_at`이 있음.
- 조직·프로젝트 표에 직접 저장한 기록(1.1의 아래 두 줄)은 바구니에 나타나지 않는다(다른 표).

### 1.4 들어오는 길과 편집 창

공용 큰 편집 창은 `app/md-editor.js`의 `openMarkdownEditor` 하나다. 이 모듈은 **스스로 저장하지 않고**, 여는 쪽이 넘겨준 저장 동작만 부른다(파일 머리 주석). 여는 곳은 세 군데뿐이다.

| 들어오는 길 | 처음 보이는 창 | 큰 창 | 큰 창에 [저장] | 저장 대상 | 근거 |
| --- | --- | --- | --- | --- | --- |
| 메뉴 [쓰기] | 바로 큰 창 | 머리줄 [메모 \| 노트] 전환(기본 메모) | **있음** | 메모 → `app_notes` basket 새 행 / 노트 → `app_notes` note 새 행(제목 = 첫 줄) | `app/topbar-actions.js` `openWriter` |

**같은 큰 창인데 다르게 동작하는 지점(정리)**

1. [쓰기]로 열면 저장 버튼이 있고, 메모·노트 고치기에서 열면 저장 버튼이 없다(닫아야 원래 칸으로 돌아가 거기서 저장).
2. [쓰기]의 [메모|노트] 전환은 새 글에만 있다. 고치기로 열면 전환이 없다.
3. 홈·바구니 입력창은 큰 창으로 넘어가는 버튼 자체가 없다. 첨부(사진·파일)는 입력창에서만 되고 큰 창은 글만.
4. 조직·프로젝트 기록은 큰 창을 거치는 길이 없다.

### 1.5 UI-노트편집버튼 ②의 확인 질문에 대한 답(사실)

"저장 없이 X를 누르면 내용이 어디로 가나":
- 메모·노트 고치기에서 연 큰 창: **사라지지 않는다.** 입력할 때마다 원래 칸에 바로 들어가고(`onInput`), 닫을 때 원래 칸으로 돌려준다(`onClose`). 원래 칸에서 저장하거나 취소해야 끝난다.
- 메뉴 [쓰기] 큰 창: 글이 있으면 "저장 안 하고 닫을까요?"를 묻는다(탭 이동 시). 닫으면 그 탭이 열려 있는 동안만 기억해 다음 [쓰기]에서 이어 쓴다(브라우저 저장소에는 남기지 않음, `topbar-actions.js` `writeDraft`).

## 3. 편집 창 하나 + 저장할 곳 고르기 (설계)

### 3.1 모양

- 창은 지금 공용 편집기(`md-editor.js`) 하나. 작은 창 ↔ 큰 창은 **크기만** 다르고 같은 글·같은 저장 버튼.
- 저장 버튼 옆 [저장할 곳]: **[업데이트] [노트]** 두 칸 전환(지금 [쓰기]의 `kinds` 기능 재사용).
- [업데이트]를 고르면 그 아래(또는 옆)에 **[어디에 ▾]** 선택: 비워 두기(= 바구니 미분류) / 담당조직 하나 / 프로젝트 하나. 선택 창은 홈 [업데이트 ▾]의 기존 선택 창(`choice-sheet.js`, 최근 조직 + 전체 조직 + 프로젝트)을 그대로 쓴다.
- [노트]를 고르면 제목 칸이 보인다(비우면 첫 줄로 제목, 지금 [쓰기]와 같음).

### 3.2 어디서 들어오면 무엇이 미리 선택되나

| 들어오는 길 | 미리 선택 | 바꿀 수 있나 |
| --- | --- | --- |
| 메뉴 [쓰기] | 업데이트 · 어디에 = 비움(바구니) | 예 |
| 홈 입력창 | 업데이트 · 어디에 = 홈에서 고른 곳(없으면 비움) | 예 |
| 바구니 [업데이트] 쪽 입력창 | 업데이트 · 비움 | 예 |
| 바구니 [노트] 쪽 [+] | 노트 | 예 |
| 조직 상세 입력칸 → 큰 창 | 업데이트 · 그 조직 | 예(추천: 바꿀 수는 있게) |
| 프로젝트 상세 입력칸 → 큰 창 | 업데이트 · 그 프로젝트 | 예 |
| **이미 저장된 메모·노트·기록 고치기** | 그 종류·그 곳 고정 | **아니오**(종류를 바꾸는 것은 지금처럼 ⋯ [노트로 옮기기]·[바구니로 돌리기]로만) |

### 3.3 저장할 때 실제로 부르는 것 (새 저장 경로 없음)

| 고른 것 | 부르는 기존 저장 | 표 |
| --- | --- | --- |
| 업데이트 · 비움 | `basket-data.js` `createNote`(첨부 있으면 `basket-upload.js` `uploadBatch`) | `app_notes` basket |
| 업데이트 · 조직 | `quick-save.js` `saveOrganizationUpdate` | `app_suborganization_updates` |
| 업데이트 · 프로젝트 | `quick-save.js` `saveProjectProgress` | `app_project_progress_updates` |
| 노트 | `basket-data.js` `createNoteDoc` | `app_notes` note |
| 고치기 | 각 화면의 기존 저장(`updateNote`·`saveNoteDoc`·조직/프로젝트 기록 수정) | 원래 표 |

- 편집기는 지금처럼 **스스로 저장하지 않고** 여는 쪽이 넘긴 저장을 부른다. 저장할 곳 → 저장 함수 고르기는 한 곳(예: 작은 공용 모듈 하나)에 모아 길마다 따로 쓰지 않는다.
- 글자 수 한도가 표마다 다르다: 바구니 20,000자, 노트 100,000자, 조직·프로젝트 기록은 저장소에서 확인 못 함(**추정**: DB 제한이 없거나 다름). 착수 때 읽기 전용 확인 후, 고른 곳의 한도를 저장 전에 알려 준다.
- 첨부(사진·파일)는 **바구니(비움)로 저장할 때만** 된다(조직·프로젝트 기록 표에는 첨부 칸이 없음). 조직·프로젝트를 고른 상태에서 첨부를 넣으면 "첨부는 바구니로만 저장돼요"로 안내 → 사용자가 바구니로 바꾸거나 첨부를 뺀다. (대안: 바구니 메모로 저장한 뒤 그 조직·프로젝트로 확정 연결을 만들면 첨부도 함께 남는다. 이건 기존 `app_basket_confirm_links`로 되므로 DB 변경은 없지만, 같은 글이 바구니 [분류]에도 보이게 된다 — U4와 엮이므로 이번에는 넣지 않음을 추천.)

### 3.4 홈 탭 구성 제안

- 지금: [바구니] [할 일] [업데이트 ▾]
- 제안(U3-가): **[업데이트 ▾] [할 일]**. [업데이트]가 기본. ▾에서 아무것도 안 고르면 입력칸 안내 "바구니에 저장돼요", 고르면 "○○ 기록을 입력하세요"(지금 문구).
- 입력칸 오른쪽에 **[크게]**(큰 창 열기) 버튼 추가 — 지금 [할 일] 화면에만 있는 [+] 상세와 겹치지 않게 업데이트일 때만 보이기(UI-홈빠른입력상세와 함께 시안 확인).
- 저장된 "마지막 탭" 기억 값(`localStorage` `kptu-home-quick-mode`)에 옛 값 `basket`이 있으면 `update`로 읽는다(옛 값 호환).

### 3.5 바구니 탭

- 맨 위 전환 [메모 | 노트] → **[업데이트 | 노트]**(U2-가). 그 아래 [미분류] [분류] [보류]는 그대로.
- [업데이트] 쪽 목록은 지금 바구니 메모 목록 그대로(= 아직 바구니에 있는 업데이트). 조직·프로젝트로 바로 저장한 업데이트는 각 상세 화면에 있다(U4-가).
- 화면 제목·폰 하단 탭 이름 "바구니"는 유지(추천).

### 3.6 PC 사이드바

- [바구니] 아래 하위 메뉴 **[업데이트] [노트]**(U6). 누르면 바구니 화면의 해당 전환으로 들어감. UI-PC사이드바와 같은 PR(원장 비고대로).

## 4. UI-노트편집버튼 ②(큰 창 저장)와의 관계

- 원장 비고대로 지금 ②는 "열었던 화면의 저장을 그대로 부르는 최소 버튼"으로 먼저 진행할 수 있다.
- 이 설계의 PR 2가 들어가면 큰 창의 저장 버튼은 **모든 길에서 같은 버튼**이 된다: 새 글은 [저장할 곳]을 따르고, 고치기는 원래 화면의 저장을 부른다. 따라서 ②를 먼저 하더라도 버튼 위치(X 옆)·안내 문구를 PR 2와 같게 맞추면 다시 만들 일이 없다.
- 순서 제안: ②를 이미 시작했다면 먼저 merge하고 PR 2가 그 위에서 시작(AGENTS.md 2절 "줄 세우기"). 아직 시작 전이면 PR 2에 흡수.

## 1. 한 문장 요약

두 화면은 같은 일(글 하나 읽기)을 하는데 머리 줄·단추·글자 크기·실패 줄을 화면마다 따로 만들어 모양과 높이가 제각각이다. 공용 '글 보기 머리' 부품 하나로 두 화면을 같이 고치고, 찾기 줄은 공용 작은 높이(`--ds-compact-height`) 하나로 맞추며, 실패 까닭은 서버가 '로그인 필요'를 따로 알려 바르게 부른다.

## 4. 같은 부품으로 하나로 고칠 길

두 화면 모두 '글 하나 보기'다. 아래 셋을 공용 부품 하나씩으로 만들고 두 화면이 같이 쓴다(공통 원칙: 화면 CSS는 자리만).

1. **글 보기 머리**(새 공용 묶음, `app/ui-standard.css` 한 곳): 1줄 = 제목(두 줄까지, 말줄임 없음), 2줄 = 출처 · 날짜(+ 사업영역 꼬리표) 왼쪽 + 오른쪽 작은 아이콘 줄. 아이콘 줄은 모두 같은 높이 `--ds-compact-height`(32px)·테두리 없음·누르는 범위 44px(`::after`): [↗ 원래 페이지] [가−][가+] [복사] [⋯]. ⋯ 안(공용 작은 메뉴 `anchored-menu.js`):
   - 저장한 글: 수정(직접 넣은 줄만) · 밑줄을 노트로 n · 사업에 연결 · 안 읽음으로/읽음 · 원문 다시 가져오기 · 삭제
   - 읽을 거리: 저장/저장됨 ✓ · 메모 · 관심 없음 · 번역(외국어만) · 원문 다시 가져오기 · 직접 넣기
   - 이름은 `ui-words.md` 그대로(원래 페이지 하나로 통일 — '원래 사이트 ↗'를 '원래 페이지 ↗'로, 용어표에 한 줄 더함).
2. **실패 줄**: 한 줄 작은 글자(`--ds-text-meta`) + 끝에 글자 버튼 [다시 가져오기](`row-act`). 까닭 말 다섯: 로그인이 필요한 페이지예요 / 유료 기사라 앞부분만 있어요 / 이 사이트가 읽기를 막아 두었어요 / 사이트가 늦게 답해요 / 본문을 찾지 못했어요.
3. **찾기 줄 높이**: 찾기 칸·[매체 ▾]·⋯ 모두 `--ds-compact-height`. 화면 CSS의 `30px` 두 곳을 없애고 토큰만 쓴다. ⋯는 공용 ⋯ 부품의 32px 크기를 쓴다(바탕 26px `.os-more`는 줄 안에서만 쓰는 크기).

그 밖에: 안내문(`rd-tip`) 삭제 — 처음 한 번 알림은 이미 고른 글 막대가 한다(#3038 뒤). 메모 칸은 빈 상태에서 한 줄 '메모 남기기…' 칸, 누르면 커짐(공용 메모 부품 쪽 고침 — 노트·자료실 메모도 같이 한 줄이 됨).

## 7. 범위 밖 발견사항

- 같은 '높이 숫자 직접 쓰기'(`height:30px`·`26px`)가 `now.css` 105줄 `.ni-btn,.nd-act{height:26px}`에도 있다. ①에서 찾기 줄만 고치고, 나머지는 S70-25 여백 점검 표에 넘긴다.
- 메모 공용 부품을 한 줄 칸으로 바꾸면 노트·자료실·사업 보고 메모도 같이 바뀐다(공통 원칙상 맞는 방향이지만 ③ PR 본문에 쓴 곳 표를 적는다).

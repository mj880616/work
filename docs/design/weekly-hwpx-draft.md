## 1. 원본 분석 (구조만)

분석 방법: HWP 5 원본을 저장소의 rhwp 엔진(`@rhwp/core` 0.8.7, `scripts/hwp-lab/rhwp-pin.json` 고정본)으로 .hwpx로 바꾼 뒤 시제품 읽기 도구(`app/weekly-hwpx/report.mjs`)로 표를 읽었다. 같은 결과를 HWP 5 레코드(DocInfo 스타일 표, BodyText 문단·표·칸 레코드)를 직접 읽어 대조했다. 원본·변환본·중간 결과는 비공개 작업 폴더에만 두었다.

### 1.1 쪽·글꼴·스타일 (사실, 7개 파일 모두 같음)

- 쪽: A4 세로, 왼쪽·오른쪽 여백 20mm, 위·아래 15mm, 머리말·꼬리말 10mm, 쪽 테두리 있음.
- 글꼴 5종: 함초롬돋움·함초롬바탕·휴먼고딕·HY견고딕·HY견명조.
- 스타일 이름과 글자 크기는 `hwp-style-map.md` 2절 표와 같다(바탕글 13pt, 안건제목 36pt, 큰 제목 18pt, 중간 제목 16pt, 작은 제목 14.5pt 굵게, 최하위 제목[강조] 13.5pt, 세부 참고사항 11pt·왼쪽 20pt, 표내부 10pt, (기타)의결주문 13pt, 중간대제목 28pt 굵게, 문서표지제목 44pt, 쪽 번호 14pt, 각주 9.5pt). 줄간격: 바탕글·제목 180%, 안건제목·세부 참고사항 160%, 표내부 150%.
- 스타일 수: 팀 전체본 14개(양식 13 + 사본 1), **개인본 46개**(양식 13 + 다른 문서에서 붙여 넣을 때 딸려 온 스타일 33개 — 엑셀 칸 스타일·"사본" 스타일 등). 팀 전체본에서 서식을 뽑으면 이 군더더기가 없어진다.
- 표 안 글: '표내부' 스타일(휴먼고딕 10pt). 표 머리 줄은 옅은 색 칠 + 가운데 맞춤, 테두리 0.12mm 실선. 요약 표는 쪽이 넘어가면 머리 줄을 되풀이한다.
- 색 관례: 팀 전체본은 이번 주에 새로 들어오거나 바뀐 글을 **파란 글씨**(표내부와 같은 크기·글꼴, 색만 다름), 참석 요청 표의 바뀐 일정을 **빨간 글씨**로 쓴다(글자 수 기준 파란 글씨가 본문의 약 12%). 이 글자 모양들은 양식 파일 안에 이미 있다.

### 1.3 개인본 차례와 팀본과의 차이 (사실)

| | 개인본(6주 모두) | 팀 전체본 |
| --- | --- | --- |
| 1. 요청사항 | 1) 참가 요청 표(3열). 어떤 주는 2) 논의 요청 + 기획안 상자·할 일 표(할 일 \| 담당 \| 기한) | 1) 표(4열 격자) + 2) 주요 일정 |
| 2. 기본·영역·의제 사업 | 1) 요약 표(4열, **머리 + 29줄 고정**, 내 줄 말고는 빈칸) + 회의 결과 상자 (1)(2)… | 1) 요약 표(머리 + 34줄, 팀원 전부) + 2) 세부 내용 |
| 3. | 없음(번호를 건너뜀) | 투쟁 사업 |
| 4. 산하 조직 현황 | 1) 요약(2열, 머리 + 내 담당 조직 13줄), 2) 참고자료(상자), 3) 가입상담 | 4. 산하조직 현황(팀 전체 조직) |
| 5. 주요 일정 | 3열 표(7~16줄) + "※ 휴가" 줄 | 같은 모양, 팀 전체 |

- **요약 표 틀이 다르다.** 개인본은 옛 틀(29줄)을 6주 내내 그대로 썼다. 팀본에만 있는 세부 과제가 6개(새 사업영역 1개 포함, 모두 다른 팀원 담당이거나 담당 없음), 이름이 다른 세부 과제가 2개(낱말 하나 차이 1개, 띄어쓰기 차이 1개), 개인본에만 있는 빈 세부 과제 1개, 개인본 끝의 이름 없는 빈 줄 4개. → 개인본을 팀본 틀에 맞추면 팀장이 줄을 옮겨 붙일 일이 없어진다(이번 요청의 핵심).
- 내 담당 줄 수: 개인본 5→5→5→5→6→7줄. 팀본(10/19)에서는 6줄(개인본에서 끝난 항목 1줄이 팀본에서 빠짐).
- 팀장이 내 줄을 고친 정도(10/19 개인본 → 10/19 팀본): 내 줄 35문단 중 30문단 그대로, 2문단 문구 다듬음(기호 바꿈·낱말 빼기), 1줄(3문단) 정리해서 뺌.

### 1.4 개인본 6주 동안의 변화 (사실)

- 틀(쪽·스타일·차례·요약 표 29줄·조직 표 13줄)은 6주 동안 같다. 바뀐 것은 내용·요청 표 줄 수(1~7개)·회의 결과 상자 수(0~3개)·주요 일정 줄 수.

### 1.5 정리 — 초안이 지켜야 할 규칙

1. 틀은 지난주 팀 최종본의 요약 표(줄 순서·사업영역 병합·세부 과제 이름)를 그대로 쓴다.
2. 내 이름이 담당 칸에 있는 줄만 채우고, 나머지 줄의 진행·담당 칸은 비운다(세부 과제·사업영역 이름은 남김 — 팀장이 합칠 때 줄이 맞도록).
3. 팀장이 다듬은 내 줄 문구가 바탕이다. 이번 주에 바뀐 사실이 없는 줄은 손대지 않는다.
4. 새로 더한 줄·고친 줄은 파란 글씨(W5). 끝난 일은 빼는 제안만 하고 사람이 정한다.
5. 날짜("■ 일시")는 보고 주 월요일로 자동. 제목 줄도 자동.
6. 스타일·글자 모양·표 테두리는 확정본에서 뽑은 것만 쓴다(새로 만들지 않음).

## 4. 이번 주 바뀐 것만 고치기

### 4.1 흐름

1. 확정본 → 내 칸 바탕(`personalFromTeam`): 요약 표 틀 그대로, 내 줄만 남김.
2. 이번 주 재료(2절)를 모음.
3. AI에 **내 줄 글 + 이번 주 재료**를 주고 "고칠 목록"만 받음:
   - `add` — 어느 줄(사업영역·세부 과제, 같은 과제 여러 줄이면 몇 번째) 어디 뒤에 새 문단
   - `replace` — 바꿀 문단 **원문 그대로** + 새 문장(예: 지난주 "…예정"이 이번 주 일이 되어 "…완료")
   - `remove` — 뺄 문단 원문(끝난 일)
4. 화면이 목록을 검사(`applyPatch`): 내 줄이 아니면 거절, 바꿀 원문이 바탕에 정확히 없으면 거절, 이번 주에 이미 고친 줄을 또 고치면 거절. 거절된 항목은 버리지 않고 "확인 필요"로 보여 준다.
5. 줄마다 [받아들이기]/[버리기]. 받아들인 줄만 파란 글씨로 들어간다.
6. .hwpx(또는 HWP) 내려받기.

문단·표 줄 단위 대조는 시제품 `diffLines`(문단 단위 최장 공통 순서)와 `diffRows`(줄 짝짓기)를 쓴다. 비교 화면에서 "지난주 그대로 / 고침 / 새 줄 / 뺌"을 보여 줄 때도 같은 함수를 쓴다.

### 4.2 AI가 맡을 것 / 사람이 확정할 것

| AI(ChatGPT, 서버 `ai-assist`) | 사람(명진) |
| --- | --- |

- 지금 `ai-assist`는 요청 2KB·답 800토큰 상한이라(`supabase/functions/ai-assist/handler.ts` `MAX_BODY_BYTES`, `MAX_OUTPUT_TOKENS`) 이 쓰임에는 작다 → 새 kind와 상한은 3단계에서 Edge 재배포(정지 지점).

## 5. .hwpx를 어디서 만들까 — 브라우저(추천, W6)

## 6. .hwpx가 안 열릴 때 (W8)

### 12.2 생성기에 반영한 규칙

1. 차례: 제목 → 빈 바탕글 → "■ 일시" → 빈 바탕글 → 1. … 요청 표 → 빈 작은 제목 문단 → 2) 주요 일정. (시험: "사용자가 한글에서 고친 서식")
2. 칸 높이(`layout.mjs`): 칸 높이 = 위·아래 안쪽 여백 + Σ(문단 줄 수 × (글자 크기 + 줄 사이 간격)) − 마지막 줄 간격. 줄 사이 간격 = 글자 크기 × (줄간격% − 100). 표내부(10pt·150%·여백 285)는 1줄 1570, 2줄 3070, 3줄 4570 — 고친 판의 값과 같다. 줄 수는 글자 종류별 폭(한글 0.9, 숫자 0.43, 영문 0.5, 빈칸 0.45, 기호 0.3~0.6 × 글자 크기)으로 어림한다. 고친 판 2개와 팀 확정본 표 칸 1,418문단의 실제 줄 수와 98.6% 맞고, 많게 센 것은 0.4%(한글은 칸 높이를 최소 높이로 보아 모자라면 늘리므로 적게 세는 쪽이 안전).
3. 세로로 합친 칸 = 걸친 줄 높이의 합, 줄 높이 = 그 줄의 합치지 않은 칸 중 가장 큰 값, 합친 칸 글이 더 길면 마지막 줄을 늘린다. 표 크기 = 열 너비 합 × 줄 높이 합.
4. 열 너비·여백·문단 모양·글자 모양·테두리는 확정본 그대로 둔다(사용자가 바꾸지 않음). 줄은 문단으로 나누고 강제 줄바꿈을 쓰지 않는다.
5. 줄 배치 정보(`linesegarray`)는 계속 넣지 않는다(한글이 열 때 만든다).

v2 시연본(비공개)과 고친 판 비교: 앞부분 차례(빈 줄 포함) 같음, 열 너비 모든 칸 같음, 요약 표 줄 높이 36줄 중 33줄 같음·3줄은 v2가 한 줄(1500) 낮음(한글이 늘림), 가장 높은 칸이 약 34cm → 약 15cm로 줄어듦.

## 13. 2단계 — 업무일지 [주간 정리]에서 한글 파일 만들기 (2026-10-21)

### 13.1 흐름(사용자 화면)

[주간 정리] 맨 위 [주간보고 한글 파일 만들기] → 상자가 열린다.

1. **지난주 확정본 고르기**: [자료실 최신 "주간보고 확정본" 쓰기](자료실 분류 이름이 정확히 "주간보고 확정본"인 가장 최근 자료, 기존 `document-actions` `hwp-open`으로 기기에 받음) 또는 [기기에서 파일 고르기](.hwp·.hwpx, 30MB까지). 없으면 "분류 자료가 없어요"로 멈춘다.
2. **바탕 만들기(기기 안)**: HWP 5면 HWP 편집기와 같은 칸막이 엔진(`hwp-frame.js` sandbox iframe, 숨김)이 .hwpx로 바꾼다. 확정본을 읽고(`readReport`) 빈 서식을 뽑아 **빈 서식 검사**(`assertBlank` + 확정본 글 조각 `reportWords`)를 통과해야 다음으로 간다. 요약 표·양식 표를 못 찾거나 검사에 걸리면 멈추고 아무것도 만들지 않는다.
3. **고칠 칸**: 담당 팀원 칸의 내 이름(프로필 이름, 화면에서 고치면 바탕을 다시 만듦)과 ■ 일시(보고 주 월요일, 고칠 수 있음). 요약 표의 **내 줄**과 산하조직·투쟁 사업장 표의 **내 담당 조직 줄**(`my-organizations.js`, 별칭·띄어쓰기 무시)만 줄마다 글 칸으로 보인다. 담당 사업장이 없으면 모든 활성 조직을 내 조직으로 보고 그렇다고 알린다.
4. **이번 주 기록 붙이기**: 같은 주 [주간 정리] 묶음의 기록을 사업영역·세부 과제 이름이 같은 줄 옆에, 조직 소식을 같은 조직 줄 옆에 보이고 [붙이기]로 "- 내용" 한 줄을 더한다(3단 기록은 "- 사안: 내용"). 이름이 맞지 않는 기록은 "줄을 찾지 못한 이번 주 기록"에 모아 붙일 줄을 고른다(짝은 기억하지 않음 — 13.4).
5. **받기**: [한글 파일 만들기(.hwpx)] → `주간보고_YYYYMMDD.hwpx`(규격 검사 통과한 것만 내려받음). [HWP로 받기]는 같은 엔진이 HWP 5로 저장(W8). 바탕과 글자가 다른 줄(새 줄·고친 줄)만 파란 글씨(W5).
6. **[확정]**: 한 번 묻고 그 파일을 기존 `library-files`로 자료실에 1회 저장한다(분류 **"주간보고 개인본"**, 제목 "주간보고 (■ 일시)", 자료 날짜 = 보고 주 월요일). 제목을 주므로 서버는 파일 내용으로 제목을 추측하지 않는다. 결과를 모르면 다시 보내지 않고 자료실을 먼저 보라고 한다. 같은 초안은 한 번만 저장한다.

- 1. 요청사항 표는 설계대로 직전 주 확정본 그대로 + "※ 직전 주 확정본 그대로임 — 이번 주 확인 필요"(12.3절). [주간 정리] 탭의 보류 3개(초안 복사 순서, 요청사항 입력, 주요 일정 위치)는 바꾸지 않았다.

### 13.3 산하조직 표 줄별 테두리 (12.3절 마지막 위험 해소)

확정본 산하조직 표(비공개 원본 확인, 테두리 번호·굵기만 봄): 바깥 왼쪽·오른쪽 0.15mm, 조직 묶음 사이 위 선 0.15mm, 같은 조직이 이어지는 줄은 위 선 없음, 칸 사이 0.12mm — 줄마다 테두리가 다르다. 1단계는 견본 줄 하나의 테두리를 모든 줄에 썼다.

- 2단계: 확정본 줄마다 칸 테두리 번호를 읽어(`pairsFromTable` `borders`) 개인본 줄에 그대로 쓴다(`pairGrid`). 테두리 번호는 양식 머리(header.xml)에 이미 있는 것만 쓰고 새로 만들지 않는다(머리는 한 글자도 안 바뀜 — 시험).
- 내 담당 조직만 남기면 바로 위 줄이 빠지는 줄이 생긴다(`cutAbove`). 그 줄의 위 선이 "없음"이면 위 선만 다르고 나머지가 같은 양식 안 테두리로 바꾼다(없으면 그대로).
- 투쟁 사업장 표도 같은 2열 표라 같은 규칙을 쓴다. 사람이 새로 더한 줄(테두리 정보 없음)은 견본 줄 테두리.
- 비공개 확인: 팀 확정본(산하조직 92줄)에서 5개 조직을 골라 만든 표의 줄 테두리가 확정본 줄과 같고 규격 검사 통과.

- **기간(사용자 결정)**: 금요일에 개인 보고를 쓰고 일요일에 합쳐 월요일 상집에 보고하므로, 쓰는 때 기준 **다음 주 월요일부터 2주(월~일 × 2, 14일)** — 보고일(월) 기준으로는 "보고하는 그 주 + 그다음 주". 화면은 오늘이 아니라 **보고 있는 주**로 정한다(보고 있는 주의 다음 월요일부터 14일). 목·토·일에 써도 같은 주를 보고 있으면 같은 2주다. 지난 주를 열어도 그 주 기준이라 바뀌지 않는다.
- **표 모양(사실, 비공개 확정본·개인본 7개를 구조만 확인)**: 주 구분 줄 없이 날짜가 이어진다. 개인본은 14일을 하루 한 줄씩 모두 적고(일정 없는 날도 날짜만), 같은 날 일정이 여럿이면 날짜 칸을 세로로 합친다. 날짜는 "M.D.(요일)", 여러 날 일정은 "M.D.(요일) ~ M.D.(요일)" 줄을 따로 둔다. 내용 칸은 "HH:MM / 행사 / 장소"(종일은 "종일"). 표 글은 모두 검은 글씨(파란 글씨 아님). 표 아래 빈 줄 하나 다음에 "※ 날짜 이름 휴가·반차" 줄.
- **채우는 법**: 업무일지가 이미 쓰는 Google Calendar 읽기(google-calendar `events`, 선택한 캘린더)를 2주 범위로 한 번 더 읽는다(새 서버·DB 없음). 참석자 칸은 담당 팀원 칸의 내 이름. 제목에 휴가·연차·반차·월차·병가·공가·휴무가 있으면 표가 아니라 "※ 10.23.(금) 이름 연차" 줄로. 제목이나 메모에 "일기"·"비공개"가 있는 일정은 뺀다(지금 읽기에는 Google의 비공개 표시가 오지 않아 글로 표시한다).
- [주간 정리] 5번 묶음은 같은 2주를 일정 있는 날만 표로 보이고, 휴가는 "※ 휴가: 10/23(금) 연차" 한 줄. [주간보고 초안 복사]도 양식 순서(1 → 2 → 4 → 5 → 참고)로 같은 묶음을 글로 복사한다(사용자 승인). 이번 주 일정은 하루 카드에만 있고 [주간 정리] 참고에서는 빠졌다.

## 1. 지금(사실, main 기준)

| 무엇 | 어디 | 비고 |
| --- | --- | --- |
| 쓰기 | `app/ledger-auto.js` → `ai-assist` `ledger_auto` | 재료(업데이트·노트·업무일지 한 줄·사업 보고·담당조직 기록·프로젝트 기록·사업 기록·통화·참고 일정) 저장 신호를 받아 마지막 저장 10분 뒤(처음부터 길어도 30분) 한 번. 아직 안 본 원문만(`app_ledger_auto_sources`). 입력 상한 6만 자, 답 상한 3천 토큰, 한 번 새 기록 20개까지 |
| 읽기 | 교섭 전 한 장·다음 주 준비 한 장('약속'), 홈 '내일 약속', 업무일지 '새로 기록된 약속', 담당조직 주요 인물, 전체 검색 | 모두 '약속(commitment)' 위주. 주간 보고 초안은 원장을 안 읽음 |
| Claude용 | `app/ledger-export.js` → Drive 'Claude용 원장 사본'(한 시간 1번 상한) | 사용자. MCP-Claude읽기는 설계·입구 초안(#2524) |
| 비용 장치 | 사람별 한 달 AI 한도(사용자 외 3,000원), 일일 사용 표 `app_ai_daily_usage` | 운영 모델 단가 입력 140원·출력 700원 / 100만 토큰(`_shared/ai-model.ts` 기본값) |

문제: 기록은 쌓이는데 **읽는 쪽이 약속 몇 줄뿐**이라 비용 대비 쓰임이 작다. 또 뒤의 AI들(교섭 전 한 장·주간 보고 초안·조직 한 줄 등)이 각자 원문을 다시 크게 읽어 같은 내용을 여러 번 AI에 보낸다.

## 2. 목표 그림 — "상황 카드"

원장 기록(사실 하나하나)은 그대로 두고, 그 위에 **대상별 상황 카드**를 하나씩 둔다.

- 대상: 담당조직 하나, 사업영역(프로젝트) 하나, (선택) 교섭 하나.
- 카드 내용(짧게, 대상마다 1개, 덮어쓰기 + 판 기록):
  1. 지금 상황 3줄(무엇이 진행 중인지)
  2. 다음 일정·마감(날짜)
  3. 열린 약속·요청(누가 누구에게, 언제까지)
  4. 최근 바뀐 것(지난 카드 이후)
  5. 근거 — 원장 기록 ID·원문 링크(줄마다)
- 원칙: AI는 제안까지만(사실은 원문 근거가 있어야 카드에 들어감). 사용자가 카드 줄을 고치거나 빼면 다음 갱신이 그걸 지킨다(사람 수정 우선). 기존 원장 기록은 고치지 않고 더하기만(현행 규칙 그대로). S2(교섭·전략) 기록 제목을 AI에 보내지 않는 현행 규칙 그대로.

## 3. 효율화 — 덜 부르고, 덜 보내고, 한 번 만든 걸 여러 곳에서

| # | 방법 | 효과 |
| --- | --- | --- |
| E1 | **카드를 재료로 재사용**: 교섭 전 한 장·다음 주 준비·주간 보고 초안·조직 한 줄·제안은 원문 대신 해당 대상 카드(+ 카드 이후 새 기록만)를 읽는다 | 뒤 AI 입력이 크게 줄어듦. 가장 큰 절약 |
| E2 | **바뀐 대상만 갱신**: 새 기록이 붙은 조직·사업 카드만 고쳐 쓴다. 바뀐 게 없으면 AI를 부르지 않는다 | 조용한 날은 0번 |
| E3 | **묶는 간격 늘리기**: 지금 10분 묶음 → 하루 2번(낮 12시대·저녁 6시대, 사용자가 앱을 연 때 이어서) + '약속·마감'처럼 급한 것만 저장 뒤 바로 | 호출 수가 하루 많아야 2~3번 |
| E4 | **두 단계 나누기**: ① 사실 뽑기(작은 싼 모델, 원문→기록) ② 카드 고쳐 쓰기(바뀐 대상만, 카드+새 기록만 입력) | 큰 입력은 싼 모델만 받음 |
| E5 | **AI 없이 되는 것은 규칙으로**: 날짜만 바뀐 일정, 한두 단어 업데이트, 같은 원문 재저장(내용 같음)은 AI를 안 부름 | 잔 호출 제거 |
| E6 | **보내는 양 줄이기**: 6만 자 상한을 대상별로 나눠 낮추고, 이미 본 원문·이미 카드에 든 사실은 안 보냄 | 한 번 비용 축소 |
| E7 | **상한과 우선순위**: 사람별 한 달 한도 안에서만. 한도 80%가 되면 카드 갱신은 하루 1번으로 줄이고 버튼으로 부르는 기능을 먼저 살림 | 예산 초과 없음 |
| E8 | **보이게 관리**: 운영자 화면에 사람별·기능별 AI 비용(이번 달), 카드 갱신 수·건너뛴 수 | 다음 효율화 근거 |

비용 감 [추정, 6절 실측으로 바꿈]: 카드 갱신 하루 2번 × 한 번 약 5~10원 → 한 사람 한 달 300~600원. 구독료 월 4,900원 안에서 감당. 뒤 AI들은 E1로 지금보다 싸짐.

## 4. 활용 — 선순환(쓰면 쌓이고, 쌓이면 더 잘 도와줌)

| 어디 | 무엇이 좋아지나 |
| --- | --- |
| 담당조직·사업 상세 맨 위 | '지금 상황' 3줄 + 다음 일정 + 열린 약속(줄 누르면 근거 원문) |
| 교섭 전 한 장 | 카드에서 쟁점·지난 합의·열린 약속 → 더 정확하고 빠름 |
| 다음 주 준비 한 장 | 대상별 '다음 일정·마감'을 모아 한 장 |
| 주간 보고 초안 | 칸마다 해당 조직·사업 카드의 '최근 바뀐 것'을 재료로 → 손 덜 감 |
| 회의 결과 쓰기 | 저장 뒤 '이 회의로 카드가 이렇게 바뀌어요' 한 줄(제안만, 확인은 사람) |
| 홈 [하루] | '이번 주 흐름' 3줄, 놓친 약속 |
| 전체 검색 | "○○지부 지난 3달" → 카드 + 시간순 기록 |
| 사용자만 | Claude용 Drive 사본에 카드도 포함(또는 MCP-Claude읽기에서 카드 읽기) |

선순환 고리: 기록을 쓸수록 카드가 좋아짐 → 초안·제안이 좋아짐 → 사람이 고친 것(사람 수정 우선)이 카드에 반영 → 다음 초안이 더 좋아짐. 원장 화면을 따로 관리할 필요 없음.

## 5. 지킬 것

- 각자 자기 작업공간만(카드도 작업공간 주인만 읽고 씀, RLS 그대로). 팀 공유(주간 보고 모으기)는 사람이 누른 복사본만 — 카드는 보내지 않는다.
- 사용자 텔레그램 수집(업무방·1:1·가족)은 다른 사람 카드에 절대 들어가지 않음(사용자 작업공간 안에서만).
- 일기·보관·AI 내보내기 비허용 기록은 재료에서 뺌(현행 그대로).
- 무료 계정: 카드 갱신·카드 읽는 AI 모두 꺼짐. 이미 만든 카드는 읽기만(지우지 않음).
- `supabase db push`·`migration repair` 금지, DB는 시험 적용 먼저(AGENTS.md 7절).

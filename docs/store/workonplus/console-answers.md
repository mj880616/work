# WORK ON+ 플레이 콘솔 '앱 콘텐츠' 답안 초안

S69-11. CC가 플레이 콘솔(앱 `com.workonplus.app`)에 넣을 답의 초안이다. 플레이 판(play flavor) 기준이며, 권한·패키지 근거는 `docs/design/play-store-workonplus.md`(S69-10)와 `about/privacy/` 2-2절이다.
콘솔 화면의 질문 글은 바뀔 수 있으니, 아래 뜻대로 맞는 칸을 고른다. 비밀번호·토큰·개인 메일은 이 문서에 쓰지 않는다.

## 1. 개인정보처리방침

- 주소: `https://work.bokdoong.com/work/about/privacy/` — 구글 로그인 동의 화면(브랜딩)에 걸린 주소와 같다. 같은 페이지가 `https://workonplus.com/work/about/privacy/`에서도 열린다(Worker가 `about/`를 그대로 냄).
- 페이지 이름·첫 줄이 앱 이름 'WORK ON+'와 같다.

## 2. 앱 액세스

- 답: **일부 기능에 제한이 있음**(로그인해야 씀).
- 안내 글(초안):

```
WORK ON+는 Google 계정 로그인 후에 쓰는 개인 업무 앱입니다. 심사용 Google 계정으로 로그인하면 모든 기능(일정·할 일·노트·사진·저장한 글·기능 잠금)을 볼 수 있습니다. 구글 캘린더·할 일 연결은 앱 안 [연결]을 눌러 동의하면 켜집니다. 첫 로그인 때 Google 확인 화면이 나오면 '계속'을 누르세요.
```

- 심사용 계정: 사용자가 심사 전용 Google 계정을 하나 만들고(2단계 인증 없이, 개인 자료 없음), **아이디·비밀번호는 콘솔의 '로그인 정보' 칸에만 직접** 넣는다. 저장소·채팅·PR에는 쓰지 않는다.
- 이 계정은 가입 막기 목록에 넣지 않는다. 가입 스위치(`app_workspace_signup`)가 켜져 있어야 첫 로그인 때 작업공간이 생긴다 — 심사 전에 CC가 켜짐 여부만 확인.

## 3. 광고

- 답: **아니요, 광고가 없음**.
- `AD_ID` 권한: 앱 매니페스트에는 없다. 라이브러리(FCM)가 넣는 경우가 있으니 AAB를 올린 뒤 콘솔이 '광고 ID' 질문을 내면 **광고 ID를 쓰지 않음**으로 답한다(S69-10 점검표).

## 4. 콘텐츠 등급(IARC 설문)

- 카테고리: **유틸리티, 생산성, 커뮤니케이션 또는 기타**(게임 아님).
- 폭력·성적 내용·욕설·마약·도박·공포: 모두 **아니요**.
- 사용자끼리 소통·콘텐츠 공유(채팅, 다른 사용자에게 공개되는 글): **아니요** — 각자 자기 작업공간만 보고, 다른 사용자에게 보이는 게시판·채팅이 없다. (사용자가 직접 만든 공유 링크로 한 항목을 남에게 보여 주는 기능은 있으나 공개 피드·대화가 아니다. 설문에 '사용자 생성 콘텐츠 공유'를 따로 묻는다면 이 문장을 그대로 적고 **예**로 답해도 등급은 같다.)
- 사용자 위치 공유: **아니요**(사진의 촬영 위치 정보를 본인이 보고 고치는 기능뿐, 남에게 위치를 보내지 않음).
- 디지털 상품 구매: **아니요**.
- 예상 결과: 전체이용가(IARC 3+ / 한국 전체).

## 5. 타깃층

- 대상 연령: **18세 이상**만 선택(처리방침에는 만 14세 미만 가입 대상 아님). 아동을 대상으로 하지 않음.
- '어린이의 관심을 끌 수 있는 앱인가': **아니요**(업무용 도구, 그림·문구에 어린이 대상 요소 없음).

## 6. 데이터 보안 양식

공통 답

| 질문 | 답 |
| --- | --- |
| 필수 데이터 유형을 수집·공유하나 | 예 |
| 전송 중 암호화 | 예 — 모든 연결 HTTPS(앱 `usesCleartextTraffic=false`) |
| 사용자가 데이터 삭제를 요청할 수 있나 | 예 — 앱 안 내 프로필 › 계정 › [계정 삭제](바로 삭제), 웹 주소 `https://workonplus.com/work/about/delete-account/` |
| 독립 보안 검토(MASA) | 아니요 |

수집 항목(모두 '수집', 판매·광고 없음. '공유'는 아래 따로)

| 데이터 유형(콘솔 이름) | 무엇 | 목적 | 필수/선택 | 처리 |
| --- | --- | --- | --- | --- |
| 개인 정보 › 이름 | Google 기본 정보 이름, 프로필에 직접 넣은 이름 | 계정 관리, 앱 기능 | 필수(로그인) | 서버 저장 |
| 개인 정보 › 이메일 주소 | Google 로그인 이메일 | 계정 관리 | 필수 | 서버 저장 |
| 개인 정보 › 사용자 ID | Google 계정 식별자, 앱 계정 ID | 계정 관리 | 필수 | 서버 저장 |
| 사진 및 동영상 › 사진 | 사용자가 골라 올린 사진(노트·하루 기록·자료) | 앱 기능 | 선택 | 본인 Drive·서버. 폰 사진 목록 자체는 폰 안에서만 쓰고 보내지 않음 |
| 오디오 › 음성 또는 음향 녹음 | 회의 [녹음] 파일 | 앱 기능(받아쓰기) | 선택 | 본인 Drive, 받아쓰기 때 AI 업체로 전송 |
| 파일 및 문서 | 사용자가 올린 자료 | 앱 기능 | 선택 | 본인 Drive |
| 캘린더 › 캘린더 일정 | 연결한 Google 캘린더 일정 | 앱 기능 | 선택 | 화면 속도를 위한 사본 |
| 앱 활동 › 기타 사용자 생성 콘텐츠 | 노트·메모·할 일·하루 기록·저장한 글·밑줄·보내 온 의견 | 앱 기능 | 필수(앱의 본 기능) | 서버 저장 |
| 앱 활동 › 앱 상호작용 | 가입일·마지막 사용 시각, AI 기능 사용량 숫자 | 계정 관리, 분석 아님(사용량 한도) | 필수 | 서버 저장 |
| 기기 또는 기타 ID | 폰 알림 주소(FCM 토큰) | 앱 기능(알림) | 선택(알림 켤 때) | 서버 저장 |

수집하지 않음: 위치(대략·정확), 연락처, 문자·통화 기록, 금융·건강 정보, 웹 방문 기록, 광고 ID, 비정상 종료 기록·진단(분석 도구 없음).
'일시적 처리'로 볼 수 있는 것: 없음(위 항목은 저장한다).

공유(제3자 전송) — 콘솔 정의상 '서비스 제공업체에 맡겨 처리'는 공유에서 빠진다. 그래서 아래는 **공유 아님**으로 답하고 근거만 적어 둔다.

- 서버·호스팅: Supabase, GitHub Pages, Cloudflare — 서비스 제공업체(위탁).
- 폰 알림 전달: Google Firebase Cloud Messaging — 서비스 제공업체.
- AI 처리: OpenAI API(요약·초안), Google Gemini API(녹음 받아쓰기) — 사용자가 그 기능을 누를 때 필요한 내용만 보내는 서비스 제공업체. 학습에 쓰지 않음(처리방침 5절).
- Google 캘린더·할 일·Drive: 사용자가 직접 연결해 **본인 계정**과 주고받는 것 — 사용자가 시작한 전송.

## 7. 그 밖의 신고

- 포그라운드 서비스: `dataSync`(고른 사진·자료를 끝까지 올리기), `microphone`(회의 녹음, 화면 꺼도 이어짐). 둘 다 사용자가 시작하고 알림을 띄운 채 동작. 동영상 시연이 필요하면 CC가 실기기 화면 녹화 요청을 사용자에게 한다.
- 정부 앱·금융 기능·건강 앱·뉴스 앱: 모두 아니요.
- 계정 삭제(데이터 보안 › 데이터 삭제): 웹 주소는 `https://workonplus.com/work/about/delete-account/`(로그인 없이 열림, 앱 안 방법 + 앱에 못 들어갈 때 방법). 앱 안 경로는 내 프로필 › 계정 › [계정 삭제](S69 STORE-계정삭제 — DB `20261124130000_account_delete` 적용·Edge `account-delete` 배포 뒤 동작). 지우는 범위: WORK ON+ 서버의 작업공간·내 기록 전부와 연결 토큰. 로그인 Google 계정(Auth)은 남김 — 콘솔 질문 '계정 삭제 시 데이터도 삭제되나'에는 '예, 사용자 데이터 전부', '일부 데이터 보관'에는 '백업 보관 기간(최대 약 1년) 뒤 자동 삭제'로 답한다.

## 8. 연락처·출시 국가

- 연락처 메일: 사용자가 정함(공개됨). 웹사이트 `https://workonplus.com/work/about/`.
- 출시 국가: 대한민국(비공개 테스트 단계에서는 테스트 트랙 국가만).

## 9. 사용자·CC 확인 필요

1. 삭제 기간 '요청 확인 뒤 30일 안'을 공개 페이지에 적었다 — 지킬 수 있는지 사용자 확인.
2. ~~앱 안 탈퇴 기능 없음~~ → S69 STORE-계정삭제 PR에서 만듦(DB → Edge → 화면 순서로 CC 적용). 남은 결정: 로그인 계정(Auth 사용자)까지 지울지(PR 본문 선택지).
3. 콘솔 연락처 메일(공개)을 무엇으로 할지.
4. 심사용 Google 계정 만들기(사용자, 로그인 정보는 콘솔에만).

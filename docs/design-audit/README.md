## 홈 화면 후속 조사 (2026-10-01, #382)

결론은 **(나) 홈이 곧 캘린더**다. 기본 `/app/` 진입과 `?view=home`은 캘린더로 정규화되며(`app/loader-v2.js:136–148`, `app/view-loader.js:122–125`, `app/app-router.js:24–38`), 메뉴의 `일정`과 좌상단 `웹2` 브랜드도 같은 화면으로 들어간다(`app/index.html:43–44`, `app/app-router.js:141–148`). 표시 내용은 월 제목·이전/다음 달·일정 등록 버튼과 월간 일정 격자다(`app/index.html:58–63`). `homeView`는 빈 숨김 영역이고(`app/index.html:56`), 현재 로더에는 홈 모듈이 없어 시험 환경에서만 홈을 못 띄우는 경우가 아니다. 남아 있는 `home-dashboard-v2.js:34–45`에는 프로젝트·내 미완료 업무·다가오는 프로젝트 마일스톤·최근 자료 카드 코드가 있지만 현재 앱의 import·메뉴·URL 진입 경로에는 연결되지 않는다. 현재 홈에는 `오늘 할 일`·`회의 후속` 전용 칸이 없으며, `후속 할 일`은 회의 상세의 영역이다(`app/meeting-round-detail.js:20`, `app/view-loader.js:97–102`). 앱 코드나 tests/를 바꾸거나 미연결 모듈을 시험 환경에서 강제로 불러오지 않았고, 별도 홈 사진은 추가하지 않았다. 기존 캘린더 사진 6폭(`360, 412, 720, 884, 1280, 1440px`)을 홈 진입 화면의 기록으로 사용한다.

## 실행

로컬 정적 서버를 이 worktree 루트에서 띄운 뒤 실행한다. Playwright 패키지 설치 경로는 환경 변수로 지정할 수 있다. 스크립트는 로컬 loopback 외 HTTP origin을 거부하고 Supabase URL 요청은 전부 모의 응답하며 다른 외부 요청은 차단한다.

```powershell
python -m http.server 8124 --bind 127.0.0.1
$env:APP_E2E_ORIGIN='http://127.0.0.1:8124'
$env:DESIGN_AUDIT_PLAYWRIGHT='<installed-playwright-package-directory>'
node scripts/design-audit/capture.mjs
```

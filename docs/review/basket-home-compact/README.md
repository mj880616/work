# BASKET-홈첨부칸축소 검증

📱 Codex 웹·클라우드. `codex/basket-home-compact`, 시작 SHA `88ec5eac80c55d93fb2ad59072bf57f321c1a222`(#480). 원격 `origin/main`을 새로 fetch한 뒤 시작했다. PR·폰 확인은 [원장](../../roadmap.md)의 해당 행에서 추적한다.

홈 빠른 입력과 바구니 메모 상세가 같은 선택기와 바구니 전용 CSS를 사용한다. 앱 모바일 기준 760px 이하에서는 44px 한 줄에 “📎 파일 추가”와 “파일당 100MiB · 20개까지”를 표시한다. 미선택 회색 배경·패딩·빈 목록 여백과 공통 label의 기본 위아래 12px 여백을 제거했다. PC 점선 드롭 영역은 112→56px, 내부 패딩은 16→8px, 바깥 패딩은 12→6px다. 홈 전체 보기 링크 위 간격은 8→4px다. 자료실·회의의 공통 CSS와 업로드 동작은 변경하지 않았다.

홈에서 전체 저장 성공 후 배치를 새로 만들고 완료 목록·본문·“새 메모 입력” 줄과 네이티브 파일 선택을 비운다. 새 메모에는 이전 note_id를 재사용하지 않는다. 중간 실패·결과 불명은 완료/실패/대기 목록과 본문을 보존하며 기존 오류·재시도 중단 규칙과 토스트를 유지한다. 상세 화면의 메모 원문·기존 첨부 링크는 그대로 유지한다.

## 검증 결과

- 수정 전 기존 바구니 브라우저 30/30, Node 바구니 18/18 통과.
- 신규 높이 검사 2개와 전체 성공 초기화 검사 4개의 RED를 확인한 뒤 구현했다. 리뷰에서 찾은 빈 파일 거절→글 저장 후 네이티브 선택 잔존도 RED→GREEN으로 검증했다.
- 최종 바구니 33/33 + 공간·드롭·키보드·터치·콘솔 검사 2/2 = **35/35**. 기존 30개를 모두 유지했다. 새 요구와 충돌하는 성공 목록 기대값만 초기화 기대값으로 바꾸고, 중간 실패 테스트는 같은 배치의 완료·실패·대기·본문 보존까지 강화했다.
- 인접 홈 빠른 입력 14/14, 자료실 전송 26/26, 자료실·회의 선택 취소 6/6, 캐시 기대 spec 3/3: 바구니 포함 **관련 84개 모두 통과**. 화면 검증은 390/1280px, 1440px 사례는 실행에서 제외했다.
- Node `tests/*.test.mjs tests/security/*.test.mjs tests/domain/*.test.mjs scripts/*.test.mjs`: **464/464**.
- JS 구문, 정적 smoke의 의존성/기능/권한 불변식과 정적 HTTP 검사, 브라우저 저장소 감사 통과. 캐시 그래프 **395참조** 및 `git diff --check` 통과.

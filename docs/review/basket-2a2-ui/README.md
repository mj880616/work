# BASKET-2a-2 화면 검토

📱 폰 가능 — Codex 웹·클라우드. 원격 `origin/main`을 새로 받아 시작한 SHA는
`b466910e32e8e1a68e2570059144d96985791f59`(#476 merge), 브랜치는 `codex/basket-2a2-ui`다.

홈의 바구니 입력과 기존 메모 상세가 기존 자료실·회의의 파일 선택·× 취소 UI를 쓴다.
글만 저장할 때는 `app_notes` REST를 유지한다. 파일은 `copyUploadFile` 사본을 만든 뒤
한 요청에 하나씩 `basket-files`로 보낸다. 새 메모는 첫 요청에만 원문(있으면)을 보내고,
첫 성공의 `note_id`를 이후 요청에 사용한다. 기존 메모는 첫 파일부터 `note_id`만 보낸다.

파일마다 대기·업로드 중·완료·실패를 표시한다. 이미 완료한 파일은 재전송하지 않는다.
일반 실패는 큐를 멈추며 사용자가 다시 저장할 때 미완료 파일만 보낸다. 503 결과 불명은
“저장 결과를 확인하지 못했습니다. 바구니에서 확인 후 다시 시도하세요”를 표시하고
같은 큐의 재전송을 차단한다. 409 `note_changed`도 중단하고 메모 재조회로 안내한다.
홈의 새 메모 입력과 상세의 다시 불러오기는 미완료 선택이 있으면 명시적인 확인을 받는다.
사본 읽기 실패는 요청 전 실패로 표시하며 자동 재전송하지 않는다.

파일당 104857600 bytes, 메모의 기존 첨부와 새 미완료 선택 합계 20개를 전송 전에 검사한다.
일반 브라우저 FormData는 글의 줄바꿈을 CRLF로 전송하므로 첨부 원문 사전 검사는 그 길이를
기준으로 20,000 Unicode 문자까지 허용한다. 글만 저장하는 기존 REST 원문 처리는 유지한다.
목록은 첨부 개수, 상세는 이름·크기와 Drive 링크를 표시한다. Drive ID가 영문·숫자·`_`·`-`로만
이뤄진 경우에 `https://drive.google.com/file/d/<id>/view` 링크를 만든다.

AI 제외 체크·목록 표시·화면의 설정 변경 호출은 제거했다. 새 글 저장에는
`ai_export_allowed`를 보내지 않아 DB 기본 true를 사용하고 기존 값은 보존한다.
파일 삭제·이동 기능은 추가하지 않았다. 파일/원문을 브라우저 영구 저장소에 보관하지 않는다.

캡처는 로컬 모의 API와 설치된 Chromium 151로 만들었다. 운영 계정·파일이 아닌 테스트 자료다.

## 검증 범위

DB·RLS·Edge·서버 함수 코드는 변경하지 않았으며 운영 접속·workflow 수동 실행·Cloudflare 변경은 없다.
문서의 DB 2차 apply·basket-files v1 배포 완료는 2026-10-10 사용자 실행 보고를 기록한 것이다.
독립 검토에서 찾은 이전 목록 조회와 첨부 저장 간 두 경합은 실패 재현 후 수정했다.
기존 테스트를 삭제하지 않았고 AI 표시 테스트는 화면에 없는지와 기존 값 보존 검사로 갱신했다.
캐시는 basket data2·basket2/CSS2·home quick5·home read13/CSS10·view loader113·loader v2346·app234를
index.html 및 버전 기대 spec·app-smoke 고정 버전까지 연결했다.

파일 선택/취소/메모리 사본 spec 32/32, 최종 바구니 30/30(앞 묶음과 중복 포함).

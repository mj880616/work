# Web2 디자인 결정 기록

이 파일은 앞으로의 디자인 결정을 누적 기록한다. 2026-10-01 기준 결정과 미결정을 구분한다. D-1은 현행 화면을 촬영·측정하는 단계이며 앱 코드는 수정하지 않는다.

## 기기와 폭

- 갤럭시 폴드 접힘: 약 412px. 펼침: 약 870px(추정, 실측 예정).
- PC 기준: 1280px, 1440px.
- 목표 폭 3단계: 접힘 `<600px`, 펼침 `600–1023px`, PC `≥1024px`. 시스템 1.0의 `<760px` 경계와 충돌하므로 D-2에서 정리한다.

## 메뉴와 공통 부품

- 접힘: 하단 탭 5개(홈·할 일·프로젝트·회의·담당조직)와 ☰ 메뉴(자료실·성명·보도자료·게시판·설정·로그아웃).
- 펼침·PC: 왼쪽 세로 메뉴와 일정.
- 윗줄에는 `[검색·필터]`와 진한 추가 버튼을 놓고, 보조 기능은 `⋯`에 모은다. 목록은 두 줄 구성, 수정·삭제는 `⋯` 안에 둔다.
- 보기는 접힘에서 전체 화면, 펼침·PC에서 오른쪽 칸을 쓴다. 터치 영역은 최소 44px이다.

## 시각

- 글자 크기는 4단계, 기본 색은 오트밀·올리브와 회색·의미색, 모서리는 2단계로 정리한다(2026-10-05 D-2 확정).
- 회의 색 띠와 캘린더 일정 색은 유지한다. D-캘린더색 변경안은 취소했다.

## 시안 1: 홈, 접힘 폭

위에서 아래로 날짜·☰, 빠른 입력(`[할 일|업데이트]`), D-day 칩, 오늘 일정, 오늘·밀린 할 일, 회의 후속, 이번 주 업데이트, 하단 탭을 둔다.

- D-day 칩은 프로젝트 주요 일정을 가까운 순으로 보이며 임박한 일정은 빨강으로 표시한다.
- 오늘 일정은 공공운수노조 캘린더를 시간순으로 보이고 `달력 ›` 링크를 둔다.
- 오늘·밀린 할 일에는 연결 프로젝트·조직을 표시하고 `연결 안 된 할 일 N개 정리하기 ›` 링크를 둔다.
- 회의 후속에는 미완료 항목을 `회의명 · 할 일` 형식으로 보인다.
- 이번 주 업데이트는 `조직 · 내용 날짜` 형식으로 보인다. 25는 취소. 홈에는 AI 입력창을 두지 않으며, 주간보고 재료는 DRV-요약(Drive 읽기용 사본)으로 GPT가 읽는다.

## 시안 2: 빠른 입력

- `[할 일]`: 한 줄 입력과 `[프로젝트 ▾][오늘][내일][날짜]`, `추가 → Google Tasks`. 프로젝트는 선택사항이다.
- `[업데이트]`: 여러 줄 입력과 필수 `[조직 ▾]`, `저장 → 담당조직 기록`.
- 마지막으로 사용한 모드를 기억한다.

### 9/28 조정

- 할 일 줄은 할 일 화면과 같은 완료 동그라미를 쓴다. 홈에는 X 삭제를 두지 않는다.
- 진입 시 자동 조회한다. 업데이트 조직은 최근 3개를 먼저 보이고 이후 조직 순서를 따른다.
- 빠른 입력은 짧게 시작해 입력할 때 옵션이 펼쳐진다. 추가 버튼의 누름 영역은 44px이다.

### 10/1 결정

- 담당조직 목록·할 일 편집창·일정 창의 조직 체크 목록은 **묶음당 흰 상자 하나, 상자 사이 간격**으로 정리한다. 조직마다 상자를 두지 않는다(D-4).
- 할 일 완료 후 항목은 3초 동안 원래 자리에 남긴다(TASK-완료지연).
- 달력 보기는 `[목록|주간|월간]`. 접힘 기본 보기는 목록, 펼침·PC 기본 보기는 주간이다.
- 진행 순서는 `현재|시안` 비교 사진 → 사용자 선택 → PR → 폰 확인이다.

## D-2·D-4 미결정

- D-day 칩 색: 파랑 또는 남색.
- 버튼 높이: 2026-10-05 D-버튼통일 결정으로 보이는 높이 상한 36px 확정.
- `추가 → Google Tasks` 문구 길이.
- 보관함·분류 수정을 `⋯`로 옮길지.
- 추가 버튼의 최종 위치.
- 게시판 카드 내용: 아래 2026-10-06 D-게시판카드 결정으로 확정.
- 조직 상세의 전체 화면 여부, 할 일 칸 위치, 목록의 미완료 개수.
- 최근 3개 조직을 중복 표시할지.

## 2026-10-05 글자 B안·성명 폰 목록 C2 (D-3d)

- 글자는 크기만 가까운 단계로 올리는 A안 대신 역할 기준 B안을 적용한다. 프로젝트·회의·성명·보도자료·게시판·담당조직의 목록 화면 5개만 대상이다.
- 20px `--kptu-text-title`: 목록 맨 위 h2. 현재 h2가 없는 성명·게시판·담당조직에는 새 제목을 만들지 않는다.
- 16px `--kptu-text-subtitle`: 프로젝트 이름, 성명 제목·연도, 게시판 카드 제목, 회의 목록 제목, 담당조직 항목 이름.
- 14px `--kptu-text-body`: 게시판 카드 설명, 일반 빈 목록 안내. 대상 목록 primary·secondary 버튼과 성명 필터는 아래 D-버튼통일 결정으로 12px을 적용한다.
- 12px `--kptu-text-meta`: 프로젝트 개수 줄, 성명 날짜·구분·발행 주체, 게시판 badge·열기, 회의 차수·날짜, 목록 mini·updated·muted·compact 빈 안내.
- 아이콘·a11y-only·굵기는 변경하지 않는다. 일정·할 일은 현재 글자 크기를 유지하고, 자료실 구성은 D-4에서 카드형→목록형 재디자인한다. 상세·입력 창은 D-3e 역할 표 작성 후 별도 지시한다. 메뉴·계정 메뉴도 이번 적용에서 제외한다.
- 성명 폰 목록 C2: 760px 이하에서 구분 칩·날짜를 위 한 줄, 제목을 아래 전체 폭으로 표시하고 발행 주체를 숨긴다. 761px 이상은 기존 표 배치를 유지한다. Web1 /press/는 적용하지 않는다.

## 2026-10-05 글자 버튼 크기 상한 (D-버튼통일)

- 할 일 탭 + 할 일 버튼을 기준으로 보이는 높이 36px, 글자 `var(--kptu-text-meta)`(12px), 좌우 여백 12px, 일반 모서리 8px으로 맞춘다. 기준보다 높거나 글자가 큰 글자 버튼이 대상이며 상세·입력·확인 창도 포함한다.
- D-3d의 primary·secondary 버튼과 성명 필터 14px 결정은 이 결정으로 대체한다. 굵기·색과 알약 필터의 기존 둥근 모서리는 유지한다. D-3c의 44px 누름 범위 확장도 유지한다.
- 기준보다 작은 버튼, 아이콘만 있는 버튼, 줄·카드 전체 항목, 상단·사이드·계정 메뉴, 달력 칸, 공개 페이지 편집기와 Web1은 제외한다. 역할이 애매한 버튼은 변경하지 않고 보고한다.

## 2026-10-06 게시판 카드 A안 (D-게시판카드)

- 폰·PC 공통 A안(작은 카드)으로 확정한다. D-시안묶음-1의 임시 선택(390px B·760/1440px A)을 대체한다.
- 목록은 제목만 표시한다. 상태 꼬리표·제목 아래 설명·"내용 보기"는 화면과 화면 읽기에서 숨기고, 기존 카드 버튼의 읽기용 이름은 제목이다. 카드 전체 탭·클릭·Enter로 기존 안쪽 화면을 연다.
- 기존 CSS 규칙을 수정한다: 카드 padding `14px 16px`, border-radius `12px`, 제목 margin `0`, grid gap `10px`. PC 2열·폰 1열, hover, D-3d 제목 16px은 유지하며 보관 카드에도 동일하게 적용한다.
- 안쪽 화면(공유용)·데이터·공유 링크 미리보기는 변경하지 않는다. Web1은 별도 구현이면 변경하지 않는다.


## 2026-10-05~06 자료실 한 줄 목록 A안 (D-자료실목록)

- 실제 앱 시안을 보고 폰·PC 공통 A안으로 확정했다. 목록 바깥 상자와 머리줄을 유지하고 자료실 전용 행을 사용한다. 공통 `.compact-entry` 규칙은 변경하지 않는다.
- 행은 flex·가운데 정렬·간격 12px, 위아래 11px·좌우 2px 여백이다. 행 사이에 `--kptu-border` 1px 구분선을 두며 첫 행은 없다. 카드 테두리 상자·그림자·모서리는 없다.
- 왼쪽 파일 종류 표시는 36×36px·모서리 8px, `--kptu-primary-soft` 바탕·`--kptu-primary-ink` 11px 굵은 글자다. HWP/HWPX→HWP, PDF→PDF, XLS/XLSX→XLS, DOC/DOCX→DOC, PPT/PPTX→PPT, 그 외는 파일이다.
- 가운데 제목은 15px 굵게·`--kptu-ink`·한 줄 말줄임이다. 아래는 `--kptu-text-meta`(12px)·`--kptu-muted`·한 줄 말줄임으로 `MM.DD · 분류`를 표시한다. 날짜가 없으면 분류만 보인다. 이전 D-4 메모의 프로젝트 표시는 이 결정으로 대체한다.
- 오른쪽 ⋯는 보이는 크기 32px·`--kptu-muted`, D-3c 방식의 누르는 범위 44px이다. 줄 클릭·Enter는 기존 자료 열기, ⋯는 메뉴만 연다. 다운로드·정보 수정·삭제는 ⋯ 안에서 기존 동작을 호출하며 삭제 확인·Drive 휴지통 흐름을 유지한다. 메뉴는 바깥 클릭·Esc·뒤로 가기로 닫히며 화면 안에 위치한다.
- 출처·크기·요약은 목록에서 빼고 기존 자료 열기 경로와 정보 수정 데이터는 유지한다. 업로드·끌어놓기·분류 수정·검색·프로젝트 필터 동작은 변경하지 않는다.
- 머리줄 오른쪽에 `[분류 수정][+ 자료]` 순서·간격 8px·D-버튼통일 크기를 적용한다. 맨 위 단독 `.section-head.actions-only` 줄을 없앤다. 검색칸·프로젝트 선택은 기존 간격 8px을 유지한다.


## 2026-10-06 상세·입력 창 글자 역할 + 진행 기록 ⋯ (D-3e)

사용자 지시서의 역할 표와 진행 기록 메뉴 B안을 적용한다. 글자 굵기와 본문·제목 색은 유지한다.

| 역할 | 크기 | 색 |
| --- | --- | --- |
| 창·화면 제목(`.modal-head h2`, 상세 맨 위 이름) | `--kptu-text-title` 20px | 유지 |
| 구역 제목(창 안 h3·묶음 제목) | `--kptu-text-subtitle` 16px | 유지 |
| 본문·입력(설명·기록 내용, input·textarea·select) | `--kptu-text-body` 14px | 유지 |
| 입력칸 이름(label) | `--kptu-text-meta` 12px | `--kptu-muted` |
| 정보(날짜·작성자·개수·상태 꼬리표·small) | `--kptu-text-meta` 12px | `--kptu-muted` |
| 안내문(빈칸 안내·도움말·비활성) | `--kptu-text-meta` 12px | `--kptu-faint` 허용 |

## UI-버튼기준 (2026-10-22 사용자 결정): 새 버튼은 작고 낮게

사용자는 큰 버튼을 싫어하고 줄이기 요청이 반복됐다(회의 등록, 일정 등록, 바구니 파일, 챙길 것, 메뉴 창 등). 새 화면·새 버튼은 아래 기준을 먼저 따른다. 값은 `app/theme-tokens.css`의 `--ds-*`에만 있고 여기에 숫자를 복사해 새로 정하지 않는다. 앞선 D-버튼통일(글자 버튼 상한)·UI-버튼크기(보조 32px)·UI-버튼작게(서식 줄 28px) 결정을 한 문장으로 묶은 것이며, 그 값은 바꾸지 않는다.

- 기본은 작고 낮게 만든다. 새 버튼을 만들 때 큰 버튼부터 시작하지 않는다.
- 안내·상태 줄 안의 보조 버튼(예: `최신 아님 · 마지막 확인 00:07 [다시 시도]`)은 글자 버튼이나 작은 버튼이다. 안내 글자보다 크거나 테두리 상자로 눈에 띄면 안 된다. 현행 값: 보이는 높이 `--ds-compact-height-sm`(28px)·글자 `--ds-text-meta`(12px)·테두리 없음, 누르는 범위는 `::after`로 44px. 구현은 `.data-freshness-retry`(`app/ui-standard.css`).
- 목록·카드·창 안의 보조 버튼(열기·연결·복사 등)은 `--ds-compact-height`(32px) 작은 버튼이다. 전환·필터는 세그먼트·알약 칩(32px)이다.
- 크고 색을 채운 버튼(`primary`, `--ds-control-height`)은 한 화면(창)에 주 동작 하나(추가·저장·등록 등)에만 쓴다. 같은 화면에 채운 큰 버튼이 둘이면 하나는 작은 버튼으로 내린다. 큰 버튼의 크기 값 자체는 이 결정에서 바꾸지 않는다.
- 보이는 크기만 줄이고 누르는 범위(44px, `--kptu-touch-target`)는 지킨다. 줄이는 방법은 기존 작은 버튼 스타일 재사용이며, 화면마다 새 높이·글자 크기를 만들지 않는다.
- 이 기준보다 큰 기존 버튼은 한꺼번에 줄이지 않는다. 목록을 만들어 사용자가 고른 것만 수정한다(2026-10-22 점검 목록은 UI-버튼기준 PR 본문).

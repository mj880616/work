## 3. 새로 찾은 문제

### N1. 노트 PC: Ctrl·Shift+클릭이 고르기가 아니라 노트 열기 (크기: 중간)
- 일상어: 노트 목록에서 Ctrl을 누른 채 노트를 누르면 여러 개가 골라지지 않고 그 노트가 열린다(주소에 `doc=`가 붙고 목록이 사라짐). Shift도 같다. 자료실·파일은 된다.
- 원인 짐작: `basket-notes.js` 노트 줄 누르기 처리가 `ctrlKey`·`shiftKey`를 보지 않는다(grep 결과 `basket-notes.js`에는 Ctrl 처리가 없고, 보드 `note-board.js`에만 있다). 공용 `select-mode.js`의 Ctrl·범위 규칙을 노트 목록이 쓰지 않는다.
- 고칠 방법: 노트 줄 누르기 첫 줄에서 마우스 + Ctrl(⌘)/Shift면 `select-mode.js` toggle/range로 보낸다(기준표 S2·S3).
- 공용 부품: `select-mode.js`. 노트를 공용 고르기에 맞추면 S5·S6·K1도 같이 따라온다.

### N2. 자료실·노트: Ctrl+A가 목록 전체가 아니라 화면 글자 전체를 고름 (중간)
- 일상어: 줄에 커서를 두고 Ctrl+A를 누르면 페이지 글자 전체가 파랗게 칠해지고 목록은 하나도 안 골라진다. [파일]만 된다.
- 원인 짐작: 기준표 S5 '공용 부품: 없음'. [파일]은 `files.js`에 자기 처리, 자료실·노트에는 없음.
- 고칠 방법: 공용 키 부품(예: `select-keys.js`)을 만들어 목록 칸에 Ctrl+A·Esc·Delete·F2를 한 번에 건다. 글 쓰는 칸에서는 그대로 둔다.
- 공용 부품: 새 공용 키 부품 하나 → 자료실·노트·사진·[파일](옮겨 붙임) 같이.

### N3. 자료실·노트: Delete 키로 고른 것이 지워지지 않음 (중간)
- 일상어: 자료를 고르고 Delete를 눌러도 아무 일이 없다(확인 창·알림·쓰기 모두 없음). [파일]은 확인 창이 뜬다.
- 원인 짐작: `files.js:4182`에만 Delete 처리. 자료실(`library-upload.js`·`library-select.js`)·노트에는 없음(기준표 K1 '공용 부품 없음').
- 고칠 방법: N2와 같은 공용 키 부품에서 그 화면의 [삭제] 단추 동작을 부른다(R2 되돌리기 알림 그대로).
- 공용 부품: N2와 같음 — 한 PR로 묶는다.

### N4. [파일]·노트 줄: 커서만 둔 줄에서 F2가 안 됨 (작다)
- 일상어: [파일]은 줄을 먼저 '골라야' F2가 되고, 커서(포커스)만 둔 줄에서는 아무 일이 없다. 노트는 노트 줄에서 F2가 안 되고 폴더 줄에서만 된다. 자료실은 커서만 둬도 된다.
- 원인 짐작: `files.js:4181` `actRows()`가 고른 줄만 본다. `basket-notes.js:2000`은 `[data-nx-folder]`만 본다.
- 고칠 방법: 고른 줄이 없으면 커서가 있는 줄 하나를 대상으로(탐색기와 같음). 노트 줄도 이름(제목) 고치기로.
- 공용 부품: N2 공용 키 부품의 'F2 대상 = 고른 줄, 없으면 커서 줄' 규칙.

### N5. 긴 폴더 이름: … 로 잘린 뒤 전체 이름을 볼 길이 없음 (작다)
- 일상어: PC 나무에서 긴 폴더 이름은 … 로 잘리는데 마우스를 올려도 전체 이름이 안 뜬다(1280 나무 칸에서 글자 폭 442px 중 127px만 보임).
- 원인 짐작: 공용 `folder-tree-ui.mjs` `ftFolderRowHtml`의 `.ft-name`에 `title`이 없다(68행).
- 고칠 방법: 공용 줄 HTML에서 잘릴 수 있는 이름에 `title`(또는 `aria-label`과 같은 값)을 붙인다.
- 공용 부품: `folder-tree-ui.mjs` 한 곳 → 자료실·파일·노트·사진 나무 모두.

### N6. [파일] 나무 빈 곳 우클릭: 메뉴가 안 뜸 (작다)
- 일상어: [파일] 왼쪽 나무 아래 빈 곳을 우클릭하면 아무것도 안 나와서 새 폴더를 만들 수 없다. 노트는 '이 폴더에 새 폴더'가 나온다. 자료실은 S70-09가 맡음.
- 원인 짐작: `files.js` 나무 칸 `contextmenu` 처리가 줄(`[data-fx-fold]`) 위에서만 메뉴를 연다.
- 고칠 방법: 빈 곳 우클릭 = 지금 폴더 메뉴(새 폴더·올리기). S70-09 자료실 방식과 같은 규칙으로.
- 공용 부품: S70-09에서 만드는 빈 곳 메뉴 규칙을 [파일]에도. S70-09 뒤에 줄 세운다.

### N7. 같은 일의 메뉴 말이 화면마다 다름 (작다)
- 일상어: 같은 폴더 메뉴인데 화면마다 말이 다르다.

| 일 | 자료실 | 파일 | 노트(폴더 ⋯) | 노트(나무 빈 곳) |
| --- | --- | --- | --- | --- |
| 새 폴더 | 안에 새 폴더 | 새 폴더 | 새 폴더 | 이 폴더에 새 폴더 |
| 지우기 | 폴더 삭제 | 휴지통 | 폴더 삭제 | 이 폴더 삭제 |
| 색 | 색 선택… | 색 | 색 선택… | — |
| 옮기기 | 옮기기… | 옮기기 | 옮기기… | — |
| F2 표시 | 이름 바꾸기 F2 | 이름 바꾸기 | 이름 바꾸기 | — |

- 원인 짐작: 메뉴 HTML이 화면마다 따로(`library-folders.js:160`, `files-tree-menu.mjs`, `basket-notes.js`).
- 고칠 방법: `docs/design/ui-words.md`에 폴더 메뉴 말 한 벌을 정하고(사용자 확인), 공용 '폴더 메뉴 줄 목록'(예: `folder-menu-words.mjs`)에서 같은 말을 쓴다. 차례도 같게(들어가기 → 새 폴더 → 이름 바꾸기 → 옮기기 → 색 → … → 지우기 맨 끝).
- 공용 부품: 새 공용 말 목록 하나 → 세 화면.

### N8. Alt+← (확인 못함)
- 브라우저 단축키라 시험 환경(headless)에서는 앱까지 오지 않아 확인하지 못했다. 앱은 직접 처리하지 않고 브라우저 뒤로가기에 맡긴다. 기준표 T3(뒤로가기 = 한 폴더 위로)는 시험이 있다. 실기기에서 사용자 확인이 필요하면 그때 본다.

### N9. Enter = 폴더 펼치기만(기준표 K3와 T5가 부딪힘) (결정)
- [파일]·노트 오른쪽 목록 폴더 줄에서 Enter를 누르면 그 자리 펼치기만 하고 들어가지 않는다. 기준표 K3는 'Enter = 열기(폴더는 들어가기)', T5는 '누르기 = 그 자리 펼치기'. Enter가 누르기와 같은 것은 지금 결정(T5, 11/24 사용자) 쪽이다.
- 제안: 기준표 K3를 'Enter = 누르기와 같음(폴더는 펼치기·접기). 들어가기는 ⋯ 첫 줄'로 고치거나, Enter = 들어가기로 남긴다. 사용자 결정 필요(아래 5절).

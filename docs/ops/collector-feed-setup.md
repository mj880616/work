# 통화 보내기 설치 안내 (CALL-통화메뉴 3-가)

Web2 **통화** 메뉴에 업무 통화를 채우는 설정이다. 명진 님 Google 계정의 앱 스크립트가 1시간마다 새 통화의 **분석 파일과 전사 txt**를 Web2 서버(`collector-feed`)로 한 건씩 보낸다.

- 코드: [collector-feed.gs](collector-feed.gs) · 설계: [call-telegram-feed.md](../design/call-telegram-feed.md) 3.3·6절
- 서버는 이미 배포되어 있고 비밀값 `COLLECTOR_FEED_SECRET`도 Supabase에 들어 있다. 이 안내는 앱 스크립트 쪽만 다룬다.
- 텔레그램 보내기(3-나)는 이 문서 아래쪽 "텔레그램 보내기 설치"에 있다. 통화를 먼저 설치했으면 같은 프로젝트에 이어서 하면 된다.

## 무엇이 어디로 가나

| 통화 | 앱 스크립트가 하는 일 | Web2에 남는 것 |
| --- | --- | --- |
| 개인 목록(번호·연락처 이름)에 있음 | 분석이 업무라고 해도 **개인으로 고쳐** 요약·전문까지 보냄(분석이 3일 넘게 없으면 날짜별 "개인 n건" 숫자만) | 개인 통화함에만 저장 |
| 분석이 "개인"(`is_work_related: false` 또는 `status: "개인"`) 또는 "애매"(`status: "애매"`) | 분석 파일과 전사를 그대로 보냄 | 요약이 있으면 개인 통화함에 저장(애매는 "확인할 통화"). 요약 없는 옛 개인 기록은 숫자만 |
| 분석에 구분이 없음(옛 3.1 파일, 칸이 비어 있음) | 이름·요약·전사는 빼고 날짜만 보냄 | 숫자만("구분 없음") |
| 분석이 "업무"(`is_work_related: true`) | 분석 파일 전체 + 전사 txt를 보냄 | 통화 메뉴 한 줄(제목·핵심내용·상대·전문) |
| 녹음 날짜가 최근 7일보다 오래됨(옛 녹음을 한꺼번에 올린 경우) | 분석을 기다리지 않고 넘김(명진 결정 10/25) | 없음 |
| 분석이 아직 없음 | 다음 실행에서 다시 봄(3일 넘게 없으면 넘김) | 없음 |

- Drive 파일은 하나도 고치지 않는다. 분석 파일의 `status`, Drive 파일 설명도 그대로다(Q13).
- **최근 7일(한국 날짜) 안에 녹음된 통화**를 보낸다. 설치 전에 만들어진 전사라도 녹음이 7일 안이면 분석이 끝난 뒤 한 번 보낸다. 7일보다 오래된 녹음은 보내지 않는다(명진 결정 10/25). 이미 보낸 통화는 다시 보내지 않는다.
- 처음에는 **시험 모드**다: 아무것도 보내지 않고 개수만 실행 로그에 적는다.
- 통화 분석 형식은 명진의 현재 분석 **v3.2** 그대로다. 전사·분석 앱 스크립트는 고치지 않는다(2026-10-24 명진 결정: 그 스크립트는 요청함 밖 Claude 대화에서만 고친다).

## 새 프로젝트로 만든다 (추천)

기존 통화 스크립트 프로젝트에 파일을 더하지 않고 **새 프로젝트**를 만든다.

- 기존 프로젝트는 스크립트 속성이 많아서 화면에서 속성을 더 넣을 수 없다(원본 코드 `setCallContextDocId` 주석: "속성이 50개가 넘으면 화면에서 추가할 수 없으므로"). 새 프로젝트는 화면에서 바로 넣을 수 있다.
- 전사·분석 코드와 섞이지 않아서, 멈추거나 지울 때 전사·분석에 영향이 없다.
- 점검 신호 스크립트(`Web2 수집 점검`)와도 따로 둔다. 비밀값이 다르다.

## 순서

### 1단계 — 새 앱 스크립트 프로젝트 만들고 코드 붙여넣기

1. 컴퓨터 브라우저에서 https://script.google.com 을 연다(통화 전사 스크립트와 **같은 Google 계정**).
2. 왼쪽 위 **[+ 새 프로젝트]**.
3. 왼쪽 위 "제목 없는 프로젝트"를 눌러 이름을 `Web2 수집 보내기`로 바꾼다.
4. 저장소의 `docs/ops/collector-feed.gs` 내용을 전부 복사한다.
5. 편집기의 `Code.gs`(또는 `코드.gs`) 안 내용을 모두 지우고 붙여 넣는다.
6. 맨 위 한 칸을 채운다: `'여기에_통화녹음_폴더_주소_끝부분'` 자리.
   - 넣을 글자는 기존 통화 스크립트 `Code.gs` 위쪽 `PIPELINES` 안 `rootFolderId: '…'`의 따옴표 안 글자와 같다. 커맨드센터가 채팅으로 알려 줘도 된다.
   - 직접 찾을 때: Drive에서 `통화녹음` 폴더(안에 `원본`·`전사` 폴더가 있는 폴더)를 연다 → 주소창 `https://drive.google.com/drive/folders/` **뒤 글자**(`?` 뒤는 빼기).
   - 따옴표(`'`)는 그대로 두고 안쪽 글자만 바꾼다. 이 글자는 저장소·문서에 쓰지 않는다.
7. 위쪽 **저장(디스크 모양)** 버튼.

### 2단계 — 스크립트 속성 두 개 넣기

왼쪽 **톱니바퀴(프로젝트 설정)** → 맨 아래 **스크립트 속성** → **[스크립트 속성 추가]**.

| 속성 | 값 |
| --- | --- |
| `COLLECTOR_FEED_SECRET` | Supabase에 등록한 `COLLECTOR_FEED_SECRET`과 **똑같은 값** |
| `CALL_FEED_PERSONAL_LIST` | 개인 번호·연락처 이름 목록. 쉼표(`,`)로 구분. 예: `010-0000-0000, 엄마, 가상 친구` |

- 개인 목록은 **전사 파일 이름의 그 부분**(`통화 ○○○_날짜_시각.txt`의 ○○○)과 대조한다. 번호는 하이픈·빈칸을 빼고 숫자만 비교하고, 이름은 글자 그대로 비교한다(폰 연락처에 저장된 이름 그대로).
- 두 값 모두 채팅·문서·저장소에 붙여 넣지 않는다.
- 비밀값을 잃어버렸으면: 함수 칸에서 `callFeed_makeSecret` 실행 → 생긴 값을 Supabase **Edge Functions → Secrets**의 `COLLECTOR_FEED_SECRET`에 같은 값으로 바꿔 넣는다.
- **[스크립트 속성 저장]**.

### 3단계 — 시작 (시험 모드)

1. 편집기 위쪽 함수 칸에서 `callFeed_setup` → **[실행]**.
2. 처음이면 "승인 필요" 창: **[권한 검토]** → 내 계정 → "Google에서 확인하지 않은 앱"이면 **[고급]** → **[Web2 수집 보내기(으)로 이동]** → **[허용]**. 내가 만든 스크립트라 정상이다(Drive 보기·외부 주소 호출·트리거 권한).
3. 실행 로그에 아래 비슷한 줄이 나오면 정상이다.
   ```
   전사 폴더: 찾음
   분석 폴더: 2개 찾음(검토대기·검토완료)
   비밀값: 있음
   개인 목록: 번호 n개, 이름 m개
   시험 모드: 켬(보내지 않음)
   시작 시각: 2026-…
   ```
   - `통화녹음 폴더 칸을 채우세요` → 1단계 6번.
   - `"전사" 폴더가 없습니다` → 폴더 칸에 `통화녹음` 폴더가 아닌 다른 폴더(위·아래)를 넣은 것.
   - `비밀값: 없음 또는 너무 짧음` → 2단계.
4. 함수 칸에서 `callFeed_installHourlyTrigger` → **[실행]**. 로그에 `1시간 트리거를 만들었습니다`.
   - 왼쪽 **시계 모양(트리거)** 메뉴에 `callFeed_run` · 시간 기반 · 1시간마다 한 줄이 있으면 정상.

### 4단계 — 하루 뒤 개수 확인

1. 왼쪽 **실행(목록 모양)** 메뉴 → 맨 위 `callFeed_run` 줄을 누르면 로그가 보인다.
   ```
   [시험 모드 — 보내지 않음] 전사 7건 확인
   개인 번호 목록 통화: 2(내용까지 개인 통화함으로)
   보낼 것: 5 (업무 3 · 개인 1 · 애매 0 · 구분 없음(옛 분석·비어 있음) 1 · 분석 실패 0)
   분석 대기: 0 · 대기 목록: 0건 · 넘김: 0
   끝까지 봄
   ```
   - 시험 모드는 진행 위치를 앞으로 옮기지 않으므로, 이 숫자는 **설치한 뒤 지금까지 전부**다.
   - **분석 대기**는 전사는 있는데 분석 파일이 아직 없는 통화다. 이 통화에서 멈추지 않고 건너뛰어 뒤의 통화를 계속 본다(`분석 대기: n건(건너뛰고 계속)`). 시험 모드에서는 대기 목록을 저장하지 않고 개수만 센다.
   - 실제로 보내는 모드에서는 이 통화를 **대기 목록**(최대 50건)에 적어 두고, 매 실행 처음에 다시 본다. 분석이 생기면 그때 한 번 보내고 목록에서 뺀다. 만든 지 3일이 지나도 분석이 없으면 넘김으로 세고 뺀다. 목록이 50건을 넘으면 오래된 것부터 넘긴다.
2. 숫자가 그날 통화와 대충 맞는지 본다. 이 숫자를 커맨드센터에 알린다(이름·번호는 없이 숫자만).
   - "개인 번호 목록 통화"가 너무 적으면 2단계 목록 글자가 전사 파일 이름과 다른지 본다.
   - "구분 없음"은 옛 3.1 분석이거나 분석이 업무/개인 칸을 비워 둔 통화다. 요약·전문은 보내지 않고 숫자만 센다. 많으면 커맨드센터에 알린다.
   - "개인"으로 셀 통화가 "업무"로 세어졌으면, 그 번호·이름을 개인 목록에 더한다(목록 통화는 분석이 업무라고 해도 개인으로 고쳐 보낸다).

### 5단계 — 시험 모드 끄기

1. 함수 칸에서 `callFeed_testModeOff` → **[실행]**. 로그에 `시험 모드를 껐습니다`.
2. 다음 정각 무렵 자동 실행부터 Web2로 보낸다. 시험한 날의 통화도 그때 같이 간다(한 번에 20건까지, 남으면 다음 시간).
3. 바로 보고 싶으면 함수 칸에서 `callFeed_run` → **[실행]**. 로그에 `보냄: n (업무 …)`이 나오고, Web2 **통화** 메뉴를 새로고침하면 보인다.
   - `비밀값 불일치(401)` → 2단계 값과 Supabase 값이 같은지(앞뒤 빈칸 주의).
   - `서버 하루 상한(429)` → 하루 200건 상한(업무·개인 합산). 다음 날 이어서 간다.
   - `서버·연결 실패(HTTP …)` → 다음 실행에서 같은 건을 다시 보낸다(3번 실패하면 넘김). 계속되면 커맨드센터에 알린다.

## 지난 개인·애매 통화 다시 보내기 (1회용, CALL-개인통화함 3단계)

개인 통화함이 생기기 전에 지나간 개인·애매 통화는 내용이 서버에 가지 않고 개수만 남았다. 최근 7일 녹음 중 분석이 요약을 남긴 개인·애매 통화(그리고 개인 번호 목록 통화)를 한 번 더 보내 개인 통화함에 채운다. 서버가 중복을 막으므로 이미 있는 통화는 `이미 있음`으로 끝난다.

1. 코드 전체를 새로 붙여 넣고 저장한다(폴더 칸은 지금 쓰는 값 그대로).
2. 시험 모드가 켜져 있으면(`callFeed_testModeOn`) 함수 칸에서 `callFeed_resendPersonal` → **[실행]**. 로그에 `보낼 것: n (개인 … · 애매 …)`이 나오면 개수만 확인하는 것이고 아무것도 보내지 않는다.
3. 개수가 맞으면 `callFeed_testModeOff` → **[실행]**, 이어서 `callFeed_resendPersonal` → **[실행]**. 한 번에 20건까지 보낸다. 로그에 `멈춘 이유`가 있으면 다시 **[실행]**하고, `끝까지 봄`이 나오면 끝이다.
4. Web2 **통화** 메뉴 → 맨 위 `개인 통화함 n ›`에서 확인한다.
   - `서버 하루 상한(429)` → 내일 같은 함수를 다시 실행한다(진행 위치가 따로 적혀 있어 이어서 간다).
   - 처음부터 다시 보고 싶을 때만 `callFeed_resendReset`을 실행한다.
- 평소 보내기(`callFeed_run`)의 진행 위치(`CALL_FEED_STATE`)는 건드리지 않는다. 이 함수의 진행 위치는 `CALL_FEED_RESEND_STATE`에만 적힌다.

## 멈추기·되돌리기

- **보내기만 멈추기**: 함수 칸에서 `callFeed_removeTrigger` 실행(또는 트리거 메뉴에서 `callFeed_run` 줄 삭제). 전사·분석 트리거는 그대로다.
- **잠깐 보내지 않고 세기만**: `callFeed_testModeOn` 실행.
- **입구 닫기**: Supabase Secrets에서 `COLLECTOR_FEED_SECRET` 삭제 → 그 즉시 모든 보내기가 거절된다(401). 다른 Web2 기능은 영향 없다.
- 프로젝트가 필요 없으면 script.google.com 에서 `Web2 수집 보내기`를 휴지통으로 보낸다(전사·분석과 무관).
- Web2에 이미 들어간 통화는 Web2 통화 메뉴에서 지운다(화면 작업 뒤). Drive 원본은 언제나 그대로다.

## 스크립트 속성 정리

| 속성 | 누가 넣나 | 뜻 |
| --- | --- | --- |
| `COLLECTOR_FEED_SECRET` | 명진 | Web2 입구 비밀값 |
| `CALL_FEED_PERSONAL_LIST` | 명진 | 개인 번호·연락처 이름 |
| `CALL_FEED_TEST_MODE` | 스크립트(`켬`/`끔`) | `끔`일 때만 보낸다 |
| `CALL_FEED_RESEND_STATE` | 스크립트 | 지난 개인·애매 통화 다시 보내기(1회용)의 진행 위치. 평소 보내기와 따로 |
| `CALL_FEED_STATE` | 스크립트 | 어디까지 보냈는지(시각), 다시 보낼 건, 분석을 기다리는 통화 목록, 보낼 개인 개수. 지우면 `callFeed_setup`부터 다시(그 시각 뒤 통화부터) |

# 텔레그램 보내기 설치 (TG-소식메뉴 3-나)

Web2 **텔레그램 소식** 메뉴를 채우는 설정이다. **통화와 같은 프로젝트(`Web2 수집 보내기`)·같은 비밀값(`COLLECTOR_FEED_SECRET`)**을 쓰고, 코드 파일도 같은 `collector-feed.gs`다. 통화 부분은 그대로 돌고, 텔레그램 부분(`tgFeed…`)만 더해진다.

- 매일 **08:10경**(07:30 수집 뒤) 앱 스크립트가 **어제까지 끝난 날**의 메시지를 방별·날짜별로 묶어 Web2 서버(`collector-feed`)로 보낸다. 오늘 날짜는 하루가 끝난 뒤(다음 날 아침)에 보낸다.
- 서버는 이미 배포되어 있고 텔레그램 묶음을 받는다(AI가 중요한 소식만 골라 요약). 이 안내는 앱 스크립트 쪽만 다룬다.
- **허용 목록에 적은 업무방만** 읽는다. 목록에 없는 방(개인 수집 포함)은 열지 않는다. 목록이 비어 있으면 아무 방도 읽지 않고 멈춘다.
- 보내는 사람은 실제 값을 보내지 않고 방·날짜마다 A, B, C 같은 임시 이름으로 바꿔 보낸다.
- Drive 파일은 **읽기만** 한다. `검토후보` 폴더와 `telegram_ai_review_state_v2`는 열지도 고치지도 않는다.
- 한 번에 4.5분 안에서 멈춘다. 남았으면 10분 뒤 자동으로 이어서 한다(하루 12번까지). 그래도 남으면 다음 날 08:10에 이어진다.
- 같은 방·같은 날은 한 번만 보낸다. 중간에 멈췄다 이어져도 이미 보낸 묶음은 다시 보내지 않는다.
- **7일 전 날짜부터** 보낸다(하루가 끝난 날만. 그 전 날짜는 보내지 않는다). 한 번 실행에 30묶음까지만 보내고 나머지는 10분 뒤 이어 한다. 처음에는 **시험 모드**다: 서버로 보내지 않고 방·날짜별 개수만 실행 로그에 적는다.

## 순서 (PC에서)

### T1단계 — 코드 새로 붙여넣기

통화를 이미 설치했다면 코드가 바뀐 것이므로 **전체를 새로 붙여넣는다**. 통화 설정(스크립트 속성·트리거)은 그대로 남는다.

1. https://script.google.com → 목록에서 `Web2 수집 보내기`를 연다.
2. 저장소의 `docs/ops/collector-feed.gs`를 전부 복사한다.
3. 편집기 `Code.gs` 안 내용을 모두 지우고 붙여 넣는다.
4. 맨 위 **통화 칸**을 다시 채운다(`CALL_FEED_CALL_ROOT_FOLDER`, 통화 설치 때 넣은 그 글자). 새 코드를 붙이면 빈 칸으로 돌아간다.
5. 바로 아래쪽 **텔레그램 칸**을 채운다: `TG_FEED_ROOT_FOLDER`의 `'여기에_텔레그램_수집_폴더_주소_끝부분'` 자리.
   - Drive에서 텔레그램 수집 폴더(안에 `원문`, `검토후보` 등이 있는 폴더)를 연다 → 주소창 `https://drive.google.com/drive/folders/` **뒤 글자**(`?` 뒤는 빼기).
   - 따옴표는 그대로 두고 안쪽 글자만 바꾼다. 이 글자는 저장소·문서·채팅에 쓰지 않는다.
6. 위쪽 **저장(디스크 모양)** 버튼.
   - 정상: 오류 없이 저장되고 위쪽 함수 칸에 `tgFeed_setup` 같은 이름이 보인다.

### T2단계 — 허용 방 목록 넣기

왼쪽 **톱니바퀴(프로젝트 설정)** → 맨 아래 **스크립트 속성** → **[스크립트 속성 추가]**.

| 속성 | 값 |
| --- | --- |
| `TG_FEED_ROOMS` | 보낼 업무방 목록. 쉼표(`,`) 또는 줄바꿈으로 구분. 방 이름(폴더 이름에서 번호와 `_` 뒤 부분 전체), 폴더 이름 전체, 또는 앞의 방 번호. 예: `가상 업무방, -1001234567890` |

- **모든 방 보내기**: `TG_FEED_ROOMS`에 `*` 하나만 넣고, 뺄 방은 새 속성 `TG_FEED_ROOMS_EXCLUDE`에 방 이름을 쉼표로 적는다(예: `가족방, 친구방`). 새로 생긴 방도 자동으로 들어가므로 새 개인방이 생기면 제외 목록에 더한다(10/25 명진 결정).
- 방 폴더는 Drive의 수집 폴더 → `원문` 안에 `<방 번호>_<방 이름>` 모양으로 있다. 거기서 **업무방만** 골라 적는다.
- 업무 관계자 1:1 대화방은 방마다 명진 님이 넣을지 정한다. 개인 용도 방은 절대 적지 않는다.
- 이 목록은 저장소·문서·채팅에 붙여 넣지 않는다.
- 비밀값 `COLLECTOR_FEED_SECRET`은 통화 때 이미 넣었으므로 다시 넣지 않는다(없으면 2단계).
- **[스크립트 속성 저장]**.
  - 정상: 속성 표에 `TG_FEED_ROOMS`가 보인다.

### T3단계 — 시작 (시험 모드)

1. 편집기 위쪽 함수 칸에서 `tgFeed_setup` → **[실행]**.
2. 처음이면 "승인 필요" 창: **[권한 검토]** → 내 계정 → **[고급]** → **[Web2 수집 보내기(으)로 이동]** → **[허용]**. 통화 때 이미 했다면 나오지 않을 수 있다. 다시 나오면 같은 방법으로 허용한다.
3. 하단 실행 로그에 아래 비슷한 줄이 나오면 정상이다.
   ```
   원문 폴더: 찾음
   허용 방: 적은 것 3개 중 3개 찾음
   비밀값: 있음
   시험 모드: 켬(보내지 않음)
   시작 날짜: 2026-…
   ```
   - `텔레그램 수집 폴더 칸을 채우세요` → T1단계 5번.
   - `"원문" 폴더가 없습니다` → 폴더 칸에 수집 폴더가 아닌 다른 폴더를 넣은 것.
   - `허용 방: 적은 것 3개 중 2개 찾음 — 못 찾은 것: …` → 적은 글자가 `원문` 안 폴더 이름(또는 앞 방 번호)과 다른 것. T2단계를 고친다.
   - `비밀값: 없음 또는 너무 짧음` → 2단계.
4. 함수 칸에서 `tgFeed_installDailyTrigger` → **[실행]**. 로그에 `매일 08:10 트리거를 만들었습니다`.
   - 왼쪽 **시계 모양(트리거)** 메뉴에 `tgFeed_run` · 시간 기반 · 일 단위 타이머 · 오전 8시~9시 한 줄이 있으면 정상이다(앱 스크립트는 정각이 아니라 그 구간 안에서 돈다).
   - 통화 트리거(`callFeed_run`, 1시간마다)는 그대로 남아 있어야 한다.

### T4단계 — 하루 뒤 개수 확인

1. 설치 **다음 날 아침 08:30 이후** 왼쪽 **실행(목록 모양)** 메뉴 → 맨 위 `tgFeed_run` 줄을 누르면 로그가 보인다.
   ```
   [시험] 가상 업무방 2026-10-25: 전체 120개 중 글 있는 98개, 묶음 1개
   [시험 모드 — 보내지 않음] 방 3개, 날짜 3건 확인
   메시지: 글 있는 것 210개 · 글 없는 것(첨부만 있음) 25개
   보낼 묶음: 4
   허용 방 모두 찾음
   끝까지 봄
   ```
   - 시험 모드는 어디까지 봤는지를 앞으로 옮기지 않는다. 그래서 다음 날 로그는 시작 날짜부터 어제까지 전부 다시 센다.
2. 숫자가 그날 대화와 대충 맞는지 본다. 커맨드센터에 **숫자만** 알린다(방 이름·내용 없이). 같이 알릴 것: `끝까지 봄` 대신 `멈춘 이유: 시간 제한`이 나왔는지, 실행에 걸린 시간(실행 목록의 "기간" 열).
   - 허용 방이 모두 나오는데 날짜 건수가 0이면 그 방 폴더 안에 `messages` 폴더나 월 폴더(예: `2026-10`)가 없는 것이다. 커맨드센터에 알린다.
   - `멈춘 이유: 시간 제한`이 시험 모드에서 나오면 방이 많거나 파일이 많다는 뜻이다. 시험 모드는 이어 하기가 없으므로 같은 곳에서 계속 멈출 수 있다. 숫자를 알려 주면 커맨드센터가 나누는 방법을 정한다.

### T5단계 — 시험 모드 끄기

1. 함수 칸에서 `tgFeed_testModeOff` → **[실행]**. 로그에 `텔레그램 시험 모드를 껐습니다`.
2. 다음 날 08:10 무렵 자동 실행부터 Web2로 보낸다. 시험한 날까지 밀린 날짜도 그때 같이 간다.
3. 바로 보고 싶으면 함수 칸에서 `tgFeed_run` → **[실행]**. 로그에 `보낸 묶음: n (소식 m개 저장 …)`이 나오고, Web2 **텔레그램 소식** 메뉴를 새로고침하면 보인다.
   - `비밀값 불일치(401)` → 2단계 값과 Supabase 값이 같은지(앞뒤 빈칸 주의).
   - `서버 하루 상한 또는 이번 달 AI 상한(429)` → 하루 묶음 80개 또는 이번 달 AI 비용 상한. 다음 날 08:10에 이어서 간다.
   - `서버 준비 안 됨(…AI_NOT_CONFIGURED)` → Supabase에 AI 열쇠가 없다. 커맨드센터에 알린다. 다음 날 다시 시도한다.
   - `서버·연결 실패(HTTP …)` → 10분 뒤 같은 묶음을 다시 보낸다(3번 실패하면 넘기고 "판정 실패 1"로 센다).
   - `멈춘 이유: 시간 제한 … (10분 뒤 이어 하기 예약)` → 정상이다. 트리거 메뉴에 `tgFeed_continue` 줄이 잠깐 생겼다가 쓰고 나면 사라진다.

## 텔레그램이 멈췄을 때 (확인·빠진 날 다시 보내기)

1. 함수 칸에서 `tgFeed_check` → **[실행]**. 로그의 `자동 실행 트리거`(매일 08:10 `tgFeed_run`이 있는지), `방별 진행`(어제까지 못 끝낸 방 수), `마지막 실행`(멈춘 이유)을 본다. `이번 달 AI 상한`이면 다음 달 1일까지 풀리지 않는다.
2. 빠진 날을 다시 보내려면: 왼쪽 톱니(프로젝트 설정) → 스크립트 속성 → 속성 추가 `TG_FEED_REWIND_DAY` = `2026-10-25`(빠진 첫 날, 최근 7일 안·어제까지) → 함수 `tgFeed_rewind` → **[실행]** → 함수 `tgFeed_run` → **[실행]**. 같은 방·날 묶음은 서버가 중복으로 걸러 다시 저장하지 않지만, 서버 하루 상한(묶음 80개)에는 센다. 파일은 그 날 0시부터 3일 안에 고쳐진 것만 읽으므로 되도록 빨리 한다.

## 텔레그램만 멈추기·되돌리기

- **되돌리기(보내기 멈춤)**: 함수 칸에서 `tgFeed_removeTrigger` 실행(또는 트리거 메뉴에서 `tgFeed_run`·`tgFeed_continue` 줄 삭제). 통화·전사·분석 트리거는 그대로다.
- **잠깐 보내지 않고 세기만**: `tgFeed_testModeOn` 실행.
- **방 하나만 빼기**: `TG_FEED_ROOMS`에서 그 줄을 지운다. 다음 실행부터 그 방은 열지 않는다.
- **입구 닫기**: Supabase Secrets에서 `COLLECTOR_FEED_SECRET` 삭제 → 통화·텔레그램 모두 거절된다(401).
- Web2에 이미 들어간 소식은 Web2 텔레그램 소식 메뉴에서 지운다. Drive 원본은 언제나 그대로다.
- 어디까지 보냈는지를 처음으로 되돌리려면 스크립트 속성 `TG_FEED_STATE`를 지우고 `tgFeed_setup`을 다시 실행한다(그날부터 다시 시작. 이미 보낸 날짜를 다시 보내면 서버가 같은 묶음은 알아보고 건너뛰지만, 그 사이 메시지가 늘었으면 같은 소식이 한 번 더 생길 수 있으니 커맨드센터와 먼저 상의한다).

## 텔레그램 스크립트 속성 정리

| 속성 | 누가 넣나 | 뜻 |
| --- | --- | --- |
| `COLLECTOR_FEED_SECRET` | 명진(통화 때 이미) | Web2 입구 비밀값. 통화와 같은 값 |
| `TG_FEED_ROOMS` | 명진 | 보낼 업무방 허용 목록 |
| `TG_FEED_TEST_MODE` | 스크립트(`켬`/`끔`) | `끔`일 때만 보낸다 |
| `TG_FEED_STATE` | 스크립트 | 시작 날짜, 방별로 끝낸 마지막 날짜, 묶음 중간 위치, 다시 보낼 건, 이어 하기 횟수 |

## 알아 둘 점 (시험 때 확인할 것)

- 파일 한 개 읽기에 걸리는 시간은 아직 실측하지 않았다(추정 0.1~0.3초). T4단계의 "시간 제한" 여부와 실행 기간이 그 실측이다.
- 메시지 파일의 시각 칸(`date_utc`, 없으면 `date_kst`)과 월 폴더(`messages/<YYYY-MM>`) 모양은 설계 문서 기준이다. 실제와 다르면 개수가 0으로 나오므로 T4단계에서 드러난다.
- 하루가 끝난 뒤에 뒤늦게 들어온 옛 메시지(`backfill`)는 이미 보낸 날짜에는 보내지 않는다(같은 소식이 두 번 생기는 것을 막기 위해).
- 파일은 "그 날 0시부터 3일 안에 고쳐진 것"만 열어 본다. 수집이 3일 넘게 멈췄다가 한꺼번에 채운 날은 빠질 수 있다.

# 통화 요약용 맥락 문서 자동 갱신 설치 안내 (CALL-맥락문서)

하루 한 번 앱 스크립트가 Web2에서 **담당조직(정식 이름·약칭), 진행 중 프로젝트 이름, 통화 상대 "조직 — 이름 직함" 목록**을 받아, '통화 요약용 맥락' 문서의 **자동 구간**만 새로 쓴다. 명진 님이 쓴 부분은 건드리지 않는다.

- 코드: [call-context-sync.gs](call-context-sync.gs) · 서버: `supabase/functions/collector-feed/context.ts` · 설계: [call-context.md](../design/call-context.md)
- 사람 목록(CALL-맥락사람): 명진 님이 고친 상대·조직이 AI 값보다 앞서고, 개인 통화함은 빠진다. 번호·이메일·메모·통화 내용·ID는 받지도 쓰지도 않는다. 우리 쪽 사람(공공운수노조)은 조직 없이 이름·직함만 나온다. 같은 이름이 서로 다른 조직에 있으면(고친 값이 하나뿐인 경우 제외) 헷갈리지 않게 목록에서 뺀다. 우리 쪽 사람 설명 같은 긴 글은 문서의 **명진 님이 쓴 부분**에 적으면 그대로 유지된다. 사람 목록은 DB 함수(`20261026160000_call_context_people`)가 적용돼야 나온다. 적용 전에는 조직·프로젝트만 쓴다.

## 설치 순서 (Edge 배포가 먼저)

0. Edge `collector-feed` 새 판 배포(커맨드센터가 승인 요청, 명진 님은 GitHub 승인 버튼만). 배포 전에는 아래 3단계에서 "Web2 응답 400"으로 실패하며 문서는 바뀌지 않는다.
1. https://script.google.com 에서 **'Web2 수집 보내기'** 프로젝트를 연다(통화 분석 프로젝트가 아니다. 이미 `COLLECTOR_FEED_SECRET`이 들어 있다).
2. 왼쪽 파일 목록 위 **[+] → 스크립트**를 눌러 이름을 `call-context-sync`로 하고, 저장소 `docs/ops/call-context-sync.gs` 내용을 전부 붙여 넣은 뒤 저장한다.
3. 왼쪽 톱니바퀴 **[프로젝트 설정] → 스크립트 속성 → 속성 추가**: 이름 `CALL_CONTEXT_DOC_ID`, 값은 맥락 문서 주소 `/d/` 뒤 글자(분석 스크립트가 쓰는 것과 같은 문서).
4. 맥락 문서 맨 아래에 표지 두 줄을 넣는다: 위쪽 함수 선택 칸에서 `callCtx_addMarkers` → **[실행]**(처음에는 문서 접근 권한 허용 창이 뜬다). 문서 맨 아래에 `<<WEB2 자동 시작>>`, `<<WEB2 자동 끝>>` 두 줄이 생긴다. 옛 목록 중 자동으로 바꿀 부분이 있으면 두 줄 사이로 옮기거나 지운다. 이 두 줄은 지우거나 옮기지 않는다.
5. 함수 `callCtx_check` → **[실행]**: 문서는 고치지 않고 받은 개수와 "내용이 달라졌습니다"만 실행 로그에 나온다.
6. 속성 `CALL_CTX_TEST_MODE`를 `끔`으로 추가(또는 값 변경)하고 함수 `callCtx_run` → **[실행]**: 자동 구간이 처음 채워진다. 문서를 열어 확인한다.
7. 함수 `callCtx_installDailyTrigger` → **[실행]** 1회: 매일 새벽 4시대에 자동으로 돈다.

## 동작 규칙

- 표지 줄이 없거나 하나뿐이거나 순서가 바뀌었으면 아무것도 쓰지 않고 실패로 센다.
- 받은 목록이 비었거나(담당조직 0개) 모양이 다르면 덮어쓰지 않는다(마지막 성공본 유지). 내용이 같으면 문서를 건드리지 않는다.
- 연속 3번 실패하면 일부러 오류를 내서 앱 스크립트 실패 알림 메일이 온다.
- 사람 목록이 비어 있어도(DB 함수 적용 전·되돌린 뒤) 조직·프로젝트는 그대로 쓴다. 사람 목록이 사라지면 다음 갱신에서 문서의 사람 줄도 사라진다.
- 서버 하루 호출 상한은 20회(인스턴스별 최선 노력). 스크립트는 하루 1회만 부른다.

## 되돌리기

- 갱신 멈추기: 함수 `callCtx_removeTrigger` 실행. 입구 전체를 닫으려면 Supabase 비밀값 `COLLECTOR_FEED_SECRET` 삭제(통화·텔레그램 보내기도 멈춘다).
- 문서 되돌리기: 문서의 **파일 → 버전 기록 → 버전 기록 보기**에서 이전 버전 복원.
- 서버 되돌리기: 이전 소스 SHA를 `ref`에 넣어 같은 Edge workflow로 재배포(`context` action이 사라질 뿐 다른 동작은 같다).

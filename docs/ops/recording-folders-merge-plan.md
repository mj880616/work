# 녹음 폴더 합치기 계획 (AI 업무수집 · 음성 녹음 백업 · Telegram업무자료)

📱 폰 가능(계획 문서). 실행은 이 문서로 하지 않는다. CC가 사용자 확인을 받은 뒤 6절 순서로 진행한다.

- 요청(11/24 18:19 사용자): "이 AI 업무 수집하고 음성 녹음 백업 관계가 어떻게 되지? 이거 합칠 수 있으면 좋겠는데. 하나의 폴더로 중복되면 지우고."
- 이 문서에는 폴더·파일 번호(id), 녹음 파일 이름, 사람 이름을 쓰지 않는다(공개 저장소). 실제 번호는 CC가 Drive에서 그때 읽는다.
- 범위: 폴더 구조만. 앱 스크립트 셋('웹2 수집보내기'·'trascription'·'Web2 수집 점검')은 합치지 않는다(기존 결정).

## 0. 요약 (사용자용)

1. **관계**: 둘 다 같은 전사 스크립트('trascription')가 쓰는 "녹음 → 글로 바꾸기" 폴더다. `AI 업무수집 ▸ 통화 녹음`은 **통화 녹음**, `음성 녹음 백업`은 **음성 메모 녹음**이다. 폰 녹음 백업 앱이 각각 `원본`에 올리고, 스크립트가 `전사`에 글(txt)을 만든다. 통화만 AI 분석을 한 번 더 해서 `검토대기`(분석 .md)를 만든다.
2. **겹치는 것**: 같은 녹음이 두 폴더에 함께 들어가는 길은 코드에 없다. 실제로 찾아보니 `음성 녹음 백업 ▸ 원본`에 옛 통화 녹음 3개(8월, 10/1 처음 올릴 때 들어간 것)가 있는데 통화 쪽 같은 이름 파일과 **크기가 달라** 같은 파일이 아니다(통화 녹음 조각으로 보임). 검토대기 .md와 전사 .txt는 **두 벌이 아니다**: .md는 .txt를 읽고 만든 요약·후보이고, 이름 끝 번호로 .txt를 가리킨다. 둘 다 남겨야 한다.
3. **합친 모습**: `AI 업무수집` 하나 아래에 `통화 녹음`·`음성 녹음 백업`·`검토대기`·`검토완료`를 나란히 둔다. 폴더를 **옮기기만** 하고 이름·안쪽 구조(원본·전사·수동전사대기)는 그대로 둔다. 위 폴더 이름은 원하면 `녹음·AI 수집`처럼 바꿀 수 있다.
4. **사용자가 정할 것**: ① 이 모양(옮기기만)으로 할지 ② 위 폴더 이름을 바꿀지(바꾸지 않아도 됨) ③ 음성 쪽에 있는 옛 통화 조각 3개를 둘지 휴지통으로 보낼지 ④ `Telegram업무자료`는 합치지 않는 것에 동의하는지.
5. **위험**: 폰 녹음 백업 앱이 폴더를 "번호"가 아니라 "이름·위치"로 찾으면, 옮긴 뒤 녹음을 처음부터 다시 올릴 수 있다(지난번 중복과 같은 일). 그래서 하나 옮기고 → 새 음성 메모 하나로 시험 → 문제가 없을 때만 끝낸다. 지금 돌고 있는 중복 정리가 끝난 뒤에 한다.

### 3-1. CC가 더 확인할 것 (Drive 커넥터, 읽기만)

1. 음성 `원본`의 통화 파일: `parentId = '<음성 원본 번호>' and title contains '통화'` → 이름별로 `title contains '<녹음 날짜_시각>'` 검색해 통화 `원본`·통화 `전사`에 짝이 있는지 본다. 크기가 같으면 md5를 비교한다.
2. md5는 Drive 커넥터 결과에 없다. 필요하면 Drive API `files.list`(`fields=files(id,name,size,md5Checksum,parents)`)를 쓰는 **읽기 전용** 미리 보기로 본다(`previewDuplicateRecordings`처럼 바꾸는 것 없음). 기준: `md5Checksum`과 `size`가 같고 0보다 크면 같은 녹음.
3. 반대로 통화 `원본`에 `음성 …` 파일이 있는지: `parentId = '<통화 원본 번호>' and title contains '음성'`(11/24 확인: 없음).
4. 음성 `전사`에 통화 전사 txt(`통화 …txt`)가 있는지, 있으면 검토대기 .md의 `__SRC_` 번호가 그 txt를 가리키는지(이름 끝만 본다, 내용은 열지 않음).

## 4. 합치기 안

### 4-1. 목표 구조 (권장: 옮기기만)

```
내 드라이브
└─ AI 업무수집 (원하면 '녹음·AI 수집'으로 이름 변경)
   ├─ 통화 녹음 ▸ 원본 · 전사 · 수동전사대기      (그대로)
   ├─ 음성 녹음 백업 ▸ 원본 · 전사 · 수동전사대기  (맨 위에서 이리로 옮김, 이름 그대로)
   ├─ 검토대기                                      (그대로, 통화 녹음과 같은 줄)
   └─ 검토완료                                      (그대로)
Telegram업무자료                                    (그대로 둠)
```

- 지시서 예시 `녹음 ▸ 통화/음성 ▸ 원본·전사·분석·검토대기·검토완료`는 **권하지 않는다.** `검토대기`·`검토완료`를 `통화` 안으로 넣으면 보내기(`callFeed_folders_`)와 분석 스크립트가 "통화 녹음의 상위 폴더" 안에서 찾으므로 둘 다 멈춘다. 그렇게 하려면 두 스크립트 코드를 고쳐야 하고(범위 밖), `통화 녹음`·`전사` 이름을 바꾸면 웹2 '최근' 거르기도 고쳐야 한다.
- `원본`·`전사`·`수동전사대기` 이름은 스크립트가 이름으로 찾으므로 바꾸지 않는다.
- 폴더를 옮기면 Drive 번호(id)는 그대로다. 번호로 찾는 곳(PIPELINES, `CALL_FEED_CALL_ROOT_FOLDER`, `WEB2_HEARTBEAT_TRANSCRIPT_FOLDER`, `TG_FEED_ROOT_FOLDER`)은 안 깨진다.

### 4-3. 중복 정리 기준 (합친 뒤)

- 같은 폴더 종류 안에서 `md5Checksum`+`size`가 같은 것만 같은 녹음으로 본다. 이름만 같으면 지우지 않는다.
- 남기는 순서: 기록이 가리키는 파일(검토대기 .md의 `__SRC_` txt, 바로가기 대상, `RECORDING_KEEP_IDS`, 웹2 기록이 가리키는 것) → `원본`에 있는 것 → 가장 오래된 것.
- 지우는 방법은 휴지통(30일 되돌리기)만. 영구 삭제 없음. 이미 있는 `cleanupDuplicateRecordings`를 그대로 쓴다.
- 통화 ↔ 음성 사이(다른 맨 위 폴더) 중복은 지금 코드가 보지 않는다. 3-1절 확인에서 md5 같은 것이 나오면 그때 사용자에게 한 줄로 묻고 손으로 휴지통.
- 음성 `원본`의 옛 통화 조각 3개는 md5가 다르므로 중복 정리 대상이 아니다. 사용자 결정대로(그대로 / 휴지통).

## 5. 위험

1. **백업 앱이 다시 올림(가장 큼)**: 앱이 폴더를 이름·경로로 기억하면, `음성 녹음 백업`을 옮긴 순간 "폴더가 없다"고 보고 새로 만들거나 전부 다시 올릴 수 있다. 대비: 6절 3~4단계(옮긴 뒤 새 음성 메모 하나로 시험, 맨 위에 새 `음성 녹음 백업`이 생겼는지 확인). 생기면 바로 되돌린다(7절).
2. **중복 정리 진행 중**: 오늘 계획 파일이 `통화 녹음` 안에 있고 5분마다 이어 간다. 계획에는 폴더가 아니라 파일 번호가 있어 옮겨도 깨지지는 않지만, 끝난 뒤(`RECORDING_CLEANUP_LAST`에 남음 0, 이어 하기 트리거 없음) 옮긴다.
3. **이름 찾기를 놓침**: `RECORDING_CLEANUP_ROOTS`를 안 넣으면 음성 쪽 중복 정리가 조용히 빠진다(오류 없음). 6절 5단계 미리 보기 결과에 음성 묶음이 나오는지로 확인.
4. **같은 이름 폴더 둘**: 옮길 곳에 같은 이름(`음성 녹음 백업`)이 이미 있으면 스크립트 "같은 이름 폴더 2개" 멈춤. 옮기기 전에 확인.
5. 텔레그램 폴더는 수집기 동작을 모르니 옮기지 않는다(옮기면 수집이 깨질 수 있다는 기존 판단, `app-folders.mjs`).

## 6. 옮기는 순서 (사용자 확인 뒤 CC)

1. 중복 정리가 끝났는지 본다(실행 기록 마지막 줄에 `남음`이 없음, 트리거 화면에 `cleanupDuplicateRecordings` 없음).
2. 지금 상태를 적어 둔다: 두 맨 위 폴더 번호, 각 `원본`의 파일 수·최근 파일 시각(이름은 적지 않음).
3. `음성 녹음 백업`을 `AI 업무수집` 안으로 **옮긴다**(Drive에서 끌어 놓기 또는 '이동'. 복사 아님). 번호가 그대로인지 확인.
4. 사용자가 폰으로 짧은 음성 메모를 하나 녹음 → 백업 앱이 올린 뒤 `AI 업무수집 ▸ 음성 녹음 백업 ▸ 원본`에 들어갔는지, 내 드라이브 맨 위에 새 `음성 녹음 백업`이 안 생겼는지, `원본` 파일 수가 1만 늘었는지 본다. 통화도 하나(아무 통화) 같은 방법으로 본다.
5. trascription 스크립트 속성 `RECORDING_CLEANUP_ROOTS`에 음성 폴더 번호를 넣고(PIPELINES에 없을 때만) `previewDuplicateRecordings` 실행 → 결과 줄 확인(바뀌는 것 없음).
6. '웹2 수집보내기'의 `callFeed_check`(설정 확인, 보내지 않음)를 한 번 돌려 `분석 폴더: 2개 찾음(검토대기·검토완료)`가 그대로인지 본다. 웹2 홈 '마지막 수집 시각'의 통화 녹음 전사 줄이 다음 통화 뒤 갱신되는지 본다.
7. (사용자가 원하면) 위 폴더 이름 변경 → `app-folders.mjs` 안내 글 PR.
8. 3-1절 확인 결과와 사용자 결정대로 옛 통화 조각 정리(휴지통).

## 7. 되돌리기

- 폴더 옮기기: `음성 녹음 백업`을 다시 내 드라이브 맨 위로 옮긴다(번호 그대로라 스크립트는 바로 원래대로). 스크립트 속성 `RECORDING_CLEANUP_ROOTS`에 넣은 번호는 둬도 해가 없다(같은 번호는 한 번만 셈).
- 백업 앱이 새 폴더를 만들었으면: 새로 생긴 맨 위 `음성 녹음 백업`과 그 안 새 파일은 지우지 말고 먼저 원래 폴더를 맨 위로 되돌린 뒤, 새 폴더의 파일을 md5로 비교해 같은 것만 휴지통.
- 휴지통으로 보낸 파일: 30일 안에 Drive 휴지통에서 복원.
- 이름 변경: 원래 이름으로 다시 바꾼다.

## 8. 하지 않는 것

- 앱 스크립트 코드 수정·합치기, 실행. DB·Edge 변경. 파일 영구 삭제.
- `Telegram업무자료` 옮기기·지우기(`검토후보`·`telegram_ai_review_state*.json`은 Q9 결정대로 그대로).
- `원본`·`전사`·`수동전사대기`·`검토대기`·`검토완료`·`통화 녹음` 이름 바꾸기.
- 범위 밖 발견: `통화 녹음 ▸ 전사검증_2026-10-09`(10/9 확인용, 코드에서 안 씀)와 맨 위 `telegram_ai_review_state.json`(v1, 10/5 이후 안 바뀜)은 정리 후보일 뿐 이 계획에서 건드리지 않는다.

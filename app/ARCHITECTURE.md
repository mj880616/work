# 웹2 앱 구조

## 1. 진입 경로

현재 런타임 진입은 아래 한 경로를 기준으로 함.

1. `index.html`
2. `app.js`
3. `loader-v2.js`
4. `runtime-client.js`, `app-router.js` 등 공용 코어
5. 기능 모듈

`index.html`은 `app.js`만 직접 로드함. 기능 모듈 추가·삭제는 원칙적으로 `loader-v2.js`에서 관리함.

캐시 버전(CI-버전자동화 3단계): 저장소의 HTML·JS·CSS는 번호 없는 경로로 서로를 부르고 `?v=`를 손으로 쓰지 않음. GitHub Pages 배포 빌드(`.github/workflows/pages-deploy.yml` → `scripts/build-pages.mjs`)가 저장소 안 파일을 가리키는 정적 경로마다 그 파일 최종 내용의 SHA-256 앞 10자를 `?v=`로 붙임. 잎부터 계산하므로 기능 모듈이 바뀌면 `view-loader.js` → `loader-v2.js` → `app.js` → `index.html`의 해시가 차례로 바뀜. 빌드가 건드리지 않는 것: `${…}`가 든 동적 경로, 저장소 밖 주소·저장소에 없는 파일, 폴더 이름에 판 번호가 든 외부 라이브러리(`hwp-lab/rhwp-0.8.7/`, `markdown-lib/mermaid-11.17.2/` 등) 안쪽, 스크립트가 읽는 JSON 자료(`press/archive.json`), JSON 파일 안의 주소(`windows-manifest.json`의 아이콘). JS 안 문자열이 저장소 파일 경로와 같으면(예: `'./app.js'`) 빌드가 그 문자열에도 `?v=`를 붙이므로, 경로 문자열을 비교·표시용으로 쓰지 않음. 저장소 소스에 손으로 쓴 `?v=`는 CI(`scripts/check-loader-cache.mjs`)가 막음.

업데이트 기록(UI-업데이트안내): 저장소의 `app/release-notes/*.json`(PR마다 1개, 규칙은 `AGENTS.md` §10)을 같은 빌드가 모아 버전명(날짜-그날 순번)을 붙인 `app/release-notes.json`을 배포물에만 만들고 `check-pages-build.mjs`가 모양·일치를 검사함(모양·계산은 `app/release-notes-model.mjs` 한 곳). 앱은 이 파일만 읽음: 새 버전 알림(`version-notice.js`)은 열릴 때 마지막 버전명을 메모리에 기억했다가 새 배포의 기록에서 그 뒤 것만 세어 한 줄 문구를 바꾸고, 내 프로필 맨 아래 접힌 칸(`release-notes-ui.js`)이 목록을 그림. 파일이 없거나 깨지면 알림은 예전 문구, 칸은 숨김. 서버·기기 저장 없음.

`desk.bokdoong.com`의 Cloudflare Worker(`cloudflare/bokdoong-router.mjs`)는 `?v=` 파일의 내용이 `app/asset-manifest.json`(해당 `?v=` 값과 SHA-256)과 같을 때만 엣지에 보관하고 브라우저에 1년 `immutable`로 보냄. 다르면(배포 전파 중 옛 내용 등) `no-cache`로 보내고 보관하지 않음. 목록은 배포 빌드가 같은 결과물에서 만들며 저장소에는 없음(`scripts/check-pages-build.mjs`가 해시·목록·Worker 판정을 검사함).

이미 옛 내용을 `immutable`로 받아 둔 브라우저는 다시 묻지 않으므로, Worker는 Web2 페이지(HTML) 응답에 브라우저마다 한 번 `Clear-Site-Data: "cache"`를 붙여 HTTP 캐시를 비우게 함(쿠키 `kptu_cache_epoch`로 한 번만). 다시 전체를 비워야 하면 Worker의 `CACHE_EPOCH`를 바꿔 배포함(§6 정지 지점).

## 2. 화면 전환 소유권

화면 전환은 `app-router.js`가 단독 소유함.

- 기본 메뉴: `index.html`의 `.app-nav [data-view]`, 폰 하단 `.mobile-tabs`, 메뉴 창의 `.mobile-menu-panel`을 라우터가 함께 관리함
- 홈 카드 등 이동 버튼: `data-goto`
- 모바일(760px 이하, 8-9e-2): 하단 탭은 홈·바구니·일정·프로젝트·담당조직·메뉴 6칸이고, 탭 이동은 하단 탭 누르기로만 한다(좌우 밀기 탭 이동은 UI-밀기탭이동삭제로 코드째 삭제, 2026-10-25 사용자 결정). [일정] 탭(`data-mobile-schedule-tab`)은 달력(`calendar`)과 할 일(`tasks`) 두 화면을 맡으며, 라우터가 화면을 바꿀 때 그 탭의 `data-view`를 마지막으로 본 쪽으로 맞춤(새 저장소 없음). 두 화면 위의 `[달력 | 할 일]` 전환(`.schedule-switch [data-view]`)도 라우터의 `data-view` 이동임. 옛 `?view=tasks`와 홈 "할 일 ›" 등 할 일로 가는 이동은 그대로 `tasks` 화면을 열고 [일정] 탭이 선택됨. 회의·자료실·게시판·계정은 [메뉴] 탭(`#mobileMenuTab`)이 여는 메뉴 판에서 열며(오른쪽 위 ☰는 폰에서 숨김) topbar-actions.js가 메뉴 이력과 계정 노드 이동을 소유함. 폰 메뉴 판(UI-디자인손질)은 하단 탭 바로 위로 올라오는 판으로, 위쪽 손잡이(누르면 닫힘, 아래로 밀면 닫힘)·전체 검색 칸·마지막 수집 시각·"계정" 상자(내 프로필·화면 색·로그아웃)·큰 칸 3열(노트·사업 보고·자료실·HWP 편집·공유 페이지·원장·통화·텔레그램 소식) 순서이고(UI-모바일메뉴순서: 큰 칸이 하단 탭 바로 위, 엄지 가까이. 화면 순서와 키보드 순서가 같도록 `index.html`의 순서 자체가 이 순서이며 CSS `order`로 뒤집지 않음. 판이 화면보다 길면 열 때 맨 아래로 스크롤해 위쪽이 잘리고 손잡이는 위에 붙어 남음), 바깥 누르기·Esc·뒤로 가기로도 닫힘. 하단 탭의 선택 표시(진하게)는 `mobile-tab-selection.mjs` 한 곳이 정하며 언제나 한 칸이다: 메뉴 판이 열려 있으면 [메뉴]만, 닫으면 지금 화면의 칸(메뉴 판으로 들어가는 화면과 [노트]는 [메뉴]). 라우터(화면이 바뀔 때)와 `topbar-actions.js`(판을 열고 닫을 때)가 같은 `KPTUMobileTabs`를 부르고, 모양은 CSS가 `aria-current="page"` 하나만 보고 그린다(`aria-expanded`는 모양을 켜지 않음). 성명·보도자료 메뉴 칸은 PRESS-자료실편입 Contract에서 없앴음(자료실의 종류 '성명·보도자료'로 합쳐짐). 메뉴에는 [쓰기] 항목이 없음(UI-쓰기메뉴삭제, 2026-10-22 사용자 결정). 쓰기 창은 새 통합 편집기 창(`ed-window.js`; 업데이트는 `update-window.js`, 노트는 `note-window.js`)이며 PC 상단 줄 [+ 추가] → [업데이트]·[노트](`topbar-actions.js` `openWriter`), 폰 홈·바구니 입력칸 ⤢, 바구니 노트 입력칸 ⤢가 연다(옛 마크다운 큰 창은 ED③ 순서 6에서 삭제). 761~1023px는 가로 메뉴와 ☰, 1024px 이상은 사이드바를 유지함
- 모바일 하단 고정(8-9e-2): 홈·바구니 빠른 입력(`home-quick.js`)은 하단 탭 바로 위에 붙고, 자판이 열리면 자판 바로 위로 올라감(뷰포트 `interactive-widget=resizes-content`, 지원하지 않는 브라우저는 `--kptu-keyboard-inset`). 폰 자판 감지(UI-키보드하단바)는 `accessibility-dialog.js` 한 곳(`KPTUA11y.keyboard`)이 앱 전체에서 맡는다: 760px 이하에서 입력 칸(textarea·input·select·contenteditable)에 초점이 있고 화면이 120px 넘게 줄면 `body.kptu-mobile-keyboard`(하단 탭 숨김, `--kptu-mobile-tab-height` 0)·`--kptu-keyboard-inset`·초점 있는 창의 `.modal-action-footer[data-keyboard-open]`을 함께 켜고, 화면이 다시 커지면 끈다(버튼을 누르느라 초점이 빠져도 화면이 커질 때까지 유지, 확대만으로는 켜지 않음). 쓰기 창·홈 빠른 입력·검색 등 모든 화면이 같은 상태를 쓰며 화면별 감지를 새로 만들지 않는다. 전체 화면 쓰기 창(`ed-window.js`)은 폰에서 하단 탭 위에서 끝나고, 탭을 누르면 창이 먼저 닫힌 뒤 그 탭으로 간다(글이 있는 메뉴 [쓰기]는 먼저 "저장 안 하고 닫을까요?"). 넓은 화면(761px~, UI-쓰기창PC탭유지)에서는 같은 창이 앱 메뉴(`#appView>.app-nav`: 1024px~ 왼쪽 세로, 761~1023px 위쪽 한 줄)를 덮지 않고 그 옆·아래 본문 자리에서만 열린다. 자리는 `placeBesideNav()` 하나가 메뉴 위치를 재어 `--ed-window-left`·`--ed-window-top`만 정하고(화면별 보정·지연 덮어쓰기 없음), 메뉴 항목을 누르면 폰 하단 탭과 같은 `onTab` 규칙이 적용되며, Tab 키 순환은 `accessibility-dialog.js`의 선택 인자 `companions`로 메뉴를 포함한다. 일정·할 일·프로젝트·자료실·회의·바구니 [노트]·일기의 추가 버튼은 같은 버튼을 하단 탭 위 오른쪽의 동그란 [+] 모양으로만 바꿈(ui-standard.css). 위치는 그 규칙 하나(화면 기준 `position:fixed`)가 정하므로 화면 칸(`.view-panel`)과 조상에 `transform`·`will-change`·`filter`·`contain`처럼 fixed의 기준을 바꾸는 값을 두지 않는다. 폰 밀기 전환(`mobile-swipe-navigation.js`)은 손가락을 옆으로 끌 때만 칸을 `left`로 옮기고, 손가락을 대기만 해서는 칸에 아무것도 바꾸지 않는다(UI-일기손질: 예전에는 누를 때마다 `will-change:transform`이 붙어 [+]가 잠깐 칸 아래로 갔다 돌아왔다). 밀기는 목록 위뿐 아니라 내용이 없는 빈 곳에서도 시작되며(라우터의 보이는 화면 칸이 따라 움직임), 열린 창(`.modal:not(.hidden)`·`dialog[open]`·보이는 `role=dialog`/`aria-modal`, [분류 결과 입력] 시트 포함)이 있으면 시작도 확정도 하지 않고, 입력칸·고른 글·실제로 가로 스크롤되는 줄에서는 시작하지 않는다(새 전역 상태 없음, UI-밀기전환). [일기]의 [+]는 고른 날짜(있으면 고치기), 고른 날이 없으면 오늘을 쓴다. 홈 빠른 입력(HOME-빠른입력정리)은 위에서부터 [할 일]의 프로젝트·기한 줄(할 일일 때만) → [바구니]·[할 일]·[업데이트 ▾] → 입력칸 순서이고, [업데이트] 옆 ▾(`data-quick-org`)가 기존 고르기 시트로 조직을 고르며 고른 조직은 입력칸 안내 글자로 보인다. 전환 버튼·필터의 고른 쪽은 어디서든 회색(`--ds-kind-other`), 안 고른 쪽은 흰 바탕이다(UI-선택표시통일, ui-standard.css). 크기(UI-버튼크기): 큰 버튼(`--ds-control-height` 46px)은 그 화면의 주 동작만 쓰고, 전환은 왼쪽에 붙은 작은 세그먼트(홈 [바구니|할 일|업데이트 ▾]·바구니 [메모|노트]·폰 [달력|할 일]·일정 ☰/▦·일정 창 [일정|할 일]), 필터·날짜 고르기는 알약 칩(바구니 [미분류·분류·보류]·자료실·회의·성명 필터·할 일 [오늘·내일·날짜]), 보조 버튼은 32px(`--ds-compact-*`, theme-tokens.css)이다. 보이는 높이는 32px이고 누르는 범위는 `::after`로 위아래를 늘려 44px. 전환·필터는 기기 기본 탭 하이라이트를 끄고(`-webkit-tap-highlight-color:transparent`) 누르는 동안 고른 쪽과 같은 회색이다. 홈 빠른 입력칸은 세 모드 모두 한 줄(46px)에서 시작해 `home-quick.js`의 `size()`가 글에 맞춰 늘리고 5줄에서 멈추며(그 뒤 칸 안 스크롤), [추가]는 첫 줄 옆 46px 그대로다(바구니 화면 입력칸은 CSS 높이 그대로). 바구니는 [메모|노트] 오른쪽에 필터를 한 줄로 두며(`basket.js`의 `.basket-switch-row`), 목록이 숨으면 CSS(`:has`)로 필터도 숨는다. 폰 전환 줄(UI-버튼작게 ③): 760px 이하에서 일정 네 화면의 `.schedule-switch`와 바구니 `.basket-kind-switch`는 아래 탭 바로 위 한 줄(줄 높이 44px = `--kptu-switch-dock`, 가운데 알약 32px)에 화면 기준 fixed로 놓이고(ui-standard.css 한 곳), 그리는 주인은 그대로 각 화면의 그 요소 하나다(복사본 없음). 이때 바구니 위쪽 줄에는 필터만 남는다. 자판이 열리면(`body.kptu-mobile-keyboard`) 아래 탭과 함께 숨고 `--kptu-switch-dock`은 0. 공용 [+]·빠른 입력·목록 끝 여백·알림은 `--kptu-switch-dock`만큼 위로 올라간다. 뒤로 가기(BUG-뒤로가기): 열린 것(창·메뉴 판·고르기 시트·화면 안 상세)이 있으면 뒤로 가기는 가장 위의 것 하나를 닫고, 아무것도 열려 있지 않을 때만 이전 탭으로 간다. 열린 것마다 같은 주소의 기록 1개를 갖는 것이 규칙이며, 브라우저·PWA의 뒤로 가기와 안드로이드 앱 뒤로(`native-back-guard.js`의 `KPTUNativeBack` v3 → `KPTURouter.back()`)는 같은 기록을 한 칸 되돌리므로 결과가 같다. 앞으로 만드는 창·화면도 이 규칙을 따른다: `.modal`은 `mobile-modal-history.js`가 폰 폭(760px 이하, 또는 `data-kptu-history-all`)에서 기록을 붙이고, 화면 안에서 여는 상세(바구니 메모 등)는 `KPTURouter.layer.open(name,{close})`로 연다. 화면의 닫기(‹·Esc)는 스스로 닫은 뒤 돌려받은 `close()`를 불러 그 기록을 되돌린다(‹와 뒤로가 같은 결과). 뒤로로 닫힐 때 여는 쪽의 `close({fromBack:true})`가 `false`를 돌려주면(저장 안 한 글을 버리지 않음) 기록을 다시 쓰지 않고 그 칸으로 돌아간다. 다른 탭으로 옮기면 그 화면의 layer는 라우터가 잊고(여는 쪽은 `kptu:view-changed`에서 닫음), 남은 기록은 다음 뒤로 가기에서 건너뛴다. 안드로이드는 Web2의 첫 기록에서 홈이 아니면 홈으로, 홈이면 누름을 소비한다(앱은 닫지 않음, 기존 APK 결정). 바구니 메모와 노트(`basket-notes.js`)는 목록에서 열면 목록 스크롤 위치를 기억했다가 뒤로·‹로 닫을 때 되돌린다.

새로고침 제자리(NAV-새로고침제자리): 새로고침(폰 당겨서 새로고침)해도 보던 자리가 그대로 나오도록, 주소는 라우터 하나가 맡는다. ① 정리함의 쪽은 `SUB_PARAMS`의 `?pane=`이며 [노트]가 `?view=basket&pane=note`로 적힌다(메뉴 [노트]는 `KPTURouter.go('basket',{sub:'note'})`, 화면 안 쪽 바꾸기·뒤로/앞으로는 `setSub`·`kptu:sub-changed`, 그리는 주인은 `basket.js` 그대로). ② 화면 안의 자리는 화면마다 표 `PLACE_PARAMS`에 적은 칸으로만 주소에 적힌다: 정리함 `note`(열린 업데이트)·`doc`(열린 노트)·`folder`(들어간 노트 폴더), 자료실 `folder`(들어간 폴더), 일기 `day`(고른 날 YYYY-MM-DD, 고른 날이 없고 이번 달이 아니면 YYYY-MM), 업무일지 `day`(오늘이면 생략)·`mode=week`, 달력 `date`(보이는 첫날, 오늘 기본이면 생략), 담당조직 `org`, 통화 `box=personal`·`call`. 화면이 `KPTURouter.setPlace(view,{칸:값|null})`으로 쓰고(replaceState, 기록을 따로 만들지 않음 — 열린 노트·업데이트·일기의 날처럼 layer가 있는 자리는 layer 기록 위에 적으므로 뒤로 한 번에 그 칸이 빠진 이전 기록으로 간다), 들어올 때 `KPTURouter.place(view)` 또는 모듈이 처음 읽힐 때의 주소로 되살린다(자료를 읽은 뒤 적용, 적용 전에는 쓰지 않음). 다른 화면·다른 쪽으로 옮기면 라우터가 이 칸들을 모두 지우고(각 화면은 새로 시작), 새로고침은 그대로 둔다. 값은 짧은 id·날짜 모양만 받는다. 기기 저장·새 서버 상태는 쓰지 않는다. 아직 주소에 적지 않는 자리(화면 메모리): 사업 보고 고른 회차·칩, 텔레그램 소식 방·날 상세·폴더·보관함, 할 일 상세, 원장 이야기·거르기, 공유 페이지 편집기, 폰 노트 나무의 펼친 폴더(들어간 폴더만 적음), 일기·자료실의 검색어·거르기. 시험: `tests/app-e2e/refresh-same-place.spec.mjs`. 닫히는 layer의 `history.back()`이 아직 도착하지 않았을 때 온 `setSub`·`setPlace`는 라우터가 붙잡아 두었다가 그 back이 도착한 뒤 쓴다(뒤늦은 back이 방금 더한 기록을 지우지 않게, 기록 스택 주인은 라우터 하나). 새로고침하면 화면이 모듈보다 먼저 보이므로 화면 훅 대신 `kptu:sub-changed`(정리함)·모듈을 읽을 때(담당조직·자료실·일기·업무일지)에 주소의 자리를 읽고, 기록에 남은 layer 목록(폰 노트 폴더 화면, 그 위 노트)은 같은 순서로 다시 열 때 기록을 더하지 않고 제자리를 맡는다. 자료실의 `?folder=`는 폴더 묶기도 뜻하므로 그 방문 동안 폴더 묶기로 연다(새로 저장하지 않음).

고르기 시트(`choice-sheet.js`, 모양 `choice-sheet.css`)는 폰(760px 이하)에서 메뉴 판·쓰기 창처럼 하단 탭 바로 위에서 올라오고 탭을 덮지 않는다(자판이 열려 탭이 숨으면 화면 맨 아래). 탭 위에 겹쳐 있으면 맨 아래 줄을 누른 뒤 같은 자리를 한 번 더 누를 때(시트는 이미 닫힘) 그 아래 탭이 눌려 다른 화면으로 갔다(BUG-내보내기탭이동). 시트를 쓰는 모든 곳(쓰기 창 [내보내기]·"저장 안 하고 닫을까요?", 홈·바구니 빠른 입력, 바구니 [연결하기], 일정 창 프로젝트)이 이 한 규칙을 따른다.

누른 자리 펼치기(UI-PC팝업위치): 넓은 화면(761px~)에서는 같은 고르기 시트가 아래에서 올라오지 않고 누른 버튼 바로 아래(자리가 없으면 위, 위아래 모두 없으면 옆)에 작은 목록으로 열린다. 화면을 어둡게 하지 않고, 바깥 누름·Esc·×로 닫히며, 열 때 고른 항목(없으면 첫 항목)에, 닫을 때 누른 버튼에 초점이 간다. 너비 360px(조직 칩처럼 한 줄에 여럿 놓는 목록은 480px), 높이는 최대 480px(칩 560px)이고 남는 것은 목록 안에서 스크롤된다. 창 크기 바꾸기·바깥 스크롤에는 버튼을 따라가고, 버튼이 화면 밖으로 나가거나 사라지면 닫힌다. 폭이 760px 이하로 바뀌면 그 자리에서 하단 시트가 된다. 위치 계산은 `anchored-popup.js` 하나가 맡는다: `placeAnchored(panel, anchor, {maxWidth, maxHeight})`가 `position:fixed`인 판의 자리·최대 높이를 정하고(창 밖으로 나가지 않음), `followAnchor(panel, anchor, {place, lost})`가 스크롤·창 크기 변경을 따라가며 돌려준 `stop()`으로 끝낸다. `isWide()`가 폰/PC 구분이다. 고르기 시트(`createChoiceSheet`)는 이 둘을 이미 쓰므로 여는 쪽은 `open(kind, trigger)`만 부르면 되고, 버튼이 아닌 다른 상자 옆에 펼칠 때는 `open(kind, trigger, anchor)`(초점은 trigger로 돌아감), PC에서도 하단 시트로 두려면 `anchored:kind=>false`를 준다. ⋯ 메뉴처럼 시트가 아닌 작은 판도 같은 두 함수로 자리를 잡는다(새 위치 계산을 만들지 않음). 노트의 ⋯ 메뉴(UI-노트메뉴정리: 목록 줄·열린 노트 공용 `#noteDocMenu`, 폰·PC 같은 항목, `basket-notes.js`)가 그 예다. 노트 줄 미리보기 글(마크다운 기호 제거·제목 중복 제거)과 [복사] 내용은 `note-preview.mjs`가 맡는다. 노트 폴더(UI-노트폴더 1단계, `docs/design/note-folders.md`): 폴더는 노트 행의 기존 `metadata.folder`(이름 하나, 1~20자, 최대 30개, 노트에만, DB 변경 없음)이고 폴더 목록은 노트들이 가진 이름을 모은 것이다(따로 저장하지 않아 노트 없는 폴더는 이 화면 메모리에만 잠시 있음). 검색칸 아래 한 줄 [전체]·폴더들·[폴더 없음](공용 `filter-chips.js`) + 줄 끝 폴더 ⋯([새 폴더]·[폴더 이름 바꾸기]·[폴더 지우기])를 `basket-notes.js`가 그리고, 노트 ⋯의 [폴더로 옮기기]는 공용 고르기 창(`createChoiceSheet`)을 연다. 고른 폴더는 모듈 메모리에만 둔다. 폴더·고정 쓰기는 `basket-data.js`의 한 경로(`patchNoteMetadata`)가 다시 읽고 다른 metadata 칸을 그대로 두며 `updated_at`·`pinned_at`·`folder`가 읽은 때와 같을 때만 저장한다(`updated_at`은 바꾸지 않음). 폴더 이름 바꾸기·지우기는 노트마다 저장하고, 중간에 실패한 노트는 [다시 시도]로 마저 한다. [바구니로 돌리기]는 같은 조건 저장으로 `folder`를 지운다.
노트 첨부(NOTE-파일붙이기): 노트의 파일은 업데이트와 같은 `app_notes.attachments`(DB 변경 없음)이고, 올리기는 같은 `basket-files`에 노트 id를 보내는 한 경로(`basket-upload.js`의 `uploadNoteFiles`, 사진 글자 읽기 없음)다. 서버가 행의 `kind=note`를 보고 Drive "Web2 바구니/노트 첨부"(공유된 폴더 거절)에 올린다. 노트 입력칸(`home-quick.js` noteOnly)은 업데이트 입력칸과 같은 클립·끌어 놓기를 쓰고 [추가] 때 노트를 먼저 만든 뒤 파일을 올린다(파일만이면 첫 파일 이름이 제목). 큰 편집 창(`ed-window.js`)은 [📎 첨부]를 창 아래 줄에 두며(쓰기 창 [노트]·노트 [큰 창에서 수정]), 고른 파일 목록은 본문 아래에 남는다. 첨부는 본문 아래 공용 파일 줄(종류·이름·크기·[Drive에서 열기]) + ⋯ → [빼기](`basket-data.js`의 `detachNoteFile`: 다시 읽고 `updated_at`이 같을 때만 `attachments`에서 그 항목만 지움, Drive 무변경). 본문 없이 파일만 있는 노트는 "본문이 없는 노트입니다." 상자 없이 파일 줄만 보인다. 노트 삭제는 연결과 노트만 지우고 파일은 Drive에 남긴다(`deleteNoteOriginal`의 `keepFiles`).
고르기 창 내용(UI-고르기창개선, PC만): `choice-sheet.js`가 프로젝트 줄(`projectRow`/`projectRows`)과 조직 묶음 줄(`orgGroupRows`)을 함께 만든다. `render()`가 `search`(검색칸 이름)를 돌려주면 목록 위(스크롤 밖)에 검색칸이 생기고 이름으로 거른다(빈 묶음·칸 숨김, ↓로 첫 항목). PC 목록에서 프로젝트는 한 줄에 하나·작은 체크칸·하위는 들여쓰기와 흐린 글자(↳ 없음)·고른 줄 연한 초록이고, 담당조직은 묶음마다 한 줄(왼쪽 묶음 이름, 오른쪽 24px 칩, 고른 칩 초록 + ✓, 이름은 줄이지 않음)이다. 묶음과 순서는 `organization-order.js` 하나(철도/지하철/민자철도/민간도시철도, 밖은 "그 외")이며, 묶음에 든 조직이 없으면 묶음 이름 없이 한 묶음이다. 폰(아래 시트)은 검색칸·묶음 이름·체크칸 없이 예전 모양 그대로다. 쓰는 곳: 바구니·노트 [연결하기]의 담당조직·프로젝트와 할 일 만들기 프로젝트, 홈·쓰기 창 [업데이트 ▾] 기록할 곳, 홈 [할 일] 프로젝트, 일정 창 프로젝트. 할 일 상세의 "연결할 프로젝트·조직" 체크 목록(`google-tasks.js`, 창이 아닌 체크 목록)도 PC에서 하위 ↳를 숨기고 들여쓰기·흐린 글자, 조직 묶음 이름을 보인다(열 수는 #776 규칙 그대로).
기록할 곳 창(UI-기록할곳창PC·UI-기록할곳되돌리기): `render()`가 `split:true`를 주는 창(홈·쓰기 창 [업데이트 ▾])은 넓은 PC(1024px~)에서 너비 최대 880px·버튼 아래 남은 높이(최대 760px)로 열리고, 검색칸이 제목 옆으로 가며, "최근" 한 줄 아래에 왼쪽 담당조직 / 오른쪽 프로젝트 두 열(`data-sheet-col`)이 놓인다. 항목이 많으면 창이 아니라 각 열 안에서만 스크롤된다. 761~1023px와 폰은 예전처럼 위아래(최근 → 담당조직 → 프로젝트). 조직·프로젝트에 업데이트를 추가하면 홈 입력은 바구니(미분류)로 돌아가고, 방금 쓴 곳은 다시 불러오거나 로그인이 바뀌기 전까지 "최근" 맨 앞에 남는다(`update-places.js`의 `rememberPlace`, 메모리만). 추가 없이 다른 화면에 다녀오거나 [크게] 창을 저장 없이 닫아도 바구니로, 추가가 실패하면 고른 곳을 유지한다. 홈 [할 일]의 [프로젝트 ▾]도 추가가 끝나면 "프로젝트 없음"으로 돌아간다.

창 머리 고정(UI-팝업머리고정): 모든 창(`.modal-card`)의 맨 위 제목 줄(`.modal-head`, 닫기 × 포함)은 폰·PC 모두 창 위에 붙어 있고 본문만 스크롤된다(base-ui.css 한 규칙). 저장 버튼은 창 아래 고정 줄(`.modal-action-footer`)에 둔다: 이미 그 줄이 있던 창(일정·할 일·프로젝트 만들기 등)은 그대로, 저장이 내용 끝에 있던 창(자료 수정, 담당조직 추가·담당자 지정, 협의회·사업단 소속, 타임라인 추가, 주간보고 수정, 회의 결과 수정)은 이 줄로 옮겼다(폰 엄지 위치, 자판이 열리면 줄은 제자리). 상세 ⋯ 자리(UI-더보기제목줄): 상세의 ⋯는 혼자 한 줄을 차지하지 않고 제목(제목이 없으면 첫 줄 글자) 오른쪽 끝에 둔다. 공용 규칙은 `base-ui.css`의 `.kptu-title-line`(글자 + ⋯ 버튼 두 칸 가로 배치, 글자는 ⋯ 옆으로 비켜 줄바꿈). 통화 상세가 쓴다. 프로젝트 상세(`.ps3-modal-head`)·담당조직·사업 보고·정리함/노트 상세·텔레그램 소식은 이미 제목·뒤로가기·글자와 같은 줄이라 그대로이며, 원장 상세는 `ledger-import.css`의 자체 규칙(#1187)을 쓴다.

사업 보고 입력 창 칸·기본 일시(MTG-보고창칸정리·MTG-보고창기본일시, 2026-10-27): 창 안 한 줄 입력·고르기 칸 높이는 `--ds-field-height`(28px) 하나이고 `ui-standard.css`의 `.modal input/select` 공용 규칙과 `.field-btn`(칸처럼 생긴 고르기 버튼, ▾는 `::after`로 오른쪽 끝)이 맞춘다(창마다 따로 덮지 않음). 날짜 칸의 보이는 글자는 `time-input.js`가 'YYYY-MM-DD' 한 가지로 그리고(`.dt-date`), 기기 달력(`input type=date`)은 그 위에 투명하게 겹쳐 눌러서 고른다. 새 입력 창의 [일시] 기본값은 `report-default-at.mjs`의 `defaultReportAt` 하나가 정하고(오늘 한국 날짜 + 10:00, 구글 일정·날짜만 있는 길은 받은 값), `team.js openMeetingModal`만 부른다. 저장된 보고를 고치는 창은 쓰지 않는다. 고른 줄 표시는 공용 `.kptu-pick-row`(연한 강조 바탕 + 왼쪽 굵은 줄 + 진한 글자, 색 열 가지 값 사용)이고 사업 보고 3단 첫 칸이 쓴다.

각 기능 모듈은 직접 모든 `.view-panel`을 숨기거나 활성 메뉴를 다시 계산하지 않음. 화면 전환이 필요하면 `window.KPTURouter.go(view)`를 사용함.

화면 진입 때 추가 작업이 필요하면 클릭 핸들러를 또 만들지 말고 `window.KPTURouter.on(view, callback)`을 사용함. 캘린더와 알림 화면의 진입 후 갱신도 이 방식으로 연결함.

## 3. 세션·API 공용 런타임

`runtime-client.js`가 세션 읽기·저장·만료 확인·refresh token 갱신 잠금과 공용 API 호출을 제공함.

2차 안정화 기준 공용 런타임을 사용하는 주요 모듈:

- `team.js`
- `library-upload.js`
- `collaboration-center.js`
- `notification-center-ui.js`
- `calendar-persistence.js`
- `task-workflow.js`
- `meeting-round-detail.js`

일정·할 일·프로젝트·회의 핵심 보조 모듈에 남아 있던 별도 세션 저장·refresh token 갱신 로직을 제거함. 여러 모듈이 동시에 refresh token을 사용해 각각 세션을 갱신하지 않도록 `runtime-client.js` 안에서 하나의 refresh promise를 공유함.

로그인 방식, Google OAuth 진입·복귀 방식, 세션 저장 키와 DB 구조는 변경하지 않음.

## 7. 변경 규칙

- 화면 이동은 `app-router.js`만 담당함.
- 새 창·판·상세 화면은 열 때 기록 1개를 갖고 뒤로 가기로 가장 위의 것부터 닫혀야 함(2절 "뒤로 가기"). 화면별 popstate 임시 처리·지연 덮어쓰기를 만들지 않음.
- 같은 버튼에 여러 모듈이 `onclick`/`click`을 중복 등록하지 않음.
- 세션 refresh 로직을 기능 모듈에 새로 만들지 않고 `runtime-client.js`를 사용함.
- DOM 생성 시점을 기다리기 위한 전역 `MutationObserver`는 최후 수단으로만 사용함. 가능하면 명시적 이벤트를 사용함.
- 단순 CSS 변경을 JavaScript 주입 모듈로 만들지 않음.
- 새 기능은 기존 소유 모듈에 통합하는 것을 우선함.
- 비활성 파일은 바로 삭제하지 않고 의존성 검사 후 `legacy`에 격리함.
- 사용자 기능 변경과 인증·세션 구조 변경을 한 커밋에 섞지 않음.

두 검사는 작업 브랜치의 매 커밋마다 실행하지 않고 `main` 반영 또는 `main` 대상 Pull Request에서 실행하도록 제한함. 개발 중간 실패 메일이 반복되는 문제를 줄이고, 반영 직전 회귀검사에 집중함.

## 9. 2차 안정화 이후 운영 방식

2차 안정화 이후에는 별도의 대규모 구조개편을 계속하지 않음.

1. 기능 개발은 기존 소유 모듈에 통합함.
2. 변경 전후 정적 smoke와 브라우저 E2E를 회귀 기준으로 사용함.
3. 실패가 발생한 기능 단위만 수정함.
4. 인증·Android OAuth·DB 구조는 별도 필요가 확인되지 않는 한 유지함.
5. 새 보정 파일을 늘리기보다 공용 라우터·공용 런타임·명시적 이벤트 구조를 유지함.

- 원장 재료 C-4(개인 공유 캘린더 참고 일정, 설계 `docs/design/ledger-sources.md` 5절): 판단 규칙은 `calendar-ref-model.mjs`(순수), 서버 읽기·쓰기는 `calendar-ref-data.js`(owner RLS REST만, 브라우저 저장소 없음), 고르기 화면은 `calendar-ref-settings.js`가 `profile-settings.js`의 `#psCalRefPanel` 안을 그린다(칸 하나에 renderer 하나, 프로필 [저장]과 따로 바로 저장). 업무일지는 `journal.js`의 reader `calendarRefs`가 한 주를 맞추고 읽으며, 하루 카드 접힌 줄은 `journal.js`, [주간 정리] '참고' 묶음은 `journal-weekly.js`가 그린다(체크 저장은 `journal.js`의 한 핸들러). 주간보고 '5. 주요 일정'에는 섞지 않는다.
